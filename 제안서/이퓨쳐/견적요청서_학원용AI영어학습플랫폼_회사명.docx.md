**1\.  문서의 목적**

당사는 **학원(어학원·입시학원)을 대상으로 한 AI 영어 학습 플랫폼** 구축을 추진하고 있으며, 이를 함께 개발할 파트너사를 선정하고자 합니다. 본 문서는 개발 범위·기술 요건·단계별 로드맵을 공유하고, 이에 대한 **개발 비용 및 개발 기간 견적**을 요청하기 위한 제안요청서(RFP)입니다.

정확하고 **업체 간 비교가 가능한 견적**을 받기 위해, 아래 6\~9장의 **표준 회신 양식**에 맞추어 회신해 주시기 바랍니다. 총액만 기재된 견적은 평가에서 제외될 수 있습니다.

|  | 회신 시 유의사항 · 본 RFP는 확정된 상세 기능명세서가 아닌 사업기획 단계의 요건 정의서입니다. 불명확한 부분은 '가정(Assumption)'으로 명시해 주십시오. · 견적은 (1) 초기 개발비와 (2) 월 운영비/라이선스를 반드시 분리하여 기재해 주십시오. · 외부 AI(LLM) API 사용료 등 변동비는 개발비와 별도로 산정해 주십시오. |

**2\.  사업 및 플랫폼 개요**

AI가 각 학원에 맞춘 **원본 학습 콘텐츠를 생성**하고, 그 콘텐츠로 **중·고등 내신형 교재(POD)를 출판**하며, **진단 → 처방 → 실행 → 증명**의 루프로 학생의 성장을 데이터로 증명하는 학습 플랫폼입니다.

**2-1. 서비스 정체성 및 설계 원칙**

“AI가 학생의 약점을 자동으로 진단하고, 성장을 데이터로 증명하는 학습 플랫폼”

| 원칙 1 | 학생이 얼마나 성장했는지 측정 가능해야 한다 |
| :---- | :---- |
| **원칙 2** | 학습효과가 얼마나 개선되었는지 알 수 있어야 한다 |
| **원칙 3** | 축적된 데이터로 다시 서비스 개선에 연결할 수 있어야 한다 |
| **원칙 4** | 자동화는 선생님의 업무를 '줄여야' 하며, 업무를 늘리는 방향으로 설계되어서는 안 된다 |

**주요 사용자 역할(권한):** 학원장(승인·관리) · 강사(수업·검수) · 학생(학습·응시) · 학부모(성장 리포트 열람)

**3\.  개발 범위 (기능 모듈)**

전체 서비스는 아래 **수업 준비(A) · 수업 실행(B) · 관리(C)** 3개 영역, 8개 기능 모듈로 구성됩니다. 각 모듈 단위로 공수·기간·비용을 산정해 회신해 주십시오.

| No. | 기능 모듈 | 주요 요구 기능 (요약) |
| :---: | ----- | ----- |
| **M1** | **AI 콘텐츠 생성 엔진** | 4영역(독해·문법·어휘·서술형) 원본 지문·문항 자동 생성 · 프롬프트/형식 워크벤치 · 난이도·범위 조건 지정 · 원본 저작권 자산 귀속 |
| **M2** | **교재 스튜디오 / POD 출판** | 생성 콘텐츠 편집·조판·QA · 앱 eBook 변환 · 실물 교재 POD(주문형 인쇄) · 인쇄·유통 연동 · 원장 형식 템플릿 · 북빌더 |
| **M3** | **진단 모듈** | 2종 테스트(PT 배치·AT 성취) · 적응형 CAT · 15분 공통 서브테스트 · 학습 난이도 초기값·구간 증명 산출 |
| **M4** | **수업 실행 모듈** | 4영역 데일리 수업·시험 운영(Reading·Writing·Vocabulary·Speaking) · 과정 데이터(시도·시간·오답 패턴) 수집 |
| **M5** | **QR·OCR 채점** | 종이 시험지 QR 결속 · 손글씨 OCR 채점 · 자동 오답 정리 · 진단 데이터 연동 |
| **M6** | **성장 리포트 / 관리** | 월간 성장 리포트 자동 생성(레벨·속도·델타) · 과정 데이터 대시보드 · 학부모용 성장 증명 · 재원 관리 연동 |
| **M7** | **구독·결제·승인 게이트** | 학생당 구독 SW(recurring) 결제 · 학원장 검수/승인 게이트(HITL) · 미승인 콘텐츠 발행·POD 차단 |
| **M8** | **역할별 화면 / 계정** | 학원장·강사·학생·학부모 4개 역할별 웹/앱 화면 · 권한관리 · 학원(다중 테넌트) 계정 체계 |

|  | 의존 관계 주의 (반드시 견적서에 반영) · M1(생성 엔진)은 M2(교재)·M3(진단)·M4(수업)의 상류 모듈로, 우선 개발이 필요합니다. · 문법·채점 모듈(M4/M5)이 없으면 생성 엔진(M1)의 문법 문항 활용 루프가 끊깁니다 — 상호 의존 관계를 일정에 반영해 주십시오. |

**4\.  개발 단계 및 우선순위 (로드맵)**

검증된 자산(원본·콘텐츠)을 먼저 확보한 뒤 목적형 기능을 얹는 순서로 개발 리스크를 낮춥니다. **P1(파일럿)은 상세 견적, P2·P3는 개략 견적**으로 구분하여 회신해 주십시오.

| 단계 | 성격 / 목표시점 | 핵심 범위 | 포함 모듈 |
| :---: | ----- | ----- | ----- |
| **P1** | 파일럿 / 12월 (MVP · 상세 견적) | 콘텐츠 생성 엔진 \+ 교재 스튜디오 — 내신형 원본 콘텐츠·문항 생성, 검수 승인 게이트, 북빌더 → 앱 eBook \+ 실물 POD | M1, M2, M7(승인·결제 최소), M8(기본 화면) |
| **P2** | 정규 / 상시 운영 (개략 견적) | 정규 스택 — 4영역 학습 모듈, 적응형 진단(PT/AT), 과정 데이터 수집, 월간 성장 리포트 자동 완성 | M3, M4, M6, 문법(Grammar) 영역 신설 |
| **P3** | 방학 / 신규 유입 (개략 견적) | 방학 스피킹 \+ 진단 온보딩 — 단계별 말하기 커리큘럼, 발화량·마스터리 대시보드, 신입생 진단 온보딩 | Speaking 강화, 온보딩 진단 |
| **후속** | 조건부 (참고 견적) | QR·OCR 채점 고도화 — 종이·디지털 브리지, 내신 exact 대비 | M5 고도화 |
