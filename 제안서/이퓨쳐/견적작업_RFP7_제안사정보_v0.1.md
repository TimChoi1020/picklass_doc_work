## 0. 평가 배점 대응 — 이 문서가 겨냥하는 지점

| RFP §9 평가 항목 | 배점 | 본 문서 대응 |
|---|:---:|---|
| **기술 역량 / 유사 실적** | **30** | §2 유사 실적 · §3 기술 역량 ← **최대 배점** |
| 요구사항 이해 / 제안 충실도 | 25 | *(6-1~6-4 + 별첨 A·C가 담당)* |
| 개발 비용 합리성 | 25 | *(§3-3 단가표 + 별첨 C WBS가 담당)* |
| 일정 / 실행 가능성 | 10 | §4 개발 방법론 · 마일스톤 |
| **유지보수 / 사후지원** | **10** | §5 하자보수 · SLA |
| | **100** | |

> ★ **§7은 40점(30+10)을 직접 겨냥한다.** 특히 **기술 역량 30점은 단일 최대 배점**이며, 우리는 **이미 운영 중인 자산**이라는 가장 강한 형태의 증거를 갖고 있다.

## 3. 기술 역량 ✅ *(근거 확보됨 — 최대 배점 구간)*

### 3-1. AI / LLM 활용

**운영 중인 구성**

| 구분 | 현황 |
|---|---|
| LLM | **Anthropic Claude** (Tool Use) · **Google GenAI** |
| 음성 | **Azure Speech (TTS)** · **Google STT** |
| 생성 방식 | ★ **On-demand 생성** — 모듈 진입 시점 실시간 생성 (선생성 미채택) |
| 원가 추적 | 도메인에 **`AIUsage` 엔티티** 설계 — 학생·문항 단위 사용량 집계 |

**본 사업 제안 구성 — 3-tier 모델 배치**

| 모델 | 단가 (입력/출력, $/1M) | 용도 |
|---|---:|---|
| Claude Opus 5 | $5 / $25 | 서술형 내용 채점 · 리포트 코멘트 |
| **Claude Sonnet 5** | $3 / $15 | **원본 문항·지문 생성 (주력)** |
| Claude Haiku 4.5 | $1 / $5 | 어휘·규칙형 채점 · 분류 (대량) |

**원가 최적화 실적 — 학생 1인 월 $1.164 → $0.835 (−28%)**

| 장치 | 절감 | 상태 |
|---|---|---|
| **프롬프트 캐싱** | 캐시 읽기 0.1배 (60% 히트) | 적용 |
| **Batch API** | 야간 일괄 생성분 −50% | 적용 |
| **On-demand 생성 원칙** | 미사용 콘텐츠 생성 비용 0 | ★ **아키텍처 반영 완료** |
| 모델 티어링 | Haiku ↔ Opus 5배 단가 차 활용 | 적용 |

> ★ **이 표가 기술 역량 30점의 핵심 증거다.** "LLM을 쓸 줄 안다"가 아니라 **"LLM 원가를 28% 설계로 낮춘다"** 는 것이 차별점이다. 단일 모델을 무조건 호출하는 제안과 갈린다.

### 3-2. 적응형 진단 ✅

| 자산 | 내용 |
|---|---|
| **레벨 체계** | **PPS(0~100) → CEFR 7밴드 → 파트너 레벨 L1~L18** 3단 매핑 (설계 확정) |
| **CAT 알고리즘** | 능력 추정 · 문항 선택 · 종료 조건 판정 설계 완료 |
| **역량 모델** | 8대 역량 (Speaking·Reading·Listening·Writing·Vocabulary·**Grammar**·Fluency·Pragmatics) |
| 문서 | [06_진단평가_PPD](../../기획문서/00_공통/06_진단평가_PPD.md) 상세기획 확정 |

> ★ 이퓨쳐가 요구하는 **학년·교육과정 성취기준 축**은 이 3단 매핑의 **파트너 레벨 슬롯을 재활용**한다 — 신규 체계 구축이 아니라 **축 하나를 추가**하는 작업이다(M3-04).

## 4. 개발 방법론 · 프로젝트 관리 ✅

### 4-1. 방법론

| 항목 | 내용 |
|---|---|
| 개발 방식 | **산출물 단위 반복 개발** — 산출물 52건을 에픽으로 전환해 2주 단위 인도 |
| 산정 기준 | **표준 단위공수 원단위표**(화면 A~E · 리포트 R · 연동 N · 엔진 G) 기반 (§3-3) |
| 학습 모듈 | 모듈당 **2주 (개발 1주 + 테스트 1주)** — **실측 단위공수** |
| 품질 관리 | 산출물별 단위·기능 테스트 → 단계별 통합 테스트 |
| 변경 관리 | **CR 단가표 = §3-3 원단위표** 를 그대로 적용 (범위 고정 원칙) |

### 4-2. 마일스톤 (5인 투입 · 8월 초 착수 기준)

| 단계 | 기간 | 주요 산출물 | 완료 시점 |
|:---:|:---:|---|---|
| **P1** 파일럿 | **11주** | 생성 엔진 · 교재 스튜디오(북빌더→POD·eBook) · 검수 승인 게이트 · 연동 | **10월 하순** |
| — | — | **파일럿 개시** (학원 5~10개소) | **11~12월** |
| **P2** 정규 | **15주** | 학습 모듈 9종 · 문법 영역 신설 · 적응형 진단(PT/AT) · 성장 리포트 | 3월 중순 |
| **P3** 방학 | **0주** | ★ **기보유 완료 자산으로 충당 — 추가 개발 없음** | — |
| 후속(조건부) | 3주 | QR·OCR 채점 | 협의 |

> ★ **P3가 0주·0원**인 것이 표에서 드러난다. RFP가 정식 단계로 요구한 범위 하나를 **완료 자산으로 충당**한다.

| 인도 | 운영 매뉴얼 · 관리자 가이드 · 인수인계 문서 |

### 4-4. 프로젝트 관리

| 항목 | 방식 |
|---|---|
| 진척 관리 | 산출물 ID 단위 이슈 트래킹 (별첨 C WBS = 에픽 목록) |
| 보고 | 주간 진척 보고 · 단계별 종료 보고 |

| **AI 원가 모니터링** | ★ 학생당 월 사용량 리포트 제공 — **상한(3,500원) 초과 시 사전 통보** |

> ★ **AI 원가 모니터링 제공은 타사가 쓰기 어려운 항목**이다. `AIUsage` 엔티티가 도메인에 이미 설계돼 있어 **즉시 가능**하다.
