## 6. 결론

### 6.1 최대 리스크는 CLR 문항 수 폭주 ★

CLR은 `question_max_count = 1`인데 실제로 **지문당 13.3문항**이 생성된다(§3-C).
holistic 채점이라 문항 수 = LLM 콜 수이므로 그 모듈만 **4.0원 → 25.3원 (6.3배)** 이 되고,
CLR이 편성된 레슨(53개)의 원가가 **19.5 → 40.8원 (2.1배)** 로 뛴다.

- 원인은 생성 지시문이 `question_max_count`를 무시하는 것 — speaking LRN에서도 관측된 공통 문제
- **운영 시작 전에 잡아야 한다.** 실사용이 96건뿐인 지금이 가장 싸게 고칠 시점이다
- 조치: CLR `content_generation_instruction` 점검 → 문항 수 상한을 프롬프트에 명시하거나,
  생성 후 `question_max_count` 초과분을 잘라내는 가드 추가

### 6.2 KPI description 콜이 원가의 40~70%를 먹는다

`generateLlmKpiDescriptions`는 **모듈 종료마다 1회**(2.28원) 호출된다.
평균 5.9모듈 레슨이면 **13.5원** — 대표 레슨 런타임 19.5원의 **69%**다.

레슨 종료 시 전 모듈 KPI를 모아 **1콜로 통합**하면 13.5 → 2.3원(**−11원, −57%**).
설명문은 학습자에게 레슨 리포트에서 한 번에 보이므로 모듈마다 나눠 부를 이유가 약하다.

### 6.3 튜터링 레슨은 speaking의 약 1/5이다

| | speaking 정규 레슨 | 튜터링 대표 레슨 |
|---|---:|---:|
| 사전생성 / 지문 | 105원 (LLM 56 + TTS 49) | **35원** (LLM만) |
| 세션 런타임 | 148원 | **19.5원** |
| 지배 원가 | **STT 99%** | **LLM 채점 84%** |
| N=1.9 레슨당 | **203원** | **38원** |
| N=10 레슨당 | 159원 | **23원** |

차이의 원인은 단순하다 — **발화 채점(STT)이 거의 없다.** speaking은 레슨당 210초를 채점하는데
튜터링은 음성 모듈(RRD·WSD)이 편성된 레슨만 21~34초다. TTS도 사전 합성 자산이 없어 사전생성이 가볍다.

### 6.4 N 민감도는 speaking과 비슷하다

사전생성 35원 : 런타임 19.5원 = **1 : 0.56** — 오히려 사전생성 비중이 speaking보다 높다.

| N | 레슨당 원가 | 사전생성 비중 |
|---:|---:|---:|
| 1 | 54.5원 | 64.2% |
| 5 | 26.5원 | 26.4% |
| 10 | 23.0원 | 15.2% |
| 50 | 20.2원 | 3.5% |

절대 금액이 작아 우선순위는 낮지만, **비율로는 튜터링이 N에 더 민감하다.** 지문 351건에
과정 86개뿐이라 재사용률 관리가 speaking보다 중요할 수 있다.
