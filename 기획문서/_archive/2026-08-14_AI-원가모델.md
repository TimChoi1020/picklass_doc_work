## 1. 원가 구분 — 사전생성(고정) vs 세션 런타임(변동)

| 구분 | 발생 시점 | 과금 대상 | 상각 |
|---|---|---|---|
| **사전생성(고정)** | studio 지문 등록 1회 | ① 문항·핵심표현·대화문 생성 **LLM 11콜**<br>② 모듈 콘텐츠 **TTS 합성** | 콘텐츠당 1회 → 재사용 학습자 N명으로 분할 |
| **세션 런타임(변동)** | 학습자가 학습할 때마다 | **STT(실시간 전사 + 발음평가)** · SMK/OMP 코칭 **LLM 2~3콜**<br>(FRT만 예외 — TTS·LLM도 런타임) | 학습자·세션당 매번 발생 |

**모듈 TTS가 사전생성인 근거** — 세 문서가 일치한다:

| 출처 | 문장 |
|---|---|
| 마스터플랜 §6 (`2026-06-04_마스터플랜.md:447`) | "종속돼 **사전 생성·저장**되므로, 보이스를 고르게 하면 콘텐츠 자산이 보이스 수만큼 배수가 된다" |
| 마이페이지 §12.1 (`2026-07-09_...:501`) | "모듈 콘텐츠(SHD·SFB·LRN…)의 음성은 **지문에 붙어 미리 생성·저장**된다" |
| 같은 문서 `:514` 표 (2026-08-10 결정) | 정규 모듈(SHD·SFB·LRN·SMK·VLM 등) → **사전 생성**(지문 종속) / **FRT → 런타임** |

→ **SHD 3패스·VLM 단어 3회 반복은 저장 오디오의 재생**이며 합성 과금은 1회뿐이다.
정규 모듈의 런타임 TTS는 **0원**(스토리지·CDN 전송만, 본 모델 범위 밖).

## 4. 사전생성 원가 (지문 1건)

### 4.1 LLM 11콜 — 56원

콜 수는 확정값이다(사전생성 개발계획 §4.1 unit DAG). 토큰은 추정.

| 항목 | 값 |
|---|---:|
| 입력 토큰 합 (11콜) | 22,300 |
| 출력 토큰 합 (thinking 2.5× 가정 포함) | 20,000 |
| 원가 | 22,300 × 0.00021 + 20,000 × 0.00175 = 39.7원 |
| 실패·재시도 보정 ×1.4 (실측 15/11콜) | **≈ 56원** |

> `gemini-2.5-flash`는 thinking 기본 ON이고 `ai.service.ts`에 `thinkingConfig`가 없다 →
> 출력 원가의 대부분이 사고 토큰일 수 있다. 런타임처럼 Flash-Lite로 내리면 56 → **10원** (§7-2).

### 4.2 TTS 합성 — 49원 (밴드 39~59원)

반복 재생분은 제외한다(저장 오디오 재생 = 합성 과금 없음).

| 근거 | 문자 수 | 원가 |
|---|---:|---:|
| 실측 문항 데이터 총량 (§3-E) — **상한** | 11,499 | 241원 |
| TTS 대상 bottom-up 추정 (영어 발화문·안내문만) | 1,850 | 39원 |
| 상한의 25% 가정 | 2,800 | 59원 |
| **채택 (중앙값 2,300자)** | **2,300** | **≈ 49원** |

bottom-up 내역: LRN 270(표현 카드 3) · VLM 390(6어휘) · SHD 180(3문장) · SFB 180 · SMK 120 · RPB 280(AI 4턴) · RPF 350(AI 5턴) · OMP 80 = 1,850자

**멘트는 미포함** — DB 구조가 아직 없다(§3-D). 시나리오 §8.3대로 `seed_messages`·`slot_templates`를 구현하면 모듈당 약 280자 × 8 = 2,240자 → **+47원**.

## 6. 결론

### 6.1 재사용 학습자 수(N)는 원가의 핵심 변수가 맞다 — 그리고 지금 최악 구간에 있다

사전생성 105원 : 런타임 148원 = **1 : 1.4**

```
학습자 1명이 지는 레슨당 원가 = 148 + 105/N
```

| 재사용 학습자 N | 레슨당 원가 | 사전생성 비중 |
|---:|---:|---:|
| **0** (미학습 지문) | 105원 전액 손실 | — |
| 1 | 253원 | 41.5% |
| **1.9 ← 현재 실측 (§3-F)** | **203원** | **27.2%** |
| 5 | 169원 | 12.4% |
| 10 | 159원 | 6.6% |
| 50 | 150원 | 1.4% |

> **이 비중은 과정 회차 수와 무관하다.** 사전생성(지문 수)과 런타임(세션 수)이 둘 다 회차 수에
> 비례하므로 약분된다. 8회차든 24회차든 N=1.9면 언제나 27.2%다.
> 과정 총액은 마지막에 회차 수를 곱한다 — 16회차·N=1.9면 **3,248원**, N=50이면 2,400원.

따라서 **원가 관리의 1순위는 지문 재사용률(N) 확보**다:
- 정규과정 편성 시 **같은 지문을 여러 기수·기관이 재사용**하도록 카탈로그를 좁게 유지
- **생성했으나 편성되지 않은 지문(N=0)** 을 정기 집계 — 순손실 항목
- 지문 대량 백필을 지양한 2026-08-01 "일괄 백필 취소" 결정(사전생성 개발계획 §7.2)은 **원가 측면에서도 옳았다**

### 6.2 나만의 수업(FRT)이 정규 레슨보다 4배 싸다

FRT **48원**(실측) vs 정규 레슨 203원(N=1.9) · 159원(N=10).

FRT는 ① 사전생성이 0이고 ② 채점 발화가 41초로 정규(210초)의 1/5이다. 런타임 LLM·TTS가 매 턴 발생하지만 그 합(14.4원)이 정규의 STT 격차를 상쇄하지 못한다.

자유 학습을 FRT 단일 모듈로 묶은 시나리오 §8.0의 판단은 옳지만, **근거는 원가가 아니라 진입 지연**이다 — 9모듈을 쓰려면 진입 시점에 11콜 + TTS 2,300자를 처리해야 하고 30초 이상 걸린다. 제약은 돈이 아니라 시간이다.

### 6.3 LLM은 원가 항목에서 사실상 사라졌다

런타임 LLM은 Flash-Lite 전환으로 정규 1원·FRT 1.2원이다. 남은 LLM 원가는 **사전생성 56원 한 곳**이고, 그마저 Flash-Lite로 내리면 10원이 된다(§7-2). **원가는 STT(런타임)와 TTS(사전) 두 축으로 정리됐다.**

## 9. 재계산 공식

```
# 원/초  STT 0.665 (deepgram 0.152 + azure-pron 0.513) — 정규에서 실시간 전사 제거 시 0.513
# 원/자  TTS 0.021 (inworld-tts-1.5-mini)
# 원/tok LLM 런타임(flash-lite) in 0.00007 / out 0.00028
#        LLM 사전생성(2.5-flash)  in 0.00021 / out 0.00175
# 1 USD = 1,400원

사전생성원가(지문 1건)
  = LLM: (22,300 × 0.00021 + 20,000 × 0.00175) × 1.4     # ≈ 56원
  + TTS: 합성문자수 × 0.021                                # ≈ 49원  ← 반복 재생분 제외
                                                           # 계 ≈ 105원

세션런타임원가(정규)
  = STT: 발화초 × 0.665
  + LLM: (in × 0.00007 + out × 0.00028)
  × 1.05(재도전)                                           # ≈ 148원

레슨당 원가(학습자 1명) = 세션런타임원가 + 사전생성원가 ÷ N    # 회차 수와 무관한 정본 비율
과정 총원가(학습자 1명) = 레슨당 원가 × 회차수                 # 회차 수는 마지막에 한 번만 곱한다
```

### rev.2 (2026-08-14) — 모듈 TTS 분류 정정
