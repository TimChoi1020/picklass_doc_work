## 개요

AI 생성물(문항·자료·리포트 코멘트)을 **원장/강사가 최종 검수·수정**하고, **AI 개입강도를 직접 조절**하게 한다. 완제품 강요형 도구에 대한 불신을 해소하는 **신뢰 장치**. 이미 존재하는 §9.5 검수 골격을 표준 워크플로우로 전면화한다.

**시장 근거**: 완제품 불신·자기주도 침해 우려 각 23%. 족보닷컴 AI "70%만 만족, AI 티 나서 허접하게"(강사 인터뷰). 설계형 원장은 프롬프트 직접 설계 선호.

**원칙**: 사람이 최종 통제. 검수 없는 자동 발행 금지.

---

## AI 개입강도 3단계

| 강도 | 동작 | 대상 |
|---|---|---|
| **최소** | 사람 주도, AI는 초안(소재)만 제공 | 설계형 원장 |
| **보통** | AI가 초안 생성, 사람이 수정·확인 | 기본값 |
| **최대** | AI가 완전 자동 생성, 사람은 검수만 | 효율 우선 |

설정 위치: 기관 기본값(Institution 설정) + 항목별 오버라이드.

## 원장 형식 템플릿 (형식 자유도)

AI가 초안을 대신 만들어주는 데 그치지 않고, **원장이 학생을 가르치는 그 방식·형식 그대로** 자료를 생성한다. 진짜 차별점은 "AI 생성물을 원장이 검수하느냐"가 아니라, **원장마다 다른 자기만의 자료 형식·구성을 자유롭게 구현**하는 유연함이다(차별점 축: 학원 범위 종속=*무슨 내용*, 형식 자유도=*어떤 형태*). 위의 검수·개입강도·톤은 이 유연성을 **받치는 신뢰 장치(부속물)**일 뿐, 차별점의 본질이 아니다.

- **정의**: 원장이 문항 형태·구성·출력 레이아웃을 지정한다.
- **저장**: 지정한 형식을 원장 소유의 "형식 템플릿"으로 저장한다.
- **재사용**: 같은 범위·같은 내용을 저장된 템플릿의 **그 형태로 반복 생성**한다.

**예시 — 단어 퀴즈 형식 3형태**:

| 형태 | 구성 |
|---|---|
| ① 뜻→단어 | 뜻 30개 제시 → 학생이 영단어 작성 |
| ② 음성→철자+뜻 | 단어 음성 제시 → 학생이 철자+뜻 작성 |
| ③ 표 블랭크 | 단어·뜻 표에서 한쪽(단어 또는 뜻)을 블랭크로 비워 채우기 |

## 기능 요구사항 (FR)

| # | 요구사항 | 판정 |
|---|---|---|
| FR-1 | 검수 큐 — Studio "검수 대기" 목록 (문항·리포트 등 생성물) | 재사용+확장 |
| FR-2 | 검수 패널 — 원본 표시 + 인라인 수정 + [승인]/[반려·재생성] | 확장 |
| FR-3 | 승인 게이트 — 미승인 생성물의 학생 배포·학부모 발행 차단 (P0-2·P0-5 연동) | 신규 |
| FR-4 | AI 개입강도 설정 — 기관 기본값 + 항목별 오버라이드, 생성 프롬프트에 반영 | 신규 |
| FR-5 | 재생성 — 반려 시 사유·톤 지정 → 재생성 요청 (Seed/LLM 전략 연동) | 재사용+확장 |
| FR-6 | 이력·감사 로그 — 수정·승인자·시각 기록 (§22.4 연계) | 재사용 |
| FR-7 | 톤 조절 — 리포트 코멘트에 "우리 학원 톤" 프리셋 제공 | 신규 |
| FR-8 | 형식 템플릿 — 원장이 문항 형태·구성·출력 레이아웃을 지정·저장, 같은 범위를 그 형태로 반복 생성 | 신규 |

## 예외·리스크

- **대량 검수 부담**: 일괄 승인(신뢰 항목) + 스팟 체크 옵션 제공.
- **개입강도 최대 + 검수 생략 설정**: 최소한 사후 열람 로그 보장(완전 무검수 금지 정책).
- **재생성 반복 실패**: N회 후 수동 편집 유도.
