## 개요

학생의 진단·수업·과정 데이터를 모아 **학부모에게 성장을 정확히 증명하는 리포트를 자동 생성**한다. 이것이 Picklass의 **지불 스위치**다.

**시장 근거**: 과금 가능 부가서비스 1순위 = AI 진단 리포트 31%. 학부모 클레임 1위 = "학습 상황을 잘 모르겠다" 21%. "정확하게 피드백을 보내 준다면 가격이 중요하겠습니까?"(LTS 원장) 2차 정성조사 재확인: 12곳 공통으로 **"자동 채점 → 리포트 → 실시간 학부모 전송"이 곧 '관리 잘하는 학원' 신뢰**("시험 본 게 바로바로 엄마한테 간다" 김포IH), 성장 증명은 "1년 전 알파벳, 지금 라이팅"(더그로우)으로 표현([학원장AI니즈 §2·§3](../시장조사/학원장AI니즈_2차정성조사_v1.0.md)).

**핵심 원칙**: 화려한 그래프보다 **'이 아이만의 정확한 데이터'** 우선. 부정확한 리포트는 오히려 이탈(재원 손실)을 부른다.

## 리포트 5개 섹션

| # | 섹션 | 내용 | MVP |
|---|---|---|---|
| ① | 현재 레벨 | 어휘·독해(·작문) 레벨(1–18), 6그룹 표현 | ✅ |
| ② | 강약점 | 영역별 강점·보완 필요 사항 | ✅ |
| ③ | 학습량·성실도 | 출석·완주율·과정 데이터(시도·시간·오답) | ✅ (일부) |
| ④ | 성장 추이 | 진단 시점(PT) vs 현재 레벨 비교 | ✅ |
| ⑤ | 선생님 코멘트 | LLM 자동완성 + 원장 검수 | ✅ |

> 📌 **MVP 데이터 한계**: Writing·Speaking KPI는 P1-1·P1-2 완성 전까지 "데이터 축적 중" 표기. 과정 데이터(G8)는 현재 WPM·정확도만 수집 완료, 시도·시간·오답은 P1-2 완성 후 보강.

## 기능 요구사항 (FR)

| # | 요구사항 | 판정 |
|---|---|---|
| FR-1 | 데이터 집계 — `DiagnosticResult`(P0-1) + 모듈 KPI(§11.5 ✅) + 과정 데이터 수집 | 재사용+확장 |
| FR-2 | 리포트 구성 — 5개 섹션 자동 조립 | 신규 |
| FR-3 | 코멘트 자동완성 — 원장 키워드·톤 선택 → LLM 문장 생성 (Seed+LLM 전략 준용) | 신규 |
| FR-4 | 검수·수정 — P0-4 검수 워크플로우 연동, 승인 전 발송 불가 | 재사용 |
| FR-5 | 정확성 가드 — 실제 저장 데이터에만 근거, 데이터 부족 시 "축적 중" 표기 | 신규 |
| FR-6 | 브랜딩·출력 — 기관 로고·이름 헤더(§7.10 ✅), PDF/웹 링크 export | 재사용 |
| FR-7 | 이력 보존 — 발행 리포트 버전 저장, 다음 리포트에서 성장 비교의 기준점 | 신규 |
| FR-8 | (P1) 발송 예약 — 알림톡/이메일 자동 발송 (§11.12 푸시 자산 연계) | P1 |

## 데이터 모델 — `GrowthReport`

| 필드 | 설명 |
|---|---|
| id, studentId, institutionId | 대상·기관 |
| periodStart, periodEnd | 리포트 기간 |
| levelSnapshot | 발행 시점 레벨(1–18) |
| metrics | { wpm, accuracy, completionRate, attendance } |
| growthDelta | 직전 리포트/진단 대비 변화 |
| comment | LLM 생성 + 원장 승인 최종본 |
| status | draft \| approved \| published |
| brandingRef, pdfUrl, version | 브랜딩·출력 |

## 화면·플로우

```
[Studio] 리포트 센터 → 학생 선택 (또는 반 일괄)
  → 데이터 집계 프리뷰 (레벨·KPI·성실도 자동 표시)
  → 코멘트 키워드·톤 선택 → [코멘트 자동생성]
  → 리포트 미리보기 → [검수·수정] (P0-4 연동)
  → [승인] → PDF/링크 발행 (기관 브랜딩)
  → (P1) 발송 예약 (알림톡·이메일)
```
