> 📋 **기획 단계 (P0 필수).** P0-2 리포트가 학부모에게 보여줄 **성장·과정 지표를 데이터 원천 단위로 확정**하는 스펙. 부정확한 리포트는 이탈을 부르므로 **과장 0**을 데이터 스펙 차원에서 강제한다.

## 핵심 관점 — 성장 축과 과정 축

| 축 | 답하는 질문 | 성격 | 지불 스위치 역할 |
|---|---|---|---|
| **성장 (Growth)** | "얼마나 컸나?" | 결과의 증명 | 학부모가 돈을 내는 이유 |
| **과정 (Process)** | "제대로·꾸준히 했나?" | 성장의 근거 | 성장 수치의 신뢰 + 다음 달 예측 |

성장만 있으면 불신이 남고, 과정만 있으면 "그래서 얼마나 컸냐"에 답을 못 한다. **과정이 성장을 뒷받침**하는 구조.

## 데이터 가용성 매트릭스

리포트(P0) vs 과정데이터·Achievement(P1) 선후 역전을 관리한다. **12월 MVP는 ✅ 범위만, 나머지는 "데이터 축적 중" 표기**.

| 지표 | 원천 필드 | MVP (12월) | P1 |
|---|---|:---:|:---:|
| 현재 레벨 (1–18 / CEFR 6그룹) | `DiagnosticResult.finalLevel` | ✅ | |
| 영역 스코어 (어휘·독해속도·이해) | `DiagnosticResult.skillScores` | ✅ | |
| 수업 중 WPM·정확도 | 모듈 KPI (§11.5 ✅) | ✅ | |
| 출석률·완주율·학습량 | 기존 과정 데이터 | ✅ | |
| 강·약점 태그 | `itemLog` (정오답·난이도) 1차 도출 | ✅ 근사 | ✅ 정밀 |
| **성장 델타 (레벨·영역)** | AT `deltaFromPrevious` | △ WPM 추이 근사 | ✅ P1-3 정식 |
| 문항별 시도·소요 시간 | `ProcessMetric.avgAttempts/avgElapsed` | ❌ | ✅ |
| 오답 패턴 → 약점 태그 | `ProcessMetric.errorPatterns` | ❌ | ✅ |
| 무성의 통과 지수 | `ProcessMetric.integrityFlag` | ❌ | ✅ |

### MVP 성장 추이 근사 규칙

- **방식**: 진단 시점 WPM·정확도 → 최근 4주 수업 KPI 평균의 변화로 성장 표현
- **레벨 델타**: MVP는 진단 레벨을 "현재 위치"로 표기. 레벨 상승은 재진단(원장 선택) 또는 P1-3 AT 시점에만 갱신 (**자동 레벨 상승 추정 금지**)
- **첫 리포트**: 비교 대상 부재 시 성장 섹션은 "**출발점 기록**"으로 표기, 성장 델타는 2회차부터

## 측정 지표 카탈로그

### 성장(Growth) — "증명"

| 지표 | 측정식 | 표시 예시 | Phase |
|---|---|---|:---:|
| 읽기 속도 성장 | 진단 WPM → 최근 4주 평균 WPM | `82 → 118 WPM (+44%)` | ✅ MVP |
| 정확도 성장 | 진단 정확도 → 최근 정확도 | `71% → 86%` | ✅ MVP |
| 레벨 성장 | AT `finalLevel` − 기준점 레벨 | `Lv.6 → Lv.8 (+2)` | 재진단/P1-3 |
| 영역별 성장 | `skillScores` 델타 | 어휘 ▲ / 이해 ▲ / 속도 → | P1-3 |
| 목표 달성률 | `AchievementResult.achievementRate` | `학기 목표의 92%` | P1-3 |

### 과정(Process) — "근거"

| 하위축 | 지표 | 측정식 | 표시 예시 | Phase |
|---|---|---|---|:---:|
| 성실도 | 출석률 | 출석/예정 | `19/20회(95%)` | ✅ MVP |
| 성실도 | 완주율 | 완료 모듈/배정 | `37/40(93%)` | ✅ MVP |
| 성실도 | 학습량 | 누적 시간·세션 수 | `총 14h, 37세션` | ✅ MVP |
| 이해도 | 정확도 | 정답/시도 | `평균 86%` | ✅ MVP |
| 이해도 | 평균 시도 횟수 | `avgAttempts` | `문항당 1.3회` | P1-2 |
| 이해도 | 성실 학습 지수 | `integrityFlag` 없음 비율 | `무성의 통과 0건` | P1-2 |
| 이해도 | 오답 유형 | `errorPatterns` → 약점 태그 | `추론형 오답 집중` | P1-2 |

## 리포트 화면 구성 (1페이지 원칙)

"화려한 그래프보다 정확한 데이터" — 그래프는 **WPM 추이 1개**로 절제, 나머지는 숫자·배지·화살표.

| # | 섹션 | 내용 | Phase |
|---|---|---|:---:|
| ① Hero | 한 줄 요약 | 성장 1 + 과정 1을 한 문장 | ✅ MVP |
| ② 현재 위치 | 레벨 배지 | 레벨 배지 + CEFR + 6그룹 위치 | ✅ MVP |
| ③ 성장 추이 | Growth 축 | 레벨·영역 화살표 + **WPM 추이 그래프** + 정확도 변화 | ✅ MVP (근사) |
| ④ 학습 과정 | Process 축 | 성실도(출석·완주·시간) + 이해도(정확도·[P1]시도·무성의) | ✅ MVP (일부) |
| ⑤ 강점·보완점 | 다음 달 예고 | 강점 2 + 보완 2 | ✅ MVP |
| ⑥ 코멘트 | 선생님 메시지 | LLM 생성 → 원장 검수·승인(P0-4). 수치는 시스템 값 고정 | ✅ MVP |
| Footer | 신뢰 문구 | "모든 수치는 실제 학습 기록에 근거합니다" | ✅ MVP |

## 정확성·신뢰 가드 (과장 0 구현)

| 규칙 | 구현 방식 |
|---|---|
| 수치 고정 | 모든 숫자는 시스템 집계값을 **문자열로 고정** 주입. LLM은 문장만 생성(수치 재계산·인용 금지) |
| 데이터 부족 | 임계 미만(세션 5회 미만) 섹션은 그래프·델타 숨기고 "데이터 축적 중" |
| 첫 리포트 | 성장 섹션 "출발점 기록", 성장 델타는 2회차부터 |
| 성취 하락 | 부정 표기 대신 "보완 예정" 톤 (P1-3 §4.3 가이드) |
| 오탐 방지 | 무성의 플래그(P1)는 리포트 미노출, 원장 검수 화면에만 참고 표시 |
| 기준점 명시 | 성장 델타에 기준점(진단 일자 / N회차) 항상 표기 |
