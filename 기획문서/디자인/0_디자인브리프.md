# 0. 디자인 브리프

> **가장 먼저 읽어 주세요.** 이 문서 하나만 읽어도 제품이 무엇인지, 무엇을 그려야 하는지, 무엇을 바꾸면 안 되는지 알 수 있게 썼습니다.

---

## 1. 이 제품은 무엇인가

**Picklass Speaking Tutor** — AI와 영어로 말하며 연습하는 학습 앱입니다.

- 학습자는 **말을 합니다.** 앱은 그 발화를 인식하고 발음·문법·표현을 채점합니다.
- 학습은 **9개 모듈**로 나뉩니다. 영상 보기 → 단어 익히기 → 따라 말하기 → 빈칸 채우기 → 문장 만들기 → 역할극 → 발표 순으로 난이도가 올라갑니다.
- 별도로 **레벨 진단 테스트(P-ALT)** 가 있습니다.
- **혼자 쓰는 앱이 아닙니다.** 학원 플랫폼 **픽클래스**가 학습자를 보내고 콘텐츠를 넣어 줍니다.

### 학습자

| 항목 | 내용 |
|---|---|
| 대상 | 한국어 사용자, 영어 회화 학습자 |
| 레벨 | **L1~L18** 18단계 (CEFR A1~C2에 대응) |
| 환경 | **모바일 브라우저** — 앱스토어 앱이 아닙니다 |
| 상황 | 소리를 내야 하므로 **혼자 있는 조용한 공간**을 가정합니다 |
| 1회 학습 시간 | 모듈 하나당 3~10분 / 레벨테스트 10~15분 |

## 2. 디자인 캔버스 — **390 × 844**

앱은 **모바일 전용**입니다. PC 브라우저에서 열면 화면 가운데에 아이폰 모양 프레임이 뜨고 그 안에서 동작합니다.

```
데스크톱에서 볼 때            모바일에서 볼 때
┌───────────────────┐        ┌─────────────┐
│  (연한 민트 배경)   │        │ ▬▬▬ 다이나믹 │
│   ╭───────────╮   │        │ 09:41  📶🔋 │
│   │▬▬▬ 09:41  │   │        ├─────────────┤
│   ├───────────┤   │        │             │
│   │           │   │        │  앱 콘텐츠   │
│   │ 앱 콘텐츠  │   │        │             │
│   │           │   │        │             │
│   ├───────────┤   │        ├─────────────┤
│   │    ▬▬▬    │   │        │     ▬▬▬     │
│   ╰───────────╯   │        └─────────────┘
└───────────────────┘         전체 화면
   390×844 프레임
```

| 항목 | 값 |
|---|---|
| **디자인 기준 크기** | **390 × 844** (iPhone 14 기준) |
| 상단 점유 | 다이나믹 아일랜드 약 36px + 상태 바 약 35px |
| 하단 점유 | 홈 인디케이터 약 20px |
| **실제 콘텐츠 높이** | **약 750px** |
| 모바일 실기기 | 프레임 없이 전체 화면. 상단/하단 장식도 표시되지 않음 |

> **콘텐츠 높이 750px를 기준으로 설계해 주세요.** 특히 발화 화면은 상단 카드 + 본문 + 하단 액션 바가 모두 들어가야 해서 세로 여유가 빠듯합니다.

**다크 모드** — 색상 토큰은 준비돼 있으나 현재 다크 모드 화면은 검증되지 않았습니다. **이번 범위에서는 라이트 모드만** 진행하는 것을 권합니다.

## 3. 9개 모듈 한눈에

| 코드 | 이름 | 학습자가 하는 일 | 발화 | 캐릭터 |
|---|---|---|---|---|
| **FRT** | 자유 대화 | AI와 자유롭게 대화 | ✓ | 원어민 선생님 |
| **LRN** | 강의 영상 | 영상 보고 표현 카드 읽기 | ✗ | 피클 |
| **VLM** | 어휘 워밍업 | 단어 듣고 뜻 확인 | ✗ | 피클 |
| **SHD** | 쉐도잉 | 듣고 그대로 따라 말하기 | ✓ | 피클 |
| **SFB** | 빈칸 채우기 | 빈칸을 채워 문장 말하기 | ✓ | 피클 |
| **SMK** | 문장 만들기 | 표현을 써서 새 문장 만들기 | ✓ | 피클 |
| **RPB** | 역할극 기본 | 정해진 대사로 역할극 | ✓ | NPC |
| **RPF** | 역할극 자유 | 대사 없이 자유 역할극 | ✓ | NPC |
| **OMP** | 1분 발표 | 60초 단독 발표 | ✓ | 피클 |

### 캐릭터 3층

| 층 | 누구 | 어느 모듈 |
|---|---|---|
| **피클** | 친근한 AI 튜터 | LRN·VLM·SHD·SFB·SMK·OMP |
| **NPC** | 상황 속 등장인물(웨이터 Alex 등) | RPB·RPF |
| **원어민 선생님** | 대화 상대 | FRT |

> ⚠️ **캐릭터 비주얼이 현재 존재하지 않습니다.** 코드에는 `피클 · 쉐도잉` 처럼 **이름만 텍스트로** 들어가 있고 이미지·일러스트는 없습니다. 캐릭터를 어떻게 시각화할지가 **이번 디자인의 큰 결정 사항**입니다.

## 4. 용어집

문서를 읽다 막히면 여기로 돌아오세요.

### 학습 구조

| 용어 | 뜻 |
|---|---|
| **모듈** | 학습 방식 하나. 총 9개 |
| **세션** | 모듈을 한 번 진행한 기록 |
| **문항** | 세션 안의 문제 하나. 진도바의 분모 |
| **턴** | 대화에서 한 사람이 말하는 차례 |
| **라운드** | SHD에서 같은 문장을 속도를 바꿔 반복하는 단위 |
| **6단계** | 모든 모듈이 따르는 진행 구조(준비→시작→제시→수행→피드백→완료) |
| **재시도** | 같은 문항에서 발화를 다시 하는 것 |
| **재도전** | 세션 전체를 처음부터 다시 하는 것(통과율 70% 미만 시) |
| **무발화** | 아무 말도 하지 않은 상황 |

### 화면·콘텐츠

| 용어 | 뜻 |
|---|---|
| **Seed 멘트** | 미리 정해 둔 안내 문장. AI가 만드는 게 아님 |
| **Slot** | 문장 안에 숫자를 끼워 넣는 자리 (`표현 {N}개 완료!`) |
| **PTT** | Push To Talk — 버튼을 눌러 말하기를 시작/종료하는 방식 |
| **VAD** | 음성 자동 감지 — 버튼 없이 말하면 자동 인식 |
| **자막/전사** | 말하는 대로 화면에 뜨는 텍스트 |
| **페르소나** | AI가 연기하는 캐릭터 설정 |
| **미션 표현** | 그 활동에서 꼭 써야 하는 영어 표현 |
| **이어하기** | 중단한 세션을 이어서 진행 |

### 평가

| 용어 | 뜻 |
|---|---|
| **KPI 5축** | 발화량·발음·유창성·화용성·문법 — FRT 리포트의 5개 지표 |

## 5. 이미 정해진 것 — 바꾸면 안 되는 것

### 🔒 절대 바꾸면 안 됨

**① KPI 5축 색상** — 브랜드가 바뀌어도 이 색은 유지합니다.

| KPI | 색상 |
|---|---|
| 발화량 | `#0f6e56` |
| 발음 | `#185fa5` |
| 유창성 | `#534ab7` |
| 화용성 | `#d4537e` |
| 문법 | `#ba7517` |

**② 0~100 종합점수를 만들지 않습니다.**
여러 지표를 평균 내 "종합 82점" 같은 숫자를 만드는 것은 **제품 원칙상 금지**입니다. 항상 절대 단위(`8문장`, `95 WPM`, `85%`, `6/8`)나 레벨(`L11`)로만 표기합니다.

**③ 어휘량은 모집단과 함께 표기합니다.**
`약 4,200 / 12,000단어 (픽클래스 코퍼스 근사 기준)` — 앞 숫자만 단독으로 쓰면 안 됩니다.

**④ 공인시험 환산에는 "임시(예시)" 표시를 유지합니다.**
실제 환산 공식이 확정되지 않았습니다. OMP 결과 화면의 뱃지와 주의 문구를 빼면 안 됩니다.

**⑤ 레벨테스트에서 하락을 부정적으로 표현하지 않습니다.**
성취 확인(AT) 모드에서 레벨이 내려가도 빨간색·하향 화살표·"떨어졌어요" 같은 표현을 쓰지 않습니다.

**⑥ 비교군 지표를 넣지 않습니다.**
"동일 레벨 평균 대비 상위 20%" 같은 항목은 실제 데이터가 없어 **의도적으로 뺐습니다.** 자리표시자로도 넣지 마세요.

## 6. 콘텐츠는 대부분 "가변"입니다

**이것이 이 프로젝트에서 가장 자주 문제가 되는 지점입니다.**

화면에 들어가는 내용의 상당 부분이 두 곳에서 옵니다.

| 출처 | 무엇 | 왜 가변인가 |
|---|---|---|
| **픽클래스** | 문항·문장·단어·대본·영상 | 학원마다·수업마다 다름. 개수와 길이가 정해져 있지 않음 |
| **AI** | 코칭·총평·피드백·오류 지적 | 매번 새로 생성됨. 길이 예측 불가 |

**그래서 이렇게 설계해 주세요.**

- 텍스트는 **2~3줄까지 늘어날 수 있다**고 가정
- 목록은 **0개일 수도, 예상보다 많을 수도** 있다고 가정
- **"내용이 없어서 블록이 통째로 사라지는" 경우**를 반드시 고려 (실제로 자주 발생합니다)
- 각 화면 명세의 **「제약」 칸에 구체적인 범위**를 적어 두었습니다

## 8. 디자인 결정이 필요한 지점

기능 개발이 먼저 진행되어 **의도적으로 비워 둔 곳**과 **손봐야 할 곳**을 모았습니다. 각 문서에 ⚠️ 표시로 다시 나옵니다.

| # | 지점 | 현재 상태 |
|---|---|---|
| 1 | **캐릭터 비주얼** | 이름 텍스트만 있음. 이미지·표정·모션 전부 없음 |
| 2 | **오류 상태 표현** | 전부 "작은 빨간 텍스트" 하나. 마이크 권한 거부처럼 치명적인 상황도 동일 |
| 3 | **빈 상태 / 로딩** | 스피너 + 한 줄 문구 수준. FRT 리포트 로딩만 전용 표현이 있음 |
| 4 | **이탈 확인** | 모듈 [나가기]가 확인 없이 즉시 이탈 |
| 5 | **진도 표현** | LRN·RPF·OMP는 진도바가 사실상 움직이지 않음 |
| 6 | **레벨테스트 통일감** | 파트마다 레이아웃이 제각각, 전체 진행 표시 없음, 중단 불가 |
| 7 | **마이크 권한 안내** | 타이틀에서 이유 설명 없이 바로 권한 팝업 |
| 8 | **세션 생성 폼** | 설정 항목 8개로 대화 시작까지 스크롤이 김 |
| 9 | **결과 화면 크기 불일치** | 통과/실패 아이콘이 44/56/64px 세 종류 |
| 10 | **비어 있는 본문** | SFB·SMK 발화 중 본문이 비어 있음 |

## 9. 문서 읽는 순서

```
0. 디자인 브리프          ← 지금 여기
     ↓
1. 화면 흐름도 & 공용 화면  ← 전체 지도 + 진입·홈·FRT
     ↓
2. 모듈 공통 화면 패턴     ← 8개 모듈의 공통 뼈대
     ↓
3. 모듈별 화면 명세        ← 모듈마다 다른 부분 (가장 큼)
     ↓
4. 화면 인벤토리 & 상태    ← 체크리스트. 작업하며 계속 참조
     ↓
5. 리포트 · 지난 기록      ← 결과 화면
6. 레벨테스트 P-ALT        ← 별도 흐름 (독립적으로 읽어도 됨)
```

## 10. 각 화면 명세를 읽는 법

문서 1·3·5·6은 모두 같은 틀로 화면을 서술합니다.

| 항목 | 뜻 |
|---|---|
| **목적** | 학습자가 이 화면에서 무엇을 하는가 |
| **진입 / 이탈** | 어떻게 들어오고 나가는가 |
| **와이어** | 현재 구현된 요소 배치. **디자인 시안이 아니라 구조 참조용** |
| **요소 표** | 요소 · 내용 · **데이터 출처** · **제약** |
| **상태 변형** | 이 화면이 가질 수 있는 모든 시각 상태 |
| **카피** | 실제 노출 문구 원본 |
| **참조** | 개발자 확인용 코드 경로 (디자이너는 무시해도 됩니다) |
| 📷 캡처 | 실제 화면 캡처 (별도 첨부) |

**「데이터 출처」와 「제약」 칸을 꼭 확인해 주세요.** §6에서 설명한 가변성이 여기에 구체적으로 적혀 있습니다.
