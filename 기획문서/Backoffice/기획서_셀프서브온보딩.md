## 개요

개발이 파고다(대형 B2B) 중심으로 설계돼 있으나, 시장의 진짜 수요층은 **중소형 보습학원(설계형 원장)**이다. 기존 대형 계약 트랙은 유지하되, **원장이 스스로 가입→학원 세팅→학생 배포까지 며칠 안에 끝내는 셀프서브 경로**를 병행 제공한다.

**시장 근거**: 지불의향 보습 86%(1위). 대형 어학원은 자체 시스템 보유로 니즈 낮음.

**핵심 엔티티**: `AcademyScope` — 학원 교과서·진도·내신 범위 정보. P0-1(진단), P0-2(리포트), P0-5(출제)가 참조하는 **학원 스코프의 단일 소스**.

---

## 온보딩 위저드 4스텝

```
[Studio] studio.picklass.com/app → 원장 가입 → 7일 체험 자동 활성
  → 온보딩 위저드
      Step 1. 기관 정보·로고 (§7.10 재사용)
      Step 2. 학원 범위 등록 (교과서·진도·학년·내신범위)  ← G6 핵심
      Step 3. 학생 초대 / 액세스코드 일괄 발급 (§17.1 재사용)
      Step 4. 첫 진단·수업 안내
  → Studio 대시보드 (빈 상태 가이드: 진단→수업→리포트)
```

## 기능 요구사항 (FR)

| # | 요구사항 | 판정 |
|---|---|---|
| FR-1 | 자가가입 — studio.picklass.com/app에서 원장 가입 → 7일 체험 자동 활성 (§5.4 ✅) | 재사용 |
| FR-2 | 온보딩 위저드 — 4스텝 진행률 표시, 이탈 후 이어하기 | 신규 |
| FR-3 | **학원 범위 등록 (`AcademyScope`)** — 학년·교과서(출판사)·진도 단원·내신 시험범위 텍스트 입력/업로드. P0-1/P0-2/P0-5 스코프로 전파 | 신규 (핵심) |
| FR-4 | 학생 관리·배포 — 학생 일괄 등록 + 액세스코드 발급/만료 (§17.1 ✅) | 재사용 |
| FR-5 | 체험 상태 표시 — 잔여 체험일, 결제 전환 안내 진입점 노출 | 재사용+확장 |
| FR-6 | 빈 상태 가이드 — 각 화면에 "다음 할 일" 유도 (진단 → 수업 → 리포트) | 신규 |

## 데이터 모델

**신규 엔티티 `AcademyScope`**

| 필드 | 설명 |
|---|---|
| id, institutionId | 소속 기관 |
| grade | 학년 배열 |
| publisher | 교과서 출판사 |
| textbook | 교과서명 |
| progressUnit | 진도 단원 |
| examScopeText | 내신 시험범위 전문(P0-5 입력 소스) |
| updatedAt | 최종 수정 |

## 예외·엣지 케이스

- 학원 범위 미등록 상태로 진단/출제 시도: 기본 범위 폴백 + 등록 유도 배너
- 위저드 중도 이탈: 저장 후 이어하기, 미완료 스텝 배지 표시
- 체험 만료: 읽기전용 전환, 데이터 보존, 결제 유도
