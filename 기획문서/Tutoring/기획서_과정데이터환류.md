## 개요

**"완료했는가"가 아니라 "진짜 학습했는가"**를 과정 데이터(시도 횟수·소요 시간·오답 패턴)로 포착해 리포트·진단으로 되돌린다.

**시장 근거**: 온라인 도구가 완료 여부만 보여줘 아이들이 꼼수(뒤로가기·베끼기), 강사가 다시 감시자가 됨. "완료 여부만 보이지 몇 번 시도했는지는 안 나온다"(현장 인터뷰).

**현행 상태**: WPM·정확도 수집 ✅ 완료. 시도·시간·오답 패턴의 리포트·진단 환류가 **미완성**. P0-2 리포트 MVP는 기존 데이터로 경량 시작, P1-2 완성 후 풍부해진다.

**온라인 유인**: 과정 지표(시도·시간·오답)는 종이로는 수집 불가 — "온라인으로 풀면 과정까지 분석된다"는 온라인 사용 권장 유인으로 활용.

## 기능 요구사항 (FR)

| # | 요구사항 | 판정 |
|---|---|---|
| FR-1 | 과정 이벤트 수집 — attempt / time / hint / retry / 오답선택 로그 적재 (§11.4·§14.6 확장) | 확장 |
| FR-2 | 지표 산출 — 문항·모듈·학생 단위로 시도수·평균 소요·오답률·오답 유형 집계 | 신규 |
| FR-3 | 무성의 통과 플래그 — 최소 소요시간 미만 + 즉답 반복 등 규칙 기반 감지 → 강사 알림 | 신규 |
| FR-4 | 리포트 환류 — 성실도·이해도 지표를 P0-2 `GrowthReport.metrics`로 전달 | 신규 |
| FR-5 | 진단 환류 — 오답 패턴을 약점 태그로 변환 → P0-1/P1-3 진단 정밀화, §10 시퀀싱 가중치 | 신규 |
| FR-6 | 강사 뷰 — 학생별 과정 데이터 요약(시도·시간·플래그) 대시보드 | 신규 |

## 데이터 모델 (요약)

| 엔티티 / 필드 | 설명 |
|---|---|
| `ProcessEvent` (신규) | studentId, moduleCode, eventType(attempt/time/hint/retry), value, timestamp |
| `ProcessSummary` (신규) | studentId, moduleCode, attempts, avgTime, errorRate, errorPatterns[], lazyFlag |
| `GrowthReport.metrics` 확장 | diligence(완주·시도), comprehension(오답 패턴 기반) |

---

## 환류 파이프라인

```
[Tutoring] 모듈 실행 → 과정 이벤트 로그 적재 (런타임)
  → 집계 파이프라인 (시도·시간·오답·플래그)
       ├─ 리포트(P0-2): 성실도 diligence + 이해도 comprehension
       ├─ 진단(P0-1/P1-3): 오답 패턴 → 약점 태그 → 레벨 정밀화
       └─ 강사 대시보드: 무성의 통과 플래그 알림
```
