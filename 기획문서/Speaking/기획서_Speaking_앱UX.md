### 14.9 독립 앱 UX (Speaking 전용 UI/UX)

> ✅ **B-12 확정 (2026-07-18) — 앱 실행 주체**: 독립 앱은 **대시보드 셸(`apps/web`) + 별도 학습앱** 2계층으로 확정. 셸은 홈·수업·챌린지·리포트·MY 5탭 IA와 진입/결과 조회를 담당하고, 실제 녹음·ASR·5축 측정·완료 처리는 **별도 학습앱**이 수행한다. 본 절 세션 화면(§14.9.1~)은 별도 학습앱 소유. (셸↔학습앱 결과 데이터 유입 경로는 구현 상 알려진 미해결 블로커 — 리포 `docs/` 추적.)

#### 14.9.0 앱 정보구조 (5탭 IA + 3-Layer) *(v1.3 신설)*

독립 앱은 **3-Layer 구조**로 화면을 조직한다. 세션 화면(§14.9.1~)은 Layer 2에 해당한다.

| Layer | 명칭 | 역할 |
|---|---|---|
| Layer 1 | 5탭 영구 네비게이션 | 일상 진입점, 항상 화면 하단 노출 |
| Layer 2 | 학습 흐름 오버레이 | Pick-Speak 5단계 풀스크린 + 탭바 자동 숨김 |
| Layer 3 | 글로벌 요소 | 푸시·토스트·모달·피클 Agent 멘트 |

**5탭 영구 네비게이션** *(⚠️ v1.3 — 구현 배포본 기준 확정: B-2)*

| 탭 | 역할 | 주요 콘텐츠 |
|---|---|---|
| 1. 홈 | 오늘의 학습 진입점 | 오늘의 학습(이어하기 + FRT), 학습 현황(이수율·발화량 2행), 스피킹 밸런스 레이더 |
| 2. 수업 | 과정·레슨 라이브러리 | 진행 중·추천·카테고리·시험·즐겨찾기, "원하는 주제로 학습하기"(→ [Tutoring §11.8](../Tutoring/기획서_Tutoring.md)) |
| 3. 챌린지 | 게이미피케이션 | 아래 챌린지 탭 구성 참조 |
| 4. 리포트 | 학습 회고·성장 추적 | 5축 추이(Quality/Quantity/Growth 3블록), 레슨 이력, 1MP 기록, 표현 노트, 약점 분석 |
| 5. MY | 프로필·결제·설정 | 히어로 헤더 + 설정 단일 카드 (아래 마이 탭 참조) |

> ✅ **B-2 확정 (2026-07-18)**: 탭 순서·명칭을 구현 배포본에 맞춰 확정 — "학습→수업", "피드백→리포트"로 개명하고 챌린지를 3번(리포트 앞)으로 배치.
> ✅ **B-7 확정 (2026-07-18)**: 홈은 오늘의 학습·학습 현황·스피킹 밸런스만 구성하고 **망각곡선 미니카드는 홈에서 제외**(챌린지 탭 내에서만 노출).

**챌린지 탭 구성** — 앱이 소유하는 게이미피케이션 허브. 챌린지 3종 + 랭킹 + 뱃지 + 친밀도.

| 블록 | 내용 | 소유 정책 |
|---|---|---|
| 발화량 챌린지 HERO | **주간·월간 2미터**("주간 리듬 대시보드") | [§14.4.6 차별점 5](./기획서_Speaking.md) (SSoT) |
| 진도율 챌린지 | 출석 + 진도율 | 앱 IA |
| 망각곡선 챌린지 | 지난 학습·표현노트 표현을 망각곡선 복습 시점에 제안·발화 | 아래 정의 |
| 표현카드 챌린지 | 저장 표현을 반복 발화하여 레벨업 (표현노트) | 아래 정의 |
| 랭킹 | 발화량·리워드 × 일간/주간/월간 (기업별) | [Tutoring §11.11.3](../Tutoring/기획서_Tutoring.md) |
| 뱃지 컬렉션 | 스트릭·등급 뱃지 | [§14.4.9 계층 1](./기획서_Speaking.md) (SSoT) |
| AI 캐릭터 친밀도 | 캐릭터별 친밀도 진행 | [§14.4.9 계층 4](./기획서_Speaking.md) (SSoT) |

**문장 마스터리 엔진 (망각곡선 챌린지 + 표현카드 챌린지)** *(⚠️ v1.3 재정의 — 단일 엔진 통합)*

두 챌린지는 별개 기능이 아니라 **동일한 "문장 마스터리(발화 반복)" 엔진**이며, **진입점만 다르다**: 망각곡선(Quiz)=시스템 복습 큐 / 표현카드=상시 표현노트. "저장은 학습 중(피드백 탭) → 복습은 챌린지 탭" 역할 분리.

| 항목 | 정책 |
|---|---|
| **마스터 레벨 임계값** | Lv0=0 / Lv1=1~2 / Lv2=3~4 / Lv3=5~7 / **Lv4(마스터)=누적 발화 8회** (mastery_target 기본 8) |
| **발화당 리워드** | 발화 1회 = pip 1칸(8칸 게이지). 매 발화 시 즉각 3감각 반응(시각 pip팝+숫자 / 청각 성공음 / 촉각 햅틱). **반응 지연 최소화 = 절대 원칙** |
| **게임성 채택** | 순간 피드백(Juice) + 수집·완성(Collection) 2축 채택. 발음 별점·스트릭 상실회피는 그라인드 우려로 후속 유보. 배지는 완성 결과로만 부여 |
| **문장 출처 3소스** | `learning`(과정 핵심표현 학습완료 시 자동 편입) / `note`(수동 저장) / `preset`(backoffice 큐레이션 필수문장, 기관·레벨 매핑, B2B 차등) |
| **Quiz 제공량** | 세션당 6문장(5~8 상한), 문장별 1~2발화, 하루 1세션 권장 · "짧고 자주(2~4분)" · 과다 제공 금지, due 초과분 이월 |
| 발화량 시너지 | Quiz/표현노트 발화가 발화량 챌린지 미터([§14.4.6 차별점5](./기획서_Speaking.md))의 실제 데이터 유입원 — 질(마스터리)+양(발화량) 이중 리워드 |

> 📎 망각곡선 복습 간격 수식·레벨 임계값 계산 등 알고리즘 구현은 리포 `docs/` 소유. 여기서는 **정책·확정 임계값·UX 원칙**만 기술한다.
> ✅ **B-10 확정 (2026-07-18)**: 챌린지 탭에서 **AI 캐릭터 챗 카드는 제거**(후속 유보)한다. 친밀도 정책·캐릭터 SSoT([§14.4.9](./기획서_Speaking.md))는 유지하되, 챌린지 탭 내 친밀도 블록 노출은 축소한다.

**MY 탭 — 히어로 헤더 + 설정 단일 카드** *(⚠️ v1.3 확정: B-6)*

MY 탭은 **블루 히어로 헤더**(아바타·이름·레벨 배지·수강권·로그아웃) + **설정 단일 카드**로 구성한다(4그룹 섹션 라벨은 제거). 설정 항목은 아래 범주를 단일 카드에 담는다. 알림은 5개 서브 메뉴로 세분화(정책 수준).

| 범주 | 설정 항목 |
|---|---|
| 계정 | 로그인, 비밀번호, SSO, 2단계 인증 |
| 프로파일 | 기본 정보, 레벨(18변형 라벨·파트너 레벨명 병기), 학습 시작일, 뱃지 미니 |
| 학습 설정 | 학습 목적, 시험 정보, 직무·관심사, 페르소나, 학습 시간대, **일일 목표(기본 20분)**, 선호 모드, **자막·재생속도(기본 1.0×)** |
| 앱 설정 | 알림(5서브: 푸시 9종 ON/OFF · 방해 금지 시간대(기본 22:00~08:00) · 알림톡·이메일·마케팅 수신 동의), 다크모드, 언어, 사운드·햅틱, 데이터·캐시, 권한, 접근성 |

> ✅ **B-6 확정 (2026-07-18)**: 4그룹 라벨 IA를 폐기하고 히어로 헤더 + 설정 단일 카드로 통합. 위 범주는 설정 카드 내부 분류로만 유지. 공지사항(알림 내역)은 히어로 하위에 노출.

**프로필·수강 정책** *(v1.3 신설)*

| 항목 | 정책 |
|---|---|
| 레벨 변경 3경로 | 현재 레벨은 **PT(최초·재응시) / AT(성장 확인) / 학습 중 조정(무세션)** 3경로로만 변경. 이력 전량 추적 |
| 영어 닉네임 | 원어민 호명 + 랭킹 표시용. 영문·16자·**유일성 없음**(중복 허용). 없으면 가입명 폴백 |
| 수강내역 | **단일 통합 목록**(수강중/종료 미분할) + 상태 배지. 카드 단위=수강 계약(재수강은 각각 카드). 클릭 시 수강중→수업 계속 / 종료→리포트 |

> 📎 알림 **발송 트리거 룰·채널·옵트인 법적 정책**은 [Tutoring §11.12](../Tutoring/기획서_Tutoring.md) 소유(SSoT). 본 절은 **앱 설정 화면의 IA 구조**만 기술한다.

**피드백(리포트) 탭 구성** *(v1.3 신설)* — 3블록 구조로 조직한다.

| 블록 | 내용 |
|---|---|
| **Quality (질)** | 발음·유창성·문법·화용 + 기관 평균 대비 비교 |
| **Quantity (양)** | 발화·듣기 누적·섀도잉 카운트 (기간 학습량 집계) |
| **Growth (성장)** | 5축 절대 변화량 (100점 환산·CEFR 도달% 의존 폐기) |

역할 분리: 리포트=기간(period) 학습량 집계 / 챌린지 탭=목표 진행도.

> ✅ **B-13 확정 (2026-07-18) — 리포트 노출 단위**: 리포트 탭은 **Quality를 0~100 정규화 점수**로 표시하고, 듣기 단위는 **"회"**, 추이 기간은 **30일(30d)** 로 확정. ([기획서_Speaking_KPI측정 §14.6](./기획서_Speaking_KPI측정.md)의 도메인 단위(WPM·오류율·분)는 **엔진 내부 측정 단위**이고, 리포트 화면 노출은 정규화 점수를 사용 — 두 계층 분리.) **학생 리포트의 기관 평균 비교는 v1.3에서 제외**(소스 부재), 향후 소스 확보 시 재도입.

#### 14.9.1 세션 시작 화면
- 레벨 선택 (1–18) / 주제 / 세션 시간
- 목표·힌트 안내
- **모드 선택 (FRT 전용)**: `Chatting Mode` / `Audio Only` 토글 (§14.9.5)

#### 14.9.2 대화 화면
- 음성 파형 시각화
- 자막 on/off 토글
- 힌트 버튼 (레벨/상황별 3단계)

#### 14.9.3 실시간 피드백 패널
- 추임새(즉각) → 교정 텍스트 → 따라 읽기(L1–12)

#### 14.9.4 세션 종료 리포트
- KPI **5축** 차트 (발음정확도·유창성·문법정확성·화용성·발화량)
- 대화 스크립트 + 오류 하이라이트
- 다음 권장 주제/레벨

#### 14.9.5 Chatting Mode / Audio Only 토글 *(v0.8 신설)*

Free Talking(FRT) 세션은 두 가지 모드로 운영된다. 사용자가 세션 시작 화면에서 선택.

| 모드 | 인터페이스 | 사용 상황 | 특징 |
|---|---|---|---|
| **Chatting Mode** | 채팅창 + 음성 말풍선 병행 | 초·중급 학습자, 자막 필요 시 | AI·학습자 발화 텍스트 말풍선으로 표시, 피드백 말풍선 색상 구분(일반 대화와 다른 색), 레벨별 바이링구얼 피드백(초·중급: 한국어+영어) |
| **Audio Only** | 음성 파형 + 최소 UI | 고급 학습자, 실전 회화 훈련 | 텍스트 최소화, 대화 몰입 극대화, 발화 감지 시 파형 시각화, 고급 전용 서브 코멘트 사이드 패널(논리흐름·표현대안·반론대응) |

**공통 규칙**
- AI 원어민 발화 완료 후 마이크 자동 활성화
- 무응답 5초(화이트노이즈만 입력) 시 자동 종료 또는 레벨별 개입
- 발화 말풍선/파형은 학습자 [Stop] 클릭 또는 제한 시간 만료 시 종료

> 📎 레벨별 개입 전략(초급 힌트 / 중급 AI 리프레이즈 / 고급 서브 코멘트)은 [§14.5](./기획서_Speaking.md) 참조.

### 14.10 통합 모듈 연동 (튜터링 레슨 내 삽입)

> 📎 전체 사용자 플로우·인증 메커니즘은 **§3.3.1 통합 모듈 플로우** 참조. 본 절은 엔진·데이터 레이어 상세.

#### 14.10.1 LessonPlan 내 스피킹 모듈 슬롯
- ModuleSequence에 Speaking 모듈 code 추가
- `passageExposureMode = "full"` (지문 기반 대화 시)

#### 14.10.2 오케스트레이터 ↔ SpeakingConversationAgent 핸드오프
- ModuleOrchestratorAgent가 Speaking 모듈 진입 시 세션 시작 신호
- Speaking 세션 종료 시 KpiResult를 ModuleResult에 포함

#### 14.10.3 결과 데이터 표준화
- ModuleHistory 테이블에 호환 저장
- SpeakingSession 테이블에 상세 턴/오디오/교정 저장 (외래키 연결)

#### 14.10.4 ONETIME TOKEN 기반 크로스도메인 인증 (§3.3.1 연동)

Tutoring(`tutoring.picklass.com`) → Speaking(`speaking.picklass.com`) 도메인 이동 시 **단일 사용 토큰**으로 인증과 설정을 전달한다.

**토큰 라이프사이클**

```
[1] Tutoring: 사용자가 "스피킹 선택" 클릭
      ↓ 서버에서 ONETIME_TOKEN 발급 (UUID, TTL 5분)
      ↓ 토큰·사용자ID·레벨·콘텐츠·대화분량·음성모드 레코드 생성
[2] Tutoring → Speaking: 쿼리스트링으로 토큰 전달
      https://speaking.picklass.com/?token={TOKEN}
[3] Speaking 세션 시작 화면 진입 시:
      POST /api/auth/get-auth { token }
        응답: { userId, name, accessCode, level, content, dialogLength, voiceMode }
      → 이름·설정 자동 채움 (이름은 사용자 수정 가능)
[4] 사용자 "세션 시작" 클릭:
      POST /api/auth/revoke-token { token }
      → 토큰 상태를 소멸 처리 (이후 동일 토큰 재사용 불가)
[5] 세션 진행·종료 → ModuleHistory 및 SpeakingSession 기록
```

**보안 요구사항**
- 토큰 TTL ≤ 5분 (만료 시 자동 무효)
- 토큰 1회 사용 강제 (GET_AUTH 호출 후 세션 시작 시점에 즉시 소멸)
- IP/User-Agent 핑거프린팅으로 도용 탐지 (선택)
- 토큰 로그는 감사 로그(§22.4)에 기록

**실패 처리**
- 만료·사용된 토큰: Speaking 측 "세션 초기화 실패" 안내 → Tutoring 복귀 CTA
- GET_AUTH API 장애: 5초 타임아웃 후 재시도(최대 2회), 실패 시 사용자에게 수동 재진입 유도

**API 스키마 (요약)**

```typescript
// GET_AUTH 요청

// GET_AUTH 응답

  userId: string;
```

#### 14.10.5 외부 시스템 임베드 — `GET /external/verify` *(✅ 구현 완료)*

> §3.3 외부 임베드 채널의 **실제 운영 API**. 2026-04-09자 외부 API 명세서에 정의되어 있으며 이미 동작 중.
>
> 📎 **v0.19 cross-ref**: 본 verify API는 **[§16. B2B 제휴 운영 모델](../00_공통/07_B2B제휴운영모델.md)**의 표준 인증 방식 중 하나(§16.7 ONETIME TOKEN)이며, **§16.10.2 Speaking 채널 적용**에서 Pick-Speak Method 임베드의 핵심 진입점으로 사용된다. 본 절은 API 명세 중심, §16.10.2.6은 운영 흐름 중심으로 다룬다.

외부 시스템(예: 파고다SCS)이 자체 사용자·과정을 관리한 채로 픽클래스의 Speaking 학습 화면만 임베드 형태로 제공하기 위한 API.

**인증 방식**

| 헤더 | 필수 | 설명 |
|---|---|---|
| `X-Access-Token` | ✓ | 픽클래스에서 발급한 원타임 토큰. 토큰 유효 시간 **60분** |
| `X-Module-Code` | ✓ | 조회할 모듈 코드 (외부 임베드 전용 별칭: `SNR` Scenario Talking = 롤플레이(RPB·RPF) 임베드, `FRT` Free Talking). ※`SNR`은 9모듈 레지스트리 코드가 아닌 외부 API 계약 별칭 |

**엔드포인트**

```
GET https://tutoring.picklass.com/api/external/verify
```

**응답 구조 (200 OK)**


**사용 흐름**

```
[외부 시스템 (예: 파고다SCS)]
    │
    │ 1. 픽클래스에 미리 발급받은 ONETIME TOKEN을 자체 학습자에게 제공

    │
    │ 2. "스피킹 학습 시작" 클릭 → 픽클래스 임베드 위젯/페이지로 이동
    │    (token + module-code를 헤더로 전달)
    ▼
[픽클래스 Tutoring API]
    │
    │ 3. GET /external/verify (토큰 검증 + 사용자·모듈·지문 정보 반환)
    │ 4. 임베드 위젯이 응답 데이터로 학습 화면 구성
    ▼
[학습 진행 → 학습 결과 저장 (외부 시스템 + 픽클래스 자체 로그 동시)]
```
