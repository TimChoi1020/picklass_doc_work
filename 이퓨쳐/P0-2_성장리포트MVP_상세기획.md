# P0-2. 성장 리포트 MVP (Parent Growth Report) 상세 기획

| 항목 | 내용 |
|---|---|
| 코드 | P0-2 (Gap G1) — **지불 스위치, 최우선 가치** |
| 우선순위 | P0 (12월 파일럿 필수) |
| 연계 | P0-1 진단(입력), §11.5 성과카드·KPI(✅), §7.10 기관 브랜딩(리포트 PDF 헤더), 과정 데이터(G8) |
| 상태 | 확장 — v0.20에서 "부모/관리자 정기 리포트"는 Phase 3(Q4+) → **Phase 1~2로 앞당김** |

---

## 1. 목적·배경

학생의 진단·수업·과정 데이터를 모아 **학부모에게 성장을 정확히 증명하는 리포트를 자동 생성**한다. 이것이 Picklass의 지불 스위치다.

- 시장 근거: 과금 가능 부가서비스 1순위 = **AI 진단 리포트 31%**(§0.2), 학부모 리포트 자동생성 38%(⚠️ 출처 미확인 — §0.2 채점 38%와 숫자 충돌, 원 설문 확인 필요). 학부모 클레임 1위 = "학습 상황을 잘 모르겠다" 21%. "정확하게 피드백을 보내 준다면 가격이 중요하겠습니까?"(LTS 원장)
- 원칙: **화려한 그래프보다 '이 아이만의 정확한 데이터'** (에이플러스 원장). 부정확한 리포트는 오히려 이탈(재원 손실)을 부른다(토피아 원장).

## 2. 사용자 스토리

- (원장) 키워드 몇 개만 고르면 아이별 리포트 문장이 자동 완성되어, 매달 전 학생 리포트를 몇 분 안에 보내고 싶다.
- (강사) 선생님마다 코멘트 편차 없이 일관된 품질의 리포트를 내고 싶다.
- (학부모) 우리 아이가 1년 전 대비 이만큼 성장했다는 걸 객관적 데이터로 확인하고 싶다.

## 3. 범위 (In/Out)

**In (MVP)**
- 학생별 리포트 자동 생성: 진단 결과 + Reading 수업 KPI(WPM·정확도) + 과정 데이터(출석·완주) 종합
- 원장 키워드 선택 → LLM 문장 자동 완성(코멘트) → 원장 검수·수정(P0-4 연계)
- 리포트 뷰/PDF export, 기관 로고·브랜딩 적용(§7.10)
- 성장 추이(진단 시점 vs 현재) 간단 비교

**Out (후속)**
- 자동 발송(알림톡/이메일 예약)은 P1(§11.12 푸시 자산 연계)
- Writing/Speaking 지표(P1), 반·기관 단위 집계 리포트(P2)

## 4. 기능 요구사항 (FR)

- **FR-1** 데이터 집계: 학생의 `DiagnosticResult`(P0-1) + 모듈별 KPI(§11.5 ✅) + 과정 데이터(시도·시간·오답·출석) 수집.
- **FR-2** 리포트 구성: 섹션 = ①현재 레벨 ②강약점 ③기간 내 학습량·성실도 ④성장 추이 ⑤선생님 코멘트.
- **FR-3** 코멘트 자동 완성: 원장이 키워드/톤 선택 → LLM이 코멘트 문장 생성(Seed+LLM 전략, §Voca_Reading 대화전략 준용).
- **FR-4** 검수·수정: 생성된 코멘트를 원장이 편집·승인(P0-4 검수 워크플로우 표준 단계 적용). 승인 전 발송 불가.
- **FR-5** 정확성 가드: 리포트 수치는 실제 저장 데이터에만 근거(추정·과장 금지). 데이터 부족 항목은 "데이터 축적 중" 표기.
- **FR-6** 브랜딩·출력: 기관 로고·이름 헤더(§7.10) 적용, PDF/웹 링크 형태 export.
- **FR-7** 이력: 발행 리포트 버전 보존, 다음 리포트에서 성장 비교의 기준점.

## 5. 화면·플로우

```
[Studio] 리포트 센터 → 학생 선택(또는 반 일괄)
   → 데이터 집계 프리뷰 (레벨·KPI·성실도 자동 표시)
   → 코멘트 키워드/톤 선택 → [코멘트 자동생성]
   → 리포트 미리보기 → [검수·수정] (P0-4)
   → [승인] → PDF/링크 발행 (기관 브랜딩)
   → (P1) 발송 예약
```

## 6. 데이터 모델 / 입출력

**입력**: `DiagnosticResult`, 모듈 KPI 로그, 과정 데이터, `institutionBranding`, 원장 선택 키워드.

**신규 엔티티 `GrowthReport`(요약)**

| 필드 | 설명 |
|---|---|
| id, studentId, periodStart/End | 대상·기간 |
| levelSnapshot | 발행 시점 레벨(1–18) |
| metrics | { wpm, accuracy, completionRate, attendance } |
| growthDelta | 직전 리포트/진단 대비 변화 |
| comment | LLM 생성 + 원장 승인 최종본 |
| status | draft / approved / published |
| brandingRef, pdfUrl, version | |

**출력**: 브랜딩 적용된 리포트(웹/PDF).

## 7. 기존 자산 연계 (재사용/확장)

- **재사용**: 성과카드·KPI 시각화(§11.5 ✅), WPM·정확도 수집(✅), 기관 브랜딩·리포트 PDF 헤더(§7.10 ✅), Seed+LLM 콘텐츠 전략, 강사 검수 골격(§9.5).
- **확장**: 흩어진 KPI/진단/과정 데이터를 리포트 스키마로 통합, 성장 비교 로직 신규.

## 8. 예외·엣지 케이스

- 데이터 부족(신규생, 수업 이력 적음): 해당 섹션 "축적 중" 표기, 진단 결과 위주로 발행.
- LLM 코멘트 오류/과장: 원장 검수 필수(FR-4), 수치 인용은 시스템 값으로 고정.
- 브랜딩 미설정 기관: Picklass 기본 템플릿 폴백.
- 반 일괄 생성 중 일부 실패: 성공분 발행 + 실패 목록 표기.

## 9. 완료 정의(DoD) · QA

- 진단·수업 이력 있는 학생 1명 → 리포트 자동 집계 → 코멘트 생성 → 검수·승인 → PDF 발행 E2E.
- 리포트의 모든 수치가 저장 데이터와 일치(과장 0건, QA 대조).
- 기관 로고·브랜딩이 PDF에 반영.
- 2회차 리포트에서 1회차 대비 성장 델타가 표시.

## 10. 의존성 · 오픈 이슈

- **선행**: P0-1 진단(입력), P0-4 검수 UX(코멘트 승인 단계).
- **오픈 이슈(개발팀 확인)**: ①현재 수집 KPI/과정 데이터로 리포트 구성에 충분한지, 추가 수집 지표(§5 G1) ②리포트 발행 주기 정책(월/수시) ③PDF 렌더링 스택.
- **하류**: P1 자동 발송(§11.12 푸시·알림톡).
