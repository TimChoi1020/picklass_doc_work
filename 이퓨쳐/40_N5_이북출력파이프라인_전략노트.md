## 0. 배경 — 왜 이 노트인가

[N4](40_N4_원장교재스튜디오_POD_전략노트.md)가 교재 스튜디오의 소재(S1/S2/S3)·라이브러리·북빌더·산출(eBook+POD)을 정의했으나, **산출물이 실제로 어떻게 생성되는지(파이프라인)** 는 미정이었다. 외부에 이미 운영 설계가 존재하므로(레퍼런스), 검증된 골격을 차용하고 **Picklass 고유 요구(QR 결속·교재 연동 학습·학원 단위 발행)만 확장**한다.

---

## 1. 차용하는 핵심 원칙 (레퍼런스 §1)

1. **Single Source of Truth** — 북빌더가 확정한 교재 원본 1개(`TextbookProject` 병합 Markdown)가 모든 출력의 원천. 원본 수정 → 세 출력 모두 동기화 대상.
2. **화면은 즉시, 이북·PDF는 발행 트리거 시** — 앱 학습 화면은 API 응답을 실시간 렌더. EPUB·인쇄 PDF는 발행 이벤트 시 서버 비동기 생성.
3. **버전 연결 보존** — 생성 파일은 어느 교재 버전 기준인지 추적(`textbookVersionId`). 개정판·재인쇄 관리의 기반.

---

## 2. Picklass 적용 파이프라인

```
 교재 스튜디오 (N4)
   └─ TextbookProject 병합 원본 (Markdown, SSoT)     ← ContentAsset(S1/S2/S3, 승인분) 조합
           │
           │  [발행 이벤트]
           │
           ├──► [경로 A] 앱 실시간 렌더 (Tutoring 클라이언트)
           │      └─ HTML → 교재 연동 학습 화면 · 과정 데이터 수집(P1-2)
           │
           └──► [경로 B] 서버 비동기 생성 (Pandoc 계열)
                  │
                  ├──► B-1. EPUB  →  앱 eBook 뷰어 (구독 기본 포함, N2)
                  │       └─ 교재↔학습 모듈 딥링크 삽입 (§3-2)
                  │
                  └──► B-2. 인쇄용 PDF (B5·CMYK)
                          └─ QR 삽입 (§3-1, N3) → 파일 자산 저장 → POD 발주(N4 PublishOrder)
```

| 출력 | 처리 주체 | 용도 |
|---|---|---|
| HTML (앱 화면) | 클라이언트 실시간 파싱 | 교재 연동 온라인 학습 (과정 데이터 수집) |
| EPUB | 서버 비동기 | 앱 eBook 뷰어 — 구독 기본 포함 |
| 인쇄용 PDF | 서버 비동기 (LaTeX 엔진) | POD 인쇄 원본 — 유료, 페이지수 가변 제작비 |

## 3. Picklass 고유 확장 (레퍼런스에 없는 3가지)

### 3-1. QR 삽입 단계 — 2-티어 설계 (제안)

N3는 "QR = 이 종이 = 이 학생 × 이 문항"을 원칙으로 하나, **학원 교재는 반 전체 공통 인쇄**라 학생별 QR은 비경제적. 산출물 성격에 따라 이원화한다.

| 산출물 | QR 페이로드 | 학생 식별 |
|---|---|---|
| **학원 교재 (공통 인쇄)** | 교재×문항 토큰 (콘텐츠 식별만) | 캡처 시 **앱 로그인 세션**으로 식별 |
| **학생별 워크북·답안지 (개인화 인쇄)** | 학생×문항 토큰 (N3 원안) | QR 자체로 식별 |

→ 공통 교재는 대량 인쇄 단가를 지키고, 개인화가 필요한 워크북만 학생 단위 생성. **N3 §3에 이 2-티어를 역반영 필요**(제안 액션 C).

### 3-2. 교재↔학습 모듈 딥링크

eBook(EPUB)의 각 단원·문항에 **앱 학습 모듈로 진입하는 링크**를 삽입 — "교재 연동 온라인 학습"(N1 §3-1)의 구현 지점. 종이 교재에서는 같은 위치의 QR이 이 역할을 한다(스캔 → 해당 모듈/채점 진입).

### 3-3. 두 제품군 매핑 — 레퍼런스 이원 구조와 동형

| 레퍼런스 | Picklass | 생성 단위 | 트리거 |
|---|---|---|---|
| 메타씽크북 (과정 공통) | **학원 자기 교재** (N4) | 학원(기관) 단위 | 교재 발행·버전 업 |
| 포트폴리오북 (학습자별) | **월간 약점 워크북 + 리포트 합본** (N2 ②(b)) | 학생 단위 | **월간 리포트 발행 이벤트**(P0-2) |

→ 월간 워크북은 레퍼런스의 "수료 이벤트 → 학습자별 개별 생성" 패턴을 그대로 차용하되, 트리거만 리포트 발행으로 치환.

## 4. 트리거 정책 (차용 + 수정)

| 트리거 | 생성 대상 | 비고 |
|---|---|---|
| 교재 Published 전환 | EPUB + 인쇄 PDF | 최초 발행. 원장 최종 승인(N4 검수 게이트) 후 |
| Major 버전 업 (단원 개편·개정 대응) | EPUB + 인쇄 PDF | `podReorderRequired = true` — 재인쇄 필요 플래그 |
| Minor 버전 업 (문항 교체·보강) | EPUB | PDF 재생성은 원장 결정 |
| Patch (오탈자) | 재생성 없음 | 앱 화면 즉시 반영으로 충분 |
| **월간 리포트 발행 (P0-2)** | 학생별 워크북 EPUB/PDF | Picklass 고유 — 리포트 승인 시 합본 생성 |
| 원장 수동 재생성 | 선택 대상 | Studio 내 "재생성" 버튼 |

생성 상태는 `pending → completed / failed`로 추적(비동기 큐).

---

## 5. 데이터 · 스토리지 (차용)

- **`GeneratedBook`** (레퍼런스 `generated_ebooks` 번안): id, textbookRef(또는 studentWorkbookRef), textbookVersionId, purpose(`app_viewer` / `pod_print` / `monthly_workbook`), fileAssetId, status. → N4 `PublishOrder`가 이 레코드를 참조해 발주.
- **파일 자산**: 메타데이터 테이블 + 오브젝트 스토리지(S3 호환).
  - 공통 교재 EPUB → CDN 배포.
  - **학생별 워크북·POD PDF → CDN 미노출, 서명 URL(24h)** — 학생 개인 데이터 포함물 보호(레퍼런스 CDN 정책 준용, §22.3 개인정보 정합).

## 6. 기술 스택 후보 · 미결 사항

레퍼런스 스택(Pandoc + XeLaTeX + Noto Sans KR, B5·CMYK·300dpi)을 1차 후보로 차용하되, 아래는 Picklass 검증 필요.

| 이슈 | 내용 | 출처 |
|---|---|---|
| Pandoc/XeLaTeX 차용 여부 | 전용 워커 서버 vs API 서버 내 실행, 생성 큐(Redis vs 클라우드 큐) | 레퍼런스 §9 동일 |
| CMYK 정확도 | 인쇄 벤더별 검증(N2 §5-2 단위경제 실측과 병행) | 레퍼런스 §9 동일 |
| EPUB 뷰어 호환 | 자체 앱 뷰어 전제라면 레퍼런스보다 부담 낮음(iOS Books/Kindle 불필요) — **자체 뷰어 확정 여부** | Picklass 고유 |
| **QR 삽입 방식** | PDF 생성 시 템플릿 변수로 삽입 vs 생성 후 스탬핑 — 학생별 워크북은 대량 개별 생성이라 성능 직결 | Picklass 고유 |
| **영한 혼합 조판** | 영어 본문 + 한글 지시문 혼합 폰트·조판 품질 (레퍼런스는 한글 단일) | Picklass 고유 |
| 문항 레이아웃 | 일반 산문이 아닌 **문항·답란·보기** 조판 — Markdown 확장 또는 구조화 포맷 필요 여부 | Picklass 고유 |

## 7. 외부 플랫폼 업로드 — 열어둔 옵션 (⚠️ 미결정)

> **결정 사항 아님.** 기본 경로는 이퓨쳐 조달 인쇄 벤더(N2 §3·§5-2)다. 다만 **외부 POD·이북 플랫폼에 업로드하는 가능성을 열어두고**, 아래 기준으로 나중에 선택적으로 결정한다. (레퍼런스: 「POD 업로드 명세 v1.0」)

### 7-1. 경로 옵션

| 경로 | 내용 | 적합 상황 |
|---|---|---|
| **기본 — 이퓨쳐 조달 벤더** | `PublishOrder` → 이퓨쳐 인쇄 벤더 발주·배송 | 학원 단위 대량 인쇄, 단가·품질 관리 |
| **옵션 A — 외부 POD 플랫폼** | 인쇄 PDF를 교보POD·부크크·KDP 등에 등록 | 소량·개별 주문, 벤더 경로 확정 전 임시 운영, 일반 서점 유통 노출 |
| **옵션 B — 이북 스토어 유통** | EPUB을 외부 이북 플랫폼에 유통 | **학원 밖 판매(마켓) 결정 시** — [N4 §5](40_N4_원장교재스튜디오_POD_전략노트.md) 미결(타 학원 판매)과 한 묶음으로 결정 |

### 7-2. 외부 POD 플랫폼 후보 (레퍼런스 조사 차용)

| 플랫폼 | 특징 | API 지원 |
|---|---|---|
| 교보POD | 국내 최대, 교보문고 유통 | 제한적(FTP+수동 위주) |
| 부크크 | 독립출판·소량 인쇄 강점 | ❌ 수동만 |
| KDP (Amazon) | 글로벌 유통 | ✅ API |

### 7-3. 채택 시 반영 사항 (레퍼런스 차용)

- **업로드 방식**: **수동이 기본값**(구현 없음, 즉시 운영) → 플랫폼 API 확인 후 자동화 선택. 자동화 트리거: `GeneratedBook.status=completed` + `podReorderRequired` → 업로드 큐.
- **자동화 시 추가 스키마**: `PodUploadLog`(platform, status, platformBookId, attemptCount, error).
- **규격 확인 필수**: PDF/X-1a vs X-4(플랫폼별), 표지 별도 PDF(표지+뒤표지+책등), 폰트 아웃라인 임베드, **ISBN 발급 주체·시점**.
- **개인화 워크북 주의**: 학생별로 내용이 달라 공통 도서 등록 불가 → 학부모 직접 주문 vs 일괄 발주, 별도 결정.

### 7-4. 결정 기준 체크리스트 (선택적 결정용)

| 질문 | Yes라면 |
|---|---|
| 이퓨쳐 벤더의 단가·최소수량이 소량 주문에 불리한가? | 옵션 A 병행 |
| 학원 밖 일반 판매(마켓)를 열 것인가? (N4 §5 미결) | 옵션 A+B 검토 — ISBN·품질 인증 체계 필요 |
| 플랫폼 직접 결제(N2 §5-1)와 외부 서점 유통의 병행이 규제·계약상 가능한가? | 법률검토 스코프에 포함 |
| 외부 플랫폼 검수 기간(1~3영업일)이 학원 운영 리듬(시험기간)과 맞는가? | 옵션 A는 정규 교재만, 시험자료는 기본 경로 |

## 8. 단계화 (N4 §6과 정렬)

- **P1** — 경로 A(앱 실시간 렌더)만: 라이브러리 콘텐츠를 교재 연동 학습 화면으로. 파이프라인 인프라 불필요.
- **P2-1** — **B-1 EPUB 먼저**: 앱 eBook은 구독 기본 포함(N2)이라 수요 확실 + 인쇄 검증 불필요.
- **P2-2** — **B-2 인쇄 PDF + POD 발주**: CMYK·벤더 검증(N2 단위경제 실측) 후. QR 2-티어 포함.
- **후속** — 월간 워크북 자동 합본(리포트 발행 트리거), 개정판·재인쇄 관리.

## 9. 제안 액션

- **A. N4 §2·§3에 본 노트 포인터** — 산출 단계의 생성 파이프라인 상세로 연결.
- **B. 개발 스코핑 항목 추가** — §6의 Picklass 고유 4건(자체 뷰어·QR 삽입·영한 조판·문항 레이아웃).
- **C. N3 §3에 QR 2-티어 역반영 (✅ 반영 완료)** — 공통 교재(콘텐츠 토큰+세션 식별) vs 개인화 인쇄물(학생×문항 토큰) 구분을 N3 §3·§2에 명문화함.
- **D. 레퍼런스 미결 이슈 추적** — CMYK·Pandoc 인프라·큐는 레퍼런스 프로젝트의 검증 결과를 공유받아 중복 검증 회피.
- **E. 외부 플랫폼 옵션 결정(§7)** — 벤더 단가 실측(N2 §5-2)·마켓 여부(N4 §5)·법률검토 결과가 모이는 시점에 §7-4 체크리스트로 선택적 결정. 그 전까지 미결 유지.

> 본 노트는 결정 문서가 아니다. §2 파이프라인과 §8 단계는 §6 미결(스택·조판·QR 삽입)이 검증된 뒤 관련 P1/P2 문서로 반영·승격하며, §7 외부 플랫폼 업로드는 §7-4 기준이 충족될 때만 선택 채택한다.
