---

## 0. 왜 이 노트가 필요한가 (공백 진단)

N1 §3-1("커스텀 수업교재를 스튜디오에서 저작 → POD·eBook")과 N2 §4 ②(a)("정규 수업교재")에 **한 줄 윤곽만** 있고, 다음이 전부 미정의였다:

- 교재의 **소재가 무엇인지** (무엇으로 저작하는가)
- 승인된 콘텐츠를 **누적하는 저장소**(라이브러리) 개념
- 콘텐츠를 교재로 엮는 **편집·조판(북빌더)** 기능
- **저작권·IP 귀속** — 특히 P0-5 §8.1(교과서 변형 = 2차적저작물)이 출판물에 확대 적용되는 문제

본 노트가 이 공백을 "원장 교재 스튜디오"라는 한 기능으로 규정한다.

---

## 1. 콘텐츠 소재 3방향 (확정 방침)

교재의 소재는 다음 3가지 경로로 들어온다. **셋 모두 P0-4 검수(원장 승인)를 거쳐야 라이브러리에 축적**된다.

| 코드 | 소스 | 내용 | AI 역할 | 저작권 성격 |
|---|---|---|---|---|
| **S1** | **원장 업로드 자료** | 원장이 직접 만든 프린트·학습지·자료를 그대로 편입(디지털화·정리) | 없음 (파싱·구조화 보조만) | 원장 저작물. 단, 자료 안에 제3자 저작물(교과서 지문 등) 포함 시 리스크(§4) |
| **S2** | **원장 자료 변형 AI 생성** | 업로드 자료를 기반으로 AI가 변형·확장 — 난이도 조정, 쌍둥이 문항, 지문 재가공 | 변형 생성 | 원장 원저작 기반 2차적저작물. 원장 자료가 이미 제3자 소재의 변형이면 리스크 승계(§4) |
| **S3** | **요구사항 프롬프트 AI 생성** | 원장이 요구사항(주제·레벨·유형·분량)을 프롬프트로 입력 → AI 순수 생성 | 순수 생성 | 플랫폼 생성물 — AI 생성물의 귀속·이용권 정책 필요(§4) |

- 세 경로는 배타적이 아니라 **한 교재 안에서 혼합**된다(예: 원장 프린트 + 그 변형 문항 + 프롬프트 생성 신규 단원).
- 모든 자산은 소스 태그(S1/S2/S3)와 출처 메타를 달고 저장 — 저작권 추적성의 기반.

## 2. 기능 개요 — 파이프라인

```
 [유입]  S1 업로드  /  S2 원장자료 변형 생성  /  S3 프롬프트 생성
    │
    ▼
 P0-4 검수 (원장 승인 게이트)
    │
    ▼
 📚 콘텐츠 라이브러리         승인 자산 누적 · 소스태그(S1/S2/S3) · AcademyScope 단원 매핑
    │
    ▼
 📖 북빌더 (교재 저작)        단원 구성 · 목차 · 표지 · 조판 — 진도 기반 목차 자동 초안
    │                        └ 출판 전 원장 최종 승인(검수 게이트)
    ▼
 [산출]  앱 eBook (기본 포함)  +  실물 POD (유료, 페이지수 가변 제작비)
    │                            └ QR 결속(N3): 교재 문항 → 손글씨 답안 채점 → 리포트 환류
    ▼
 (옵션) 이퓨쳐 편집·품질관리  →  인쇄 벤더 발주  →  배송
```

- **P0-5와의 관계**: P0-5(내신 자동출제)의 승인 문항도 라이브러리로 흘러들어 교재 소재가 될 수 있다(시험대비 단원). P0-5는 "시험 세트" 단위 소비, N4는 "교재" 단위 축적·재사용이라는 점이 다르다.
- **N2와의 관계**: 본 기능이 N2 3층 BM의 **②볼륨층 (a) 정규 수업교재**의 제작 실체다. 교재비 = 페이지수 가변 제작비, 결제는 플랫폼 직접 결제(N2 §5-1) 준용.
- **생성 파이프라인**: 산출(앱 렌더·EPUB·인쇄 PDF)의 1원본 3출력 파이프라인·트리거·QR 삽입 방식은 [N5](40_N5_이북출력파이프라인_전략노트.md).

## 3. 설계 원칙

- **라이브러리 = 승인 자산만**: 검수 게이트(P0-4)를 통과한 콘텐츠만 축적. 미승인 생성물은 교재에 못 들어간다.
- **소스·출처 메타 필수**: 자산마다 S1/S2/S3 태그 + 원본 참조(uploadRef / baseAssetRef / promptRef) 저장 → 저작권 추적성(§4)과 개정판 관리의 기반.
- **AcademyScope 매핑**: 자산을 학원 진도·단원에 태깅 → 북빌더가 **진도 기반 목차 초안을 자동 생성**, 원장은 배치·수정만.
- **교재도 Human-in-the-loop**: 출판(발주) 전 원장 최종 승인. 검수 없는 자동 출판 금지(P0-4 원칙 준용).
- **QR 결속 기본**(N3): 교재 문항·페이지에 QR을 인쇄해 손글씨 답안이 채점·리포트로 돌아오게 — 교재가 루프 밖 산출물이 아니라 **루프 안 데이터 채널**이 된다.

**데이터 모델 초안**

| 엔티티 | 필드(요약) |
|---|---|
| `ContentAsset` | id, source(S1/S2/S3), originRef(upload/baseAsset/prompt), scopeRef(단원), type(지문/문항/자료), reviewStatus, ipMeta(권리·출처), version |
| `TextbookProject` | id, institutionId, title, units[{unit, assetIds[]}], coverMeta, status(draft/approved/published), version |
| `PublishOrder` | textbookRef, format(eBook/POD), pages, qty, unitCost, orderStatus |

## 4. 저작권 · IP (실행 전제 — 최대 리스크)

[P0-5 §8.1](P0-5_내신자동출제_상세기획.md)의 결론(교과서 지문 변형 문항 = 2차적저작물, 영리 서비스 면책 없음)은 **교재 POD에서 더 크게 적용**된다 — 문제세트 출력은 학원 내부용이지만, 교재는 **출판물화(복제·배포)**이기 때문.

| 소스 | 리스크 | 정책 방향(제안) |
|---|---|---|
| S1 업로드 | 원장 자료에 교과서 지문·타사 문항 포함 가능 | 업로드 시 권리 보증 약관(원장 책임) + 유사도 검사 보조. 경쟁사도 "정식 라이선스 vs 사용자 책임 전가" 양자택일(§8.1) |
| S2 변형 | 원장 원저작이면 안전측이나, 원본이 제3자 소재의 변형이면 2차적저작물 리스크 승계 | originRef 추적 + S1과 동일 보증 체계 |
| S3 프롬프트 생성 | AI 생성물의 저작권 귀속·법적 지위 미확정 | 이용권은 원장(학원)에게, 귀속·재사용권은 약관으로 명시 |
| 공통 | 원장 교재의 IP 귀속 — 원장 저작 vs 플랫폼 생성 기여 vs 이퓨쳐 편집 기여 | **교재 소유권·수익 배분(RS)을 N2 RS 정책과 한 묶음으로 결정** |

→ **법률검토 스코프에 추가**: ①원장 업로드 자료 책임 구조 ②AI 생성물 IP ③교재 출판·판매의 저작권 ④(N2 §5-1) 플랫폼 직접 결제와 교재 판매의 규제 정합.

## 5. 리스크 · 미검증 가정

| 리스크 | 내용 | 대응 |
|---|---|---|
| **업로드 자료 파싱** | 스캔 PDF·한글 파일 등 형식 다양 → 구조화 난이도 | 초기엔 텍스트·정형 포맷 우선, OCR(N3 자산) 재사용 |
| **조판 품질** | 교재급 조판은 자동화가 어려움 | 템플릿 기반 자동 조판 + **이퓨쳐 편집 역량을 품질 옵션으로**(N2 §3) |
| **원장 저작 부담** | 북빌더가 무거우면 채택 실패 | 진도 기반 목차 자동 초안 + 배치·수정만 하는 UX |
| **저작권** | §4 — 트랙 존립 이슈 | 법률검토 선행, 약관·추적 메타 설계 |
| **단위경제** | POD 제작비·최소수량 | N2 §5-2 실측과 연계 |
| **(미결) 타 학원 판매** | 원장 교재를 마켓플레이스로 타 학원에 판매할지 | **미결정 — 별도 논의 필요.** 판매 시 IP·RS·품질 인증 체계가 완전히 달라짐. 외부 유통 경로 옵션은 [N5 §7](40_N5_이북출력파이프라인_전략노트.md) |

## 6. 단계화

12월 파일럿(진단→출제→리포트 루프)과 경합하지 않도록 후행 배치.

- **P1** — **콘텐츠 라이브러리**: P0-4/P0-5 위에 승인 자산 축적 레이어(소스 태그·스코프 매핑). 신규 UI 최소.
- **P2** — **북빌더 + 출판**: 단원 구성·조판·표지 → eBook 출력 → POD 발주 연계(이퓨쳐 편집 옵션, QR 결속 기본).
- **후속** — 개정판·버전 관리, (미결) 타 학원 판매 마켓.

---

## 7. 제안 액션

- **A. N1 §3-1·N2 §4 ②(a)에 본 노트 포인터** — "커스텀 수업교재"의 제작 실체로 연결.
- **B. 법률검토 스코프 확장** — §4의 4개 항목을 N2 §6-B 법률검토 목록에 추가.
- **C. 개발 스코핑** — 업로드 파싱, `ContentAsset` 스키마, 북빌더·조판 스택.
- **D. 미결 질문 확정** — 타 학원 판매(마켓플레이스) 여부.

> 본 노트는 결정 문서가 아니다. §2 파이프라인과 §6 단계는 §4(저작권·IP)·§5 가정이 검증된 뒤 관련 P1/P2 문서로 반영·승격할 것.
