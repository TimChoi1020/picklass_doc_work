## 0. 왜 이 노트가 필요한가 (공백 진단)

기획 전반은 "종이 병존"을 말하면서도, **종이 답안을 어떻게 데이터·채점으로 되돌리는가**의 메커니즘이 비어 있었다.

- [P1-1 §11.C](P1-1_Writing영역_상세기획.md)가 **손글씨 OCR 부재를 명시적 공백**으로 남겼다(내신 서술형=손글씨, 경쟁사 킬러=손글씨 인식 채점, `HANDWRITING_MATCH` KPI만 존재).
- [N1 §3](40_N1_콘텐츠전달매체_종이vs온라인_전략노트.md)은 "과정 데이터는 종이로 수집 불가"를 종이의 약점으로 봤다.

본 노트는 이 두 공백을 잇는 **한 기능**(QR 결속 + 손글씨 OCR 채점)을 규정한다.

## 1. 근거 (문서 인용)

| 근거 | 함의 | 출처 |
|---|---|---|
| 내신 서술형 = 손글씨 정기고사 | 종이 채점이 실전 | [시장조사 §1-3](10_시장조사_서술형_v1.0.md) |
| 경쟁사(CLIPO·Engram) 킬러 = 손글씨 인식 채점 | 시장 기대치 | [시장조사 §3](10_시장조사_서술형_v1.0.md) |
| 손글씨 OCR 공백, `HANDWRITING_MATCH` KPI만 존재 | 해결 대상 | [P1-1 §11.C](P1-1_Writing영역_상세기획.md) |
| 개인화·범위 종속 문항 = 표준 답안키 없음 | **QR 식별이 채점의 전제** | [P0-5 §6](P0-5_내신자동출제_상세기획.md) |

> 핵심: Picklass 문항은 개인화·범위 종속이라 표준 답안키가 없다. **QR이 "이 종이 = 이 학생 × 이 생성 문항"을 식별해줘야** 그 문항의 `modelAnswer`·`rubricRef`·`essaySubtype`를 불러와 채점할 수 있다. QR 없이는 개인화 종이 채점이 사실상 불가능 — 이것이 본 기능의 핵심 근거다.

## 2. 기능 개요 — 동작 흐름

```
[출력] P0-5 출력 센터 → 문항 + 답란(괘선/박스) + 코너 정렬마커 + QR 인쇄
        QR payload = 불투명 인스턴스 토큰(서버 조회키) — PII 미포함
[응시] 학생 손글씨 작성 (내신 실전과 동일)
[캡처] ★학습자(학생)가 직접 촬영/스캔 → 앱 업로드
        → QR 판독으로 문항·루브릭 전개 (학생 식별: 개인화물=QR, 공통물=앱 세션 — §3 2-티어)
        → 정렬마커로 답란 크롭
[인식] 이미지 전처리 → 영어 손글씨 OCR(HWR)
        → ★학생이 인식 텍스트 확인·수정(OCR 정확도 보강)
[채점] essaySubtype별: 규칙형(배열·빈칸)=매칭 / 내용형(요약·조건영작)=LLM 루브릭
        → P0-4 검수 가중(OCR·LLM 불확실성)
[환류] P0-2 리포트(서술형 지표) · P1-2/진단 약점태그 · P1-3 Achievement
```

---

## 3. 설계 원칙

- **QR = 불투명 인스턴스 토큰**(PII 미포함), 서버에서 학생·문항·루브릭 전개(개인정보·보안, §22.3).
- **QR 2-티어** ([N5 §3-1](40_N5_이북출력파이프라인_전략노트.md)에서 역반영): 산출물 성격에 따라 페이로드를 이원화한다.

  | 산출물 | QR 페이로드 | 학생 식별 |
  |---|---|---|
  | **개인화 인쇄물** (학생별 시험지·워크북·답안지) | **학생×문항 토큰** (원안) | QR 자체로 식별 |
  | **공통 인쇄물** (학원 교재 등 반 전체 대량 인쇄) | **콘텐츠 토큰** (교재×문항) | 캡처하는 **앱 로그인 세션**으로 식별 |

  공통 인쇄물은 학생별 QR 인쇄가 비경제적이므로 콘텐츠만 식별하고, 학생은 캡처 시점의 앱 세션이 식별한다 — "이 종이 = 이 학생 × 이 문항" 원칙은 두 경로 모두에서 최종적으로 성립.
- **정렬마커(fiducial) + 정형 답란(박스/괘선)**으로 OCR 정확도 확보 — 자유 여백보다 구조화된 답란.
- **★ 학생 주도 캡처·보정 (핵심 결정)**: 스캔·촬영을 **학습자가 직접** 수행하고, OCR 인식 텍스트를 **학생이 확인·수정**해 정확도를 보강한다.
  - **원장 운영 부하 제거**: 30명분을 원장이 스캔하는 병목이 사라짐(채택 장벽 완화).
  - **채점 신뢰↑**: OCR 오인식을 채점 전에 학생이 1차 교정 → "부정확 리포트=이탈"([P0-2 원칙](P0-2_성장리포트MVP_상세기획.md)) 리스크 감소.
  - **학습 효과**: 자기 답안을 다시 읽고 확인하는 과정 자체가 복습·메타인지 터치포인트.
  - **가드**: 학생 보정본도 최종 채점물은 [P0-4](P0-4_강사검수UX_상세기획.md) 검수 가중(학생이 오답을 정답으로 고치는 악용 방지 — 원본 이미지 병행 보존).
- **essaySubtype별 OCR 리스크 차등**: 규칙형(배열·빈칸·철자 정확도)은 OCR 오독에 취약 → 검수/온라인 입력 권장. 내용형(요약·빈칸서술)은 LLM 루브릭 + 검수 가중([P0-5 §11.5](P0-5_내신자동출제_상세기획.md)).

## 4. 과정지표 = 온라인 사용 유인 (positive framing)

종이 경로는 **결과·채점만** 얻고 **과정지표(시도·시간·오답 패턴)는 남기지 못한다**([P1-2](P1-2_과정데이터환류_상세기획.md)). 이 한계를 약점이 아니라 **온라인의 강점으로 전환**한다.

- 메시지: *"종이로도 채점·분석은 되지만, **온라인으로 풀면 과정(시도·시간·이해도)까지 분석**됩니다."*
- 효과: 학원·학생이 자연스럽게 **온라인 실행으로 이동하는 넛지**. QR·OCR은 종이를 살리되, **과정 데이터 우위로 온라인 전환을 유도**하는 두 갈래 전략.
- 리포트 표기: 종이 제출분은 소스를 "종이(OCR)"로 명시, 과정지표 칸은 "온라인 학습 시 제공"으로 유도 문구.

## 5. 리스크 · 미검증 가정 (검증 필요)

| 리스크 | 내용 | 대응 |
|---|---|---|
| **영어 손글씨 OCR 정확도** | 초등 고학년 필체·영어 HWR은 인쇄체보다 어려움. 오채점 위험 | 학생 인식 보정(§3) + P0-4 검수 가중 + **벤치마크 선행** |
| **규칙형 채점의 OCR 취약성** | 배열·철자 정확도를 보는 유형인데 OCR 오독 시 정답을 오답 처리 | 규칙형은 검수 필수 / 온라인 입력 권장 |
| **인쇄·QR 품질** | POD·일반 프린터 해상도, 구겨짐 훼손 | QR 에러정정 레벨↑, 재인쇄 |
| **개인정보** | 스캔 이미지 보관·동의, QR에 PII 미포함 | 토큰화 + 동의·보존 정책(§22.3) |
| **저학년 필체** | 인식률 저하 | 대상 학년·유형 제한으로 시작 |
| **채택 부하** | (완화) 캡처를 학생이 수행 → 원장 부하는 낮음. 대신 학생 UX 단순화 필요 | 촬영 가이드·자동 크롭 |

## 6. 단계화 (12월 도입창 정합)

P0-5의 "생성 먼저, 채점 나중" 2단 폴백과 같은 리듬.

- **P0 (12월)** — **QR 결속·출력만.** [P0-5 출력 센터](P0-5_내신자동출제_상세기획.md)가 문항 + 답란 + 정렬마커 + QR을 인쇄, QR이 학생×문항 인스턴스를 묶는다. 채점은 아직 수기/온라인.
- **P1** — **학생 주도 캡처 → OCR → 채점.** 규칙형 자동채점 우선 + 학생 보정 + 검수. [P1-1 §11.C](P1-1_Writing영역_상세기획.md) 공백 해소, `HANDWRITING_MATCH` KPI 활용.
- **P2** — 배치 스캔·복합기 연동, 학교별 시험지 포맷, 정확도 고도화.

---

## 7. 제안 액션 (반영 위치)

- **A. P0-5**: 출력 산출물에 **QR 결속**(FR-6) + 종이→OCR **채점 경로**(FR-7) 명시.
- **B. P1-1 §11.C**: OCR 공백 해결책으로 본 노트 연결, 오픈이슈 ⑤(OCR) 확장.
- **C. N1**: 매트릭스 "첨삭·서술형 답안"을 **QR-OCR 브리지**로 구체화 + 과정지표 온라인 유인(§4) 반영.
- **D. N2**: POD 워크북에 **QR 결속**으로 채점·증명 고리 강화(개인화 워크북이 채점까지 돌아옴).
- **E. P1-2**: 종이 경로 데이터 한계 + **온라인 유인** 명시.

> 본 노트는 결정 문서가 아니다. §6 단계와 §7 액션은 §5 가정(OCR 정확도·개인정보·채택 부하)이 검증된 뒤 관련 P0/P1 문서에 반영·승격할 것.
