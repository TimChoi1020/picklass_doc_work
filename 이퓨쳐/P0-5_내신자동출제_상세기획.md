## 1. 목적·배경

우리 학원의 **내신 시험범위·교과서에 종속된 문제와 서술형 쌍둥이 문항을 자동 생성**한다. 시장 1순위 니즈이자 현 제품이 직접 커버하지 못하는 영역.

- 시장 근거: AI 기대영역 1위 = **자동출제 51%**, 추가희망 자동출제 36%(교습소 1순위 47%). "시험범위와 모르는 부분을 접목한 맞춤 문제"(전소영), "같은 유형 반복·변형하는 서술형 쌍둥이 문제"(디에이블), 개정 교과서 자료공백(토피아·JK).
- **현 엔진과의 차이**: 「지능형 수업 설계 자동화 로직」은 *지문(레벨)+KPI+시간 → 교수법 모듈 시퀀싱*. 본 항목은 *내신 범위 텍스트 → 시험 대비 문항 생성*. 입력과 출력이 다르다.
- **경쟁 공백(시장조사)**: 국내는 서술형 채점(CLIPO·Engram)과 변형문제 자동출제(너른터·QBank)가 **분리** 운영 — "내신 서술형 자동출제 + 범위 종속 내용 채점" 결합은 **공백**. 해외 엔진(Cambridge W&I·ETS)은 '문항 내용 적합성'을 채점하지 못함 → **범위 종속 내용 채점이 차별화 포인트**. 상세: [서술형 시장조사 v1.0](10_시장조사_서술형_v1.0.md).

### 1.1 핵심 개념 정의 — "무엇을" 출제하는가

위 문장은 두 축의 결합이다: **①출처 종속성**(어디서 뽑는가) × **②서술형 쌍둥이**(같은 유형을 몇 개·어떻게 변형하는가). 전체 유형 명세는 §11, 아래는 개념·예시.

**① 출처 종속성 — "내신 범위·교과서 종속"**
범용 문제은행이 아니라, **학원이 업로드한 그 학교 시험범위 지문**의 실제 문장·어휘·문법 포인트만을 소재로 생성한다(범위 밖 소재 배제). 이것이 범용 출제기와의 차별점이자 §8.1 저작권 이슈의 근원.

> **예시** — §11.0 공통 지문(꿀벌)의 한 문장 *"This process, called pollination, helps plants make fruits and seeds."*에서:
> - **객관식**: 어휘(`pollination` 뜻) · 문법(`would not grow` 가정법 어법) · 독해(글의 주제)
> - **서술형**: 조건 영작 · 문장 배열 · 빈칸 서술 · 요약 (§11.1~11.4)
> → 모두 **그 지문 안에서만** 출제. 같은 유형이라도 다른 학교 범위 지문을 넣으면 소재가 통째로 바뀐다.

**② 서술형 쌍둥이 — "같은 유형의 변형 세트" (FR-4)**
기준 문항 1개에서 **유형·구조는 유지하고 표면 내용만 바꾼 N개 변형**을 생성. "같은 유형을 반복·변형해 훈련"하려는 수요(디에이블)에 대응하며, 채점 루브릭은 기준 문항과 공유한다.

> **예시** — 조건 영작 기준 문항 `Without bees, many crops would not grow.` (조건: `without` + `crops`·`grow`)에서:
> - **쌍둥이1 (소재 치환)**: `crops→fruits` → `Without bees, many fruits would not grow.`
> - **쌍둥이2 (조건 유지·단어 교체)**: 가정법·`without` 구조 유지, 목표 어휘만 교체
> - **쌍둥이3 (같은 유형 다른 문장)**: 지문의 다른 문장에 동일 조건 유형 적용
> → **유형 불변 · 내용 변형**. 객관식도 선지·소재만 바꿔 동형 변형 가능(§11.2 배열형 등).

## 2. 사용자 스토리

- (원장) 우리 학교 시험범위 지문을 넣으면, 그 범위 안에서 문법·독해·서술형 문제가 자동으로 나오면 좋겠다.
- (원장) 같은 유형을 조금씩 바꾼 쌍둥이 문항을 여러 개 뽑아 반복 훈련시키고 싶다.
- (원장) 개정 교과서라 기출이 없는데, 학교 출제 스타일에 맞춘 문항을 만들고 싶다.

## 3. 범위 (In/Out)

**In (MVP — 스코핑 확정 후)**
- 입력: `AcademyScope`(P0-3)의 교과서·시험범위 텍스트/지문
- 출제 유형(1차): 어휘·문법·독해 객관식 + **서술형(쌍둥이 변형)** — 서술형 하위유형: **조건 영작·문장 완성/배열·빈칸 서술·요약**(영어 성취기준 평가 예시 준용, 시장조사 §1-3)
- 문항 생성 → **P0-4 검수** → 문제지/세트로 저장·출력
- Writing 서술형 모듈(SWR·PWR·PPR·SMW 등, §13) 채점 루브릭 재활용으로 서술형 채점 연계 (※WFT는 어휘 계열이라 부적합, SMW는 작문적 요약 신규 — [P1-1 §11.B](P1-1_Writing영역_상세기획.md#11) 참조)

**Out (후속)**
- 학교별 출제 스타일 학습(파인튜닝/RAG, P1~P2), 이미지·표 포함 문항(P2), 완전 자동 시험지 편집·제본(P2)

## 4. 기능 요구사항 (FR)

- **FR-1** 범위 입력: 시험범위 텍스트/지문 업로드 또는 `AcademyScope` 참조. §9.4 난이도 분석 적용.
- **FR-2** 유형·수량 선택: 출제 유형(어휘/문법/독해/서술형)·문항 수·난이도 선택. 서술형 선택 시 **하위유형(조건영작/문장완성·배열/빈칸서술/요약)** 지정.
- **FR-3** 문항 생성: 범위 텍스트 기반 문항+정답+해설 생성(LLM 런타임, §Voca_Reading 대화전략의 LLM/Seed+LLM 전략 준용).
- **FR-4** 서술형 쌍둥이: 기준 문항에서 유형 유지·표면 변형한 N개 변형 생성.
- **FR-5** 검수: 생성 문항을 P0-4 검수 큐로 전달, 승인 전 배포 불가(품질 가드 — "70% 만족" 문제 대응).
- **FR-6** 세트화·출력: 승인 문항을 문제지/온라인 세트로 저장, Tutoring 배포 또는 PDF 출력. **종이 출력분은 QR 결속(학생×문항 인스턴스)·정렬마커·답란 포함**([N3](40_N3_종이디지털브리지_QR_OCR_전략노트.md), P0=QR결속).
- **FR-7** 서술형 채점 연계: Writing 모듈 채점 루브릭으로 학생 답안 채점·피드백(진단 신호로도 활용). **종이 답안은 QR 식별 → 학생 주도 손글씨 OCR·보정 → 채점 경로**([N3](40_N3_종이디지털브리지_QR_OCR_전략노트.md), P1).

## 8. 예외·엣지 케이스

- 범위 텍스트 부족/저품질: 최소 입력 기준 미달 시 경고·차단.
- 생성 문항 오류(오답·맥락 불일치): P0-4 검수 필수, 반려·재생성.
- **저작권 (⚠️ 트랙 존립 이슈 — §8.1 별도 분석)**: 교과서 지문은 출판사 저작물이며, 이를 소재로 한 변형문항은 **2차적저작물**이라 "변형·자체 생성"만으로 면책되지 않는다. 상세 정책은 §8.1.
- 서술형 채점 신뢰도: 루브릭 기반 + 원장 최종 확인(LLM 채점은 과제·유형별 성능 편차가 연구로 보고됨 → **Human-in-the-loop 필수**, 시장조사 §3).

### 8.1 저작권 처리 정책 (경쟁사 조사 기반)

> 내신은 교과서 콘텐츠 종속이 본질이므로 저작권 처리가 트랙 존립을 좌우한다. 경쟁사 웹조사(2026-07 실시) 결과, **저작권을 "우회"하는 경쟁사는 없으며** 정식 라이선스 정면돌파 아니면 사용자 책임 전가 둘 중 하나다.

**(a) 법적 전제 — 사설 학원 SaaS는 교육 예외에 못 기댐**

| 근거 | 내용 | 이퓨쳐(영리 SaaS) 적용 |
|---|---|---|
| 저작권법 **제25조** | 교과서 게재 + 학교·교육기관 수업목적 이용(보상금) | ❌ "학교·교육기관"에 한정 — 사설 학원 대상 서비스 제외 |
| 저작권법 **제32조** | 시험·검정 목적 저작물 이용 | ❌ 단서 "**영리 목적은 불가**" — 상업 출제 면책 안 됨 |
| 판례(서울중앙지법 2005가합73377) | 시험문제는 독립 저작물이나 **교과서 지문 변형 문항 = 2차적저작물** | ⚠️ "변형했으니 안전"은 성립 안 함 — 원저작자 허락 필요 |

**(b) 경쟁사 처리 방식 — 두 갈래**

- **정면돌파(라이선스)**: 쏠북((주)북아이피스, 저작권대리중개업 신고 제1496호) = NE능률·YBM·다락원·지학사 등 출판사별 교재 라이선스 1년 단위 판매·중개, 원문 그대로 등록 금지·유형/선지 교체 변형만 허용. 너른터(씨앤리)도 교과서 기반 변형문제 은행이나 EBS 자료는 "사전 안내 없이 중단 가능"이라 라이선스 미확보 인정. 비상교육 비바샘(출판사 직영)은 "학교 수업 목적"으로만 한정, 학원 상업 이용 원천 차단.
- **사용자 책임 전가**: 퀘스천메이커·뚝딱 = **자체 지문 미보유**, 교사·학원이 직접 붙여넣은 텍스트를 변형·문항화 → 저작물 입력 책임을 사용자에게. (단 플랫폼 방조·기여침해 책임은 국내 판례 미확립.)

**(c) 이퓨쳐 옵션 · MVP 권고**

| 옵션 | 방식 | 리스크 | 위치 |
|---|---|---|---|
| ① **사용자 업로드**(권고) | 학원이 자기 시험범위 지문 직접 업로드, 엔진은 변형·문항화만. **이퓨쳐는 교과서 원문 저장·배포 안 함** | 플랫폼 방조책임 회색지대 → 약관으로 책임 분배 | **MVP** — AcademyScope(P0-3)의 "학원이 범위 입력" 구조와 정합 |
| ② AI 자체 지문 생성 | 교과서 원문 대신 동일 주제·난이도 완전 자체 지문 | 침해 회피 경계 불명확 + "범위 종속"이라는 상품가치와 상충 | 쌍둥이 변형과 부분 결합 |
| ③ 정식 라이선스 중개 | 쏠북식 출판사별 계약 | 요율·최소규모 미지수, 협상 리드타임 | P1~P2 |

> **MVP 설계 원칙**: **① 사용자 업로드 + 약관상 책임 분배**로 진행하되, "입력 지문은 학원 소유·이퓨쳐 미저장, 출력은 변형문항"을 아키텍처 원칙으로 명문화한다. ②는 쌍둥이 변형에 부분 활용, ③은 후속.

**(d) 수능·모의고사·EBS 특수 리스크 (교과서보다 한 단계 높음)**

내신 대비 소재로 수능/모의/EBS 기출이 함께 쓰이나, 이들은 교과서보다 저작권 리스크가 크다.

| 소재 | 권리 구조 | 실증 사례 | 리스크 |
|---|---|---|---|
| 수능·모의 **문항** | 한국교육과정평가원(KICE) 저작권 보유 | 평가원은 개인풀이·EBS 외 영리출판을 허락한 적 없고 **"묵인"**해왔을 뿐, 2012년부터 EBS 외 모의고사 이용 법적 단속 | **높음** — 묵인 철회 시 즉시 노출 |
| 수능·모의 **지문 원문** | 원저작자 | 평가원 본인이 문학·미술 155건 무단 전송으로 저작권자에 **사용료 배상 판결**(1,000만원대) | **높음** — 출제기관도 못 피함 |
| **EBS 연계교재** | EBS | EBS가 수능특강 **변형교재** 제작 업체 상대 **2022 승소·3,000만원 배상+판매금지** | **최고** — "변형"까지 실제 단속·판결 |

> **함의**: ⓐ 저작권법 제32조 시험목적 예외는 **출제 시점(평가원)에만** 적용 — 기출을 상업 서비스로 재사용하는 영리목적엔 미적용(교과서와 동일). ⓑ **"묵인"에 기대는 것은 사업 리스크**. ⓒ **EBS 지문은 변형 단속 판례가 존재**하므로 ① 사용자 업로드 모델에서도 **별도 고위험군으로 표시**(너른터도 "EBS는 사전 안내 없이 중단 가능" 경고). ⓓ 수능·EBS 기출을 서비스가 **자체 DB로 보유·배포하지 않는다**는 원칙을 §8.1(c) ① 위에 겹쳐 적용한다.

## 9. 완료 정의(DoD) · QA

- 시험범위 입력 → 유형별 문항 자동생성 → 검수·승인 → 문제세트 출력 E2E.
- 서술형 쌍둥이가 유형 유지·내용 변형으로 N개 생성됨.
- 생성 문항 정확도 QA(교사 평가 기준 만족도 목표치 설정).
- 서술형 학생 답안이 루브릭 채점되어 리포트 신호로 연결.

## 10. 의존성 · 오픈 이슈 (⚠️ 착수 전 스코핑 필수)

- **최대 미지수(§5 G3)**: 현 `analyzer`/§9 엔진이 '지문'이 아닌 '내신 시험범위'를 입력으로 받아 시험 대비 문항을 생성하도록 확장 가능한가? 별도 파이프라인/모듈 신설이 필요한가?
- **오픈 이슈**: ①MVP 출제 유형 범위(서술형 포함 여부·수량) ②학교별 출제 스타일 반영은 P1로 미룰지 ③~~저작권·교과서 원문 처리 정책~~ **→ §8.1로 1차 확정: "사용자 업로드+약관 책임분배" MVP안 채택. 잔여 검증: (a)업로드 모델 플랫폼 방조책임 판례·법률자문 (b)쏠북식 라이선스 요율·최소규모(③옵션 대비)** ④서술형 채점 루브릭을 Writing 모듈에서 얼마나 재활용 가능한지.
- **선행**: P0-3 AcademyScope, P0-4 검수. **하류**: P0-2 리포트(서술형 진단 신호).
- **의사결정 — 2단 폴백(시장조사 반영)**: 서술형은 **어학원 1순위 수요이자 정책상 정기고사 필수 영역**([서술형 시장조사](10_시장조사_서술형_v1.0.md))이므로 일괄 축소 대신 단계 분리한다.
  - **1단계(유지)**: 서술형 **문항 생성**은 MVP 유지(FR-3·FR-4).
  - **2단계(분리)**: 서술형 **자동채점(FR-7)**은 규모가 크면 P1로 분리 — 생성만 먼저, 채점은 P1-1 Writing 루브릭 연동 시점에.
  - **최후 폴백**: 그래도 규모 초과 시에만 **어휘·문법 객관식 우선 + 서술형 전체 P1** 축소.

## 11. 부록 — 서술형 유형 정의 · 문항예시

> 서술형 4개 하위유형(`essaySubtype`)의 정의·문항예시·채점·자동생성·쌍둥이 변형 명세. FR-2(유형 선택)·FR-3(생성)·FR-4(쌍둥이)·FR-7(채점) 및 §6 데이터 모델(`modelAnswer`·`rubricRef`)의 기준. 상세 시장 근거는 [서술형 시장조사 v1.0](10_시장조사_서술형_v1.0.md).

### 11.0 `essaySubtype` enum · 채점 신뢰도 스펙트럼

| enum | 유형 | 채점 방식 | LLM 채점 의존도 | MVP 우선순위 |
|---|---|---|---|---|
| `sentence-order` | 문장 완성·배열 | 규칙 매칭(어순 일치) | 낮음 | **1차** |
| `cond-writing` | 조건 영작 | 정답+조건 충족 판정 | 중 | **1차** |
| `summary` (빈칸형) | 요약문 빈칸 | 규칙 매칭(핵심어 일치) | 낮음 | **1차** |
| `blank-desc` | 빈칸 서술 | 내용 적합성(LLM 루브릭) | **상** | 2차(검수 가중) |
| `summary` (자유형) | 자유 요약 | paraphrase 판정(LLM 루브릭) | **상** | 2차(검수 가중) |

> `summary`는 enum은 하나이나 **형태로 갈린다**: `answerSpec.summary.blanks[]`가 있으면 빈칸형(규칙형·1차), 없으면 자유형(LLM·2차). §11.5 참조.

```
채점 쉬움(규칙형) ←──────────────────────────→ 채점 어려움(내용형)
sentence-order  →  cond-writing  →  summary(빈칸)  →  blank-desc / summary(자유)
```

> **예시 공통 지문(범위 지문 가정)**
> *"Honeybees are important to our food supply. When bees move from flower to flower, they carry pollen. This process, called pollination, helps plants make fruits and seeds. Without bees, many crops would not grow. Sadly, the number of bees is falling because of pesticides and climate change."*

---

### 11.1 조건 영작 (`cond-writing`)
주어진 **조건(우리말·사용 단어·어법 요소·단어 수)**에 맞춰 문장을 써내는 유형. 내신 서술형 대표 격.

**문항예시**
> 다음 우리말과 같은 뜻이 되도록, **〈조건〉**에 맞게 영어로 쓰시오.
> **우리말:** 벌이 없다면, 많은 농작물은 자라지 않을 것이다.
> **〈조건〉** ① `without`을 사용할 것 ② 주어진 단어 `crops`, `grow`를 활용할 것 ③ 총 7단어로 쓸 것

| 항목 | 값 |
|---|---|
| `modelAnswer` | `Without bees, many crops would not grow.` |
| 허용 변이 | `Many crops would not grow without bees.` (어순 변형, 조건 ③ 7단어 동일 충족) |
| 채점(rubric) | 정답의미(4) + 조건충족 `without`·단어수(3) + 어법·철자(3) = 10점, 조건 누락/철자 오류별 부분감점 |
| 자동생성 | 범위 문장에서 목표 문법요소(가정법·전치사구) 추출 → 조건 부여 → 모범답안·단어수 자동 검증 |
| 쌍둥이(FR-4) | 소재 치환(`crops→fruits`)·조건 문법 유지·단어수만 조정 |

---

### 11.2 문장 완성·배열 (`sentence-order`)
어순·어형 능력 평가. 정답 어순이 고정적이라 **자동채점 신뢰도 최상**.

**문항예시 (배열형)**
> 괄호 안의 단어를 **어법에 맞게 배열**하여 문장을 완성하시오.
> When bees move from flower to flower, ( pollen / they / carry ).

| 항목 | 값 |
|---|---|
| `modelAnswer` | `they carry pollen` |
| 채점(rubric) | 완전일치(3) / 어순 일부 오류 부분점(1) |
| 자동생성 | 범위 문장을 어절 단위 분해·셔플 → 배열형 자동 생성(하 난이도) |
| 쌍둥이 | 동일 구문의 다른 문장 어절 재분해, 배열 단어수 가감 |

**문항예시 (완성형)**
> 빈칸에 알맞은 말을 넣어 문장을 완성하시오.
> This process, called ______, helps plants make fruits and seeds.  → 정답 `pollination`

---

### 11.3 빈칸 서술 (`blank-desc`)
**지문 내용 이해**를 전제로 빈칸 내용을 서술. 해외 엔진이 못 하는 **내용 적합성** 영역 → 차별화 핵심.

**문항예시 (이유 서술)**
> 본문에 근거하여, 벌의 수가 줄어드는 **두 가지 원인**을 영어로 쓰시오.

| 항목 | 값 |
|---|---|
| `modelAnswer` | `Pesticides and climate change (are reducing the number of bees).` |
| 키워드 집합 | `["pesticides", "climate change"]` (키워드 포함도 기반 부분채점) |
| 채점(rubric) | 핵심키워드 2개 포함(각 3) + 어법·표현(4). LLM 루브릭 채점 |
| 자동생성 | 지문 핵심정보 blank화 + 모범답안·허용답안군 생성 → **P0-4 검수 가중** |
| 쌍둥이 | 같은 지문 다른 정보 지점 blank화, 질문 각도 변경(무엇→왜→어떻게) |

**문항예시 (지칭 추론)**
> 밑줄 친 `This process`가 가리키는 내용을 우리말로 쓰시오. → 정답 `벌이 꽃 사이를 옮겨 다니며 꽃가루를 옮기는 것(수분)`

---

### 11.4 요약 (`summary`)
지문을 요약문으로 재구성. 주제 파악·압축 요구. 빈칸형은 안정적, 자유요약은 검수 부담.

**문항예시 (요약문 빈칸)**
> 다음은 윗글의 요약문이다. 빈칸 (A), (B)에 알맞은 말을 본문에서 찾아 쓰시오.
> *Bees help plants through **(A)______**, but their number is decreasing due to pesticides and **(B)______**.*

| 항목 | 값 |
|---|---|
| `modelAnswer` | (A) `pollination` (B) `climate change` |
| 채점(rubric) | (A)(3) + (B)(3) + 철자(정확 시 만점) |
| 자동생성 | 요약문 생성 후 핵심어 blank화(빈칸형은 안정적) |
| 쌍둥이 | 빈칸 위치·paraphrase 표현 변경, 요약 대상 문단 교체 |

**문항예시 (한 문장 요약)**
> 윗글의 요지를 `Bees ...`로 시작하는 한 문장의 영어로 요약하시오. → 모범답안 `Bees are essential for growing crops through pollination, but their numbers are declining.`

### 11.5 데이터 모델 확장 — `answerSpec` 초안

§6 `ExamItem`의 서술형 채점을 위해 `essaySubtype`별 정답 스키마를 분화한다(현 `rubricRef` 단일 필드 보강).

```
answerSpec (essay 전용, essaySubtype에 따라 구조 상이):
  cond-writing   : { modelAnswer, acceptedVariants[], conditions[{type, value}], wordCount }
  sentence-order : { modelAnswer(어순 문자열), acceptedOrders[] }
  blank-desc     : { modelAnswer, keywords[](부분채점), acceptableAnswers[] }
  summary        : { modelAnswer, requiredElements[], blanks[{id, answer}] }
공통 rubric      : [{ dimension, maxScore }]  // 예: 내용/조건충족/어법/철자
```

> **설계 원칙**: 규칙형(`sentence-order`·빈칸형 `summary`)은 **규칙 매칭 우선**으로 LLM 호출 최소화, 내용형(`blank-desc`·자유 `summary`)만 **LLM 루브릭 채점 + P0-4 검수 가중**. LLM 채점 성능 편차 연구(시장조사 §3) 근거로 내용형은 Human-in-the-loop 필수.
