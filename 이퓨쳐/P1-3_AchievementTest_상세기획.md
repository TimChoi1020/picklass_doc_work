# P1-3. Achievement Test (정기 성취도 평가) 상세 기획 — P-ALT R/W 트랙 AT

| 항목 | 내용 |
|---|---|
| 코드 | P1-3 (Gap G2 연장) |
| 우선순위 | P1 (파일럿 직후) |
| 진단 정체성 | **P-ALT 리딩·라이팅(R/W) 트랙의 AT(Achievement Test)** — [P0-1 진단](P0-1_진단온보딩_상세기획.md)(PT)과 **동일 엔진의 AT 운영 모드**. 별개 시험 아님. 스피킹 트랙 AT는 [P-ALT 스피킹](../참고/P-ALT_Speaking_v81.docx)이 담당 |
| 연계 | v0.20 §15.3 Achievement Test·§15.4 PPD, [P0-1](P0-1_진단온보딩_상세기획.md)(PT=baseline), [P0-2 리포트](P0-2_성장리포트MVP_상세기획.md)(성장 델타), §10 시퀀싱(피드백 루프) |
| 상태 | 확장 — §15.3 기획 존재 📋 → **PT/AT 체인의 AT로 가동** |

> **핵심 전환**: "진단 테스트를 그대로 AT로 쓴다." AT는 P0-1 진단과 다른 시험이 아니라, **같은 R/W 트랙 엔진을 `testType=AT`로 돌리는 운영 모드**다(P-ALT 스피킹 트랙의 PT/AT 체인 구조 준용). 따라서 이 문서는 신규 엔진이 아니라 **P0-1 엔진의 AT 운영 규칙·성장 산출·체인 정의**다.

## 0. PT/AT 체인 구조 (P-ALT 준용)

```
PT ─── AT ─── AT ─── AT ─── ...
 │      │      │      │
 └──▶ baseline ◀──────┘   각 AT는 "직전 진단"(previousSessionId)과 비교
```

- **PT** = [P0-1](P0-1_진단온보딩_상세기획.md): 신규생 입학 시 자동 1회 → **baseline**.
- **AT** = 본 문서: 학습 사이클 후 응시 → **직전 진단(PT 또는 직전 AT) 대비 성장** 측정. 자신도 **다음 AT의 baseline**이 된다.
- **성장 = 이번 AT 레벨 − 직전 진단 레벨.** 리포트 표기: "직전 대비 +X" (선택적 "PT 누적 +Y" 병기).
- 하나의 AT는 **"직전 대비 Post"이자 "다음 대비 Pre"** 역할을 동시에 한다.
- 대상 스킬: Vocab·Reading(파일럿) → Writing(P1-1 활성 시). P0-1과 동일 3레벨 체계(Vocab/Reading/Writing).

---

## 1. 목적·배경

학습 종료·구간 시점에 **성취도를 재측정**해, 직전 진단(입학 PT 또는 직전 AT) 대비 **성장 추이를 축적**하고 리포트의 "이만큼 컸다"를 데이터로 뒷받침한다.

- 시장 근거: 리포트가 지불 스위치인데, 그 신뢰는 **성장 증명(전후 비교)**에서 나온다. "1년 전엔 알파벳, 지금 라이팅 하는 걸 보여주고 싶다"(더그로우). 재원생 정기평가 수요(정성 ⑦).
- §15.3은 이미 기획됨 + §10과의 피드백 루프(Achievement 결과를 다음 회차 사전 미션 레벨에 반영)도 문서화됨.
- **엔진 재사용**: P0-1 적응형 CAT·난이도·KPI 산출을 그대로 쓰므로 신규 개발 부담이 낮다. 신설은 **AT 운영 규칙 + 성장 델타 + 체인 관리**뿐.

## 2. 사용자 스토리

- (원장) 한 학기/구간이 끝나면 성취도 평가를 돌려, 입학 때 대비 얼마나 늘었는지 학부모에게 보여주고 싶다.
- (학생) 내 성장이 숫자로 확인되면 동기부여가 된다(작은 성공).
- (시스템) 평가 결과를 다음 수업 난이도에 자동 반영하고 싶다.

## 3. 범위 (In/Out)

**In (P1)**
- **AT 실행**: P0-1 엔진 재사용(`testType=AT`, `previousSessionId` 설정). Vocab·Reading 성취 재측정(Writing 축은 P1-1 활성 시).
- **AT 운영 규칙**(§4): 문항 범위 ±4 제한, CAT 하향 기준 강화, **하한 보호**, 결과 표현 가이드라인.
- **성장 델타 산출**: 직전 진단 대비 레벨 + **KPI 축별(Reading 3축·Writing 5축) 변화**(정체 축 경고 포함).
- **리포트 연결**: P0-2 `GrowthReport.growthDelta`에 공급.
- **§10 피드백 루프**: 평가 결과를 다음 회차 사전 미션 레벨·약점 가중치에 반영.

**Out (후속)**
- PPD 정밀 진단 풀버전(§15.4·T1, Phase 2~), 전사 레벨테스트 일원화(T6, 후속), 자동 스케줄링 고급(P2), 공인시험 성장 예상 정밀 환산(파일럿 실측 후).

## 4. AT 운영 규칙 (PT 대비 차이) — P-ALT §4 준용

AT는 P0-1(PT)과 **같은 문항 엔진·같은 KPI 축**을 쓰되, "학습 후 성장 확인"이라는 목적에 맞춰 CAT 운영과 리포트만 달라진다.

### 4.1 PT vs AT 차이표

| 항목 | PT (P0-1) | AT (본 문서) |
|---|---|---|
| 문항 범위 | 전 구간(1–18) | **직전 진단 레벨 ±4 구간** |
| CAT 시작점 | 추정 레벨/기본값 | **직전 진단 레벨 고정 — 하향 출발 없음** |
| 하향 기준 | 하 1회 → 즉시 −1 | **하 1회 유지, 연속 2회 → −1** (더 엄격) |
| 하한 보호 | 없음 | **최종 레벨 ≥ 직전 진단 레벨** (아래로 못 내려감) |
| P2 Reading 지문 | 범용 범위 지문 | **학습 이력 기반**(런타임, 학습한 범위 우선) |
| 리포트 | 절대 레벨 + KPI 프로파일 | **성장 델타 + KPI 변화 + 정체 축 경고** |

### 4.2 AT CAT 판정 (직전 진단 기준)

| AT 판정 | 난이도 이동 | PT와의 차이 |
|---|---|---|
| 상 (Exceeds) | +2 상향 | PT와 동일 |
| 중 (Meets) | +1 상향 | PT와 동일 |
| 하 1회 | **이동 없음(유지)** | PT는 즉시 −1. AT는 일시적 컨디션 변수로 처리 |
| 하 연속 2회 | −1 하향 | 연속 2회만 실제 하락으로 처리. **직전 진단 레벨 이하로는 하향 불가** |

> **하한 보호 규칙**: AT 최종 레벨은 직전 진단(PT 또는 직전 AT) 레벨보다 낮아질 수 없다. 하한 도달 시 리포트에 "일부 KPI 축 재점검 권장" 메시지를 함께 표시(학습 후 점수 하락의 구조적 방지 — 성장 리포트 신뢰 보호).

### 4.3 AT 결과 표현 가이드라인 (직전 진단 대비)

| 결과 | 리포트 헤더 표현 | 강조 |
|---|---|---|
| 이번 AT > 직전 | L{N} 달성 — {기간} 학습 후 **+{X} 레벨 성장** | 성장 수치 + (공인시험 예상 구간 향상 시 병기) |
| 이번 AT = 직전 | L{N} 유지 — {강점 KPI 축} 향상 확인 | 레벨 유지 + 상승 KPI 축 전면 표시 |
| 이번 AT < 직전 (하한 보호) | L{N} 현재 수준 — {강점 KPI 축} 성장 확인 | **"하락" 표현 금지.** 성장 KPI 강조 + 추가 학습 권장 |

- **R3(독해 유창성) 게이트 유지**: P0-1과 동일하게 이해도 ≥70% 통과 시에만 WPM을 레벨에 반영(속도-이해 트레이드오프). AT에서도 이해 없는 속도 상승은 성장으로 집계하지 않는다.
- **KPI 축별 성장 표기**: 총 레벨뿐 아니라 Reading 3축(R1·R2·R3)·Writing 5축(W1~W5) 각각의 변화(+/−)와 **정체 축 경고**를 함께 제공(P-ALT AT 리포트 §11-2 준용).

## 5. 기능 요구사항 (FR)

- **FR-1** 평가 트리거: 과정 완료/구간 종료/원장 수동 실행 시 AT 시작(§15.3). `previousSessionId` = 직전 DiagnosticResult(PT 또는 직전 AT) 자동 참조.
- **FR-2** 평가 구성: P0-1 엔진 공유, `testType=AT`. **직전 진단 레벨 ±4 범위·시작점 고정**(§4.1). P2 Reading은 학습 이력 기반 지문 우선.
- **FR-3** AT CAT 분기: §4.2 판정 규칙(하 1회 유지·연속 2회 −1) + **하한 보호** 적용.
- **FR-4** 성장 델타: 직전 진단·PT 기준점 대비 **레벨 + KPI 축별 변화량** 산출, 정체 축 플래그.
- **FR-5** 리포트 공급: 성장 델타·성취 스코어·결과 표현(§4.3)을 P0-2 리포트로 전달.
- **FR-6** 시퀀싱 반영: 결과를 §10 다음 수업 사전 미션 레벨·약점 가중치에 반영(피드백 루프).
- **FR-7** 체인 이력: 평가 회차 이력 보존, PT→AT→AT 추이 그래프 제공. 각 AT가 다음 AT의 baseline이 됨.

## 6. 화면·플로우

```
구간 종료/원장 실행 → [성취도 평가 시작] (testType=AT, previousSessionId 자동)
   → 직전 진단 레벨 ±4 문항 세트 (P0-1 CAT 엔진 공유, 시작점 고정)
   → AT CAT 판정(§4.2) + 하한 보호
   → 성취 스코어 + 성장 델타(직전 진단 대비, KPI 축별)
        ├─ 리포트(P0-2): growthDelta + 결과표현 가이드라인(§4.3)
        └─ 시퀀싱(§10): 다음 회차 레벨·약점 반영
   → 체인 이력·추이 (PT ─ AT ─ AT …)
```

## 7. 데이터 모델 / 입출력

**입력**: 학습 범위·레벨, 직전 `DiagnosticResult`(PT 또는 직전 AT — `previousSessionId`로 참조).

**엔티티** — **P0-1 `DiagnosticResult`를 재사용**(`testType=AT`)하고 성장 파생 필드를 얹는다(별도 엔진 아님).

| 엔티티 | 필드 |
|---|---|
| `DiagnosticResult`(testType=AT) | P0-1과 동일 스키마: track=readingWriting, previousSessionId(필수), vocab/reading/writingLevel, readingKPI, writingKPI, examEstimate, itemLog … |
| `AchievementResult`(성장 뷰) | id, studentId, **round**, scopeRef, diagnosticResultId(위 세션 참조), **deltaFromPrevious**{ level:{vocab,reading,writing}, kpi:{R1,R2,R3,W1…W5} }, **deltaFromBaseline**(PT 누적), **achievementRate**(목표 대비), **stalledAxes[]**(정체 축), createdAt |
| 연동 | → GrowthReport.growthDelta, → §10 next-lesson level/weakness |

**출력**: 성취 스코어 + 성장 델타(레벨·KPI 축별) + 결과표현 메시지(§4.3).

## 8. 기존 자산 연계 (재사용/확장)

- **재사용**: **P0-1 진단 엔진 전체**(CAT·난이도 8지표·KPI 축·`DiagnosticResult` 스키마), §15.3 Achievement Test 기획, §10 피드백 루프(문서화됨), KPI 체계(§14.6), 성과카드(§11.5), P-ALT 스피킹 트랙의 PT/AT 체인 설계 원칙.
- **신규(경량)**: AT 운영 규칙(±4 범위·하향 강화·하한 보호), 성장 델타 산출, 결과 표현 가이드라인, 체인 관리(previousSessionId).

## 9. 예외·엣지 케이스

- **기준점 부재**(진단 미실시): 첫 AT를 임시 baseline(PT 대용)으로 저장, 델타는 다음 회차부터. (P-ALT 체인의 재-앵커 처리 준용.)
- **범위 불일치**(학습 범위 변경): 평가 범위 명시, 비교 가능 구간만 델타 산출.
- **성취 하락**: 하한 보호로 레벨은 유지, "하락" 표현 금지·약점 재학습 유도 톤(§4.3).
- **R3 이해도 <70%**: WPM 성장 미집계, "속도 판정 보류(이해 우선)" 표기(P0-1과 동일).
- **평가 회피/미완료**: 리포트 성장 델타 생성 보류.

## 10. 완료 정의(DoD) · QA

- 구간 종료 시 AT 실행(testType=AT) → 성취 스코어·성장 델타 산출 → 리포트 반영 E2E.
- 직전 진단 대비 델타가 정확히 계산되고, **하한 보호가 실제로 하락을 막음**(QA 시나리오: 성장/유지/하락 3종).
- AT가 P0-1과 동일 KPI 축(Reading 3·Writing 5)으로 산출되고, 축별 변화·정체 경고가 표시됨.
- 평가 결과가 §10 다음 수업 레벨/약점 가중치에 반영됨. 각 AT가 다음 AT의 baseline으로 참조됨.

- **오픈 이슈(개발팀 확인)**: ~~①Achievement 문항 구성이 P0-1과 얼마나 로직을 공유하는지~~ **→ P-ALT 체인 채택으로 확정: 동일 엔진의 AT 모드(공유율 100%, 차이는 §4 운영 규칙뿐).** ②정기 실행 트리거 정책(구간 정의) ③§10 피드백 루프 반영 시점·강도 ④AT CAT 하향 강화·하한 보호 파라미터 최종값(±4 폭, 연속 하 판정 임계) ⑤PPD(§15.4) 정밀 진단과의 단계 분담.
- **하류**: P0-2 리포트(AT 성장 델타·결과표현), §10 시퀀싱.
