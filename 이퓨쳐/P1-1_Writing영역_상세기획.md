## 1. 목적·배경

Writing/서술형을 **부가기능이 아니라 코어 영역**으로 완성한다. 문항 학습 + 첨삭(교정) + 진단 신호의 3중 역할.

- 시장 근거: AI 작문·에세이 첨삭 35%, **어학원 세그먼트 1순위 = AI 작문·첨삭 50%**. 중등 서술형(수행평가) 급증. 일부 학원엔 서술형이 학원 정체성("단어랑 서술형 위주로 들어가는 학원", 디에이블).
- **진단 도구 겸용**: "이상하게 쓰는 애 = 가짜로 이해한 애"(디에이블) → 서술형이 이해도 진단 신호.
- 톤 원칙: "AI 티" 없이(전소영) — 첨삭은 교정 위주, 완벽한 재작성 강요 금지.

## 2. 사용자 스토리

- (원장) 아이가 쓴 영작을 AI가 1차 첨삭해주고, 나는 확인만 하고 싶다.
- (원장) 서론-본론-결론 프레임 훈련(더그로우)처럼 단계적 쓰기를 시키고 싶다.
- (학생) 내 문장이 왜 틀렸고 어떻게 고치면 되는지 바로 알고 싶다.

## 3. 범위 (In/Out)

**In (P1)**
- Writing 모듈 완성: 미작성 **CPW(Copy Writing)·SCP(Sentence Completion)·PWR(Process Writing)·SMW(Summary Writing, 신규)** 등록, 추가 **UNS(Unscramble)·PPR(Paraphrasing)** 합류, **SWR(✅)** 재사용 (§11 매핑 참조)
- **첨삭 엔진**: essay 홀리스틱 피드백(§12.4 재사용) + 문장 단위 교정(오류 지적·수정 제안·근거)
- 서술형 결과를 **진단 신호**로 P0-2 리포트에 연결
- 첨삭 결과 P0-4 검수(원장 최종 확인)

**Out (후속)**
- 학교별 서술형 유형 파인튜닝(P2), 자동 등급/루브릭 커스터마이징 고급(P2), Writing 쌍둥이 대량생성은 P0-5(내신 출제)와 경계 조율

## 4. 기능 요구사항 (FR)

- **FR-1** 모듈 등록: Module List v1.0 기준 Writing 6~7개(UNS·CPW·SCP·SWR·PPR·PWR·SMW) 등록·시퀀싱 편입(§13, `AiModule` 필드 세팅).
- **FR-2** 쓰기 실행: 학생이 문장/문단/에세이 작성(answerType = sentence-write / essay).
- **FR-3** 첨삭 생성: 제출 답안 → 홀리스틱 피드백(강점/개선, §12.4 ✅) + 문장 단위 오류 교정(문법·어휘·구조).
- **FR-4** 단계적 쓰기: Process Writing(PWR) — 개요→초안→수정 단계 지원(프레임워크 훈련).
- **FR-5** 진단 신호화: 서술형 수행 지표(정확성·완성도·이해 반영도)를 학생 프로필·리포트로 전달.
- **FR-6** 검수·톤: 첨삭 결과를 P0-4 검수 큐로, 톤 프리셋(교정 위주/격려형) 적용.
- **FR-7** 채점 루브릭: 레벨별 루브릭으로 정량 스코어 산출(리포트·Achievement Test 입력). 루브릭 차원은 현장 실사용 프레임인 **6항목(내용·구조·담화·문법·어휘·맞춤법)** 기준(전소영 인터뷰) — 경쟁사 Engram 5축과 비교해 **담화·맞춤법을 분리**한 형태. 상세: [서술형 시장조사](10_시장조사_서술형_v1.0.md) §3, §11 매핑.

## 5. 화면·플로우

```
[Tutoring] Writing 모듈 진입
   → 문항 제시(레벨별) → 학생 작성(sentence-write / essay)
   → [제출] → 첨삭 생성 (홀리스틱 + 문장 교정, SSE 스트리밍)
   → 학생: 교정 확인 → (PWR) 재작성
   → 강사: 검수 큐(P0-4) → 승인
   → 서술형 지표 → 리포트(P0-2) / Achievement(P1-3)
```

## 6. 데이터 모델 / 입출력

**입력**: 학생 작성 텍스트, 모듈 코드, 레벨, 루브릭.

**신규/확장(요약)**

| 엔티티 | 필드 |
|---|---|
| `WritingSubmission` | id, studentId, moduleCode, text, level, rubricScore, createdAt |
| `WritingFeedback` | submissionId, holistic{strengths,improvements}, corrections[{span, issueType, suggestion, rationale}], reviewStatus |
| 지표 | comprehensionSignal(이해 반영도), completeness, accuracy → 리포트/진단 |

## 7. 기존 자산 연계 (재사용/확장)

- **재사용**: SWR 모듈(✅), FeedbackGenerationAgent essay 홀리스틱·SSE(§12.4 ✅), Claude AI 홀리스틱 평가(§11.4), `AiModule` 시퀀싱 필드, P0-4 검수, Seed/LLM 전략.
- **확장**: 미작성 Writing 모듈 등록(CPW·PWR 등), 문장 단위 교정 피드백, 서술형 진단 신호화.

## 8. 예외·엣지 케이스

- 저품질/무의미 답안: 최소 길이·언어 감지, 재작성 유도.
- 과교정(원문 훼손): 교정은 제안 형태, 원문 보존.
- 첨삭 신뢰도: P0-4 검수 필수, 수치 인용은 루브릭 값 고정.
- essay 길이 초과(2,000자 제한, §12.8): 분할·경고.

## 9. 완료 정의(DoD) · QA

- 학생 서술형 제출 → 홀리스틱+문장 교정 첨삭 → 검수·승인 → 리포트 지표 반영 E2E.
- Writing 모듈이 LessonPlan 시퀀싱에 정상 편입.
- 서술형 수행이 이해도 진단 신호로 리포트에 표시.

## 10. 의존성 · 오픈 이슈

- **선행**: P0-4 검수. **연동**: P0-2 리포트(진단 신호), P0-5(서술형 쌍둥이와 채점 루브릭 공유 — **경계 정의: P0-5 = 출제 + 범위 종속 채점, P1-1 = 학습·첨삭·진단 신호. 루브릭은 공유하되 채점 목적 분리**), P1-3 Achievement.
- **오픈 이슈(개발팀 확인)**: ①미작성 Writing 모듈 등록 우선순위·일정 ②문장 단위 교정을 홀리스틱과 별도 파이프라인으로 둘지 ③레벨별 루브릭 정의 주체(연구팀) ④P0-5와 서술형 생성/채점 기능 중복 정리(→ §10 경계 정의로 1차 해소: 출제=P0-5 / 학습·첨삭=P1-1, 루브릭만 공유. 구현 레벨 분담은 개발팀 확인) ⑤**손글씨(OCR) 입력 지원 여부**(§11.C 공백) ⑥**루브릭 6항목 vs 5축 확정**(FR-7) ⑦**SMW(작문적 요약) 신규 모듈 스코핑** — v0.20에서 Reading SUM에 통합됐던 작문 요약(구 PWT)을 Writing 모듈로 분리, essay/holistic 루브릭 재사용 범위·개발 일정 확인.

## 11. 부록 — 시장 요구 Writing 시험형식 · 모듈 상태 매핑

> 자사 정성조사(12인 인터뷰)·[서술형 시장조사](10_시장조사_서술형_v1.0.md)에서 확인된 **현장 요구 시험형식**과 v0.20 §13 모듈 레지스트리를 대조. FR-1(모듈 등록)·FR-7(루브릭)의 근거.

### 11.A 시장 요구 형식 → 모듈 매핑

| 시장 요구 형식 | 근거(현장 발화/정책) | 대응 모듈 | 상태 |
|---|---|---|---|
| 서술형 쌍둥이(반복·변형) | "같은 유형 반복·변형 쌍둥이"(디에이블) | SWR·PPR + P0-5 FR-4 | SWR ✅ / PPR 추가 |
| 조건 영작(한 문장) | 내신 대표 서술형(시장조사 §1-3) | **SWR** | ✅ 완료 |
| 문장 완성·배열 | 내신 배열·완성형 | **UNS**(배열)·**SCP**(완성) | UNS 추가 / SCP 미작성 |
| 요약·바꿔쓰기 | "독해·요약 용도"(뛰는수학) | **SMW**·**PPR** | SMW 신규 / PPR 추가 |
| 단계적 쓰기(서론-본론-결론) | "프레임 훈련"(더그로우) | **PWR** | 미작성 |
| 100% 서술형 월말평가 | "100% 서술형 월말평가"(JK) | 세트화 = P0-5 FR-6 | — |
| 받아쓰기+파생어+문장 단어시험 | "발음 듣고 쓰는 단어시험, 파생어·문장까지"(디에이블) | **CPW**(DIC 흡수)·WFT(어휘) | 미작성 |
| 라이팅 첨삭 6항목 프레임 | "내용·구조·담화·문법·어휘·맞춤법"(전소영) | FR-3 첨삭 엔진 | 부분 구축 |

→ 시장 요구 형식은 **모듈 설계엔 반영돼 있으나, 핵심 4종(CPW·SCP·PWR·PPR)이 미작성/추가** — FR-1 7종 중 **실제 완료는 SWR 1종뿐**(SMW는 Reading SUM에서 분리한 신규).

### 11.B Writing 모듈 7종 상태 · 미기획 모듈 설명 (§13.1 기준)

| 모듈 | 이름 | answerType/채점 | 상태 | 설명 |
|---|---|---|---|---|
| **SWR** | Sentence Writing | sentence-write / holistic | ✅ 완료 | 한 문장 영작 — 조건 영작 기반 |
| **SMW** | Summary Writing | essay / holistic | **신규(미작성)** | 작문적 요약 — 읽은 내용을 자기 문장으로 압축·재구성해 써내는 생산 과제. Reading `SUM`(이해 측정용 요약, 빈칸·핵심어)과 구별. v0.20에서 SUM에 통합됐던 작문 요약(구 PWT)을 분리 |
| **CPW** | Copy Writing | short-text / exact | **미작성** | 베껴쓰기·받아쓰기(폐기 DIC 흡수) — 단어시험/받아쓰기 |
| **SCP** | Sentence Completion | mixed / exact | **미작성** | 문장 완성 — 빈칸·완성형 서술형 |
| **PWR** | Process Writing | essay / holistic | **미작성** | 개요→초안→수정 — 프레임 훈련(SWR 선행 필요) |
| **UNS** | Unscramble | drag-drop / exact | **추가** | 단어 배열 — 배열형(규칙 채점, 자동채점 신뢰 높음) |
| **PPR** | Paraphrasing | essay / holistic | **추가** | 바꿔쓰기 — 쌍둥이 변형·요약 보조 |

**미기획(상세 미정) / 어휘 계열 참고**
- **WDN**(Word DNA): §13.1 "추가 *(상세 미정)*" — **사양 미확정** 유일 모듈. 어휘 계열.
- **WFT**(Word Family Tree): 어휘 계열 추가 모듈(파생어). 디에이블 "파생어까지" 단어시험 요구와 직결 — Writing CPW와 연계 가능. **(P1-1 초안이 WFT·WDN을 Writing으로 오기 → 정정)**

### 11.C ⚠️ 시장 요구 대비 공백

1. **손글씨(OCR) 입력 부재**: 내신 정기고사 서술형은 손글씨 답안이고, 경쟁사(CLIPO·Engram) 킬러 기능이 손글씨 인식 채점(시장조사 §3). Writing KPI에 `HANDWRITING_MATCH`는 있으나 **현 Writing 모듈은 전부 타이핑 전제** → intake 모듈/기능 신설 검토 필요(오픈이슈 ⑤). **→ 해결 방향: [N3 종이–디지털 브리지(QR·OCR)](40_N3_종이디지털브리지_QR_OCR_전략노트.md)** — 출력 종이에 QR 결속 + 학생 주도 캡처·OCR 보정 채점(P1).
2. **루브릭 6 vs 5 확정**: 현장(전소영)은 6항목(내용·구조·담화·문법·어휘·맞춤법), Engram은 5축. FR-7은 **6항목으로 정합** — 담화·맞춤법 분리 유지(오픈이슈 ⑥).
