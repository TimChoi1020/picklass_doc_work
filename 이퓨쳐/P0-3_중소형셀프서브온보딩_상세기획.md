# P0-3. 중소형 셀프서브 온보딩 (SMB Self-Serve Onboarding) 상세 기획

| 항목 | 내용 |
|---|---|
| 코드 | P0-3 (Gap G5) |
| 우선순위 | P0 (12월 파일럿 필수) |
| 연계 | v0.20 §5.4 무료체험(Studio 자가가입 7일 ✅), §4 Actor·Membership(✅), §7.5 액세스코드(✅), §6.C studio/app 진입, 학원 범위 등록(G6) |
| 상태 | 재정렬(비개발 다수) + 확장 — 대형 파고다 트랙과 **병행되는 중소형 트랙** |

---

## 1. 목적·배경

개발이 파고다(대형 B2B) 중심으로 설계돼 있으나, 시장의 진짜 수요층은 **중소형 보습학원(설계형 원장)**이다. 대형 계약 트랙은 유지하되, **원장이 스스로 가입→학원 세팅→학생 배포까지 며칠 안에 끝내는 셀프서브 경로**를 병행 제공한다.

- 시장 근거: 지불의향 **보습 86%(1위)**, 대형 어학원은 자체 시스템 보유로 니즈 낮음. 첫 타깃 = 설계형 원장.
- 커스터마이징(우리 학원 범위 종속)이 도입 사활(G6). "우리 학원 범위로 안 좁혀지면 버려진다."

## 2. 사용자 스토리

- (원장) 영업 미팅 없이 직접 가입해서 7일 체험으로 우리 학원에 맞는지 확인하고 싶다.
- (원장) 우리 학원 교과서·진도 범위를 등록해서, 생성되는 문제가 우리 시험범위 안에서 나오게 하고 싶다.
- (원장) 학생들에게 액세스코드만 나눠주고 바로 시작하고 싶다.

## 3. 범위 (In/Out)

**In (MVP)**
- Studio 자가가입 7일 체험(✅ 존재) 위에 **중소형 원장용 간편 온보딩 위저드**
- **학원 범위(교과서·진도·학년) 등록 UI** — 이후 진단·출제·리포트의 스코프로 사용
- 학생 초대/액세스코드 일괄 배포(✅ 재사용)
- 최소 브랜딩(로고·이름) 설정(§7.10 ✅)

**Out (후속)**
- 결제·구독 전환 자동화 상세(P1), 그룹/본부 계층(대형 트랙), 도메인 별칭 등 고급 브랜딩(P2)

## 4. 기능 요구사항 (FR)

- **FR-1** 자가가입: studio.picklass.com/app에서 원장 가입 → 7일 체험 자동 활성(§5.4 ✅).
- **FR-2** 온보딩 위저드(4스텝): ①기관 정보·로고 ②학원 범위 등록 ③학생 초대/코드 발급 ④첫 진단·수업 안내. 진행률 표시, 이탈 후 이어하기.
- **FR-3** 학원 범위 등록: 학년·교과서(출판사)·진도 단원·내신 시험범위 텍스트 입력/업로드. 이 값이 P0-1(진단 레벨)·P0-5(내신 출제)·P0-2(리포트) 스코프로 전파.
- **FR-4** 학생 관리·배포: 학생 일괄 등록(✅) + 액세스코드 발급/만료(✅). 초대 링크/코드 안내.
- **FR-5** 체험 상태 표시: 잔여 체험일, 전환 안내(결제는 P1이나 진입점 노출).
- **FR-6** 빈 상태 가이드: 각 화면에 "다음 할 일" 유도(첫 진단 → 첫 수업 → 첫 리포트).

## 5. 화면·플로우

```
studio.picklass.com/app → [원장 가입] → 7일 체험 활성
   → 온보딩 위저드
       1) 기관 정보·로고
       2) 학원 범위 등록(학년·교과서·진도·내신범위)   ← G6 핵심
       3) 학생 초대 / 액세스코드 일괄 발급
       4) 첫 진단·수업 안내
   → Studio 대시보드 (빈 상태 가이드: 진단→수업→리포트)
```

## 6. 데이터 모델 / 입출력

**신규/확장 엔티티**

| 엔티티 | 필드(요약) |
|---|---|
| `AcademyScope` (신규) | institutionId, grade[], publisher, textbook, progressUnit, examScopeText, updatedAt |
| Membership (재사용) | 원장/학생 role, 상태, 액세스코드 연결 |
| InstitutionBranding (재사용, §7.10) | logo, name, themeColor |

`AcademyScope`는 P0-1/P0-2/P0-5가 참조하는 **학원 스코프의 단일 소스**.

## 7. 기존 자산 연계 (재사용/확장)

- **재사용(비개발)**: Studio 자가가입 7일 체험(§5.4 ✅), 단일 User+복수 Membership(✅), 사용자 일괄 생성·액세스코드(✅), 기관 브랜딩(§7.10 ✅), studio/app 진입(§6.C).
- **확장(신규)**: 온보딩 위저드 UI, `AcademyScope` 등록 및 하류 전파.

## 8. 예외·엣지 케이스

- 위저드 중도 이탈: 저장 후 이어하기, 미완료 스텝 배지.
- 학원 범위 미등록 상태로 진단/출제 시도: 기본 범위 폴백 + 등록 유도 배너.
- 체험 만료: 읽기전용 전환, 데이터 보존, 결제 유도(P1).
- 코드 중복/만료: 재발급 플로우(§17.1 규칙 준용).

## 9. 완료 정의(DoD) · QA

- 신규 원장이 가입→위저드 4스텝→학생 배포까지 30분 내 완료(무영업).
- 등록한 학원 범위가 진단·리포트에 실제로 반영됨(스코프 전파 확인).
- 체험 활성/만료 상태 전환 정상.

## 10. 의존성 · 오픈 이슈

- **재사용 다수**로 신규 개발은 위저드 UI + `AcademyScope`에 집중.
- **오픈 이슈(개발팀 확인)**: ①파고다 트랙과 중소형 셀프서브 병행 시 계정·권한 충돌(§5 G5) ②학원 범위 입력 형식(자유 텍스트 vs 구조화) — P0-5 출제 정확도에 직결 ③체험→유료 전환 결제 범위(P1 경계).
- **하류**: P0-1·P0-2·P0-5가 `AcademyScope` 참조.
