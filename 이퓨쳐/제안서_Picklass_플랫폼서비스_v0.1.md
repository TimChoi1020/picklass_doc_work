# Part I. 개요

## 1. Executive Summary

시장이 돈을 내는 지점은 "AI가 우리 애를 가르쳐줘"가 아니라 **"내 노동을 대신 없애주고, 성장을 학부모에게 증명해줘"** 입니다.

Picklass는 원장의 **자료제작·출제·채점 노동을 자동화**하고, 그 과정에 쌓인 데이터로 **학부모에게 성장을 정확히 증명**하는 플랫폼입니다. 제품의 주인공은 "AI 튜터의 수업"이 아니라 **진단 → 처방 → 실행 → 증명의 폐쇄 루프**이며, 이 플랫폼의 지불 스위치는 단 하나입니다.

> **"성취도가 정확하게 보이는가."**
> *"정확하게 피드백을 보내 준다면 가격이 중요하겠습니까?" — 현장 원장 인터뷰*

**세 가지 차별점**으로 이 루프를 경쟁 도구와 구분합니다.

1. **우리 학원 범위 종속** — 표준 문제은행이 아니라, 그 학원이 실제 가르친 진도·교과서·시험범위 안에서만 작동
2. **진단→증명 폐쇄 루프** — 출제로 끝나지 않고 학부모 리포트까지 하나로 연결
3. **원장이 통제하는 AI** — 완제품 강요가 아니라 검수·수정·개입강도 조절

이 루프는 학원의 실제 운영 리듬 — **정규수업기간(자기 교재 + 온라인 학습)과 시험기간(내신 대비 자료)** — 그대로 구성됩니다(§3-1).

---

## 2. 왜 이 플랫폼인가 — 시장 문제

잘되는 학원의 두 축은 **개별 관리**와 **학부모 소통**입니다. 그런데 이 둘이 전부 **'원장 한 사람의 시간'** 에 묶여 있습니다.

**① 원장의 시간이 병목입니다.**
현장 조사에서 최대 병목은 수업 자료·교재 준비 **52%**, 학생 평가·시험 관리 **39%**, 채점·피드백 **38%** 로 나타났습니다. 새 시도를 못 하는 이유 1위도 "시간 부족"(비용 부담의 2.5배)이었습니다.

**② 학습 성장이 '안 보입니다'.**
학부모 클레임 1위는 **"학습 상황을 잘 모르겠다" 21%**. 성장을 눈에 보이게 만드는 것 자체가 곧 상품 가치입니다.

**③ 기존 도구는 '우리 학원에 안 맞아서' 버려집니다.**
표준화된 문제은행·온라인 도구는 "우리 진도와 안 맞음", "결국 우리 데이터 직접 입력", "폼이 안 맞아 엑셀로 회귀"라는 이유로 버려졌습니다. 앱마다 따로 로그인하는 파편화도 문제입니다 — "한 화면에서 다 끝나야 한다".

> Picklass는 이 세 문제를 **정면으로** 겨냥합니다: 노동을 자동화하고, 성장을 증명하며, 우리 학원 범위에 종속시킵니다.

## 3. 솔루션 개요 — 진단 → 처방 → 실행 → 증명

Picklass는 두 개의 축으로 구성됩니다.

- **Picklass Studio (웹)** — 원장·강사용 수업 자동화 엔진. 학원 범위 등록·진단·자동출제·교재 저작·리포트·검수·출력.
- **Picklass Tutoring (앱)** — 학생용 수업 실행 환경. Reading·Writing·Speaking·Vocabulary 4영역을 한 화면에서.

이 둘이 하나의 **끊기지 않는 루프**로 돌아갑니다.

```text
 👨‍🏫 원장·강사
   │  ① 우리 학원 범위 등록 (교과서·진도·시험범위)  →  진단·출제·리포트 공통 기준
   ▼
 ━━━━━━  🔄 진단 → 처방 → 실행 → 증명 · 끊기지 않는 학습 루프  ━━━━━━
   │
 ① 진단           적응형 레벨·약점 진단  →  정기 성취도 재측정
   ▼
 ② 처방·출제       우리 학원 범위 문항 · 서술형 쌍둥이 자동 생성
   │               ├ AI 생성물 → 원장 검수(승인 게이트) → 출력(PDF·POD·QR)
   │               └ 승인 콘텐츠 축적 → 교재 스튜디오 → 학원 자기 교재(POD·eBook)
   ▼
 ③ 실행           학생 앱 4영역 수업 (Reading · Writing · Speaking · Vocabulary)
   │               └ 과정 데이터(시도·시간·오답) 수집
   ▼
 ④ 증명  ★        학부모 성장 리포트  =  지불 스위치
   ▼
 👪 학부모   →   성장 확인 · 재원   →   👨‍🏫 원장      ↺ 다음 주기 재진단으로 순환

 ─ 전달 ─  온라인 실행(과정 데이터 ✓) │ 종이·POD 출력(문제세트·학원 자기 교재) │ QR·OCR : 종이 손글씨 답안도 자동 채점
```

> **이 한 장이 전체 모습입니다.** 진단이 리포트의 입력이 되고, 실행에서 쌓인 과정 데이터가 리포트의 신뢰를 만들며, 증명이 다시 다음 진단으로 순환합니다. 원장의 손이 거의 닿지 않고 돌아가는 것이 이 플랫폼의 성패입니다.

### 3-1. 학원의 두 계절에 맞춘 구성 — 정규수업기간과 시험기간

학원의 한 해는 **정규수업기간**과 **내신 시험기간**이 반복됩니다. Picklass는 별도의 사용법을 배우게 하지 않고, **이 리듬 그대로** 구성됩니다.

| 구분 | 📖 정규수업기간 | 📝 시험기간 (내신 대비) |
|---|---|---|
| 중심 자료 | **학원 자기 교재** — 교재 스튜디오로 저작한 POD 교재(§9) | **원장·강사가 만든 내신준비 자료** — 우리 학교 시험범위 자동출제(§8) + 원장 자체 자료 |
| 학습 방식 | 교재 수업 + **교재 연동 온라인 학습**(§10) — 같은 콘텐츠가 실물 교재와 앱 양쪽으로 | 문제세트·시험지·오답노트 인쇄, **서술형 쌍둥이로 반복 훈련** |
| 종이 / 온라인 | POD 교재 + 앱 eBook·온라인 학습 병행 | 종이 인쇄물 중심 + **QR·OCR로 손글씨 답안까지 채점**(§14) |
| 쌓이는 데이터 | 과정 데이터 — 시도·시간·오답(§12) | 시험대비 수행·서술형 채점 결과 |
| 학부모에게 | 월간 성장 리포트(§11) | 시험 후 성적·성장 리포트 |

> 두 계절 모두 **같은 루프(진단→처방→실행→증명)** 위에서 돌고, 양쪽의 데이터가 **하나의 성장 리포트**로 모입니다. 정규수업 때 쌓인 과정 데이터가 시험기간의 약점 보강을 정밀하게 만들고, 시험 결과가 다시 다음 정규수업의 수준 설계로 이어집니다.

# Part II. 차별점

## 4. 차별점 ① 학원 맞춤 — "우리 학원 범위 종속"

**한 줄 가치**: 표준 문제은행이 아니라, **그 학원이 실제 가르친 범위 안에서만** 작동합니다.

원장이 학년·출판사·교과서·진도 단원·내신 시험범위를 한 번 등록하면, 이 **'학원 범위'가 진단·출제·리포트가 공유하는 단일 기준**이 됩니다. 생성되는 모든 문제는 우리 시험범위 안에서 나오고, 리포트도 그 범위 기준으로 성장을 말합니다.

이것이 경쟁 도구가 버려진 지점의 **정반대**입니다. 표준화 시험이나 범용 문제은행은 "우리 진도와 안 맞아서" 결국 버려졌습니다. Picklass는 커스터마이징을 부가 옵션이 아니라 **작동의 전제**로 둡니다.

> *"우리 학원 범위로 안 좁혀지면 버려진다." — 현장 인터뷰*

---

## 5. 차별점 ② 진단→증명 폐쇄 루프 — "데이터가 도는 구조"

**한 줄 가치**: 출제로 끝나지 않고, **학부모 리포트까지 하나로 연결**됩니다.

시장의 도구들은 대개 **조각**입니다. 출제 도구 따로, 채점 도구 따로, 리포트는 손으로. Picklass의 차별점은 이 조각들을 **하나의 데이터 흐름**으로 잇는다는 것입니다.

| 단계 | 만들어지는 데이터 | 다음 단계로 |
|---|---|---|
| 진단 | 레벨·강약점 | → 리포트 초기값 · 수업 난이도 |
| 처방 | 우리 범위 문항·서술형 쌍둥이 | → 학생 수업·시험 |
| 실행 | 과정 데이터(시도·시간·오답) | → 리포트 신뢰 · 진단 정밀화 |
| 증명 | 성장 리포트 | → 학부모 재원 · 다음 주기 재진단 |

진단이 리포트의 입력이 되고, 실행 데이터가 리포트의 근거가 되며, 정기 성취도가 성장의 전후 비교를 만듭니다. **성취도가 정확히 보이는가** — 이 폐쇄 루프가 바로 그 답입니다.

---

## 6. 차별점 ③ 원장이 통제하는 AI — "완제품 강요 아님"

**한 줄 가치**: AI가 초안을 만들되, **최종 결정은 언제나 사람**이 합니다.

AI 완제품에 대한 현장의 불신은 뚜렷합니다("70%만 만족", "AI 티 나서 다시 허접하게"). 자기 학원 색깔을 잃는다는 우려도 큽니다. Picklass는 이를 **신뢰 장치**로 정면 대응합니다 — 모든 생성물은 원장 검수를 거쳐야 배포·발행되고(검수 없는 자동 발행 없음), **AI 개입강도(최소/보통/최대)** 와 리포트의 "우리 학원 톤"까지 원장이 정합니다. 구체 워크플로우는 §13.

> 설계형 원장은 이미 AI를 직접 써보고 있습니다. Picklass는 그들에게서 통제권을 뺏지 않고 **되돌려줍니다.**

# Part III. 핵심 기능

> 루프 순서(진단→출제→실행→리포트)를 따라 소개하고, 그 사이에 콘텐츠 축(교재 스튜디오)과 이를 받치는 공통 장치(과정 데이터·검수·종이 브리지)를 배치합니다. 각 기능은 *가치 → 흐름 → 산출 → 현장 근거* 로 소개합니다.

## 7. 진단 — 적응형 레벨·약점 + 정기 성취도

**가치**: 신규생이 등록하는 순간, 종이 레벨테스트 대신 태블릿으로 **15분 진단**을 돌리고 바로 약점 리포트를 받습니다.

- **적응형 출제** — 정답이면 난이도가 오르고 오답이면 내려가는 능동형. 우리 학원 진단용.
- **산출** — 최종 레벨(강약점 스코어 포함), 이 결과가 곧 수업 난이도의 초기값이자 리포트의 출발점.
- **정기 성취도 재측정** — 학습 구간이 끝나면 다시 측정해, 입학 시점 대비 **성장 델타**를 리포트에 축적합니다.

> *"입학 테스트를 봐도 리포트 카드가 안 나온다." — 현장 인터뷰.* 표준화 시험은 거부되지만 '우리 학원 진단'은 강하게 요구됩니다.

## 8. 자동출제 — 우리 학원 범위 문항 · 서술형 쌍둥이

**가치**: 우리 학교 시험범위 지문을 넣으면, **그 범위 안에서** 문법·독해·서술형 문제가 자동으로 나옵니다.

- **출제 유형** — 어휘·문법·독해 객관식 + **서술형 4유형**: 조건 영작 / 문장 완성·배열 / 빈칸 서술 / 요약.
- **서술형 쌍둥이** — 기준 문항에서 유형은 유지하고 소재만 바꾼 변형 N개를 뽑아 반복 훈련.
- **흐름** — 범위 입력 → 자동 생성 → 원장 검수 → 문제세트 저장 → 앱 배포 또는 인쇄 출력.

자동출제는 현장이 AI에 기대하는 영역 **1위(51%)**이며, 동시에 국내 시장의 **공백**입니다. 국내 도구는 '변형문제 출제'와 '서술형 채점'이 서로 다른 사업자로 **분리**돼 있고, 해외 자동채점 엔진은 "문항에 내용상 맞게 답했는가"를 채점하지 못합니다. **"우리 학원 범위에 종속된 내용 채점"** 이 Picklass의 자리입니다.

> *"같은 유형을 조금씩 바꾼 쌍둥이 문제로 반복시키고 싶다." · "시험범위와 모르는 부분을 접목한 맞춤 문제." — 현장 인터뷰*

## 9. 학원 자기 교재 출판 — 교재 스튜디오

**가치**: 우리 학원이 만든 콘텐츠가 흩어지지 않고 **누적되어, 학원 이름을 단 자기 교재**가 됩니다.

교재의 소재는 세 갈래로 들어옵니다.

1. **원장 자료 그대로** — 직접 만들어 쓰던 프린트·학습지를 업로드해 그대로 편입
2. **원장 자료의 AI 변형** — 업로드한 자료를 바탕으로 난이도 조정·쌍둥이 문항·지문 재가공
3. **요구사항만 입력** — 주제·레벨·유형·분량을 입력하면 AI가 새로 생성

세 경로 모두 **원장 검수를 거쳐 콘텐츠 라이브러리에 축적**됩니다. 북빌더가 우리 학원 진도를 기준으로 **목차 초안을 자동 구성**하고, 원장은 배치와 수정만 합니다. 완성된 교재는 **앱 eBook과 실물 인쇄(POD)** 두 형태로 나가며, 실물 교재에도 QR이 인쇄되어 손글씨 답안이 채점·리포트로 연결됩니다(§14).

> 교재 준비에 쓰던 시간(현장 병목 1위, 52%)이 **학원의 자산**으로 바뀝니다. 표지에는 우리 학원 이름이 올라갑니다.

## 10. 학습 실행 — 4영역 수업 + Writing 첨삭

**가치**: Reading·Writing·Speaking·Vocabulary를 **한 화면에서** 이어지게 실행합니다. 앱마다 따로 로그인하는 파편화를 없앱니다.

- **교재 연동 학습** — 정규수업기간에는 학원 자기 교재(§9)의 eBook과 연동되어, 교재 진도 그대로 온라인 학습이 이어지고 과정 데이터가 쌓입니다(§3-1).
- **수준별 수업 설계** — 학생 레벨에 맞춰 대화 방식·속도·피드백을 조절.
- **Writing 첨삭** — 학생 영작을 AI가 1차 첨삭(강점·개선 + 문장 단위 오류 교정), 원장은 확인만. 완벽한 재작성을 강요하지 않고 교정 위주로.
- **서술형 = 이해도 신호** — 서술형 수행을 학습 신호로 리포트에 연결합니다.

> *"이상하게 쓰는 애 = 가짜로 이해한 애." — 현장 인터뷰.* 서술형은 곧 이해도 진단입니다.

## 11. 성장 리포트 — 성장·과정 두 축 *(지불 스위치)*

**가치**: 키워드 몇 개만 고르면 아이별 리포트 문장이 자동 완성되어, **매달 전 학생 리포트를 몇 분 안에** 보냅니다.

리포트는 두 축으로 구성됩니다.

- **성장(Growth)** — "얼마나 컸나": 레벨·읽기 속도·정확도의 전후 변화.
- **과정(Process)** — "제대로·꾸준히 했나": 출석·완주·학습량(성실도) + 정확도·이해도.

원칙은 하나, **"화려한 그래프보다 이 아이만의 정확한 데이터"**. 모든 수치는 실제 학습 기록에만 근거하며, 데이터가 부족한 항목은 "축적 중"으로 표기합니다. 부정확한 리포트는 오히려 이탈을 부르기 때문입니다.

> *"정확하게 피드백을 보내 준다면 가격이 중요하겠습니까?" — 현장 인터뷰.* 리포트의 정확성이 곧 재원(매출)과 직결됩니다.

## 12. 과정 데이터 — "완료"가 아니라 "진짜 학습했나"

**가치**: 아이가 이 문제를 **몇 번 만에, 얼마나 걸려** 맞혔는지까지 봅니다.

온라인 도구가 '완료 여부'만 보여주면, 아이들은 뒤로가기·베끼기로 꼼수를 쓰고 강사는 다시 감시자가 됩니다. Picklass는 **시도 횟수·소요 시간·오답 패턴**을 수집해:

- 리포트의 **성실도·이해도**를 실제 과정으로 뒷받침하고,
- '성의 없는 통과'를 자동으로 걸러내며(감시 노동 제거),
- 오답 패턴을 약점 태그로 바꿔 **다음 진단·수업을 정밀화**합니다.

> *"완료 여부만 보이지 몇 번 시도했는지는 안 나온다." · "다운받은 답 베껴온 상황." — 현장 인터뷰*

## 13. 검수·통제 — Human-in-the-loop 워크플로우

**가치**: AI가 만든 것을 **그대로 쓰기 전에** 원장이 훑어보고 고칩니다.

- **검수 큐** — 생성물이 "검수 대기"로 모이고, 원장은 인라인으로 수정 후 승인/반려.
- **승인 게이트** — 미승인 생성물은 학생 배포·학부모 발행이 **차단**됩니다.
- **개입강도 매핑** — 설정한 강도가 실제 생성 자동화 범위에 반영됩니다.
- **이력·감사** — 누가 언제 무엇을 수정·승인했는지 기록.

## 14. 종이–디지털 브리지 — QR 결속 + 손글씨 OCR

**가치**: 종이로 시험을 치르면서도, **온라인의 자동 채점·분석 이점**을 그대로 얹습니다.

내신 서술형은 손글씨 정기고사가 현실입니다. Picklass는 출력물에 **QR을 인쇄해 "이 종이 = 이 학생 × 이 문항"** 을 결속합니다.

- **QR 결속** — 개인화·범위 종속 문항이라 표준 답안키가 없지만, QR이 정확한 채점 기준을 불러옵니다.
- **학생 주도 캡처·보정** — 학생이 직접 촬영하고, OCR이 읽은 텍스트를 스스로 확인·수정해 정확도를 높입니다(원장 부하 없음 + 복습 효과).
- **자동 채점** — 규칙형은 자동, 내용형은 AI 루브릭 + 원장 검수 가중.

또한 **과정 데이터는 온라인의 강점**입니다. 종이로는 시도·시간을 남기지 못하므로, *"종이로도 채점되지만, 온라인으로 풀면 과정까지 분석된다"* 는 자연스러운 온라인 사용 유인이 됩니다.

# Part IV. 신뢰 근거

## 15. 신뢰·검증

Picklass의 방향은 **시장 데이터와 정책 흐름** 양쪽에서 뒷받침됩니다.

- **경쟁 공백** — 국내에서 '변형문제 자동출제'와 '서술형 내용 채점'은 서로 다른 사업자로 분리돼 있습니다. **"자동출제 + 내신 범위 종속 내용 채점"의 결합은 아직 공백**이며, 이 자리가 Picklass의 포지셔닝입니다.
- **정책 순풍** — 2022 개정 교육과정으로 서·논술형 평가가 정기고사에 구조적으로 내재됩니다. 서술형은 학원 내신 대비의 **선택이 아니라 필수 커버 영역**이 되었습니다.
- **검수의 정당성** — 대규모 연구에서 LLM의 서술형 채점은 과제·유형별 성능 편차가 보고됩니다. Picklass의 **원장 최종 검수(Human-in-the-loop)** 설계는 이 불확실성에 대한 시장 실증적 대응입니다.

> AI가 다 하되, 마지막 판단은 사람이 — 이 원칙이 신뢰의 근거이자 차별점입니다.
