# P0-2-1. 성장 리포트 — 측정·표현 데이터 정의 상세 기획

| 항목 | 내용 |
|---|---|
| 코드 | P0-2-1 (P0-2 하위 상세, Gap G1×G8) |
| 우선순위 | P0 (12월 파일럿 필수, 리포트 데이터 스펙) |
| 연계 | P0-1 진단(기준점·강약점), P1-2 과정데이터(성실도·이해도), P1-3 Achievement(정식 성장 델타), §11.5 성과카드·KPI(✅), §7.10 브랜딩 |
| 상태 | 신규 — P0-2 리포트에 **실제 표현할 지표를 데이터 원천 단위로 확정** |
| 핵심 결정 | MVP 성장 추이 = **수업 KPI 추이 근사**(진단 시점 vs 최근 4주 평균), 정식 델타는 P1-3 |

---

## 1. 목적

P0-2 리포트가 학부모에게 보여줄 **성장(Growth)**과 **과정(Process)** 데이터를, "실제 저장되는 필드"만으로 구성 가능하도록 지표 단위로 확정한다. 부정확한 리포트는 이탈을 부르므로(토피아), **과장 0**을 데이터 스펙 차원에서 강제한다.

## 2. 핵심 관점 — 성장과 과정은 리포트의 두 축

| 축 | 답하는 질문 | 성격 | 변화 속도 | 지불 스위치 역할 |
|---|---|---|---|---|
| **성장(Growth)** | "얼마나 컸나?" | 결과의 **증명** | 느림(구간·학기) | 학부모가 돈을 내는 이유 |
| **과정(Process)** | "제대로·꾸준히 했나?" | 성장의 **근거** | 빠름(월 단위) | 성장 수치의 신뢰 + 다음 달 예측 |

성장만 있으면 "이 숫자가 진짜냐"는 불신이 남고, 과정만 있으면 "그래서 얼마나 컸냐"에 답을 못 한다. **과정이 성장을 뒷받침하는 구조**가 P1-2가 P0-2를 위해 존재하는 이유다.

## 3. 데이터 가용성 매트릭스 (선후 역전 대응)

리포트=P0, 과정데이터·Achievement=P1의 선후 역전 때문에, 12월 MVP는 ✅ 범위로만 구성하고 나머지는 "축적 중"으로 둔다.

| 지표 | 원천 엔티티·필드 | MVP(12월) | P1 |
|---|---|:---:|:---:|
| 현재 레벨(1–18 / CEFR 6그룹) | `DiagnosticResult.finalLevel` | ✅ | |
| 영역 스코어(어휘·독해속도·이해) | `DiagnosticResult.skillScores {vocab, readingSpeed, comprehension}` | ✅ | |
| 수업 중 WPM·정확도 | 모듈 KPI(§11.5 ✅) | ✅ | |
| 출석률·완주율·학습량 | 기존 과정 데이터 | ✅ | |
| 강·약점 태그 | 진단 `itemLog`(정오답·난이도) 1차 도출 | ✅ 근사 | ✅ 정밀 |
| **성장 델타(레벨·영역)** | Achievement vs 진단 기준점 | △ **수업 KPI 추이 근사** | ✅ 정식 |
| 문항별 시도 횟수·평균 소요 | `ProcessMetric.avgAttempts/avgElapsed` | ❌ | ✅ |
| 오답 패턴 → 약점 정밀화 | `ProcessMetric.errorPatterns/weaknessTags` | ❌ | ✅ |
| 무성의 통과(성실 학습) 지수 | `ProcessMetric.integrityFlag` | ❌ | ✅ |

### 3-1. MVP 성장 추이 근사 규칙 (확정)

- **방식**: 진단 시점 WPM·정확도 → **최근 4주 수업 KPI 평균**의 변화로 성장을 표현.
- **근거**: 이미 저장되는 데이터(§11.5 ✅)만 사용 → 별도 재진단 부담 없음, 학생 피로 없음, 과장 0 유지.
- **레벨 델타**: MVP는 진단 레벨을 "현재 위치"로 표기하고, 레벨 상승은 재진단(원장 선택) 또는 P1-3 Achievement 시점에만 갱신. 자동 레벨 상승 추정 금지.
- **첫 리포트**: 비교 대상 부재 시 성장 섹션은 **"출발점 기록"**으로 표기, 성장 델타는 2회차부터.

## 4. 측정 지표 카탈로그

### 4-1. 성장(Growth) — "증명"

| 지표 | 측정식 | 표시 예시 | Phase |
|---|---|---|:---:|
| 읽기 속도 성장 | 진단 WPM → 최근 4주 평균 WPM | `82 → 118 WPM (+44%)` | ✅ MVP |
| 정확도 성장 | 진단 정확도 → 최근 정확도 | `71% → 86%` | ✅ MVP |
| 레벨 성장 | 현재 `finalLevel` − 기준점 레벨 | `Lv.6 → Lv.8 (+2)` | 재진단/P1 |
| 영역별 성장 | 영역 `skillScores` 델타 | 어휘 ▲ / 이해 ▲ / 속도 → | 재진단/P1 |
| 목표 달성률 | `AchievementResult.achievementRate` | `학기 목표의 92%` | P1 |

### 4-2. 과정(Process) — "근거" (성실도 + 이해도)

| 하위축 | 지표 | 측정식 | 표시 예시 | Phase |
|---|---|---|---|:---:|
| 성실도 | 출석률 | 출석/예정 | `19/20회(95%)` | ✅ MVP |
| 성실도 | 완주율 | 완료 모듈/배정 | `37/40(93%)` | ✅ MVP |
| 성실도 | 학습량 | 완료 세션·누적 시간 | `총 14h, 37세션` | ✅ MVP |
| 이해도 | 정확도 | 정답/시도 | `평균 86%` | ✅ MVP |
| 이해도 | 평균 시도 횟수 | `avgAttempts` | `문항당 1.3회` | P1 |
| 이해도 | 성실 학습 지수 | `integrityFlag` 없음 비율 | `무성의 통과 0건` | P1 |
| 이해도 | 오답 유형 | `errorPatterns`→약점 태그 | `추론형 오답 집중` | P1 |

## 5. 리포트 화면 구성 (1페이지 원칙)

에이플러스 "화려한 그래프보다 정확한 데이터" → 그래프는 WPM 추이 1개로 절제, 나머지는 숫자·배지·화살표.

- ① 한 줄 요약(Hero): 성장 1 + 과정 1을 한 문장. "…Lv.6→Lv.8 성장, 출석 95%·완주 93% 성실 학습."
- ② 현재 위치: 레벨 배지 + CEFR + 6그룹 위치.
- ③ 성장 추이(Growth 축): 레벨·영역 화살표 + **WPM 추이 그래프(유일한 그래프)** + 정확도 변화.
- ④ 이번 기간 학습 과정(Process 축): 성실도(출석·완주·시간) + 이해도(정확도·[P1]시도·무성의).
- ⑤ 강점·보완점: 강점 2 + 보완 2(다음 달 집중 예고).
- ⑥ 선생님 코멘트: LLM 생성 → 원장 검수·승인(P0-4). 수치는 시스템 값 고정.
- Footer: "모든 수치는 실제 학습 기록에 근거합니다".

FR-2의 5개 섹션(①레벨 ②강약점 ③학습량 ④성장추이 ⑤코멘트)을 **성장 축(②③)·과정 축(④)으로 재배치**한 것이며 `GrowthReport` 스키마와 1:1 매핑.

## 6. 정확성·신뢰 가드 (과장 0 구현)

| 규칙 | 구현 |
|---|---|
| 수치 고정 | 모든 숫자는 시스템 집계값을 문자열로 고정해 코멘트 슬롯에 주입. LLM은 문장만 생성(수치 재계산·인용 금지). |
| 데이터 부족 | 임계 미만(예: 세션 5회 미만) 섹션은 그래프·델타 숨기고 "데이터 축적 중". 첫 리포트 성장은 "출발점 기록". |
| 성취 하락 | 부정 표기 대신 "보완 예정" 톤(P1-3 §8). |
| 오탐 방지 | 무성의 플래그(P1)는 리포트 미노출, 원장 검수 화면에만 참고 표시(느린 학생 오탐 보호). |
| 기준점 명시 | 성장 델타 기준점 표기(진단 / N회차). 범위 변경 시 비교 가능 구간만. |

## 7. 단계별 릴리스

- **12월 MVP(P0)**: 섹션 ①~⑥ 골격 + ✅ 데이터. 성장 = **수업 KPI 추이 근사**, 과정 = 성실도 중심. 시도·오답·무성의 = "축적 중".
- **P1(파일럿 직후)**: P1-2 과정데이터로 ④에 시도·오답·성실지수, ⑤에 정밀 약점, ③에 P1-3 정식 성장 델타·목표 달성률 채움 → 완성형.

## 8. 오픈 이슈 (개발팀 확인)

- 최근 4주 KPI 평균의 윈도우·최소 세션 수 임계값.
- 재진단 트리거 정책(리포트 발행 시 자동 제안 여부).
- WPM 추이 그래프의 데이터 포인트 주기(주간/세션).
- `GrowthReport.metrics`에 과정 지표(P1) 추가 시 스키마 확장 방식.
