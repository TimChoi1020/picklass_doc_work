## 1. 목적·배경

"완료했는가"가 아니라 **"진짜 학습했는가"**를 과정 데이터(시도 횟수·소요 시간·오답 패턴)로 포착해 리포트·진단으로 되돌린다.

- 시장 근거: 온라인 도구가 완료 여부만 보여줘 아이들이 꼼수(뒤로가기·베끼기), 강사가 다시 감시자가 됨(정성 ⑨). "완료 여부만 보이지 몇 번 시도했는지는 안 나온다"(전소영). "다운받은 답 베껴온 상황"(에이플러스) → 완료 데이터만으론 이해 판별 불가.
- 가치: 과정 데이터가 리포트의 신뢰(정확성)와 진단 정밀도를 동시에 높인다.
- **온라인 유인**: 과정지표(시도·시간·오답)는 **종이로는 수집 불가** — 종이 답안은 채점만 되고 과정은 안 남는다([N3](40_N3_종이디지털브리지_QR_OCR_전략노트.md)). 이 차이를 "온라인으로 풀면 과정까지 분석된다"는 **온라인 사용 권장 유인**으로 활용.

## 2. 사용자 스토리

- (원장) 아이가 이 문제를 몇 번 만에, 얼마나 걸려 맞혔는지 보고 진짜 이해했는지 알고 싶다.
- (강사) 대충 눌러 통과하는 학생을 자동으로 걸러내고 싶다(감시 노동 제거).
- (학부모) 리포트의 성실도·이해도가 실제 학습 과정에 근거하길 원한다.

## 3. 범위 (In/Out)

**In (P1)**
- 과정 지표 수집·저장: 문항별 시도 횟수, 소요 시간, 오답 패턴, 재시도, 힌트 사용, (해당 시) 이탈·탭 전환
- 이상 패턴 탐지(경량): 즉답 반복·비정상 속도 등 "성의 없는 통과" 플래그
- 과정 지표 → P0-2 리포트(성실도·이해도), P0-1/P1-3 진단(약점 정밀화) 환류

**Out (후속)**
- 고급 부정행위 방지(디바이스·화면 감시, P2), 실시간 개입(정답률 저하 시 보충 모듈 삽입 — §고도화 2, P2)

## 4. 기능 요구사항 (FR)

- **FR-1** 과정 이벤트 수집: 모듈 실행 중 attempt/time/hint/retry/오답선택 로그 적재(§11.4·§14.6 확장).
- **FR-2** 지표 산출: 문항·모듈·학생 단위로 시도수·평균 소요·오답률·오답 유형 집계.
- **FR-3** 무성의 통과 플래그: 규칙 기반(예: 최소 소요시간 미만 + 즉답 반복) 감지 → 리포트/강사 알림.
- **FR-4** 리포트 환류: 성실도(완주·시도)·이해도(오답 패턴) 지표를 P0-2 `GrowthReport.metrics`로 전달.
- **FR-5** 진단 환류: 오답 패턴을 약점 태그로 변환 → P0-1/P1-3 진단 정밀화, §10 다음 수업 가중치.
- **FR-6** 강사 뷰: 학생별 과정 데이터 요약(시도·시간·플래그) 대시보드.

## 5. 화면·플로우

```
[Tutoring] 모듈 실행 → 과정 이벤트 로그 적재(런타임)
   → 집계 파이프라인(시도·시간·오답·플래그)
        ├─ 리포트(P0-2): 성실도·이해도 지표
        ├─ 진단(P0-1/P1-3): 오답 패턴 → 약점 태그
        └─ 강사 대시보드: 무성의 통과 플래그
```

## 6. 데이터 모델 / 입출력

**신규/확장(요약)**

| 엔티티 | 필드 |
|---|---|
| `ProcessEvent` | id, studentId, moduleCode, itemId, attemptNo, elapsedMs, hintUsed, wrongChoice, ts |
| `ProcessMetric`(집계) | studentId, period, avgAttempts, avgElapsed, errorRate, errorPatterns[], integrityFlag |
| 오답 태그 | weaknessTags[] → 진단·시퀀싱 입력 |

## 7. 기존 자산 연계 (재사용/확장)

- **재사용**: 실시간 피드백(§11.4 ✅), 성과카드·KPI(§11.5 ✅), WPM·정확도 수집(✅), §14.6 KPI 체계, 비동기 태스크(§19.7).
- **확장**: 과정 이벤트 스키마·집계 파이프라인, 무성의 통과 탐지, 리포트/진단 환류 연결.

## 8. 예외·엣지 케이스

- 개인정보(탭 전환·이탈 추적): 수집 범위·동의 정책 준수(§22.3).
- 오탐(느린 학생을 무성의로): 플래그는 참고용, 원장 판단 보조로만.
- 대량 이벤트 성능: 배치 집계·샘플링(§19.7 비동기).
- 오프라인/네트워크 유실: 재전송·유실 허용 지표 정의.

## 9. 완료 정의(DoD) · QA

- 모듈 실행 시 과정 이벤트가 적재되고 학생 단위로 집계됨.
- 리포트에 성실도·이해도 지표가 실제 과정 데이터로 표시(과장 0).
- 무성의 통과 시나리오가 플래그로 검출(QA 3종: 정상/즉답반복/느린 학생).

## 10. 의존성 · 오픈 이슈

- **연동**: P0-2 리포트, P0-1·P1-3 진단·평가, §10 시퀀싱 가중치.
- **오픈 이슈(개발팀 확인)**: ①현재 수집 이벤트로 과정 지표 구성 가능 여부·추가 계측 포인트 ②탭 전환/이탈 추적의 개인정보·기술 제약 ③무성의 통과 판정 임계값 ④이벤트 적재 스택·보존 정책.
