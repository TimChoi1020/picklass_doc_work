**연관 문서**: [회원계정시스템_개발계획](../menu-redesign/20260520_회원계정시스템_개발계획.md)

## 0. 배경 및 결정

### 쟁점

| 항목 | 현재 | 문제 |
|------|------|------|
| 과정·레슨 생성 | studio.picklass.com 전담 | 백오피스에 과정 화면 없음 |
| 기관별 과정 현황 | 파악 불가 | academy_admin이 자기 기관 과정을 볼 수 없음 |
| 과정 ↔ 액세스코드 연결 | access_codes.course_id 존재 | 어떤 과정에 코드가 발급됐는지 한눈에 보이지 않음 |
| 중복 개발 여부 | 미결 | 과정 편집 UI를 백오피스에 다시 만들어야 하는가? |

### 결정: 역할 명확화, 중복 개발 금지

```
studio.picklass.com  →  콘텐츠 생성·편집 (Creative)
                         과정/레슨 생성, 수업모듈 설정, 스피킹 지문 작성
                         → 백오피스에 절대 중복 개발하지 않음

picklass-backoffice  →  콘텐츠 배포·운영 (Administrative)
                         기관별 과정 현황 조회, 액세스코드 발급, 학습 통계
```

## 1. 현재 데이터 모델

### courses 테이블 (변경 없음)

```prisma
model Course {
  id              String   @id  @db.Uuid
  institutionId   String   @map("institution_id")  // 과정 소유 기관
  title           String
  levelCode       String   @map("level_code")
  genreCode       String   @map("genre_code")
  statusCode      String   @default("in_use") @map("status_code")
  totalLessons    Int      @default(0) @map("total_lessons")
  estimatedHours  Int?     @map("estimated_hours")
  studentCount    Int      @default(0) @map("student_count")
  deploymentCount Int      @default(0) @map("deployment_count")
  createdBy       String   @map("created_by")  // 생성자 (studio 사용자 id)
  ...
  institution Institution @relation(...)
  accessCodes AccessCode[] // 이 과정에 발급된 액세스코드들
}
```

> `courses.institution_id`가 이미 NOT NULL → 과정은 처음부터 특정 기관에 속함.  
> 별도 배분 테이블 불필요. **DB 변경 없음.**

### 흐름 요약

```
backoffice  →  institution_settings 기관별 스피킹 옵션 설정
               (FRT 최대시간, 이수조건 기본값, 나만의수업, 마이크모드)
                 ↓  GET /institutions/:id/settings
studio  →  Course 생성 시 기관 설정으로 speaking_options pre-fill
           (frt_minutes, 이수조건, freeLearning, micMode 초기값 자동 입력)
           institution_id 지정 후 저장
           ↓
backoffice  →  Course 목록 조회 (읽기 전용)
               AccessCode 발급 시 course_id 연결 (기존 기능)
               ↓
tutoring  →  학습자가 AccessCode 등록 → 과정 수강
```

> **institution_settings 연관**: 백오피스 기관 상세 [설정] 탭에서 관리하는 값이 Studio 과정 생성의 스피킹 옵션(speaking_options) 초기값으로 흘러들어간다. 과정 저장 후에는 독립적인 값으로 유지되므로, 기관 설정 변경이 기존 과정에 영향을 주지 않는다.

## 2. 신규 개발 항목

### 2-1. `/admin/courses` — 과정 목록 페이지

**접근 권한**: `ALL_ADMIN`  
**역할**: 읽기 전용. studio에서 생성된 과정을 기관 범위에 맞게 조회.

#### 목록 화면

| 컬럼 | 내용 |
|------|------|
| 과정명 (title) | 클릭 시 상세 이동 |
| 레벨 (levelCode) | 코드관리 기반 표시 |
| 장르 (genreCode) | 코드관리 기반 표시 |
| 총 레슨 수 (totalLessons) | |
| 수강 인원 (studentCount) | |
| 배포 횟수 (deploymentCount) | 액세스코드 발급 수 |
| 상태 (statusCode) | in_use / archived |
| 소속 기관 | `system_admin`·`partner_admin`·`group_admin` 에게만 표시 |

#### 필터

| 필터 | 내용 | 노출 조건 |
|------|------|----------|
| 상태 | in_use / archived | 전체 |
| 레벨, 장르 | 코드관리 항목 | 전체 |
| 검색 | 과정명 | 전체 |
| 파트너 선택 | 전체 파트너 기관 목록 | `system_admin`만 |
| 그룹 선택 | 선택한 파트너 산하 그룹 목록 | `system_admin`, `partner_admin` |
| 기관 선택 | 선택한 그룹 산하 기관 목록 | `system_admin`, `partner_admin`, `group_admin` |

> `academy_admin`은 자기 기관 고정 — 조직 필터 UI 미노출.

#### 데이터 범위 및 필터 제한 (role별)

| Role | 조회 범위 | 노출 필터 | 고정값 |
|------|----------|----------|--------|
| `system_admin` | 전체 | 파트너·그룹·기관·상태·레벨·장르·검색 | 없음 |
| `partner_admin` | 자기 산하 기관(재귀 CTE)의 과정 | 그룹·기관·상태·레벨·장르·검색 | 파트너 고정 |
| `group_admin` | 자기 산하 기관(재귀 CTE)의 과정 | 기관·상태·레벨·장르·검색 | 파트너·그룹 고정 |
| `academy_admin` | 자기 institution_id의 과정 | 상태·레벨·장르·검색 | 기관 고정 |

#### 다운로드

목록 우상단에 **[다운로드 ▾]** 버튼을 배치한다.

- 접근 권한: `ALL_ADMIN` (전체)
- 다운로드 범위: 현재 적용된 필터 및 Role별 조회 범위와 동일
- 파일 형식 선택: `xlsx` / `csv` (드롭다운)
- 컬럼 구성: 목록 화면 컬럼과 동일 (과정명, 레벨, 장르, 총 레슨 수, 수강 인원, 배포 횟수, 상태, 소속 기관)

#### 과정 상세 (`/admin/courses/[id]`)

읽기 전용 상세 페이지:

```
탭: [기본정보] [액세스코드(N)]
```

- **[기본정보]**: title, levelCode, genreCode, description, totalLessons, estimatedHours, courseFocus, studentCount, deploymentCount
- **[액세스코드(N)]**: 이 과정에 발급된 액세스코드 목록 (statusCode, 등록 학습자, 만료일) → `/admin/access-codes/[id]` 링크

> 편집 버튼 없음. "studio에서 편집하기" 링크(외부)만 표시.

### 2-2. 기관 상세 — 과정 딥링크 버튼

기관별 과정 탭은 별도 개발하지 않는다. 대신 기관 상세 페이지 우상단에 딥링크 버튼을 추가한다.

#### 기관 상세 페이지 탭 구조 (Phase 4 최종)

```
/admin/institutions/[id]
  탭: [기본정보] [강사(N)] [학습자(N)]
```

#### 딥링크 버튼

기관 상세 페이지의 institution type에 따라 쿼리 파라미터를 분기하여 `/admin/courses`로 이동한다.

| institution type | 딥링크 URL | 결과 |
|-----------------|-----------|------|
| 파트너 | `/admin/courses?partnerId={id}` | 해당 파트너 산하 전체 과정 |
| 그룹 | `/admin/courses?groupId={id}` | 해당 그룹 산하 전체 과정 |
| 기관(academy) | `/admin/courses?institutionId={id}` | 해당 기관의 과정 |

- [기본정보] 탭 우상단에 위치, 버튼 레이블은 공통: `[이 기관의 과정 보기 →]`
- 클릭 시 `/admin/courses`로 이동하며 해당 계층 하위 전체 과정이 표시됨
- 과정 목록 진입점을 `/admin/courses`로 단일화하여 UX 일관성 유지
- 접근 가능한 Role이어야 버튼이 표시됨 (데이터 범위 내에 해당 기관이 있어야 함)

> **설계 결정**: `/admin/courses` 목록에 조직 계층 필터(파트너·그룹·기관)와 Role별 제한을 구현하므로, 기관 상세 내 과정 탭은 중복이 됨. 딥링크 버튼으로 컨텍스트 이동 UX를 보완한다.

## 3. API 설계

### 3-1. 과정 목록 API

```
GET /courses?page=&limit=&status=&levelCode=&genreCode=&search=&partnerId=&groupId=&institutionId=
```

| 파라미터 | 설명 | 사용 가능 Role |
|----------|------|---------------|
| `partnerId` | 파트너 기관 id 필터 | `system_admin`만 |
| `groupId` | 그룹 기관 id 필터 | `system_admin`, `partner_admin` |
| `institutionId` | 기관 id 필터 | `system_admin`, `partner_admin`, `group_admin` |
| 그 외 | 상태·레벨·장르·검색 | 전체 |

- `academy_admin`은 JWT의 `institutionId` 서버에서 고정 적용 (파라미터 무시)
- 응답: `CourseListResponse { data: CourseResponse[], pagination }`

### 3-2. 과정 단건 API

```
GET /courses/:id
```

### 3-3. 과정 목록 다운로드 API

```
GET /courses/export?format=xlsx&page=&limit=&status=&levelCode=&genreCode=&search=&partnerId=&groupId=&institutionId=
```

| 파라미터 | 설명 |
|----------|------|
| `format` | `xlsx` 또는 `csv` (기본값: `xlsx`) |
| 나머지 | 3-1 목록 API와 동일 (필터·Role 범위 동일 적용) |

- 응답: `Content-Disposition: attachment` 파일 스트림
- `academy_admin`은 JWT의 `institutionId` 서버에서 고정 적용 (파라미터 무시)
- 다운로드 파일명: `courses_YYYYMMDD.xlsx` / `courses_YYYYMMDD.csv`

### 의도적 제외 (백오피스 미개발)

```
POST   /courses      → studio 전담
PUT    /courses/:id  → studio 전담
DELETE /courses/:id  → studio 전담
```

## 6. 구현 순서

```
Phase 4 — 과정 목록/상세 + 기관 딥링크 (메뉴개편 Phase 4 병행)
  ├─ packages/types: CourseResponse, CourseListResponse 추가
  ├─ packages/core: CourseService (findAll — 재귀 CTE scope 계산 포함, findById, exportToBuffer)
  ├─ admin/backend: CourseQueryDto 신규 (backend 전용)
  ├─ admin/backend: CourseController (GET /courses, GET /courses/:id, GET /courses/export)
  │     └─ Role별 데이터 범위 제한: JWT role 기반 scopeInstitutionIds 계산
  │            · system_admin  → 전체
  │            · partner_admin → 재귀 CTE로 산하 기관 id 목록
  │            · group_admin   → 재귀 CTE로 산하 기관 id 목록
  │            · academy_admin → JWT의 institutionId 고정
  ├─ pnpm run build (core)
  ├─ admin/frontend: /admin/courses 목록 (조직 계층 필터 + Role별 노출 제한)
  ├─ admin/frontend: /admin/courses/[id] 상세 페이지
  └─ admin/frontend: /admin/institutions/[id] 딥링크 버튼 (type별 파라미터 분기)

Phase 5 — 과정 ↔ 액세스코드 연결 강화
  └─ 과정 상세 [액세스코드(N)] 탭 구현 (기존 access-codes API 활용)

Phase 6 — 통계 연동
  └─ /admin/stats: studentCount·deploymentCount 기반 기관별·과정별 집계
```

## 7. 의도적 제외

| 항목 | 이유 |
|------|------|
| 과정·레슨 생성·편집 UI | studio 전담 — 중복 개발 금지 |
| AI 모듈 콘텐츠 편집 | studio 전담 |
| 학습자 학습 인터페이스 | tutoring.picklass.com 전담 |
| 과정 소속 기관 변경 | 데이터 정합성 리스크 — studio에서만 허용 |
| 과정 복제·템플릿 | 향후 과제 |
| 기관 상세 `[과정(N)]` 탭 | `/admin/courses` 단일 진입점으로 통합, 딥링크 버튼으로 대체 |
| `GET /institutions/:id/courses` API | 기관 탭 제거로 불필요 — institutionId 쿼리 파라미터로 대응 |
