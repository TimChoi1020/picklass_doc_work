## 0. 배경 및 목표

### 배경

픽클래스는 기본적으로 B2B 서비스이며, 학습결과 관리는 두 가지 유형으로 나뉜다.

| 구분 | 설명 | 진도 기준 |
|------|------|----------|
| **[일반]** | 픽클래스 직접 계약 기관 서비스 | 과정(Course) |
| **[B2B]** | 외부 파트너사 API 연동 서비스 | 수강신청은 실시간 처리 전용 → 저장된 학습관리 불가, 레슨/모듈 결과만 조회 |

### 목표

- 통계/리포트 대메뉴에 학습결과 관련 소메뉴 추가
- [일반] 학습결과는 기존 **기관 학습 현황** 메뉴에 드릴다운 확장
- [B2B] 학습결과는 **B2B 학습데이터** 메뉴 신규 추가 (파트너 API 제공 데이터 백오피스 뷰)
- **출석률** 메뉴 신규 추가

### 3-1. 기관 학습 현황 — [일반] 학습결과

**URL**: `/admin/stats/institutions`  
**권한**: `ORG_ABOVE` (SYS·PRT·GRP)  
**데이터 소스**: `courses` + `access_codes` + `lesson_results` + `module_histories`

#### 설계 방향 (2026-05-25 개정)

기관 → 과정 → 학습자로 내려가는 5단계 드릴다운 대신, **검색 필터 + 평면 리스트 + 페이지네이션** 방식으로 재설계한다.

- 리스트 1행 = 학습자 1명 × 과정 1개
- 조건 없이 검색 시 전체 데이터 표시 (페이지 진입 시 자동 로드)
- 행 클릭 → 레슨 상세 → 레슨 클릭 → 모듈 상세 (기존 하위 2단계 재활용)

#### 역할별 필터 범위

```
필드:  상위파트너 | 상위그룹 | 기관명 | 과정명 | 학습자 아이디

system_admin
  상위 파트너   [              ]  입력 가능
  상위 그룹     [              ]  입력 가능
  기관명        [              ]  입력 가능
  과정명        [              ]  입력 가능
  학습자 아이디 [              ]  입력 가능

partner_admin
  상위 파트너   [ ABC 파트너   ]  🔒 비활성 (자기 파트너 고정)
  상위 그룹     [              ]  입력 가능
  기관명        [              ]  입력 가능
  과정명        [              ]  입력 가능
  학습자 아이디 [              ]  입력 가능

group_admin
  상위 파트너   [ ABC 파트너   ]  🔒 비활성 (소속 파트너 고정)
  상위 그룹     [ 서울 그룹    ]  🔒 비활성 (자기 그룹 고정)
  기관명        [              ]  입력 가능
  과정명        [              ]  입력 가능
  학습자 아이디 [              ]  입력 가능
```

> **HARD 마커**: 상위 파트너 / 상위 그룹 필터는 DB에 기관 계층 구조(`parent_id`)가 없어 아래와 같이 제한적으로 구현되어 있다.
>
> | role | 파트너 필드 | 그룹 필드 | API 실제 전달 |
> |------|-----------|---------|-------------|
> | `partner_admin` | 자기 기관명 🔒 표시 | 입력 가능 | **미전달** — `institutionName`으로 대체 불가, UI 고정만 적용 |
> | `group_admin` | **비어 있음** (소속 파트너명 조회 불가) | 자기 기관명 🔒 표시 | **미전달** — 동일 |
>
> `partnerName` / `groupName` 값은 프론트 UI에 표시만 되고 `fetchSearchLearners` 호출 시 API에 전달되지 않는다.  
> 향후 DB 스키마에 `parent_id` 추가 + 백엔드 Guard 구현 후 실제 계층 필터링 활성화.

#### 페이지네이션 설계

| 항목 | 내용 |
|------|------|
| 기본 페이지 크기 | 20행 (고정) |
| 파라미터 | `page` (1-based), `limit` (기본 20, 최대 100) |
| 응답 포함 필드 | `total`, `page`, `limit`, `rows[]` |
| 컨트롤 | 이전/다음 버튼 + 페이지 번호 (최대 10개 노출) |
| 총 건수 표시 | 테이블 상단 "총 N명" |
| 필터 변경 시 | page = 1로 초기화 |

#### 3-2-9. 백엔드 API 엔드포인트

**파트너 외부 API** (backoffice에서 서빙, API Key 인증)

```
  → 3-2-5 스펙 참조  (Phase B-2 이후 구현 예정)
```

**백오피스 내부 API** (SYS 전용, JWT 인증) — ✅ 재구성 완료

```
GET /stats/b2b/results
  Query:
    startDate?: string    ← 완료일 기간 시작
    endDate?: string      ← 완료일 기간 종료
    courseTitle?: string  ← 과정명 부분 일치 (ILIKE)
    lessonTopic?: string  ← 레슨명 부분 일치 (ILIKE)
    page?: number         ← 1-based (기본 1)
    limit?: number        ← 기본 20, 최대 100

  내부 처리:
    1. courseTitle ILIKE → course.id[] 해석
    2. lessonTopic ILIKE → courseLessonId[] 해석 (courseId 교집합 적용)
    3. lessonResult.findMany(date filter + lessonId/courseId filter)
    4. User.findMany(id IN studentIds)    → userNameMap 배치 조회
    5. Course.findMany(id IN courseIds)   → courseTitleMap 배치 조회
    6. B2bLessonRow[] 구성 → 인메모리 페이지네이션

  응답: B2bLessonListResponse
  {
    "total": 100,
    "page": 1,
    "limit": 20,
    "rows": [
      {
        "studentId": "uuid",
        "studentName": "홍길동",
        "courseId": "uuid",
        "courseTitle": "영어회화 기초",
        "lessonId": "uuid",
        "lessonOrder": 1,
        "topic": "Unit 1 - Greetings",
        "completed": true,
        "score": 85,
        "durationSec": 1820,
        "completedAt": "2026-05-20T10:30:00Z"
      }
    ]
```

### STEP 3. packages/core — B2B Stats 서비스 재구성 ✅ 완료

**`packages/core/src/stats/b2b-stats.service.ts`** — `getResults` 단일 메서드로 재구성:

```typescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import type { B2bLessonRow, B2bLessonListResponse, B2bResultsQuery } from '@repo/types';

@Injectable()
export class B2bStatsService {
  constructor(private readonly prisma: PrismaService) {}

  async getResults(query: B2bResultsQuery): Promise<B2bLessonListResponse> {
    const page = Math.max(1, query.page ?? 1);
    const limit = Math.min(100, Math.max(1, query.limit ?? 20));

    // Step 1: 과정명 → courseIds
    let courseIdFilter: string[] | undefined;
    if (query.courseTitle) {
      const courses = await this.prisma.course.findMany({
        where: { title: { contains: query.courseTitle, mode: 'insensitive' }, deletedAt: null },
        select: { id: true },
      });
      courseIdFilter = courses.map((c) => c.id);
      if (courseIdFilter.length === 0) return { total: 0, page, limit, rows: [] };
    }

    // Step 2: 레슨명 → courseLessonIds (courseIdFilter와 교집합)
    let lessonIdFilter: string[] | undefined;
    if (query.lessonTopic) {
      const lessons = await this.prisma.courseLessonReadonly.findMany({
        where: {
          topic: { contains: query.lessonTopic, mode: 'insensitive' },
          ...(courseIdFilter && { courseId: { in: courseIdFilter } }),
        },
        select: { id: true },
      });
      lessonIdFilter = lessons.map((l) => l.id);
      if (lessonIdFilter.length === 0) return { total: 0, page, limit, rows: [] };
    }

    // Step 3: lessonResult 조회
    const lessonResults = await this.prisma.lessonResult.findMany({
      where: {
        ...((query.startDate || query.endDate) && {
          completedAt: {
            ...(query.startDate && { gte: new Date(query.startDate) }),
            ...(query.endDate && { lte: new Date(`${query.endDate}T23:59:59`) }),
          },
        }),
        ...(lessonIdFilter
          ? { courseLessonId: { in: lessonIdFilter } }
          : courseIdFilter
            ? { courseLesson: { courseId: { in: courseIdFilter } } }
            : {}),
      },
      include: { courseLesson: true },
      orderBy: { completedAt: 'desc' },
    });

    if (lessonResults.length === 0) return { total: 0, page, limit, rows: [] };

    // Step 4: 학습자 이름 배치 조회
    const studentIds = [...new Set(lessonResults.map((r) => r.studentId))];
    const users = await this.prisma.user.findMany({
      where: { id: { in: studentIds } },
      select: { id: true, name: true },
    });
    const userNameMap = new Map(users.map((u) => [u.id, u.name]));

    // Step 5: 과정명 배치 조회
    const courseIds = [...new Set(lessonResults.map((r) => r.courseLesson.courseId))];
    const courses = await this.prisma.course.findMany({
      where: { id: { in: courseIds } },
      select: { id: true, title: true },
    });
    const courseTitleMap = new Map(courses.map((c) => [c.id, c.title]));

    // Step 6: 행 구성 + 인메모리 페이지네이션
    const allRows: B2bLessonRow[] = lessonResults.map((lr) => ({
      studentId: lr.studentId,
      studentName: userNameMap.get(lr.studentId) ?? lr.studentId,
      courseId: lr.courseLesson.courseId,
      courseTitle: courseTitleMap.get(lr.courseLesson.courseId) ?? null,
      lessonId: lr.courseLessonId,
      lessonOrder: lr.courseLesson.lessonOrder,
      topic: lr.courseLesson.topic,
      completed: lr.completedAt !== null,
      score: lr.averageScore !== null ? Number(lr.averageScore) : null,
      durationSec: lr.totalDuration,
      completedAt: lr.completedAt?.toISOString() ?? null,
    }));

    const total = allRows.length;
    const rows = allRows.slice((page - 1) * limit, page * limit);
    return { total, page, limit, rows };
  }
}
```

**핵심 설계 결정**:
- Enrollment 의존 완전 제거 — 과정명/레슨명 텍스트로 직접 필터링
- N+1 방지 — User/Course 이름을 배치 쿼리(2회)로 조회
- 인메모리 페이지네이션 — lessonResult 전체 fetch 후 slice (데이터 볼륨 허용 범위)
