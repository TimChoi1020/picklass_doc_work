# Picklass 랜딩페이지 (index.html)

## 개요
Pickclass는 AI 기반 영어 학습 플랫폼으로, B2B 기관 중심의 서비스를 제공합니다. 이 문서는 사용자 인증(로그인/회원가입) 및 프로필 관리 시스템의 구조를 정의합니다.

---

## 사용자 흐름 (User Flow)

### 1. 랜딩페이지 방문 흐름
```
사용자 접속
  ↓
Picklass 랜딩페이지 로드
  - 헤더: 네비게이션 + 로그인/회원가입 버튼
  - 히어로 섹션: 서비스 소개
  - 주요 기능 섹션
  - 요금제 섹션
  - 파트너 제휴 섹션
  - 데모 신청 섹션
  - 푸터: 연락처 정보
```

### 2. 로그인 흐름
```
사용자 → "로그인" 버튼 클릭
  ↓
로그인 모달 열기
  ↓
1단계: 사용자 타입 선택
  - 학습자 / 기관장 택일
  ↓
2단계: 인증 방법 선택
  - 이메일 & 패스워드 OR 소셜 로그인 (Google/Kakao/Naver)
  ↓
3단계: 인증 정보 입력
  - 이메일 방식: 이메일 + 패스워드 입력
  - 소셜 방식: 소셜 로그인 버튼 클릭
  ↓
로그인 성공
  ↓
4단계: 추가 정보 입력 모달 자동 열기
  - 학습자: 닉네임(이름) 입력
  - 기관장: 기관명, 기관유형, 성명, 연락처 입력
  ↓
완료 → 모달 닫기, 서비스 접근
```

### 3. 회원가입 흐름
```
사용자 → "+ 회원가입" 버튼 클릭 OR 로그인 모달에서 "회원가입" 링크 클릭
  ↓
회원가입 모달 열기
  ↓
1단계: 사용자 타입 선택
  - 학습자 / 기관장 택일
  ↓
2단계: 인증 방법 선택
  - 이메일 & 패스워드 OR 소셜 로그인 (Google/Kakao/Naver)
  ↓
3단계: 공통 정보 입력
  - 이메일 및 인증 정보 (선택한 방식에 따라)
  ↓
4단계: 타입별 추가 정보 입력
  - 학습자: 닉네임(이름)
  - 기관장: 기관명, 기관유형, 성명, 연락처
  ↓
5단계: 이용약관 동의
  ↓
"회원가입" 버튼 클릭
  ↓
가입 완료 → 모달 자동 닫기 → 서비스 접근
```

### 4. 추가 정보 입력 흐름 (로그인 후)
```
로그인 완료
  ↓
추가 정보 입력 모달 자동 열기
  ↓
사용자 타입에 따른 정보 입력
  - 학습자: 닉네임(이름) - 필수 1개 필드
  - 기관장: 기관명, 기관유형, 성명, 연락처 - 필수 4개 필드
  ↓
"완료" 버튼 클릭
  ↓
정보 저장 → 모달 닫기 → 대시보드/튜토링 페이지로 이동
```

### 5. 비로그인 사용자 행동 흐름
```
비로그인 사용자 → 데모/제휴 문의 클릭
  ↓
해당 모달 열기 (제휴 문의 / Studio 데모 신청)
  ↓
정보 입력 후 제출
```

### 6. 액세스코드 입력 흐름
```
사용자 → "액세스코드" 버튼 클릭
  ↓
액세스코드 입력 모달 열기
  ↓
1단계: 액세스코드 입력
  - 액세스코드 텍스트 입력 (필수)
  ↓
2단계: 확인 버튼 클릭
  ↓
액세스코드 검증
  - 유효한 6자리 코드 확인
  - 미사용 상태의 코드 확인
  ↓
검증 성공
  ↓
축하 메시지 표시
  ↓
서비스 접근 (액세스코드에 연결된 기관의 학생용 Tutoring 서비스)

검증 실패
  ↓
오류 메시지 표시
  ↓
재입력 또는 문의 안내
```

## 기능 정의 (IA)

### F1. 로그인

| 항목 | 내용 |
|------|------|
| **목적** | 기존 사용자가 계정으로 서비스에 접근 |
| **입력** | 사용자 타입 선택 (학습자/기관장) + 인증 방식 선택 (이메일/소셜) + 인증 정보 |
| **출력** | 로그인 성공 → 추가 정보 입력 모달 또는 대시보드 접근 |
| **조건** | 등록된 계정만 로그인 가능 |
| **트리거** | 헤더 "로그인" 버튼 클릭 |

**상세:**
- 사용자 타입: 학습자(Learner) / 기관장(Institution Head)
- 인증 방식 선택:
  - **이메일 & 패스워드**: 이메일 입력 + 패스워드 입력
  - **소셜 로그인**: Google, Kakao, Naver 중 택일
- 로그인 성공 후 추가 정보 입력 모달 자동 전환
- 회원가입 링크로 신규 가입 페이지 이동 가능

---

### F2. 회원가입

| 항목 | 내용 |
|------|------|
| **목적** | 신규 사용자가 계정 생성 및 서비스 등록 |
| **입력** | 사용자 타입 + 인증 방식 + 공통 정보 + 타입별 추가 정보 + 약관 동의 |
| **출력** | 계정 생성 → 서비스 접근 |
| **조건** | 모든 필수 필드 입력 필수, 이용약관 동의 필수 |
| **트리거** | 헤더 "+ 회원가입" 버튼 또는 로그인 모달의 "회원가입" 링크 클릭 |

**상세:**
- 사용자 타입 선택: 학습자 / 기관장
- 인증 방식:
  - **이메일 & 패스워드**: 이메일, 패스워드, 패스워드 확인
  - **소셜 로그인**: Google/Kakao/Naver 계정 연결
- 공통 필드:
  - 이메일 (이메일 방식인 경우)
  - 패스워드 (이메일 방식인 경우)
- 타입별 필드:
  - **학습자**: 닉네임(이름) 1개
  - **기관장**: 기관명, 기관유형, 성명, 연락처 4개
- 이용약관 동의 필수
- 회원가입 완료 후 로그인 모달로 이동 가능

---

### F3. 추가 정보 입력

| 항목 | 내용 |
|------|------|
| **목적** | 로그인 후 누락된 프로필 정보 수집 |
| **입력** | 사용자 타입별 추가 필드 정보 |
| **출력** | 프로필 정보 저장 → 대시보드/튜토링 서비스 접근 |
| **조건** | 로그인 성공 후 필수 정보가 없는 경우 자동 호출 |
| **트리거** | 로그인 성공 자동 전환 |

**상세:**
- 학습자 추가 정보:
  - 닉네임(이름): 필수, 텍스트 입력
- 기관장 추가 정보:
  - 기관명: 필수, 텍스트 입력
  - 기관유형: 필수, 선택지(학원/어학원/학교/기업교육/기타)
  - 성명: 필수, 텍스트 입력
  - 연락처: 필수, 전화번호 형식
- 모든 필드는 필수 입력
- "완료" 버튼으로 정보 저장 및 모달 종료

---

### F4. 사용자 타입 선택

| 항목 | 내용 |
|------|------|
| **목적** | 로그인/회원가입 시 사용자 역할 구분 |
| **입력** | "학습자" 또는 "기관장" 버튼 클릭 |
| **출력** | 선택한 타입에 따른 필드 표시/숨김 |
| **조건** | 이후 흐름이 선택한 타입에 따라 결정됨 |
| **트리거** | 로그인/회원가입 모달 열기 |

**상세:**
- **학습자**: 학습자용 서비스 (Tutoring) 접근
- **기관장**: 기관 관리자용 서비스 (Studio/Admin) 접근
- 기관장이 교실 운영 및 학생 관리를 담당
- 학습자의 필드가 더 간단함 (닉네임만)

---

### F5. 인증 방식 선택

| 항목 | 내용 |
|------|------|
| **목적** | 로그인/회원가입 시 인증 방법 결정 |
| **입력** | "이메일 & 패스워드" 또는 "소셜 로그인" 라디오 버튼 선택 |
| **출력** | 선택한 방식에 따른 입력 필드 표시/숨김 |
| **조건** | 최초 선택 시 기본값: 이메일 & 패스워드 |
| **트리거** | 로그인/회원가입 모달 열기 |

**상세:**
- **이메일 & 패스워드**:
  - 이메일 입력 필드
  - 패스워드 입력 필드
  - 회원가입 시: 패스워드 확인 필드 추가
- **소셜 로그인**:
  - Google 로그인 버튼
  - Kakao 로그인 버튼
  - Naver 로그인 버튼
- 선택 변경 시 즉시 필드 전환
- 이메일 방식에서 소셜 방식으로 변경 시 이메일/패스워드 required 해제

### F6. 모달 전환

| 항목 | 내용 |
|------|------|
| **목적** | 로그인/회원가입/추가정보입력 모달 간 원활한 전환 |
| **입력** | 모달 링크 클릭 또는 자동 전환 |
| **출력** | 다음 모달 열기 + 이전 모달 닫기 |
| **조건** | 각 모달 간 순차적 전환 |
| **트리거** | 사용자 액션 또는 자동 (로그인 성공 후) |

**상세:**
- 로그인 클릭 → 로그인 모달 열기
- 회원가입 클릭 → 회원가입 모달 열기
- 로그인 모달의 회원가입 링크 → 회원가입 모달로 전환
- 회원가입 모달의 로그인 링크 → 로그인 모달로 전환
- 로그인 성공 → 자동으로 추가 정보 입력 모달로 전환
- X 버튼 또는 외부 클릭 → 모달 종료

### F7. 액세스코드 입력

| 항목 | 내용 |
|------|------|
| **목적** | 발급받은 액세스코드로 학생 계정 접근 |
| **입력** | 액세스코드 (6자리) |
| **출력** | 액세스코드 검증 → 서비스 접근 |
| **조건** | 유효한 미사용 액세스코드만 승인 |
| **트리거** | 헤더 "액세스코드" 버튼 클릭 |

**상세:**
- 액세스코드: 6자리 영문+숫자 조합 (I, O, 0, 1 제외)
- 입력 필드: 텍스트 입력 (자동 대문자 변환)
- 검증 프로세스:
  - 코드 형식 확인 (6자리)
  - 코드 존재 여부 확인
  - 코드 상태 확인 (미사용: 사용 가능, 사용/휴예: 이미 사용 중)
- 검증 성공: 축하 메시지 표시 + Tutoring 서비스 접근
- 검증 실패: 오류 메시지 표시 + 문의하기 링크 제공
- 모달 닫기: X 버튼 또는 외부 클릭

## 정책 (Policy/Business Rules)

### B1. 사용자 타입 관련 정책

**사용자 분류:**
- **학습자 (Learner)**: 학습용 플랫폼 (Tutoring) 접근
- **기관장 (Institution Head)**: 기관 관리 및 교실 운영 (Studio/Admin) 접근

**필수 정보:**
- **학습자**: 
  - 회원가입: 이메일/소셜 + 닉네임(이름)
  - 로그인 후 추가 정보: 닉네임(이름) (누락시)
- **기관장**:
  - 회원가입: 이메일/소셜 + 기관명, 기관유형, 성명, 연락처
  - 로그인 후 추가 정보: 기관명, 기관유형, 성명, 연락처 (누락시)

**기관 유형 (기관장만 해당):**
- 학원
- 어학원
- 학교
- 기업교육
- 기타

---

### B2. 인증 및 보안 정책

**인증 방식:**
- **이메일 & 패스워드**:
  - 이메일: 유효한 이메일 형식 필수
  - 패스워드: 8자 이상 (권장)
  - 패스워드 확인: 회원가입 시 필수
- **소셜 로그인**:
  - Google: Google OAuth 연동
  - Kakao: Kakao OAuth 연동
  - Naver: Naver OAuth 연동
  - 소셜 로그인 시 프로필 정보 자동 매핑 (이메일)

**세션 관리:**
- 로그인 성공 후 세션 생성
- 추가 정보 입력 완료 후 대시보드 접근 허용
- 필수 정보 미입력 시 서비스 접근 제한

---

### B3. 데이터 검증 정책

**필수 필드 검증:**
- 모든 필수 필드는 비워둘 수 없음
- 폼 제출 전 클라이언트 측 검증 필수

**데이터 형식 검증:**
- **이메일**: 표준 이메일 형식 (example@domain.com)
- **연락처**: 010-0000-0000 형식 권장
- **닉네임/성명**: 1자 이상 텍스트
- **기관명**: 1자 이상 텍스트
- **기관유형**: 선택지에서만 선택

**데이터 길이 제한:**
- 이메일: 최대 254자
- 패스워드: 8자 이상, 최대 128자
- 닉네임: 1~50자
- 성명: 1~50자
- 기관명: 1~100자
- 연락처: 10~11자

---

### B4. 액세스코드 정책

**액세스코드 발급:**
- 기관 관리자(학원관리자)가 사전에 코드 대량 생성
- 코드 형식: 6자리 (A-Z [I, O 제외], 2-9 [0, 1 제외])
- 생성 예: A2K9P5, J7N3Z8, M4G6Q2 등
- 각 코드는 고유하며 중복 불가

**액세스코드 상태:**
- **미사용**: 생성 직후 상태, 학생이 입력 가능
- **사용**: 학생이 코드로 가입 완료, 더 이상 입력 불가
- **휴예**: 코드 발급 대기 중, 입력 불가
- **정지**: 관리자 정지 처리, 입력 불가

**액세스코드 입력 규칙:**
- 대문자만 입력 (자동 변환)
- 공백 자동 제거
- 6자리 정확히 일치하는 코드만 승인
- 미사용 상태의 코드만 수락 가능
- 같은 코드로는 1회만 가입 가능

**액세스코드 유효기간:**
- 기본: 90일 (관리자가 발급 시 설정 가능)
- 유효기간 내에만 입력 가능
- 만료된 코드는 입력 불가능

---

### B4. 사용자 경험 정책

**모달 상태 관리:**
- 로그인 모달 열기 시: 사용자 타입/인증 방식 초기화
- 회원가입 모달 열기 시: 모든 필드 초기화
- 추가 정보 입력 모달: 사용자 타입에 따른 필드만 표시

**에러 처리:**
- 필수 필드 미입력: 경고 메시지 표시
- 이메일 중복: "이미 사용 중인 이메일입니다" 메시지
- 로그인 실패: "이메일 또는 비밀번호가 올바르지 않습니다" 메시지
- 소셜 로그인 실패: "로그인에 실패했습니다. 다시 시도해주세요" 메시지

**확인 메시지:**
- 회원가입 성공: "회원가입이 완료되었습니다!"
- 로그인 성공: "로그인되었습니다!"
- 추가 정보 저장: "정보가 저장되었습니다!"

**모달 닫기:**
- X 버튼: 모달 닫기
- 배경 클릭: 모달 닫기
- 완료/로그인/회원가입 버튼: 폼 제출 후 모달 닫기

---

### B5. 비로그인 사용자 정책

**접근 가능 기능:**
- 랜딩페이지 모든 섹션 조회
- 제휴 문의 폼 작성
- Studio 데모 신청
- 로그인/회원가입 모달 열기

**접근 제한:**
- Studio/Admin 대시보드 접근 불가 → 로그인 필요
- Tutoring 서비스 접근 불가 → 로그인 필요
- 학생 프로필 조회/수정 불가

---

### B6. 이용약관 및 동의 정책

**회원가입 필수 동의:**
- 이용약관 동의: 필수
- 개인정보 수집동의: 필수
- 마케팅 정보 수신 동의: 선택

**정보 수집:**
- 회원가입 시: 이메일, 사용자 타입, 인증 정보
- 회원가입/로그인 후: 추가 타입별 정보

**정보 사용:**
- 서비스 제공
- 고객 지원
- 서비스 개선 (선택 동의 시)

---

### B7. 로그인 후 워크플로우

**로그인 완료 직후:**
1. 세션 생성
2. 사용자 정보 조회
3. 필수 정보 확인
4. 누락된 정보가 있으면 추가 정보 입력 모달 열기
5. 추가 정보 입력 완료 후 대시보드 접근

**대시보드 접근:**
- 학습자: Tutoring 페이지로 이동
- 기관장: Studio/Admin 페이지로 이동

---

### B8. 데이터 보존 및 삭제 정책

**계정 정보 보존:**
- 회원가입 정보: 계정 삭제 시까지 보관
- 로그인 로그: 보안 감시 목적으로 일정 기간 보관
- 추가 정보: 업데이트되면 최신 정보로 덮어쓰기

**계정 삭제:**
- 사용자 요청 시 계정 삭제 가능
- 계정 삭제 후 개인정보 처리 방침에 따라 처리

## 향후 개선 사항

1. **2FA (2단계 인증)** - 보안 강화
2. **비밀번호 초기화** - "비밀번호 찾기" 기능
3. **이메일 확인** - 회원가입 후 이메일 검증
4. **프로필 수정** - 추가 정보 수정 기능
5. **로그아웃** - 세션 종료 기능
6. **회원 탈퇴** - 계정 삭제 기능
7. **소셜 계정 연결** - 기존 계정에 소셜 추가 연결
8. **리마인더** - 로그인/가입 후 자동 튜토리얼
