# 기관 관리 시스템 (Institution Management)

## 1. 사용자 흐름 (User Flow)

### 1.1 기관 등록 흐름
```
기관 관리 페이지 → "+ 기관 등록" 버튼 → 기관 등록 페이지 → 필수 정보 입력 → 등록 → 관리 페이지로 이동
                 (/admin/institute)   (/admin/institute/register)
```

**세부 단계:**

1. **기관 관리 페이지 접근**
   - URL: `/admin/institute`
   - 등록된 기관 목록 조회
   - "+ 기관 등록" 버튼 우측 정렬

2. **기관 등록 페이지로 이동**
   - URL: `/admin/institute/register`
   - 제목: "기관 등록"
   - 신규 기관 등록 폼 표시

3. **필수 정보 입력**
   - 기관명 입력
   - 관리자 이메일 입력
   - 요금제 선택 (Starter, Pro, Enterprise)
   - 단가 입력 또는 선택
   - 최대 학생 수 입력
   - 계약 기간 선택
   - 상태 설정 (활성/휴회)

4. **등록 버튼 클릭**
   - 유효성 검사 수행
   - 기관 데이터 저장
   - 성공 메시지 표시
   - `/admin/institute`로 리다이렉트

5. **등록 완료**
   - 새로 등록된 기관이 목록에 추가
   - 상태는 선택한 값으로 설정

### 1.2 기관 정보 수정 흐름
```
기관 목록 → 기관 행의 "수정" 버튼 → 기관 수정 페이지 → 정보 수정 → 저장 → 관리 페이지로 이동
           (InstitutionTable)     (/admin/institute/[name]/edit)
```

**세부 단계:**

1. **기관 목록에서 수정 버튼 클릭**
   - 해당 기관의 정보 로드
   - 기관명 기반으로 수정 페이지 이동

2. **기관 수정 페이지 열기**
   - URL: `/admin/institute/{기관명}/edit`
   - 기존 기관 정보 표시

3. **정보 수정**
   - 관리자 이메일 수정
   - 요금제 변경
   - 단가 변경
   - 최대 학생 수 수정
   - 계약 기간 변경
   - 상태 변경 (활성 ↔ 휴회)

4. **저장 버튼 클릭**
   - 유효성 검사 수행
   - 수정된 데이터 저장
   - 성공 메시지 표시
   - `/admin/institute`로 리다이렉트

5. **변경 완료**
   - 기관 목록에 수정된 정보 반영

### 1.3 기관 검색 흐름
```
기관 목록 → 검색 필드 입력 → "검색" 버튼 클릭 → 필터링된 결과 표시
```

**검색 필드:**
- 기관명 검색
- 관리자 이메일 검색
- 요금제 필터
- 상태 필터
- 계약 기간 범위 검색

### 1.4 기관 상태 조회 흐름
```
기관 관리 페이지 → 통계 카드(InstitutionStatsCards) 확인 → 기관 현황 파악
               (전체 기관 수, 활성 기관, 휴회 기관 등)
```

## 2. 기능 정의 (Information Architecture)

### 2.1 기관 등록 기능

#### 기능명
**Institution Registration**

#### 목적
새로운 기관을 시스템에 등록하여 관리

#### 입력 (Input Parameters)
| 항목 | 타입 | 필수 | 제약사항 | 설명 |
|-----|-----|------|--------|------|
| name | string | ✓ | 2-100자 | 기관명 |
| adminEmail | email | ✓ | 유효한 이메일 형식 | 기관 관리자 이메일 |
| plan | enum | ✓ | 'Starter' \| 'Pro' \| 'Enterprise' | 구독 요금제 |
| unitPrice | string | ✓ | - | 단가 (예: "1.0만원" 또는 "협의 중") |
| maxStudents | number | ✓ | 1 이상 | 최대 학생 수 |
| contractPeriod | date | ✓ | 미래 날짜 | 계약 기간 |
| status | enum | ✓ | '활성' \| '휴회' | 기관 상태 |

#### 출력 (Output)
```json
{
  "success": true,
  "message": "기술학원이 등록되었습니다.",
  "data": {
    "name": "기술학원",
    "adminEmail": "admin@tech-academy.com",
    "plan": "Pro",
    "unitPrice": "1.0만원",
    "currentStudents": 0,
    "maxStudents": 350,
    "contractPeriod": "2025-12-01",
    "status": "활성",
    "statusColor": "green",
    "registeredAt": "2026-03-10T00:00:00Z"
  }
}
```

#### 유효성 검사
- name: 2자 이상 100자 이하
- adminEmail: 유효한 이메일 형식, 중복 불가
- plan: 정의된 요금제 값만 허용
- maxStudents: 1 이상의 정수
- contractPeriod: 미래 날짜만 허용
- status: '활성' 또는 '휴회'만 허용

#### 비즈니스 로직
1. 입력값 유효성 검사
2. 기관명 중복 확인
3. 관리자 이메일 중복 확인
4. 기관 데이터 저장
5. 기관 생성 완료
6. 관리 페이지로 리다이렉트

---

### 2.2 기관 수정 기능

#### 기능명
**Institution Update**

#### 목적
등록된 기관의 정보를 수정 및 관리

#### 입력 (Input Parameters)
| 항목 | 타입 | 필수 | 제약사항 | 설명 |
|-----|-----|------|--------|------|
| name | string | ✓ | 읽기 전용 | 기관명 (변경 불가) |
| adminEmail | email | ✓ | 유효한 이메일 형식 | 관리자 이메일 |
| plan | enum | ✓ | 'Starter' \| 'Pro' \| 'Enterprise' | 요금제 |
| unitPrice | string | ✓ | - | 단가 |
| maxStudents | number | ✓ | 1 이상 | 최대 학생 수 |
| contractPeriod | date | ✓ | 미래 날짜 | 계약 기간 |
| status | enum | ✓ | '활성' \| '휴회' | 기관 상태 |

#### 출력 (Output)
```json
{
  "success": true,
  "message": "기술학원이 수정되었습니다.",
  "data": {
    "name": "기술학원",
    "adminEmail": "admin@tech-academy.com",
    "plan": "Enterprise",
    "unitPrice": "협의 중",
    "currentStudents": 320,
    "maxStudents": 400,
    "contractPeriod": "2026-12-01",
    "status": "활성",
    "statusColor": "green",
    "updatedAt": "2026-03-10T14:30:00Z"
  }
}
```

#### 변경 제약사항
- **기관명**: 읽기 전용 (변경 불가)
- **현재 학생 수**: 읽기 전용 (변경 불가)
- **기타 필드**: 모두 수정 가능

#### 조건부 검증
- 새로운 maxStudents는 currentStudents보다 같거나 크야 함
- 계약 기간 변경 시 미래 날짜만 허용

### 2.3 기관 목록 조회 기능

#### 기능명
**Institution List View**

#### 목적
등록된 모든 기관의 현황을 조회 및 관리

#### 입력 (Filter/Search Parameters)
| 항목 | 타입 | 필수 | 설명 |
|-----|-----|------|------|
| name | string | × | 기관명 검색 |
| adminEmail | string | × | 관리자 이메일 검색 |
| plan | enum | × | 요금제 필터 |
| status | enum | × | 상태 필터 (활성/휴회) |
| contractPeriodStart | date | × | 계약 기간 시작일 |
| contractPeriodEnd | date | × | 계약 기간 종료일 |

#### 출력 (Table Columns)
| 컬럼명 | 타입 | 설명 |
|-------|-----|------|
| 기관명 | string | 등록된 기관명 |
| 관리자이메일 | string | 기관 관리자 이메일 |
| 요금제 | enum | Starter/Pro/Enterprise |
| 단가 | string | 추가 학생당 단가 |
| 현재학생수/최대학생수 | number | 학생 수 현황 |
| 계약기간 | date | 계약 기간 |
| 상태 | enum | 활성/휴회 (배지) |
| 작업 | button | 수정 버튼 |

#### 페이지네이션
- 기본 표시: 10개 항목/페이지
- 네비게이션: 이전/다음 페이지 버튼

#### 정렬
- 기관명 가나다순
- 계약 기간 최신순 (옵션)

### 2.4 기관 통계 조회 기능

#### 기능명
**Institution Statistics**

#### 목적
기관 현황의 주요 지표를 시각화

#### 출력 (Statistics Cards)
| 항목 | 계산식 | 설명 |
|------|--------|------|
| 전체 기관 수 | COUNT(*) | 등록된 모든 기관의 수 |
| 활성 기관 | COUNT(status='활성') | 현재 활성 상태의 기관 |
| 휴회 기관 | COUNT(status='휴회') | 휴회 중인 기관 |
| 총 학생 수 | SUM(currentStudents) | 모든 기관의 현재 학생 수 합계 |
| 전체 수용 인원 | SUM(maxStudents) | 모든 기관의 최대 수용 인원 |

### 2.5 기관 search/filter 기능

#### 기능명
**Institution Search & Filter**

#### 목적
기관 목록을 조건에 맞게 필터링 및 검색

#### 검색 필드
| 필드 | 타입 | 설명 |
|------|------|------|
| 기관명 | text | 기관명 부분 검색 (LIKE) |

- 함수: `handleSearch(filters)`
- 모든 필드는 선택사항
- AND 조건으로 필터링
- 결과는 테이블에 반영

## 3. 정책 (Policy & Business Rules)

### 3.1 기관 관리 정책

#### 기관명 정책
```
- 필수 입력 필드
- 길이: 2자 이상 100자 이하
- 특수문자 제한: 일부만 허용 (예: 점, 하이픈, 괄호)
- 중복 불가
- 등록 후 변경 불가 (고정값)
```

#### 관리자 이메일 정책
```
- 필수 입력 필드
- 유효한 이메일 형식 필수
- 중복 불가 (시스템 내 다른 관리자와 중복 불가)
- 수정 가능
```

#### 요금제 정책
```
요금제별 특성:

◆ Starter
  - 요금: 1.2만원/학생
  - 최대 학생 수: 200명 제한
  - 기본 기능 제공
  - 지원 시간: 평일 9:00-18:00

◆ Pro
  - 요금: 1.0만원/학생
  - 최대 학생 수: 무제한
  - 고급 기능 제공
  - 지원 시간: 평일 9:00-22:00

◆ Enterprise
  - 요금: 협의 중 (맞춤 요금)
  - 최대 학생 수: 무제한
  - 전체 기능 제공
  - 지원 시간: 24/7
  - 전담 계정 관리자 제공
```

#### 단가 정책
```
- 요금제별 기본 단가 설정
- Enterprise의 경우 "협의 중"으로 표시
- 수정 가능 (협정 변경 시)
```

#### 학생 수 관리 정책
```
- 현재 학생 수: 자동 계산 (읽기 전용)
  └─ 기관에 등록된 활성 학생의 수
- 최대 학생 수: 관리자 설정
  └─ 수정 시 현재 학생 수 이상으로만 설정 가능
- 초과 시 경고: 현재 수 > 최대 수일 경우 주의 메시지
```

#### 계약 기간 정책
```
- 필수 입력 필드
- 형식: YYYY-MM-DD
- 미래 날짜만 허용
- 만료일 당일까지 서비스 제공
- 만료 후 자동 조치:
  └─ 상태: 자동으로 '휴회'로 변경 (선택지 있음)
  └─ 학생 접근: 제한됨
```

#### 기관 상태 정책
```
상태 흐름:
활성 ↔ 휴회

├─ 활성 (Active)
│  └─ 정상적으로 서비스 제공 중
│  └─ 학생/강사 접근 가능
│  └─ 모든 기능 제공

└─ 휴회 (Inactive)
   └─ 일시적으로 서비스 중지
   └─ 학생/강사 접근 불가
   └─ 데이터는 보존됨
   └─ 재활성화 가능
```

### 3.2 기관 등록 정책

#### 중복 확인
```
기관명 체계:
- 기관명 중복 불가
- 관리자 이메일 중복 불가
- 두 기관이 동일한 관리자를 가질 수 없음
```

#### 초기값 설정
```
새 기관 등록 시:
- currentStudents: 0 (자동)
- status: 사용자 선택 (활성 또는 휴회)
- registeredAt: 등록 시간 (자동)
```

#### 검증 순서
1. 기관명 유효성 확인 (길이, 형식)
2. 기관명 중복 확인
3. 관리자 이메일 형식 검증
4. 관리자 이메일 중복 확인
5. 요금제 유효성 확인
6. 계약 기간 유효성 확인 (미래 날짜)
7. 최대 학생 수 유효성 확인 (양수)

### 3.3 기관 수정 정책

#### 수정 불가 필드
```
- 기관명: 변경 불가 (식별자)
- 현재 학생 수: 변경 불가 (자동 계산)
- 등록일: 변경 불가 (기준점)
```

#### 수정 가능 필드
```
- 관리자 이메일: 수정 가능 (중복 확인)
- 요금제: 수정 가능 (플랜 변경)
- 단가: 수정 가능
- 최대 학생 수: 수정 가능 (currentStudents 이상)
- 계약 기간: 수정 가능 (미래 날짜)
- 상태: 수정 가능 (활성 ↔ 휴회)
```

#### 수정 검증
```
변경 전후 데이터 비교:
- 실제 변경사항만 업데이트
- 변경 이력 기록
- 관리자 알림 (선택)
```

### 3.4 학생 수 관리 정책

#### 현재 학생 수 계산
```
공식: currentStudents = COUNT(학생이 활성 상태이고 기관과 연결됨)

자동 갱신 시점:
- 학생 등록 시 +1
- 학생 탈퇴 시 -1
- 학생 상태 변경 시 재계산
```

#### 수용 인원 초과 방지
```
if (currentStudents > maxStudents):
  - 경고 메시지: "최대 수용 인원을 초과했습니다."
  - 작업: 못하도록 제한하거나 경고만 표시 (설정에 따라)
  - 해결: maxStudents 증가 또는 학생 외전 필요
```

### 3.5 계약 관리 정책

#### 계약 기간 도래
```
만료일 30일 전: 관리자에게 갱신 알림
만료일 당일: 
  - 자동 상태 변경 알림 (수동 처리)
  - 또는 자동으로 '휴회' 변경
만료일 이후:
  - 서비스 제한
  - 학생 접근 차단
```

#### 계약 갱신 프로세스
```
1. 관리자가 새로운 계약 기간 설정
2. contractPeriod 업데이트
3. 상태 변경 (휴회 → 활성, 필요시)
4. 서비스 복구
```

### 3.6 요금제 변경 정책

#### Starter → Pro/Enterprise
```
- 최대 학생 수 제한 해제
- 요금 재계산
- 추가 기능 활성화
```

#### Pro/Enterprise → Starter
```
- 현재 학생 수 > 200일 경우: 경고
- 제한 기능 안내
```

#### Enterprise 특별 조건
```
- 보정: 전담 계정 관리자 지정
- 맞춤 기능 개발 가능
- SLA(Service Level Agreement) 체결
```

### 3.7 상태 변경 정책

#### 활성 → 휴회
```
상황:
- 관리자 임의 변경
- 계약 만료
- 과금 연체 (향후)

영향:
- 모든 학생 접근 차단
- 강사 접근 차단
- 데이터 보존
```

#### 휴회 → 활성
```
조건: 관리자 수동 활성화
영향: 즉시 서비스 복구

주의: 계약 기간 유효성 확인 필수
```

### 3.8 보안 정책

#### 접근 제어
- 기관 관리는 시스템 관리자 역할만 접근 가능
- `/admin/institute` 페이지는 인증된 관리자만 접근
- `/admin/institute/register` 페이지는 인증된 관리자만 접근
- `/admin/institute/[name]/edit` 페이지는 인증된 관리자만 접근

#### 감시 및 로깅
```
기록될 이벤트:
- 기관 등록 (기관명, 관리자, 등록자, 시간)
- 기관 정보 수정 (변경 필드, 변경 전후 값, 시간)
- 상태 변경 (이전 상태, 새 상태, 시간)
- 계약 기간 수정
- 요금제 변경
```

#### 데이터 보호
```
- 기관 정보는 암호화 보관
- 관리자 이메일 마스킹 (표시 시 부분 표시)
- 학생 정보 접근 권한 제한
```

## 4. 데이터 모델

### 4.1 Institution 인터페이스
```typescript
interface Institution {
  name: string                // 기관명 (PK)
  adminEmail: string         // 관리자 이메일
  plan: string              // 요금제 (Starter, Pro, Enterprise)
  unitPrice: string         // 단가 (예: "1.0만원", "협의 중")
  currentStudents: number   // 현재 학생 수 (자동 계산)
  maxStudents: number       // 최대 학생 수
  contractPeriod: string    // 계약 기간 (YYYY-MM-DD)
  status: string            // 상태 (활성, 휴회)
  statusColor: string       // 상태 색상 (green, orange)
}
```

### 4.2 테이블 스키마 (예)
```sql
CREATE TABLE institutions (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100) UNIQUE NOT NULL,
  adminEmail VARCHAR(255) UNIQUE NOT NULL,
  plan ENUM('Starter', 'Pro', 'Enterprise') NOT NULL,
  unitPrice VARCHAR(50) NOT NULL,
  currentStudents INT DEFAULT 0,
  maxStudents INT NOT NULL,
  contractPeriod DATE NOT NULL,
  status ENUM('활성', '휴회') DEFAULT '활성',
  registeredAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  created_by INT,
  updated_by INT
);
```
