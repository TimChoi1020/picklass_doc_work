## 문제 설명

기관 등록 폼 및 수정 폼에서 **회원 상태(status)**와 **계약 상태(contractStatus)**의 옵션값이 중복·혼용되어 구분이 불명확함.

### 현재 상태값 정의

| 구분 | 현재 옵션 | 코드 |
|------|-----------|------|
| 회원 상태 | 활성, 휴회, 정지, 탈퇴 | active, inactive, suspended, withdrawn |
| 계약 상태 | 협의중, 계약완료, **활성**, 만료, 해지 | negotiating, contracted, active, expired, terminated |

### 핵심 문제점

1. **값 중복**: `활성`이 회원 상태와 계약 상태 양쪽에 존재
   - DB 매핑: 둘 다 `active` 코드로 저장됨 → 어느 맥락의 활성인지 불명확
   - UI에서 사용자 혼란 유발 (회원 계정의 활성화 vs 계약의 진행 중 상태)

2. **잘못된 동기화 로직** (`register/page.tsx` L85-94, `[id]/edit/page.tsx` L121-130)
   ```typescript
   // 회원 상태 변경 시 → 계약 상태도 강제로 같은 값으로 변경
   if (name === 'status') {
     setForm((p) => ({ ...p, status: value, contractStatus: value }));
   }
   // 계약 상태가 MEMBER_STATUS_OPTIONS에 포함된 값이면 → 회원 상태도 변경
   if (name === 'contractStatus') {
     setForm((p) => ({ ...p, contractStatus: value, ...(MEMBER_STATUS_OPTIONS.has(value) ? { status: value } : {}) }));
   }
   ```
   - 두 상태는 독립적 개념인데 양방향 동기화가 걸려 있어 의도치 않은 값 변경 발생

3. **백엔드 매핑 테이블 혼용** (`packages/core/src/institution/institution.service.ts` L57-76)
   - `CONTRACT_STATUS_TO_CODE`에 회원 상태 전용 값(휴회, 정지, 탈퇴)까지 포함되어 있음
   - 단일 매핑 테이블로 두 상태를 처리하는 구조적 문제

## Day 2 이후 잔존 문제 분석 (2026-03-12)

### 근본 원인: DB `contractStatusCode` 단일 컬럼 한계

현재 `institutions` 테이블에는 상태 컬럼이 `contractStatusCode` 하나뿐이다.
이 컬럼 하나로 두 가지 독립적인 개념을 동시에 표현하려 하기 때문에 어떤 매핑을 해도 한쪽이 손실된다.

**충돌 시나리오 예시:**

| 사용자 입력 | 저장 결과 | 조회 결과 | 문제 |
|------------|-----------|-----------|------|
| 회원상태=휴회, 계약상태=계약중 | contractStatusCode='active' (계약중 우선) | 회원상태='활성' | 회원 상태 '휴회' 손실 |
| 회원상태=정지, 계약상태=협의중 | contractStatusCode='negotiating' (계약중 우선) | 회원상태='활성' (CODE_TO_MEMBER_STATUS 임의 매핑) | 회원 상태 '정지' 손실 |

**조회 오류 시나리오:**

DB에 `contractStatusCode='inactive'` (또는 'suspended', 'withdrawn')가 저장된 기관을 수정 폼에서 열면:
- `contractStatus = CODE_TO_CONTRACT_STATUS['inactive']` → `undefined` → raw `'inactive'` 반환
- 계약 상태 드롭다운 옵션에 `inactive`가 없으므로 → **드롭다운이 빈 상태로 로드됨** ❌

**Day 2 패치의 한계:**
- 매핑 레이블 변경 (`활성→계약중`)과 동기화 로직 제거는 표면적 수정
- `toSimpleResponse`에서 `CODE_TO_MEMBER_STATUS['negotiating'] = '활성'` 같은 **임의 파생 매핑**을 추가했는데, 이는 데이터 왜곡 (협의중 계약인데 회원 상태가 '활성'으로 표시)
- `updateSimple`에서 `contractStatus`가 있으면 `status`(회원 상태)는 여전히 **완전 무시됨**
