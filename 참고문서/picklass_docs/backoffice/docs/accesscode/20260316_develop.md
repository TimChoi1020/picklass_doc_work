## 상태 코드 불일치 분석

### 문서 스펙 (accesscode.md)
```
active    → 활성 (사용 중인 유효한 코드)
reserved  → 예약됨 (생성됨, 아직 배포 전)
used      → 사용됨 (모든 허용량 사용 완료)
expired   → 만료됨 (유효기간 만료)
```

### 현재 constants.ts
```
active     → 활성
inactive   → 비활성  ← 사용 중 (createBatch에서 초기값으로 사용)
suspended  → 정지    ← User 상태코드
withdrawn  → 탈퇴    ← User 상태코드
```

### 현재 서비스 실제 사용 코드
- 생성 시 기본값: `inactive`
- 활성화 시: `active`
- 목록 페이지 표시: `사용(active)` / `미사용(inactive)` 토글

### 결정: 현재 구현(active/inactive) 유지
> 문서 상태 코드(active/reserved/used/expired)는 향후 확장용이며, 현재 서비스는 active/inactive 2단계로 동작 중. 기존 DB 데이터와 서비스 로직 변경 최소화를 위해 active/inactive 유지.
> `ACCESS_CODE_STATUSES` 상수만 실제 사용 값으로 교체.

#### 2-2. 필터 연동

### Step 3. 상태 전환 실제 API 연동
**API:** `updateAccessCodeStatus(id, statusCode)`

#### 상태 전환 규칙
| 현재 상태 | 버튼 텍스트 | 전환 후 | 버튼 색 |
|----------|------------|---------|--------|
| `inactive` | 사용 전환 | `active` | 파랑 |
| `active` | 미사용 전환 | `inactive` | 회색 |
| 기타(`used`, `expired`) | - | - | 없음 |

#### 구현
```ts
const handleStatusToggle = async (id: string, currentStatus: string) => {
  const newStatus = currentStatus === 'active' ? 'inactive' : 'active';
  if (!confirm(`상태를 변경하시겠습니까?`)) return;
  await updateAccessCodeStatus(id, newStatus);
  // 목록 새로고침
};
```
