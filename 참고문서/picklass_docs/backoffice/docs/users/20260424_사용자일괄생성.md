## 1. 사용자 흐름 (User Flow)

### 1.1 일괄 생성 흐름
```
관리자
 → [사용자 관리] 페이지 (/admin/users)
 → "사용자 일괄 생성" 버튼 클릭
 → [아이디 일괄 생성] 페이지 (/admin/users/access-code)
 → 사용자 유형 선택 (강사/학생)
 → 소속 기관 선택
 → 생성할 아이디 개수 입력 (1~1000)
 → 고유코드 4자리 입력 (예: ABCD)
 → "생성" 버튼 클릭
 → 생성 완료 alert 표시
   "N개의 강사/학생 아이디가 생성되었습니다.\n초기 비밀번호는 아이디와 동일합니다."
 → /admin/users 로 이동
```

### 1.2 생성된 계정 로그인 흐름 (전제 조건 미구현)
```
사용자
 → 아이디 / 초기 비밀번호(=아이디) 로 로그인
 → [미구현] isTempPassword: true 이면 비밀번호 변경 화면으로 강제 리다이렉트
 → 비밀번호 변경 후 서비스 이용
```

## 2. IA 구조 및 기능 정의

### 2.1 사용자 일괄 생성 기능

**목적:** 기관 단위로 강사/학생 계정을 대량 생성하여 즉시 로그인 가능한 상태로 배포

**진입 경로:** `/admin/users` → "사용자 일괄 생성" 버튼 → `/admin/users/access-code`

#### 입력 (Input)
| 필드 | 타입 | 필수 | 제약 | 설명 |
|------|------|------|------|------|
| userType | `'teacher' \| 'student'` | ✓ | - | 사용자 유형 |
| institution | string (UUID) | ✓ | - | 소속 기관 ID |
| idCount | number | ✓ | 1 ~ 1000 | 생성할 계정 수 |
| customCode | string | ✓ | 4자리 대문자 | 이메일 고유코드 (예: `ABCD`) |

#### 자동 생성되는 값
| 항목 | 생성 규칙 |
|------|---------|
| userId | `{고유코드소문자}{3자리일련번호}@{고유코드소문자}.pick` (예: `abcd001@abcd.pick`) |
| password | userId와 동일 (임시, `isTempPassword: true`) |
| 일련번호 시작값 | 동일 도메인의 기존 사용자 수 + 1 (중복 방지) |
| registrationExpiry | 생성일 + 365일 |
| usagePeriodDays | 365 |
| statusCode (사용자) | `active` |
| statusCode (액세스코드) | `active` |

#### 출력 (Output)
- `AccessCodeResponse[]` (생성된 액세스코드 배열)
- 각 액세스코드에 `generatedUserId`, `generatedPassword` 포함
- 동시에 `users` 테이블에 계정 생성됨

## 3. 정책 (Policy / Business Rules)

### 3.1 비밀번호 정책 (변경)
- **초기 비밀번호 = 아이디** (예: `abcd001@abcd.pick`)
- `isTempPassword: true` 로 저장 → 첫 로그인 시 변경 강제 로직 필요 (미구현)
- 평문 비밀번호는 `access_codes.generated_password` 컬럼에 보관 (관리자 배포용)
- 해시(`bcryptjs`, salt 10)는 `users.password_hash` 에 저장

### 3.2 계정 활성화 정책 (변경)
- 일괄 생성 시 계정 즉시 `active` 상태로 생성
- 액세스코드 활성화 플로우(`activate()`) 없이도 로그인 가능
- 기존 activate 메서드는 별도 흐름에서 여전히 사용 가능

### 3.3 userId 중복 방지 정책 (신규)
- 생성 전 `users` 테이블에서 동일 도메인(`endsWith @{domain}`) 사용자 수 카운트
- 카운트 + 1 부터 일련번호 시작 → 재생성 시 충돌 방지
- 예: `abcd.pick` 도메인에 5명 존재 시 → 006번부터 생성

### 3.4 액세스코드 정책
- 체크박스 제거로 항상 액세스코드와 사용자 계정 동시 생성
- 액세스코드는 `access_codes` 테이블에 기록 (이력 관리 용도)
- 6자리 알파뉴메릭 코드, 중복 불가 (최대 100회 재시도 후 실패)

### 3.5 개수 제한 정책
- 최소 1개, 최대 1,000개 (UI 제한)
- 서비스 내부 처리 상한: `Math.min(Math.max(dto.count, 1), 100)` — **주의: 서비스가 100개로 클램핑 중**

## 4. 개발자 추가 작업 항목

### 4.1 [필수] isTempPassword 강제 변경 로직 구현
**설명:** 현재 `isTempPassword: true` 플래그가 저장되지만 아무 동작도 하지 않음  
**작업 위치:** 튜터링/스튜디오 서비스의 로그인 응답 처리 또는 미들웨어  
**구현 방향:**
```typescript
// 로그인 응답에서 isTempPassword 확인
if (loginResponse.isTempPassword) {
  router.push('/change-password'); // 비밀번호 변경 페이지로 강제 이동
}
```

### 4.2 [권장] 서비스 상한선 100개 → 1,000개 수정
**설명:** 프론트엔드는 1,000개까지 허용하지만, `createBatch()` 내부에서 `Math.min(..., 100)`으로 잘림  
**작업 위치:** `packages/core/src/access-code/access-code.service.ts:53`
```typescript
// 현재
const count = Math.min(Math.max(dto.count, 1), 100);
// 수정
const count = Math.min(Math.max(dto.count, 1), 1000);
```
단, 1,000개 생성 시 루프 내 DB 호출이 N+1 발생하므로 `createMany` 로 최적화 필요

### 4.3 [권장] alert() → toast/notification UI로 교체
**설명:** 현재 성공/실패 메시지를 `alert()`으로 표시 중  
**작업 위치:** `access-code/page.tsx:59, 62`

### 4.4 [선택] 생성 후 자격증명 Excel 내보내기
**설명:** 생성 결과(`generatedUserId`, `generatedPassword`)를 관리자가 배포할 수 있도록 Excel 다운로드 제공  
**API:** 생성 응답의 `AccessCodeResponse[]` 에 이미 데이터 포함됨, 프론트엔드에서 xlsx 처리 필요

## 8. DB/API 구조 (Data Contract)

### 8.1 API 엔드포인트

#### 사용자 일괄 생성
```
POST /access-codes
```

**Request Body (`CreateAccessCodeDto`):**
```typescript
{
  roleCode: 'teacher' | 'student';     // 사용자 유형
  institutionId: string;               // 기관 UUID
  count: number;                       // 생성 개수 (1~1000, 서비스 내부 상한 100)
  registrationExpiry: string;          // ISO date (현재: 생성일 +365일 고정)
  usagePeriodDays: number;             // 사용 기간 일수 (현재: 365 고정)
  statusCode?: string;                 // 액세스코드 상태 (현재: 'active')
  createUserSimultaneously?: boolean;  // 사용자 동시 생성 여부 (현재: true 고정)
  userIdPrefix?: string;               // 이메일 prefix (고유코드 소문자)
  userIdDomain?: string;               // 이메일 도메인 (예: 'abcd.pick')
}
```

**Response (`AccessCodeResponse[]`):**
```typescript
{
  id: string;
  code: string;                     // 6자리 액세스코드 (예: 'AB3C7X')
  institutionId: string;
  institutionName: string | null;
  roleCode: string;
  userId: string | null;            // 활성화 후 연결된 userId
  courseId: string | null;
  statusCode: string;               // 'active'
  registrationExpiry: string;       // 'YYYY-MM-DD'
  usagePeriodDays: number;
  usageStartDate: string | null;
  usageEndDate: string | null;
  generatedUserId: string | null;   // 생성된 이메일 아이디
  generatedPassword: string | null; // 생성된 임시 비밀번호 (평문)
  activatedAt: string | null;
  createdAt: string;
}[]
```

### 8.2 관련 DB 테이블

#### `access_codes` 테이블
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | string | PK |
| code | string | 고유 6자리 코드 |
| institution_id | string | FK → institutions |
| role_code | string | teacher / student |
| status_code | string | active / inactive |
| registration_expiry | datetime | 등록 만료일 |
| usage_period_days | int | 사용 기간 (일) |
| generated_user_id | string\|null | 생성된 userId (평문) |
| generated_password | string\|null | 생성된 비밀번호 (평문) |
| user_id | string\|null | 활성화 후 연결된 user UUID |
| activated_at | datetime\|null | 활성화 시각 |
| created_at | datetime | 생성 시각 |

#### `users` 테이블 (일괄 생성 시 추가되는 필드)
| 컬럼 | 값 | 설명 |
|------|-----|------|
| user_id | `{prefix}{index}@{domain}` | 이메일 형식 아이디 |
| password_hash | bcrypt(userId, 10) | 아이디와 동일한 값 해시 |
| status_code | `active` | 즉시 활성 |
| is_temp_password | `true` | 임시 비밀번호 표시 |
| name | userId 동일 | 초기 이름 (추후 변경 필요) |
