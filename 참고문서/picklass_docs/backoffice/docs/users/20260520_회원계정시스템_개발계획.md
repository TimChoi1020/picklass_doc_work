## 0. 배경 및 목표

### 현황

| 구분 | 현재 방식 | 문제점 |
|------|----------|--------|
| 메뉴 노출 제한 | `MenuItem.restrictedToEmails` — 이메일 하드코딩 | 확장 불가, 임시방편 |
| 역할 구분 | USER_ROLE: `system_admin`, `academy_admin`, `teacher`, `student` | `partner_admin`, `group_admin` 미분화 |
| 조직 계층 | `institutions` 단일 테이블 | Partner·Group 계층 없음 |
| 기관/사용자 관리 | 기관관리 ↔ 사용자관리 분리 | 소속 사용자를 두 메뉴에서 이중 관리 |
| 데이터 범위 제한 | 없음 | 모든 로그인 사용자가 전체 데이터 조회 가능 |

### 목표

1. `roleCode` 기반 메뉴 노출/숨김 + 라우트 접근 제한 (2-Tier 권한 모델)
2. 2-depth 메뉴 구조로 재편 (대메뉴 6개)
3. `institutions` 테이블 확장 — `type`·`parent_id` 추가로 Partner·Group·Institution 계층 통합
4. `users.institution_id` 유지 — partner_admin·group_admin도 institutions 레코드 id 사용
5. 조직 상세 ↔ 사용자 관리 양방향 연계 UI
6. API 레이어 데이터 범위 제한 기반 마련 (org hierarchy 기반)

| 현재 코드 | 신규 코드 | UI 명칭 | 소속 조직 레벨 | 비고 |
|----------|---------|--------|--------------|------|
| `system_admin` | `system_admin` | 시스템관리자 | 없음 (Platform) | 유지 |
| _(없음)_ | `partner_admin` | 파트너 담당자 | Partner | 신규 |

| `teacher` | `teacher` | 강사 | Institution | 유지, 백오피스 미접근 |

## 2. DB 설계 — institutions 테이블 확장

### 2-1. 설계 결정

`institutions` 테이블에 `type`과 `parent_id` 두 컬럼만 추가해 Partner·Group·Institution 계층을 하나의 테이블에서 표현한다.  
`users.institution_id`는 **변경 없음** — partner_admin·group_admin도 자신의 institutions 레코드 id를 그대로 사용한다.

```
institutions (type='partner',     parent_id=null)
  └── institutions (type='group',       parent_id=partner.id)
        └── institutions (type='institution', parent_id=group.id)  ← 기존 레코드
```

> Partner 없는 Group, Group 없는 Institution 모두 parent_id=null로 허용.  
> 기존 모든 institution 레코드는 type='institution', parent_id=null로 자동 세팅됨.

### 2-2. Prisma 스키마 변경

```prisma
model Institution {
  id   String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid

  // ── 신규 추가 ──────────────────────────────
  type     String  @default("institution") @db.VarChar(20)
  // 'partner' | 'group' | 'institution'
  parentId String? @map("parent_id") @db.Uuid

  // ── 가입정보 (유지) ────────────────────────
  name                String  @db.VarChar(200)
  adminEmail          String  @default("") @map("admin_email") @db.VarChar(255)
  institutionTypeCode String? @map("institution_type_code") @db.VarChar(50)
  // nullable로 변경 — partner·group에는 불필요
  contactName         String  @map("contact_name") @db.VarChar(100)
  contactPhone        String  @map("contact_phone") @db.VarChar(20)
  contactEmail        String? @map("contact_email") @db.VarChar(255)
  statusCode          String  @default("active") @map("status_code") @db.VarChar(20)
  // memberStatusCode rename → statusCode (단순화)

  // ── 시스템 (유지) ──────────────────────────
  createdAt DateTime  @default(now()) @map("created_at") @db.Timestamptz
  updatedAt DateTime  @updatedAt @map("updated_at") @db.Timestamptz
  deletedAt DateTime? @map("deleted_at") @db.Timestamptz

  // ── Relations ─────────────────────────────
  parent   Institution?  @relation("InstitutionHierarchy", fields: [parentId], references: [id])
  children Institution[] @relation("InstitutionHierarchy")
  users       User[]
  accessCodes AccessCode[]
  courses     Course[]

  @@index([type])
  @@index([parentId])
  @@index([statusCode])
  @@map("institutions")
}
```

### 2-4. 마이그레이션 SQL

```sql
-- ① institutions 계층 컬럼 추가
ALTER TABLE institutions
  ADD COLUMN type      VARCHAR(20) NOT NULL DEFAULT 'institution',
  ADD COLUMN parent_id UUID REFERENCES institutions(id);

CREATE INDEX ON institutions(type);
CREATE INDEX ON institutions(parent_id);
-- 기존 데이터: type='institution', parent_id=null 자동 세팅됨

-- ② member_status_code → status_code rename
ALTER TABLE institutions RENAME COLUMN member_status_code TO status_code;

-- ③ 삭제 대상 컬럼 DROP (부가정보)
ALTER TABLE institutions
  DROP COLUMN IF EXISTS branch_count,
  DROP COLUMN IF EXISTS operation_type_code,
  DROP COLUMN IF EXISTS current_students;

-- ④ 삭제 대상 컬럼 DROP (라이선스 & 요금제)
ALTER TABLE institutions
  DROP COLUMN IF EXISTS plan_code,
  DROP COLUMN IF EXISTS unit_price,
  DROP COLUMN IF EXISTS price_per_student,
  DROP COLUMN IF EXISTS base_students,
  DROP COLUMN IF EXISTS max_students,
  DROP COLUMN IF EXISTS max_admin_accounts,
  DROP COLUMN IF EXISTS monthly_price,
  DROP COLUMN IF EXISTS billing_cycle_code,
  DROP COLUMN IF EXISTS annual_discount_rate,
  DROP COLUMN IF EXISTS api_integration_fee,
  DROP COLUMN IF EXISTS tech_support_fee,
  DROP COLUMN IF EXISTS content_ip_fee,
  DROP COLUMN IF EXISTS notes;

-- ⑤ 삭제 대상 컬럼 DROP (계약 기본 정보)
ALTER TABLE institutions
  DROP COLUMN IF EXISTS contract_status_code,
  DROP COLUMN IF EXISTS contract_start_date,
  DROP COLUMN IF EXISTS contract_end_date,
  DROP COLUMN IF EXISTS is_auto_renewal,
  DROP COLUMN IF EXISTS renewal_conditions;

-- ⑥ index 정리 (삭제된 컬럼의 인덱스 제거)
DROP INDEX IF EXISTS institutions_plan_code_idx;
DROP INDEX IF EXISTS institutions_contract_status_code_idx;
DROP INDEX IF EXISTS institutions_member_status_code_idx;
CREATE INDEX ON institutions(status_code);
```

## 2-7. institution_settings 테이블 신규 추가

기관별 협의 내용(수업 시간 상한, 스피킹 옵션 기본값, 기능 플래그)을 관리하는 1:1 관계 테이블.  
Studio 과정 생성 시 `GET /institutions/:id/settings`로 조회해 form 초기값(pre-fill)으로 사용한다.

> `type='institution'`인 기관만 수업설정 탭 노출. partner·group에는 미노출.

### 2-7-1. Prisma 스키마

```prisma
model InstitutionSettings {
  id            String  @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  institutionId String  @unique @map("institution_id") @db.Uuid

  // ① 수업 시간 상한 — Studio 과정 생성 시 초과 불가
  // 전체 수업 최대시간 프리셋: 5 / 10 / 15 / 20 / 25 / 30 / 35 / 40 / 45 / 50 (분)
  maxTotalClassMinutes Int?  @map("max_total_class_minutes")
  // FRT 모듈 최대시간 프리셋: 5 / 10 / 15 / 20 / 25 / 30 (분)
  maxFrtModuleMinutes  Int?  @map("max_frt_module_minutes")

  // ② 이수조건 기본값 — Studio 과정 생성 시 pre-fill (null = 해당 조건 체크 해제)
  defaultCompletionSentences  Int?  @map("default_completion_sentences")   // 발화량(문장 수)
  defaultCompletionLessonRate Int?  @map("default_completion_lesson_rate") // 레슨이수율(%)
  defaultCompletionMinutes    Int?  @map("default_completion_minutes")     // 누적 수업시간(분)

  // ③ 기능 플래그
  freeLearningEnabled Boolean @default(false) @map("free_learning_enabled") // 나만의수업 허용 여부

  // ④ FRT 마이크 모드 설정
  // 기관이 허용하는 마이크 모드 목록 — Studio 과정 생성 시 목록에 없는 모드 버튼 비활성화 (최소 1개 필수)
  allowedMicModes   String[] @default(["push_to_talk", "hybrid", "always_on"]) @map("allowed_mic_modes")
  micModeUserChange Boolean  @default(true) @map("mic_mode_user_change")

  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz
  updatedAt DateTime @updatedAt     @map("updated_at") @db.Timestamptz

  institution Institution @relation(fields: [institutionId], references: [id])
  @@map("institution_settings")
}
```

### 2-7-2. 마이그레이션 SQL

```sql
CREATE TABLE institution_settings (
  id                             UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id                 UUID        UNIQUE NOT NULL REFERENCES institutions(id) ON DELETE CASCADE,
  max_total_class_minutes        INT,
  max_frt_module_minutes         INT,
  default_completion_sentences   INT,  -- null = 체크 해제
  default_completion_lesson_rate INT,  -- null = 체크 해제
  default_completion_minutes     INT,  -- null = 체크 해제
  free_learning_enabled          BOOLEAN     NOT NULL DEFAULT FALSE,
  allowed_mic_modes              TEXT[]      NOT NULL DEFAULT ARRAY['push_to_talk', 'hybrid', 'always_on'],
  mic_mode_user_change           BOOLEAN     NOT NULL DEFAULT TRUE,
  created_at                     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at                     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 기존 institution 레코드에 기본값 레코드 일괄 생성
INSERT INTO institution_settings (institution_id)
SELECT id FROM institutions WHERE type = 'institution' AND deleted_at IS NULL;
```

### 2-7-3. 기관 상세 [수업설정] 탭 UI (Phase 4)

| FRT 마이크 모드 | 학습자 변경 허용 | 체크박스 |

### 2-7-4. Studio 연동 API

```
GET /institutions/:id/settings   → Studio 과정 생성 form pre-fill용
```

**Studio 적용 규칙 요약**:

| 기관 설정 | Studio 과정 생성 시 적용 방식 |
|----------|----------------------------|
| `maxTotalClassMinutes` | 레슨 수 × 레슨당 시간 합산 초과 시 경고 |
| `maxFrtModuleMinutes` | FRT 프리셋 중 max 이하만 버튼 활성화 |
| `defaultCompletionSentences` | Option C 발화량 초기값. null이면 체크 해제 상태 |
| `defaultCompletionLessonRate` | Option C 레슨이수율 초기값. null이면 체크 해제 상태 |

## 5. 회원계정 시스템 연계

### 5-1. users 테이블 — 변경 없음

`users.institution_id`는 **변경하지 않는다**. partner_admin·group_admin도 자신이 속한 institutions 레코드의 id를 `institution_id`로 가진다.

| roleCode | institution_id 의미 |
|---------|-------------------|
| `system_admin` | null (플랫폼 전체 관리) |
| `partner_admin` | 자신의 Partner 레코드 id (type='partner') |
| `group_admin` | 자신의 Group 레코드 id (type='group') |
| `academy_admin` | 자신의 Institution 레코드 id (type='institution') |

### 5-2. 역할별 계정 생성 방식 (확정)

모든 관리자 계정은 **해당 조직 등록 폼에서 동시에 생성**한다. 기존 기관 등록 폼(`adminEmail` + `tempPassword` → academy_admin 계정 자동 생성)과 완전히 동일한 패턴을 파트너·그룹에도 적용한다.

| 역할 | 계정 생성 경로 | 계정 수정 경로 |
|------|--------------|--------------|
| `system_admin` | 시스템 > 시스템관리자 계정 (`/admin/system/admins`) | 동일 페이지 또는 사용자 계정 |
| `partner_admin` | 조직관리 > 조직 등록 (`/admin/institute/register`) → RADIO: 파트너 선택 | 사용자 관리 > 사용자 계정 |
| `group_admin` | 조직관리 > 조직 등록 (`/admin/institute/register`) → RADIO: 그룹 선택 | 사용자 관리 > 사용자 계정 |
| `academy_admin` | 조직관리 > 조직 등록 (`/admin/institute/register`) → RADIO: 기관 선택 | 사용자 관리 > 사용자 계정 |
| `teacher` | 사용자 관리 > 사용자 계정 > **강사/교사 등록** 버튼 | 사용자 관리 > 사용자 계정 |
| `student` | 사용자 관리 > 사용자 계정 > **학생/임직원 등록** 버튼 | 사용자 관리 > 사용자 계정 |

**조직 등록 폼 구성** (단일 페이지 `/admin/institute/register`):

모든 조직 유형(파트너·그룹·기관)을 하나의 페이지에서 등록한다. 페이지 최상단에 유형 선택 박스를 배치하고, 유형에 따라 상위 조직 콤보박스가 표시된다.

```
[조직 유형 선택 — HARD(type·parentId API 연동 전)]
  ○ 파트너  ○ 그룹  ○ 기관   (role에 따라 옵션 필터링)

  상위 파트너 [콤보박스 — HARD]   ← 그룹 선택 시 표시
  상위 그룹   [콤보박스 — HARD]   ← 기관 선택 시 표시

1. 가입정보 (기관명, 담당자, 상태 등)
```

**role별 유형 선택 범위 및 상위 조직 콤보박스 동작**

| role | RADIO 옵션 | 상위 파트너 콤보박스 | 상위 그룹 콤보박스 |
|------|-----------|------------------|--------------------|
| `system_admin` | 파트너·그룹·기관 | 그룹 선택 시 전체 파트너 목록 | 기관 선택 시 전체 그룹 목록 |
| `partner_admin` | 그룹·기관 | 그룹 선택 시 자기 파트너 고정(비활성) | 기관 선택 시 전체 그룹 선택 가능 |
| `group_admin` | 기관 고정(비활성) | 표시 안 함 | 자기 그룹 고정(비활성) |
| `academy_admin` | — (등록 권한 없음) | — | — |

**Backend**: `POST /institutions` 엔드포인트에 `type` 파라미터(`partner` | `group` | `institution`) 추가. type에 따라 관리자 계정의 `role_code`를 자동 결정 (`partner` → `partner_admin`, `group` → `group_admin`, `institution` → `academy_admin`).

### 5-3. JWT payload 명세

로그인 성공 시 발급하는 JWT에 포함될 클레임:

```typescript
interface JwtPayload {
  sub: string;          // users.id (UUID)
  userId: string;       // users.user_id (로그인 ID)
  roleCode: string;     // users.role_code
  institutionId: string | null; // users.institution_id
  name: string;
}
```

> `institutionId`는 OrgScopeGuard에서 산하 조직 목록을 계산할 때 사용.  
> ✅ JWT 포함 확인 완료 — `roleCode`·`institutionId` 모두 포함됨 (변경 불필요).

### 5-4. AuthUser 타입 (packages/types)

```typescript
export interface AuthUser {
  id: string;
  userId: string;
  email: string | null;
  name: string;
  roleCode: string;             // 사이드바 필터링 + AdminRoleGate에서 사용
  institutionId: string | null; // OrgScopeGuard 데이터 범위 산정
}
```

현재 이미 `roleCode`·`institutionId` 포함 — **변경 없음**.

#### 조직관리 페이지 UI 설계

**검색 필터 — 소속 범위 고정 방식**

역할에 따라 필터 필드를 숨기는 대신, 자신의 소속 조직명을 미리 입력한 상태로 비활성화한다.

```
필드:  역할(파트너/그룹/기관) | 상위 파트너 | 상위 그룹 | 기관명 | 아이디

system_admin
  상위 파트너  [              ]  입력 가능
  상위 그룹    [              ]  입력 가능

partner_admin
  상위 파트너  [ ABC 파트너   ]  🔒 비활성 (자기 파트너 고정)
  상위 그룹    [              ]  입력 가능

group_admin
  상위 파트너  [ ABC 파트너   ]  🔒 비활성 (소속 파트너 고정)
  상위 그룹    [ 서울 그룹    ]  🔒 비활성 (자기 그룹 고정)

academy_admin
  상위 파트너  [              ]  입력 가능
  상위 그룹    [              ]  입력 가능
  (데이터는 자기 기관 소속만 표시)
```

- 비활성 필드 스타일: 배경색 `#f5f5f5`, 텍스트 `#999`
- 비활성 필드 툴팁: "내 소속 기준으로 고정됩니다"
- 역할 필터: `partner_admin`은 '파트너' 옵션 제외, `group_admin`은 '파트너'·'그룹' 옵션 제외

**등록 버튼**

```
system_admin  → [+ 조직 등록]  (등록 페이지에서 파트너·그룹·기관 RADIO 선택)
partner_admin → [+ 조직 등록]  (등록 페이지에서 그룹·기관 RADIO 선택)
group_admin   → [+ 조직 등록]  (등록 페이지 진입 시 기관 고정)
academy_admin → (등록 버튼 없음 — 조직 등록 권한 없음. 조직관리 메뉴 자체는 접근 가능)
```
