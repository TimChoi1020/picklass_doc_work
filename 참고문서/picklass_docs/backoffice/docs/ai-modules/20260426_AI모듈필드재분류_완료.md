## 1. 사용자 흐름

### 관리자 (백오피스)

```
AI 모듈 등록/수정 폼
  └─ 탭1: 기본 정보 (skill, code, name, purpose)
  └─ 탭2: 커리큘럼 배치 (passageExposure, cognitiveLevel, ...)
  └─ 탭3: 문항 설계 (answerType, scoringMode, questionCount, hintTypes[])
  └─ 탭3.5: 문항 설계2 (retryScope, inputLanguage, passageRole, questionMaxAttempts)
  └─ 탭4: 성과 KPI
  └─ 탭5: AI 동작 설정 (passageMode, questionFlowMode, pedagogyInstruction)
```

- **hintTypes**: 다중 선택 체크박스 (String[] — 쉼표 구분 CSV 아님)
- **passageMode**: 5개 값 중 선택 (`full / hidden / preview / timed-blur / timed-select`)
- **제거된 필드**: `passageExposureMode` (탭 UI에서 제거), `feedbackType` (탭 UI에서 제거)

### 학습자 (튜터링)

변경 없음. 필드 재분류는 내부 타입·흐름 정리로, 학습자 화면에는 직접 영향 없음.

## 3. 정책

### passageMode 값 정책

| 값 | 의미 | 해당 모듈 |
|---|---|---|
| `full` | 처음부터 전체 공개 (기본값) | SUM, QAR, SWR, RRD, PRD 등 |
| `hidden` | 지문 패널 없음 | WRD, WSD |
| `preview` | 첫 단락만 → 답변 후 전체 공개 | PRD |
| `timed-blur` | N초 전체 노출 → blur 처리 | SCN |
| `timed-select` | N초 후 문장 선택 모드 | (예정) |

> **이름 변경**: `preview-then-reveal` → `preview`, `timed-then-blur` → `timed-blur`  
> DB 마이그레이션: `UPDATE ai_modules SET passage_mode = 'preview' WHERE passage_mode = 'preview-then-reveal'`

### hintTypes 정책

- 빈 배열 `[]` 또는 `['none']` → 힌트 없음
- 복수 선택 가능 (e.g. `['syllable-guide', 'meaning-hint']`)
- `parseHintTypes(null | [])` → `['none']` (기본값)
- 유효한 HintType 값은 `agent-types.ts`의 `HintType` union 참조

### feedbackType 제거 정책

- 구형 contentConfig 스테이지 시스템 잔재 (`Slot/LLM/Button`) — 현재 Orchestrator에서 미사용
- `AiModuleData`, `RawAiModuleResponse`, DB 컬럼 모두 제거 완료

```typescript
  if (!raw || raw.length === 0) return ['none'];
```

```typescript
// ❌ 구형 값 (DB에서 마이그레이션 완료, 코드에서 사용 금지)
```

### 브릿지 코드 (GenericAdapter)

```typescript
// GenericAdapter.ts — passageMode → passageExposureMode 매핑
```

> `ModulePedagogyProfile`이 `passageExposureMode`를 유지하는 이유: `buildModuleFlags()`가 이 필드를 참조하며,

## 6. 기술부채 / 알려진 문제

### P1 — AiModuleFlags 계획 대비 구현 불일치

계획 문서에서 제안한 flags와 실제 구현된 flags가 다름:

| 계획 flags | 실제 구현 flags | 비고 |
|---|---|---|
| `passageVisible` | `isPassageHidden` | 반전 방향으로 구현 |
| `passageStartsPreview` | `isPassagePreview` | 이름만 다름 |
| `passageTimedBlur` | `isPassageTimedBlur` | 동일 의미 |
| `isPassiveModule` | (미구현) | CLR 전용 플래그 |
| `isAudioInput` | `isVoiceModule` | 이름 다름 |
| `isWritingInput` | (미구현) | |
| `isHolisticScoring` | (미구현) | `hasRightWrongConcept`(반전)으로 대체 |
| `isPronunciationScoring` | (미구현) | |
| `isSingleQuestion` | (미구현) | `isMultiQuestion`(반전)으로 대체 |
| `isContentDriven` | (미구현) | |

→ Orchestrator 규칙에서 여전히 `context.pedagogyProfile.scoringMode === 'holistic'` 등 직접 비교 남아 있음.

### P2 — passageExposureMode 브릿지 코드

`ModulePedagogyProfile`에 `passageExposureMode` 필드가 남아 있으며, `GenericAdapter`가 `passageMode → passageExposureMode`로 매핑.  
이 브릿지가 없어지면 `buildModuleFlags()`와 여러 규칙이 한 번에 변경되어야 함.

### P3 — seed.ts 데이터와 passageMode 값 동기화

`prisma/seed.ts`의 모듈 시드 데이터가 신규 `passageMode` 값을 반영하고 있는지 검증 필요.  
`preview-then-reveal` / `timed-then-blur` 구형 값이 남아 있으면 seed 실행 시 파서에서 기본값(`full`) fallback됨.

### P4 — `contentConfig` 내부 `feedbackType` 잔재

`contentConfig` JSONB에 `stage1Items[].feedbackType` 등 `feedbackType` 키가 여전히 포함됨.  
이는 레거시 스테이지 시스템의 구성 데이터로, 현재 Orchestrator는 읽지 않지만 DB 및 코드에서 완전 제거되지 않은 상태.
