## 1. 사용자 흐름 (User Flow)

### 1-1. 모듈 등록/수정 공통 흐름
1. `/admin/ai-modules/register` 진입
   - `?id=` 파라미터 있음 → 수정 모드: `getAiModule(id)` 호출로 기존 데이터 로드
   - 파라미터 없음 → 신규 등록 모드
2. 페이지 진입 시 `getAllCodes()` 호출 → 전체 코드 그룹을 `codeMap`으로 변환 (SKILL, PASSAGE_MODE, QUESTION_FLOW_MODE, LEARNING_OBJECTIVES 등 포함)
3. 탭 6개를 통해 설정 입력:
   - **기본 정보** → **커리큘럼 배치 설정** → **문항설계(QuestionData)** → **문항설계2** → **성과KPI설정** → **AI 동작 설정**
4. [저장] 클릭 → `createAiModule()` 또는 `updateAiModule()` API 호출
5. 성공 시 `/admin/ai-modules` 목록으로 이동

### 1-2. 학습 목적(learningObjectives) 입력 흐름
- 위치: **문항설계(QuestionData)** 탭 하단
- `codeMap['LEARNING_OBJECTIVES']` 에서 항목 로드 (DB 연동, 22개)
- 선택된 항목: 보라색 테두리 + 연보라 배경으로 시각적 구분
- 선택 해제: 다시 클릭하면 배열에서 제거
- 저장 시 `formData.learningObjectives: string[]` (항목의 `name` 값) 형태로 API 전달

## 3. 정책 (Policy / Business Rules)

### 3-1. learningObjectives 정책
- 복수 선택 가능 (0개 이상)
- 저장 시 선택된 `name`(한국어) 문자열 배열로 DB에 저장 (`String[]`)
- 미선택 시 빈 배열(`[]`)로 저장 — `null` 아님
- 선택지는 `LEARNING_OBJECTIVES` 코드 그룹으로 DB 관리 (백오피스 코드 관리 페이지에서 항목 추가/수정 가능)

### 3-2. 모듈 코드(code) 정책
- 자동 대문자 변환 처리 (입력 시 `.toUpperCase()`)
- 시스템 어댑터 등록 키와 반드시 일치해야 함
- 수정 불가 (수정 모드에서 disabled 처리 필요 여부 검토)

### 3-3. 필드 기본값 정책
- 모든 String 필드: `""` (빈 문자열) 기본값
- Array 필드(`roles`, `prerequisites`, `incompatibleWith`, `learningObjectives`): `[]` 기본값
- Int 필드(`questionMinCount`, `questionMaxCount`): `1` 기본값

## 5. 코드 규칙 (Coding Rules)

### 사용해야 하는 공통 유틸/컴포넌트
| 항목 | 위치 | 용도 |
|------|------|------|
| `fetchApi` (내부 `getAiModule`, `createAiModule` 등) | `src/lib/api.ts` | 모든 API 호출 |
| `getAllCodes` | `src/lib/api/code.ts` | 전체 코드 그룹 로드 → `codeMap` 변환 |
| `AiModuleResponse`, `CreateAiModuleDto`, `UpdateAiModuleDto` | `@repo/types` | 타입 정의 |

### 금지 패턴
- `any` 타입 사용 금지
- `@ts-ignore` 사용 금지
- 선택지 목록(학습 목적 등) 하드코딩 금지 → 코드 그룹 API 사용으로 이전 예정
- `alert()` 직접 사용 금지 (현재는 임시 허용, 교체 예정)
- Nullable 외래키 필드: 빈 문자열은 반드시 `null`로 변환 후 API 전달

### 파일 위치 규칙
- 타입 정의: `packages/types/src/index.ts`
- 비즈니스 로직: `packages/core/src/ai-module/ai-module.service.ts`
- API 함수: `apps/admin/frontend/src/lib/api.ts`
- 페이지: `apps/admin/frontend/src/app/(admin)/admin/ai-modules/`

### `packages/core` 수정 시 규칙
- `packages/core` 수정 후 반드시 `pnpm run build` 실행 후 백엔드 재시작
- `@repo/types` 수정 → `@repo/core` 수정 → 프론트엔드 사용 순서로 진행
