## 1. 배경 및 문제 정의

### 해결한 문제

| 구분 | 현황 (Before) | 해결 (After) |
|---|---|---|

## 2. 설계 결정 사항 (확정)

### 2-1. 통합 힌트 레벨 정의

```
Level 0 (사용자 요청, 선택적)
  트리거 : 힌트 버튼 클릭
  조건   : hints.button 존재 + 미답변 + 버튼 미사용 + questionMaxAttempts > 1
  방식   : hints.button 직접 표시 — LLM 호출 없음

Level 1 (오답 1회 감지, 자동)
  트리거 : 오답 제출 1회
  방식   : hints.direct 직접 표시 — LLM 호출 없음

Level 2 (오답 2회 감지, 자동) — 문항 종료
  트리거 : 오답 제출 2회 (힌트 버튼 사용 시 1회로 간주)
  방식   : q.answer 직접 표시 후 해당 문항 강제 완료
  표시   : "✅ 정답은 [answer]입니다. 다음 문항으로 넘어갑니다."
```

> **세션 중 LLM 호출**: 기존 최대 3회 → **0회**  
> 모든 힌트 데이터는 문항 생성 시(getOrGenerate) 사전 저장.

### 2-2. `hint String?` → `hints JsonB?` 필드 변경 (원안 대비 변경)

> **원안**: `hint` 컬럼 유지, `hints` 추가 후 `hints?.button ?? hint` fallback  
> **실제 구현**: Supabase에서 `hint` 컬럼 DROP, 코드에서 `hint` 필드 전면 제거  
> → fallback 로직 불필요, 코드 단순화

```json
{
  "button": "짧은 단서 (Level 0 버튼용, 정답 미노출)",
  "direct": "오답 후 방향 안내 (Level 1용, 1문장 구체적 안내)"
}
```

### 2-3. `module_questions` 필드 분리

| 필드 | 타입 | 의미 | extract | instruct |
|------|------|------|---------|----------|
| `instruction` | `String?` | 지시문 | ✅ | ✅ |
| `source` | `String?` | 추출 소재 (지문 발췌) | ✅ | ❌ (null) |
| `text` | `String` | 핵심 질문 본문 | ✅ | ✅ |

### 2-4. `questionMaxAttempts` 의미 재정의

- `null` / 빈값: 힌트 없음, 재시도 없음 (CLR 등)
- `1`: 단일 제출 후 AI 피드백 (GMN, PRD, SUM 등)
- `2`: 힌트 1회 + 오답 2회 후 정답 제시 (WRD, QAR 등)
- 백오피스 UI: `max=2` 제한. 기존 DB 값 3 등은 Orchestrator에서 `Math.min(attempts, 2)` clamp 처리.

## 3. 구현 완료 내역

### Phase 1 — DB 스키마 변경 ✅

Supabase `module_questions` 테이블에 수동 실행:

```sql
-- 신규 컬럼 추가
ALTER TABLE module_questions
  ADD COLUMN IF NOT EXISTS hints       JSONB,
  ADD COLUMN IF NOT EXISTS instruction TEXT,
  ADD COLUMN IF NOT EXISTS source      TEXT;

-- 기존 hint 컬럼 제거 (원안과 다름: 유지 대신 DROP)
ALTER TABLE module_questions
  DROP COLUMN IF EXISTS hint;
```

**캐시 무효화**: 기존 `hints = null` 레코드를 재생성하려면 아래 쿼리 실행:

```sql
-- 특정 모듈만 무효화 (권장)
UPDATE module_questions
SET status = 'archived'
WHERE module_id = '<moduleId>'
  AND status = 'active';

-- 전체 무효화 (주의: 첫 진입 시 Gemini 전량 재생성 → 비용 발생)
UPDATE module_questions
SET status = 'archived'
WHERE status = 'active';

-- 무효화 현황 확인
SELECT
  am.code,
  am.name,
  COUNT(*) FILTER (WHERE mq.status = 'active')   AS active_count,
  COUNT(*) FILTER (WHERE mq.status = 'archived') AS archived_count
FROM module_questions mq
JOIN ai_modules am ON mq.module_id = am.id
GROUP BY am.code, am.name
ORDER BY am.code;
```
