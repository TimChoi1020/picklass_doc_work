## 1. 개요

학습자의 **로그인 이력 기준** 출석률을 기관·학습자별로 조회하는 어드민 페이지.
이전 설계안(module_histories.started_at 기준)에서 **로그인 기준으로 변경**.

메뉴 경로: `통계 / 리포트 > 출석률` (`/admin/stats/attendance`)

---

## 2. 출석 정의

| 항목 | 내용 |
|---|---|
| 출석 기준 | 해당 날(KST) 1회 이상 로그인 |
| 출석률 공식 | `로그인 일수 / 조회기간 평일 수 × 100` |
| 조회기간 | `수강기간 ∩ 조회월` (교집합) |
| 평일 정의 | 월~금 (getDay() ≠ 0, 6) |
| 시간대 | DB: UTC, 화면 집계: KST (+9h) |

## 3. 신규 테이블: `user_login_logs`

### DDL 위치

```
tutoring.picklass.com/apps/api/prisma/manual-sql/2026-05-27_user_login_logs.sql
```

> **⚠️ DB 실행 필수**: 이 SQL을 Supabase Studio 또는 psql에서 **직접 실행해야** 기능이 동작한다.
> `prisma migrate` / `prisma db push` 사용 금지 (§15 정책).

### 스키마

```sql
CREATE TABLE user_login_logs (
  id              UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID         NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  institution_id  UUID         REFERENCES institutions(id) ON DELETE SET NULL,
  logged_in_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

### `app_code` 컬럼 추가 (2026-05-27) ✅ DB 실행 완료

tutoring / speaking 로그인을 구분하기 위한 컬럼.  
DDL 파일: `tutoring.picklass.com/apps/api/prisma/manual-sql/2026-05-27_alter_user_login_logs_app_code.sql`

```sql
ALTER TABLE user_login_logs ADD COLUMN app_code VARCHAR(20);
CREATE INDEX idx_ull_app_code ON user_login_logs(app_code, logged_in_at DESC);
```

### 인덱스

| 이름 | 컬럼 | 용도 |
|---|---|---|
| `idx_ull_user_id` | `user_id` | 학습자별 단순 조회 |
| `idx_ull_logged_in_at` | `logged_in_at DESC` | 날짜 범위 필터 |
| `idx_ull_user_date` | `(user_id, logged_in_at DESC)` | 학습자 × 기간 복합 조회 |
| `idx_ull_inst_date` | `(institution_id, logged_in_at DESC)` | 기관별 출석 집계 핵심 |
| `idx_ull_app_code` | `(app_code, logged_in_at DESC)` | 앱별 필터 + 날짜 범위 |

### INSERT 위치

#### tutoring: `tutoring.picklass.com/apps/api/src/auth/auth.service.ts`
#### speaking: `speaking.picklass.com/apps/api/src/auth/auth.service.ts`

두 서비스 모두 `login()` 메서드 내에서 `$executeRawUnsafe`로 INSERT.  
`app_code` 값은 각 서비스에서 하드코딩.

```typescript
// login() 안에서 users 테이블 SELECT 시 institution_id 포함
const rows = await this.prisma.$queryRawUnsafe<UserRow[]>(
  `SELECT id, email, name, role_code, institution_id, password_hash, status_code
   FROM users WHERE user_id = $1 AND deleted_at IS NULL LIMIT 1`,
  userId,
);
const user = rows[0];

// 로그인 이력 INSERT (app_code로 앱 구분)
await this.prisma.$executeRawUnsafe(
  `INSERT INTO user_login_logs (user_id, institution_id, app_code, logged_in_at)
   VALUES ($1::uuid, $2::uuid, $3, NOW())`,
  user.id,
  user.institution_id ?? null,  // 미소속(관리자 등)은 NULL
  'tutoring',                   // speaking에서는 'speaking'
);
```

**`institution_id` 출처**: 같은 `login()` 안의 `users` SELECT 결과(`user.institution_id`).  
학습자가 기관에 소속돼 있지 않은 경우(관리자 등) `NULL`이 저장된다.

> tutoring / speaking 스키마에는 `UserLoginLog` Prisma 모델이 없으므로 raw SQL 사용.  
> backoffice `prisma/schema.prisma`에는 `UserLoginLog` 모델이 추가됨.

### API 서버 재시작 필수

`auth.service.ts` 코드 변경은 **API 서버를 재시작해야 반영**된다.

```bash

```

## 5. API 스펙

### GET `/stats/attendance/institutions`

기관별 출석률 목록.

**Query params**

| 파라미터 | 타입 | 설명 |
|---|---|---|
| `institutionName` | string? | 기관명 부분 일치 |
| `courseId` | string? | 특정 과정 UUID |
| `yearMonth` | string? | YYYY-MM (기본값: 현재 월) |
| `appCode` | string? | `'tutoring'` \| `'speaking'` \| 미입력(전체) |

**Response**: `InstitutionAttendanceListResponse`

```typescript
{
  yearMonth: string;
  total: number;
  items: InstitutionAttendanceRow[];  // 기관별 집계
}
```

---

### GET `/stats/attendance/institutions/:institutionId/learners`

기관 내 학습자별 출석 현황.

**Path**: `institutionId` — 기관 UUID

**Query params**: `courseId?`, `yearMonth?`, `appCode?`

**Response**: `LearnerAttendanceListResponse`

```typescript
{
  institutionId: string;
  institutionName: string;
  yearMonth: string;
  learners: LearnerAttendanceRow[];
}
```

---

### GET `/stats/attendance/learners/:studentId/calendar`

학습자 월별 출석 캘린더.

**Path**: `studentId` — 학습자 UUID

**Query params**: `yearMonth?`, `appCode?`

**Response**: `LearnerAttendanceCalendarResponse`

```typescript
{
  studentId: string; studentName: string; yearMonth: string;
  usageStartDate: string | null; usageEndDate: string | null;
  days: AttendanceCalendarDay[];   // 해당 월 전체 날짜
  loginDays: number;
  weekdaysInPeriod: number;
  attendanceRate: number | null;   // 소수점 1자리, 0~100
}
```

## 9. 알려진 제약 / 향후 개선

- **과거 데이터 없음**: `user_login_logs` 기록 시작일 이전 로그인은 조회 불가. UI에 안내 표시 있음.
- **월 경계 KST 오차**: UTC 기준으로 월 범위를 잡으므로 KST 날짜 기준으로 첫날 00:00~09:00 KST 구간 로그 누락 가능. 실운영 영향 미미.
- **상위 파트너/그룹 필터 HARD**: institution 계층 구조 구현 후 제거.
- **tutoring schema**: tutoring `prisma/schema.prisma`에는 `UserLoginLog` 모델이 없음. 필요 시 tutoring repo에도 추가.
