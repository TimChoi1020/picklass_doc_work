## 배경 및 목표

픽클래스는 CEFR 기반 18단계 레벨 시스템(`A1-` ~ `C2+`)을 사용한다.  
B2B 파트너사(예: PAGODA)는 자체 레벨 체계를 사용하므로, 클라이언트 프로그램에서 학습자에게 레벨을 표시할 때 파트너의 레벨명으로 보여줄 필요가 있다.

### 픽클래스 18개 레벨 (고정 기준)

| 구분 | CEFR | Picklass Level |
|------|------|----------------|
| 고급 | C2 | C2+, C2, C2- |
| 고급 | C1 | C1+, C1, C1- |
| 중고급 | B2 | B2+, B2, B2- |
| 중급 | B1 | B1+, B1, B1- |
| 초중급 | A2 | A2+, A2, A2- |
| 초급 | A1 | A1+, A1, A1- |

### PAGODA 매핑 예시 (참고용)

| PAGODA Level | Picklass Level (해당) |
|-------------|----------------------|
| Proficient | C2+, C2, C2- |
| Fluent | C1+ |
| Upper Advanced | C1 |
| Advanced | C1-, B2+ |
| Lower Advanced | B2, B2- |
| Upper Intermediate | B1+ |
| Intermediate | B1, B1- |
| Lower Intermediate | A2+ |
| Beginner | A2, A2- |
| Basic | A1+, A1, A1- |

## 1. 설계 결정

### 1-1. 매핑 구조 (N:1)

픽클래스 레벨(N) → 파트너 레벨명(1)의 단방향 매핑.  
복수의 픽클래스 레벨이 동일한 파트너 레벨명을 가질 수 있다 (예: C2+, C2, C2- → "Proficient").  
`partnerLevelName`이 빈 문자열이면 픽클래스 레벨명 그대로 사용한다.

### 1-2. 적용 대상

`institutions.type = 'partner'` 레코드에만 레벨 매핑을 설정한다.  
산하 그룹·기관의 클라이언트에서 조회 시 상위 파트너 매핑을 상속받는다.

### 1-3. 저장 방식

신규 테이블 `partner_level_mappings` 사용 (JSON 컬럼 방식 대비 쿼리·인덱스 활용 용이).

## 2. DB 스키마 ✅

### 2-1. 마이그레이션 SQL

실행 파일: `picklass-backoffice/prisma/manual-sql/2026-06-05_partner_level_mappings.sql`

```sql
BEGIN;

CREATE TABLE IF NOT EXISTS partner_level_mappings (
  id                 UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  partner_id         UUID        NOT NULL REFERENCES institutions(id) ON DELETE CASCADE,
  picklass_level     VARCHAR(5)  NOT NULL,
  partner_level_name VARCHAR(100) NOT NULL DEFAULT '',
  created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(partner_id, picklass_level)
);

CREATE INDEX IF NOT EXISTS partner_level_mappings_partner_id_idx
  ON partner_level_mappings(partner_id);

COMMIT;
```

### 2-2. Prisma 모델 (prisma:pull 후 실제 반영 결과)

`picklass-backoffice/prisma/schema.prisma`

```prisma
model PartnerLevelMapping {
  id               String      @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  partnerId        String      @map("partner_id") @db.Uuid
  picklassLevel    String      @map("picklass_level") @db.VarChar(5)
  partnerLevelName String      @default("") @map("partner_level_name") @db.VarChar(100)
  createdAt        DateTime    @default(now()) @map("created_at") @db.Timestamptz(6)
  updatedAt        DateTime    @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(6)
  partner          Institution @relation(fields: [partnerId], references: [id], onDelete: Cascade, onUpdate: NoAction)

  @@unique([partnerId, picklassLevel])
  @@index([partnerId])
  @@map("partner_level_mappings")
}
```

`Institution` 모델에 relation 추가:

```prisma
levelMappings PartnerLevelMapping[]
```

## 3. API 설계 ✅

### 3-1. 엔드포인트

| Method | Path | 설명 | 권한 |
|--------|------|------|------|
| `GET` | `/institutions/:id/level-mappings` | 파트너의 18개 레벨 매핑 전체 반환 | 백오피스 로그인 |
| `PUT` | `/institutions/:id/level-mappings` | 18개 전체 upsert (partial 허용) | system_admin, partner_admin |
| `GET` | `/institutions/:id/level-mappings/effective` | 기관→그룹→파트너 상속 해소 후 최종 매핑 반환 | 클라이언트 앱 |

> **라우트 순서 주의**: NestJS에서 `/level-mappings/effective`가 `/level-mappings/:id`보다 먼저 등록되어야 한다. 현재 controller에서 `effective` 엔드포인트를 먼저 선언하여 처리.

### 3-2. 요청/응답 형식

**GET `/institutions/:id/level-mappings` 응답**
```json
{
  "partnerId": "uuid",
  "mappings": [
    { "picklassLevel": "A1-", "partnerLevelName": "Basic" },
    { "picklassLevel": "A1",  "partnerLevelName": "Basic" },
    { "picklassLevel": "A1+", "partnerLevelName": "Basic" },
    ...
  ]
}
```
미설정 레벨은 `partnerLevelName: ""`으로 반환 (18개 전체 항상 반환).

**PUT `/institutions/:id/level-mappings` 요청**
```json
{
  "mappings": [
    { "picklassLevel": "A1-", "partnerLevelName": "Basic" },
    { "picklassLevel": "A1",  "partnerLevelName": "Basic" },
    ...
  ]
}
```
partial 허용 — 포함되지 않은 레벨은 기존 값 유지.

**GET `/institutions/:id/level-mappings/effective` 응답**  
기관 ID를 받아 상위 파트너를 찾아 매핑 반환. 파트너 매핑이 없거나 레벨명이 빈 문자열이면 픽클래스 레벨명을 그대로 반환.
```json
{
  "source": "partner",
  "mappings": [
    { "picklassLevel": "A1-", "displayLevel": "Basic" },
    { "picklassLevel": "A1",  "displayLevel": "Basic" },
    { "picklassLevel": "C2+", "displayLevel": "C2+" },
    ...
  ]
}
```
`source: "default"` — 상위 파트너가 없거나 매핑이 없을 때.

### 3-3. 유효성 검사

`picklassLevel`은 아래 18개 값만 허용. 이외 값은 upsert 시 무시(skip).

```ts
const PICKLASS_LEVELS = [
  'A1-', 'A1', 'A1+', 'A2-', 'A2', 'A2+',
  'B1-', 'B1', 'B1+', 'B2-', 'B2', 'B2+',
  'C1-', 'C1', 'C1+', 'C2-', 'C2', 'C2+',
] as const;
```

## 6. 클라이언트(tutoring / speaking) 연동 (Phase C — 미시작)

### 6-1. 사용 방식

```ts
// 세션 시작 시 1회 조회 후 메모리 캐싱
const { mappings } = await fetchEffectiveLevelMappings(institutionId);

// 레벨 표시가 필요한 모든 곳에서
function displayLevel(picklassLevel: string): string {
  return mappings.find(m => m.picklassLevel === picklassLevel)?.displayLevel ?? picklassLevel;
}
```

### 6-2. 연동 위치 (향후 단계에서 결정)

- tutoring: 학습 현황 레벨 표시, 레포트 레벨 표시
- speaking: 홈 학습 현황, 발음 평가 결과 레벨 표시
