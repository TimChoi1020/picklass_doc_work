## 1. 배경 및 결정 사항

### 왜 Backoffice에서 관리하는가

신규 지문은 Studio 등록 시 `SpeakingCoreDataService.generateAll()`이 자동 실행된다.
기존 지문 소급 생성·모니터링은 **운영 도구** 성격이므로 Backoffice에서 일원화 관리한다.

| 대안 | 검토 결과 |
|------|----------|
| Studio UI 버튼 | 지문 단위 재생성은 가능하나 전체 현황 파악·일괄 처리 불가 |
| Studio API 크로스 콜 | 인증/CORS 복잡도 추가, 불필요한 의존성 |
| **Backoffice 직접 구현** ✅ | 같은 Supabase DB에 Prisma 직접 접근, `speaking_passage_prompts`도 이미 관리 중 |

### Studio 측 현황 (참고)

Studio API의 `POST /passages/:textId/core-data/generate`(개별 재생성)는 이미 구현 완료.
Backoffice는 이와 독립적으로 동일 DB에 직접 접근하는 구조로 구현한다.

## 2. 구현 범위

### 2-A 개별 재생성

특정 지문 1건의 `core_expressions` · `core_dialog`를 재생성한다.

### 2-B 일괄 재생성

`core_expressions IS NULL`인 지문 전체를 백그라운드로 순차 처리한다.

## 3. Backend (`packages/core` + `apps/admin/backend`)

### 3.1 의존성 추가

`packages/core/package.json`에 `@google/genai ^1.0.0` 추가.
(Studio·Tutoring과 동일 버전 고정)

### 3.2 `packages/core/src/speaking-core-data/` 신규 모듈

Studio의 `speaking-core-data.service.ts`를 그대로 이식한다.

```
packages/core/src/speaking-core-data/
  speaking-core-data.service.ts   ← generateAll / generateCoreExpressions / generateCoreDialog
  speaking-core-data.module.ts
```

**모듈 의존성**: `ConfigModule`, `PrismaModule`, `InstitutionModule` (조직 필터 Scope 해석용)

**추가 메서드**: `generateMissing(userId?: string)`
- `core_expressions IS NULL`인 texts 조회 (userId 필터 선택적)
- concurrencyLimit = 3 (Gemini 429 방지, `p-limit` 또는 수동 세마포어)
- 개별 실패는 로그만 남기고 나머지 계속 처리 (`Promise.allSettled` 패턴)
- 반환: `{ total: number; done: number; failed: number; failedIds: number[] }`

### 3.3 `apps/admin/backend/src/speaking-core-data/` 컨트롤러

```
GET  /speaking-core-data/texts
     → 전체 지문 목록 (core_expressions·core_dialog 존재 여부 포함)
     Query: page, limit, search, level, category, hasCoreData(all|missing|complete)
            partnerId?, groupId?, institutionId?  ← 조직 필터 (OrgFilter 연동)

POST /speaking-core-data/texts/:textId/generate
     Body: { force?: boolean }
     → 개별 재생성 (2-A). force=false: 이미 있으면 skip, force=true: 덮어쓰기
     Response: { textId, status: "started" | "skipped" }

POST /speaking-core-data/generate-missing
     → 일괄 재생성 (2-B). 즉시 반환 후 백그라운드 처리
     Response: { status: "started", totalCount: number }
```

### 3.4 응답 스키마 — 지문 목록

```ts
interface SpeakingTextRow {
  id: number;
  title: string;
  level: string | null;            // CEFR 레벨
  category: string | null;         // 장르 (UI에서 "장르"로 표시)
  word_count: number | null;       // 단어수
  text_type: 'A' | 'I' | 'T';    // AI원문 / 직접입력 / 쌍둥이
  created_at: string;
  has_core_expressions: boolean;   // core_expressions IS NOT NULL
  has_core_dialog: boolean;        // core_dialog IS NOT NULL
}
```

> **주제(topic) 필드 제거**: UI 컬럼 및 서비스 응답에서 제외. DB에는 남아 있음.

## 4. Frontend (`apps/admin/frontend`)

### 4.1 페이지 위치

```
app/(admin)/admin/speaking-core-data/page.tsx
```

사이드바 메뉴 위치: **콘텐츠 플랫폼** 하위 첫 번째 항목 — **지문 관리** (`/admin/speaking-core-data`)

```
콘텐츠 플랫폼
├── 지문 관리  ← 신규 (최상위)
├── 과정 목록
├── 액세스코드
└── 과정 카테고리
```

### 4.2 지문 목록 테이블

Studio 라이브러리 리스트와 동일한 필드 + 핵심데이터 생성 여부 컬럼 추가.

| 컬럼 | 내용 | 비고 |
|------|------|------|
| ID | texts.id | |
| 제목 | title | |
| 레벨 | level | CEFR 레벨 배지 |
| 장르 | category | |
| 단어수 | word_count | N단어 |
| 유형 | text_type | A/I/T 배지 |
| 생성일 | created_at | YYYY-MM-DD |
| **핵심표현** | has_core_expressions | ✅ / 생성 버튼 |
| **대화문** | has_core_dialog | ✅ / 생성 버튼 |

> **주제 컬럼 제거**: 불필요 필드로 판단, 제외.

### 4.3 핵심표현 · 대화문 컬럼 동작

| 상태 | 핵심표현 셀 | 대화문 셀 |
|------|------------|----------|
| 둘 다 있음 | ✅ | ✅ |
| 핵심표현만 없음 | **[생성]** 버튼 | ✅ |
| 둘 다 없음 | **[생성]** 버튼 | **[생성]** 버튼 |
| 핵심표현은 있고 대화문만 없음 | ✅ | **[생성]** 버튼 |

**[생성] 버튼 클릭 시**: `POST /speaking-core-data/texts/:textId/generate { force: false }` 호출
→ 완료 후 해당 행만 re-fetch하여 상태 갱신

### 4.4 필터 영역 (테이블 상단)

```
[ 상위 파트너 ▼ ] [ 상위 그룹 ▼ ] [ 소속 기관 ▼]   ← OrgFilter (접근권한 Scope 인프라)
[ 검색: 제목 ] [ 레벨 ▼ ] [ 핵심데이터: 전체 / 미생성만 / 생성완료 ▼ ]
```

- OrgFilter: `courses` 페이지의 `OrgFilter` 컴포넌트를 그대로 재사용 (cascading 선택 방식)
  - `partnerId → groupId → institutionId` 순으로 연동 해석 (`resolveSelectionScope` → `User.institutionId IN (...)` → `texts.user_id IN (...)`)
  - 지문 관리는 SYS ONLY 페이지이므로 roleScope=null (전체 접근); OrgFilter는 수동 검색 필터 역할
- **미생성만** 필터: 운영 시 가장 자주 사용하는 뷰 — 기본값으로 설정 권장
- 스타일: Tailwind 제거 → `card`, `card-header`, `table`, `btn btn-primary`, `btn btn-secondary` CSS 클래스 + `FILTER_INPUT` inline style (과정목록 패턴 일치)

### 4.5 일괄 생성 버튼 (테이블 하단)

```
[ 누락 핵심데이터 일괄 생성 (N건) ]
```

- N: 현재 필터 기준 `has_core_expressions = false`인 지문 수
- 클릭 시 confirm 다이얼로그: `"core_expressions가 없는 지문 N건을 일괄 생성합니다. 계속하시겠습니까?"`
- `POST /speaking-core-data/generate-missing` 호출
- 버튼이 즉시 **"생성 중..."** 상태로 전환, 진행상황은 주기적 폴링 (5초 간격)으로 목록 갱신

### 4.6 진행상황 표시 (1차 버전 — 단순 폴링)

별도 `async_tasks` 인프라 없이 1차 버전 구현:

```
일괄 생성 중... (완료 N / 전체 M건) [새로고침]
```

- 일괄 생성 API 호출 후 5초 간격으로 `GET /speaking-core-data/texts` 재조회
- 미생성 건수가 0이 되면 자동으로 폴링 종료 + 완료 토스트

> 추후 개선: SSE 또는 `async_tasks` 테이블 기반 실시간 진행률로 업그레이드
