1. 시스템 흐름

1-1. B2B 로그인 흐름 로그인 화면 제공: 파트너 → 픽클래스

파트너가 로그인 화면을 제공하고, 픽클래스는 그 화면으로 학습자를 redirect한다. 픽클래스는 비밀번호를 수신하지 않는다.

학습자: GET /auth/b2b/login?institutionCode=xxx
          ↓
tutoring:
  ① institutionCode → institution_id 해석
  ② 파트너 login_page_url 확인
  ③ state nonce 생성 → 단기 캐시 저장 (5분 TTL)
  ④ {login_page_url}?callback={callback_url}&institutionId={id}&state={nonce} 로 redirect

파트너 로그인 페이지 (파트너 제공):
  학습자 ID/PW 입력 → 파트너 자체 인증 처리 (픽클래스는 PW 알 수 없음)
  인증 성공 → auth_secret으로 HS256 JWT 서명 (exp: 5분)
  → GET {callback_url}?token={signed_jwt}&state={nonce} redirect
          ↓
tutoring callback (/auth/b2b/callback):
  ⑤ state 검증 (캐시 nonce 비교 후 소비, 불일치/재사용 시 400)
  ⑥ alg(HS256 고정)·서명(auth_secret) 검증
  ⑦ 시각(exp 만료·iat leeway)·jti(replay)·iss·institutionId 검증
  ⑧ 인증 검증 결과 로그 기록 (토큰·시크릿 마스킹)
  ⑨ 픽클래스 JWT 발급 (payload: institutionId, user_pk_id, userId, level, loginScope='institution')
  ⑩ 픽클래스 학습 화면으로 redirect

1-2. B2B 수강목록 조회 흐름 수강목록: 파트너 → 픽클래스

수강중·수강완료 강좌를 하나의 파트너 API로 실시간 조회한다.

학습자: GET /lessons/enrolled-courses
  header: JWT (institutionId, user_pk_id 포함)
          ↓
tutoring:
  ① 로컬 DB: INTERNAL 수강 목록 조회 (기존 쿼리 유지)
  ② loginScope = 'institution'이면:
       파트너 enrollment_endpoint 확인
       파트너 수강목록 API 호출 (수강중 + 수강완료 통합):
         GET {enrollment_endpoint}?user_pk_id={user_pk_id}
                ↓
       파트너 응답: { active: [{ course_id, completion_rate, ... }], completed: [...] }  ← 픽클래스는 소유하지 않음
                ↓
       호출 결과 로그 기록
       응답에서 픽클래스 courseId를 매핑하여 과정 정보 조회
  ③ INTERNAL + B2B(파트너 API 실시간 조회) 병합하여 반환

2. 파트너 API 표준 스펙

B2B 연동에 필요한 API 규격서. 제공 방향에 따라 구현 주체가 다르다.

섹션제공 방향구현 주체
§2-1 로그인 화면 제공파트너 → 픽클래스파트너가 구현 (로그인 페이지 + 서명 토큰 callback)
§2-2 수강목록 API (수강중·수강완료)파트너 → 픽클래스파트너가 구현
§2-3 학습 결과 조회 API픽클래스 → 파트너픽클래스가 구현

2-1. 로그인 화면 제공

파트너 → 픽클래스 (redirect 방식)

파트너가 로그인 페이지를 제공한다. 픽클래스가 그 페이지로 학습자를 redirect하고, 파트너가 자체 로그인을 처리한 후 서명된 토큰을 callback으로 전달한다. 픽클래스는 비밀번호를 수신하지 않는다.

Step 1 — 파트너 로그인 페이지 진입

GET {login_page_url}?callback={picklass_callback_url}&institutionId={institution_uuid}&state={nonce}
파라미터설명
callback픽클래스 callback URL (예: https://api.tutoring.picklass.com/auth/b2b/callback)
institutionId픽클래스 기관 UUID
stateCSRF 방지용 nonce — 픽클래스가 생성, 단기 캐시에 5분 저장

파트너는 이 URL에 GET 요청이 들어오면 자체 로그인 폼을 표시한다.
학습자 인증 실패 시 파트너는 callback 호출 없이 자체 오류 페이지를 표시한다.

Step 2 — 인증 완료 후 callback redirect

학습자 인증 성공 시 파트너가 픽클래스 callback URL로 redirect한다.

GET {picklass_callback_url}?token={signed_jwt}&state={nonce}

signed JWT payload (파트너가 auth_secret으로 HS256 서명):

{
  "iss": "partner-inst-001",              // 발급 파트너 식별자 (연동 설정과 대조)
  "institutionId": "inst-uuid-001",       // 픽클래스 기관 UUID (echo-back)
  "user_pk_id": "partner-internal-pk-001",
  "userId": "partner_user_001",
  "level": "B5(CEFR)",                      // 사용자 레벨 (로그인 후 학습 화면 표시용, 없으면 null)
  "jti": "0190e8c2-8f3a-7c41-b0a2-uuidv7", // 토큰 고유 ID (UUID v7, 1회성·replay 방지)
  "iat": 1716883200,                       // 발급 시각 (epoch sec)
  "exp": 1716883500                        // 만료 시각 — 발급 후 5분 이내
}
필드설명
iss발급 파트너 식별자 — 연동 설정의 등록 파트너와 대조
institutionId픽클래스 기관 UUID (echo-back)
user_pk_id파트너 시스템의 사용자 PK
userId파트너 시스템의 사용자 로그인 ID
level사용자 레벨 — 로그인 후 학습 화면 표시용 (예: LEVEL 5). 파트너가 레벨 체계를 운용하지 않으면 null
jti토큰 고유 ID (UUID v7) — exp 윈도우 내 재사용 거부 (replay 방지)
iat발급 시각 (epoch sec) — 시계 오차 leeway 내 검증
exp만료 시각 — 발급 후 5분 이내 필수

오류 코드 규격 (픽클래스 callback 기준):

codeHTTP의미 / 처리
STATE_INVALID400state 불일치·재사용 — CSRF·replay 의심, 로그 기록 후 거부
TOKEN_SIGNATURE_INVALID401auth_secret 불일치 — 서명 검증 실패
TOKEN_EXPIRED401exp 만료 — 재로그인 유도
TOKEN_TIMESTAMP_OUT_OF_WINDOW401iat가 허용 시계오차(leeway) 밖 — 미래 발급 토큰 거절
TOKEN_REPLAYED401exp 윈도우 내 동일 jti 재사용 — replay 차단
INSTITUTION_MISMATCH400iss·institutionId 불일치 — 위변조 의심
INSTITUTION_NOT_REGISTERED404등록되지 않은 institutionId / 연동 설정 없음

2-2. 수강목록 API (수강중 · 수강완료 강좌)

파트너 → 픽클래스

X-API-Key: {api_key}   ← 파트너가 요구하는 경우만

2-3. 학습 결과 조회 API

픽클래스 → 파트너 (파트너 Pull 방식)

픽클래스가 학습 결과 데이터를 제공하고, 파트너가 픽클래스 API를 호출하여 수집한다. 파트너는 이 데이터로 수강생의 이수 여부·성과를 직접 판단한다.

제공 방식

Pull 방식(RESTful 조회)으로 구현한다. Webhook은 구현 범위 외.

인증

모든 학습 결과 조회 API는 API Key 인증을 사용한다. 키는 고정 헤더 X-API-Key로 전달한다 (Authorization: Bearer 미사용).
API Key는 백오피스 시스템 > API키관리 (/admin/b2b/api-keys)에서 파트너사별로 발급·만료 관리한다.

X-API-Key: {apiKey}
항목내용
키 형식UUID v4 기반 랜덤 문자열
범위파트너 기관 단위 발급 — API Key로 기관 범위 자동 적용
만료백오피스에서 수동 만료 처리
갱신신규 발급 후 구키 만료 처리 (동시에 두 개 운용 가능, 전환 기간)

Pull API 스펙

백엔드 ↔ 백엔드 호출

학습 결과 조회 API는 파트너 백엔드 → 픽클래스 백엔드의 server-to-server 호출이다 (학습자 브라우저·앱 미경유). 따라서:

  • API Key(X-API-Key)는 파트너 백엔드에만 보관 — 프론트엔드·클라이언트에 노출 금지.
  • 브라우저 CORS와 무관. 필요 시 파트너 서버 IP allowlist로 접근을 추가 제한할 수 있다.
  • 응답 데이터는 파트너 백엔드가 수신·저장하며, 학습자 단말에 직접 전달되지 않는다.

Base URL: https://api.picklass.com

공통 Query Parameters (3개 엔드포인트 동일):

파라미터타입필수설명
startDatestring (ISO 8601)필수기간 시작일
endDatestring (ISO 8601)필수기간 종료일
userIdstring선택특정 회원 필터 (파트너 로그인 ID)
courseIdUUID선택특정 과정 필터

API Key로 파트너 기관 범위 자동 적용 — 타 기관 데이터 접근 불가.
userName은 제공하지 않음 — 파트너가 userId · userPkId 기준으로 자체 매핑.

3-3. 오류 처리 전략

상황동작
파트너 API 응답 없음 (timeout)로그 기록 후 ServiceUnavailableException
파트너 응답 4xx로그 기록 후 적절한 HTTP 오류로 변환
파트너 연동 설정 없음로그 기록 후 NotFoundException
수강목록 응답 빈 배열정상 처리 (active·completed·expired 빈 배열 반환)
verifyAuthCallback() 검증 실패 (state·서명·만료·institutionId)인증 로그에 success: false 기록 후 PartnerAuthException throw — HTTP 출처 없음 (로컬 검증)
