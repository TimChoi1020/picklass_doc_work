## 0. 배경 및 설계 원칙

### 기존 설계의 문제점

기존 설계는 **파트너가 픽클래스 API를 호출하는 PUSH 방식**이었다.

```
파트너: POST /api/b2b/enrollments  →  픽클래스 (수신 후 저장)
```

이 구조는 픽클래스가 파트너 회원 정보와 수강 내역을 **직접 소유**하는 것을 전제로 한다.

### 정정된 아키텍처

> **픽클래스는 파트너의 회원정보와 수강내역을 소유하지 않는다. 다만 API 호출 로그를 저장할 뿐이다.**

픽클래스가 **API 클라이언트**로서 파트너 API를 호출하는 **PULL 방식**이다.

```
픽클래스 (클라이언트)  →  파트너 API (서버)
```

필요한 API는 다섯 가지:

| 방향 | API | 호출 시점 |
|------|-----|---------|
| 픽클래스 → 파트너 | **로그인 인증 API** | B2B 로그인 시 |
| 픽클래스 → 파트너 | **수강목록 API** | 수강 화면 진입 시 |
| 픽클래스 → 파트너 | **이수 완료 Push** | 수강신청 이수 조건 충족 시 |
| 픽클래스 → 파트너 | **이전 학습내역 API** | 이전 학습내역 화면 진입 시 |
| 파트너 → 픽클래스 | **학습결과 API** | 파트너가 학습 결과 수집 시 (Pull) |

픽클래스 DB에는 원본 데이터를 저장하지 않고, 호출 결과를 **로그로만** 기록한다.

### 수강 방식 비교 (INTERNAL vs B2B)

| 항목 | INTERNAL (픽클래스 내부) | B2B 파트너 |
|------|------------------------|-----------|
| 수강 과정 수 | 1개 (`access_codes.course_id`) | N개 (파트너 API 실시간 응답) |
| 과정 옵션 | `courses` 테이블 기본 설정 사용 | 파트너 시스템이 보유 (픽클래스 DB 저장 안 함) |
| 인증키 | 6자리 `code` | 없음 (파트너 API 인증으로 대체) |
| 수강 데이터 저장 | `access_codes` DB 레코드 | `partner_enrollment_logs` API 호출 이력만 |
| 관리 화면 | `/admin/courses` + `/admin/accesscode` | `/admin/b2b/enrollments` (로그 조회) |

## 1. 시스템 흐름

### 1-1. B2B 로그인 흐름

```
학습자: GET /auth/b2b/login?institutionCode=xxx
          ↓
tutoring:
  ① institutions 테이블에서 institutionCode → institution_id
  ② partner_api_configs에서 login_page_url 확인
  ③ state nonce 생성 → 단기 캐시 저장 (5분 TTL)
  ④ {login_page_url}?callback={callback_url}&institutionId={id}&state={nonce} 로 redirect

파트너 로그인 페이지:
  학습자 ID/PW 입력 → 파트너 자체 인증 처리 (픽클래스는 PW 알 수 없음)
  인증 성공 → auth_secret으로 HS256 JWT 서명 (exp: 5분)
  → GET {callback_url}?token={signed_jwt}&state={nonce} redirect
          ↓
tutoring callback (/auth/b2b/callback):
  ⑤ state 검증 (캐시 nonce와 비교, 불일치 시 400)
  ⑥ JWT 서명 검증 (HS256, auth_secret)
  ⑦ JWT 만료·institutionId 검증
  ⑧ partner_auth_logs에 검증 결과 기록 (로그)
  ⑨ 픽클래스 JWT 발급 (payload: institutionId, user_pk_id, userId, loginScope='institution')
  ⑩ 픽클래스 학습 화면으로 redirect
```

### 1-2. B2B 수강목록 조회 흐름

```
학습자: GET /lessons/enrolled-courses
  header: JWT (institutionId, user_pk_id 포함)
          ↓
tutoring:
  ① 로컬 DB: INTERNAL 수강 목록 조회 (기존 쿼리 유지)
  ② loginScope = 'institution'이면:
       partner_api_configs에서 enrollment_endpoint 확인
       파트너 수강목록 API 호출:
         GET {enrollment_endpoint}?user_pk_id={user_pk_id}
                ↓
       파트너 응답: { enrollments: [{ enrollment_id, ... }] }  ← 픽클래스는 소유하지 않음
                ↓
       partner_enrollment_logs에 호출 결과 기록 (로그)
       응답에서 픽클래스 courseId를 매핑하여 과정 정보 조회
  ③ INTERNAL + B2B(파트너 API 실시간 조회) 병합하여 반환
```

## 2. DB 구조

### 2-1. partner_api_configs 테이블 (신규)

파트너별 API 엔드포인트 및 인증 설정을 저장한다.

```sql
CREATE TABLE partner_api_configs (
  id                   UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id       UUID        NOT NULL REFERENCES institutions(id),
  login_page_url       VARCHAR(500) NOT NULL,   -- 파트너 로그인 페이지 URL (redirect 대상)
  auth_secret          VARCHAR(500) NOT NULL,   -- JWT 서명 검증용 shared secret (HS256)
  enrollment_endpoint  VARCHAR(500) NOT NULL,   -- 수강목록 API URL
  completion_endpoint  VARCHAR(500),            -- 이수 완료 Push URL (nullable, 미설정 시 Push 생략)
  history_endpoint     VARCHAR(500),            -- 이전 학습내역 API URL (nullable)
  api_key              VARCHAR(500),            -- 픽클래스가 파트너에 전달하는 API 키 (파트너가 요구하는 경우)
  timeout_ms           INT         NOT NULL DEFAULT 5000,
  status_code          VARCHAR(20) NOT NULL DEFAULT 'active',  -- active | inactive
  created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (institution_id)
);
```

> **partner_api_keys 테이블과의 차이**:  
> `partner_api_keys`는 **파트너가 픽클래스 API를 호출할 때 사용하는 키** (파트너→픽클래스 방향, Phase G에서 구현 예정 — §5-3 참조).  
> `partner_api_configs`는 **픽클래스가 파트너 API를 호출할 때 필요한 설정** (픽클래스→파트너 방향, 본 Phase F 범위).

## 3. 파트너 API 표준 스펙

B2B 연동에 필요한 API 규격서. 방향에 따라 역할이 다르다.

| 섹션 | 방향 | 구현 주체 |
|------|------|---------|
| §3-1 로그인 인증 API | 픽클래스 → 파트너 | **파트너**가 구현 |
| §3-2 수강목록 API | 픽클래스 → 파트너 | **파트너**가 구현 |
| §3-3 이수 완료 Push | 픽클래스 → 파트너 | **파트너**가 구현 |
| §3-4 이전 학습내역 API | 픽클래스 → 파트너 | **파트너**가 구현 |
| §3-5 학습결과 조회 API | 파트너 → 픽클래스 | **픽클래스**가 구현 |

### 3-1. 로그인 인증 API

**픽클래스 → 파트너** (redirect 방식)

픽클래스가 파트너의 로그인 페이지로 학습자를 redirect한다. 파트너가 자체 로그인을 처리한 후 서명된 토큰을 callback으로 전달한다. **픽클래스는 비밀번호를 수신하지 않는다.**

#### Step 1 — 파트너 로그인 페이지 진입

```http
GET {login_page_url}?callback={picklass_callback_url}&institutionId={institution_uuid}&state={nonce}
```

| 파라미터 | 설명 |
|---------|------|
| `callback` | 픽클래스 callback URL (예: `https://api.tutoring.picklass.com/auth/b2b/callback`) |
| `institutionId` | 픽클래스 기관 UUID |
| `state` | CSRF 방지용 nonce — 픽클래스가 생성, 단기 캐시에 5분 저장 |

> 파트너는 이 URL에 GET 요청이 들어오면 자체 로그인 폼을 표시한다.  
> 학습자 인증 실패 시 파트너는 callback 호출 없이 자체 오류 페이지를 표시한다.

#### Step 2 — 인증 완료 후 callback redirect

학습자 인증 성공 시 파트너가 픽클래스 callback URL로 redirect한다.

```http
GET {picklass_callback_url}?token={signed_jwt}&state={nonce}
```

**signed JWT payload** (파트너가 `auth_secret`으로 HS256 서명):
```json
{
  "institutionId": "inst-uuid-001",
  "user_pk_id": "partner-internal-pk-001",
  "userId": "partner_user_001",
  "iat": 1716883200,
  "exp": 1716883500
}
```

| 필드 | 설명 |
|------|------|
| `institutionId` | 픽클래스 기관 UUID (echo-back) |
| `user_pk_id` | 파트너 시스템의 사용자 PK |
| `userId` | 파트너 시스템의 사용자 로그인 ID |
| `exp` | 만료 시각 — **발급 후 5분 이내** 필수 |

> 서명 알고리즘: **HS256**. `auth_secret`은 `partner_api_configs.auth_secret`에 저장된 shared secret.

#### 픽클래스 callback 검증 순서

```
① state 검증 — 캐시의 nonce와 비교 (불일치 시 400, CSRF 방지)
② JWT 서명 검증 — auth_secret으로 HS256 검증 (실패 시 401)
③ exp 검증 — 만료 여부 확인 (만료 시 401)
④ institutionId 검증 — 요청 기관과 일치 여부 확인 (불일치 시 400)
⑤ partner_auth_logs 기록
⑥ 픽클래스 JWT 발급 → 학습 화면 redirect
```

**오류 코드 규격** (픽클래스 callback 기준):

| 상황 | HTTP | 처리 |
|------|------|------|
| state 불일치 | 400 | CSRF 의심 — 로그 기록 후 거부 |
| JWT 서명 오류 | 401 | auth_secret 불일치 — 로그 기록 후 거부 |
| JWT 만료 | 401 | 재로그인 유도 |
| institutionId 불일치 | 400 | 위변조 의심 — 로그 기록 후 거부 |

### 3-2. 수강목록 API

**픽클래스 → 파트너**

```http
GET {partner_enrollment_endpoint}?user_pk_id={user_pk_id}
Authorization: Bearer {api_key}   ← 파트너가 요구하는 경우만
```

**Response (성공)**:
```json
{
  "enrollments": [
    {
      "enrollment_id": "partner-enroll-001",
      "enrolled_at": "2026-01-15T09:00:00Z",
      "expires_at": "2027-01-15T23:59:59Z",
      "status": "active",
      "course_scope": "SPECIFIC",
      "picklass_course_ids": ["uuid-a", "uuid-b"],
      "options": {
        "course_type": "MANDATORY_COURSE",
        "completion_criteria": {
          "utterance_goal": 300,
          "lesson_completion_rate": 0.8
        },
        "free_learning_enabled": false,
        "frt": {
          "termination_mode": "TIME",
          "termination_value": 900,
          "mic_mode": "PTT"
        }
      }
    },
    {
      "enrollment_id": "partner-enroll-002",
      "enrolled_at": "2026-03-01T00:00:00Z",
      "expires_at": null,
      "status": "active",
      "course_scope": "ALL",
      "picklass_course_ids": [],
      "options": null
    }
  ]
}
```

**응답 필드 설명**:

| 필드 | 타입 | 설명 |
|------|------|------|
| `enrollments` | array | 수강 목록 — 1명이 동시에 N개 보유 가능 |
| `enrollment_id` | string | 파트너 수강신청 고유 ID — 이수 완료 Push 시 echo-back 용도 |
| `course_scope` | string | `SPECIFIC` (지정 과정만) \| `ALL` (픽클래스 전체 과정) |
| `picklass_course_ids` | string[] | 수강 대상 픽클래스 과정 UUID 목록. `course_scope=ALL`이면 빈 배열 |
| `expires_at` | string \| null | nullable |
| `options` | object \| null | 수강신청 옵션. `null`이면 픽클래스 기본 설정 적용 |
| `options.course_type` | string | `MANDATORY_COURSE` (정해진 커리큘럼) \| `TOTAL_LESSON_COUNT` (수강 레슨 수 기준) |
| `options.completion_criteria.utterance_goal` | number | 이수 조건 — 목표 발화 횟수 |
| `options.completion_criteria.lesson_completion_rate` | number (0–1) | 이수 조건 — 레슨 이수율 (예: 0.8 = 80%) |
| `options.free_learning_enabled` | boolean | 나만의 수업(자유 학습) 진행 여부 |
| `options.frt` | object \| null | FRT 옵션. `null`이면 해당 수강에 FRT 모듈 없음 |
| `options.frt.termination_mode` | string | 학습 종료 조건 — `TIME` (시간) \| `TOKEN` (토큰) |
| `options.frt.termination_value` | number | 종료 조건 수치 — `TIME`: 초(sec), `TOKEN`: 개수 |
| `options.frt.mic_mode` | string | 마이크 모드 — `PTT` \| `HYBRID` \| `ALWAYS_ON` |

> `options.frt`는 해당 수강의 전체 FRT 모듈에 일괄 적용된다 (레슨 단위 개별 설정 없음).

**오류 코드 규격**:

| code | HTTP | 의미 |
|------|------|------|
| `MEMBER_NOT_FOUND` | 404 | 존재하지 않는 파트너 회원 |
| `NO_ENROLLMENT` | 200 | 수강신청 없음 (enrollments: []) |
| `INVALID_OPTIONS` | 400 | 옵션 값 규격 불일치 (`course_type` / `termination_mode` / `mic_mode` 허용값 외) |

### 3-3. 이수 완료 Push

**픽클래스 → 파트너** (수강신청 이수 조건 충족 시 자동 호출)

```http
POST {partner_completion_endpoint}
Content-Type: application/json
Authorization: Bearer {api_key}   ← 파트너가 요구하는 경우만
```

> `completion_endpoint`가 설정되지 않은 기관은 Push를 생략한다.  
> 이수 조건(`completion_criteria`) 충족 여부는 픽클래스가 판단한다.

**Request Body**:
```json
{
  "institutionId": "inst-uuid-001",
  "userPkId": "partner-internal-pk-001",
  "userId": "partner_user_001",
  "enrollmentId": "partner-enroll-001",
  "completedAt": "2026-05-28T10:00:00Z",
  "achievement": {
    "utteranceCount": 350,
    "lessonCompletionRate": 0.9
  }
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `institutionId` | string | 픽클래스 기관 UUID |
| `userPkId` | string | 파트너 회원 PK (수강목록 API에서 전달받은 값) |
| `userId` | string | 파트너 로그인 ID |
| `enrollmentId` | string | 파트너 수강신청 ID (수강목록 API 응답값 echo-back) |
| `completedAt` | string | 이수 완료 시각 (ISO 8601) |
| `achievement.utteranceCount` | number | 총 발화 횟수 |
| `achievement.lessonCompletionRate` | number (0–1) | 레슨 이수율 |

**Response (성공)**:
```json
{ "result": "ok" }
```

**재시도 정책**:
- Push 실패(네트워크 오류 / 5xx) 시 **1회 재시도** (즉시 재시도, 추가 대기 없음).
- 재시도 후에도 실패 시 `partner_completion_logs`에 `success: false`로 기록하고 종료.
- Push 실패가 학습자 학습 흐름에 영향을 주지 않는다 (비동기 처리).

**오류 코드 규격**:

| code | HTTP | 의미 |
|------|------|------|
| `ENROLLMENT_NOT_FOUND` | 404 | 파트너가 해당 수강신청을 찾을 수 없음 |
| `ALREADY_COMPLETED` | 409 | 이미 이수 처리된 수강신청 |

### 3-5. 학습결과 조회 API

**파트너 → 픽클래스** (파트너 Pull 방식)

파트너가 픽클래스 API를 호출하여 학습자 결과 데이터를 수집한다.

> **구현 시점**: Phase B-2 (선행 조건: Phase G — API Key 인프라 완료)

#### 제공 방식

Pull 방식(RESTful 조회)으로 구현한다. Webhook은 구현 범위 외.

#### 인증

모든 파트너 API는 API Key 인증을 사용한다.  
API Key는 백오피스 **시스템 > API키관리** (`/admin/b2b/api-keys`)에서 파트너사별로 발급·만료 관리한다.

```http
Authorization: Bearer {apiKey}
```

| 항목 | 내용 |
|------|------|
| 키 형식 | UUID v4 기반 랜덤 문자열 |
| 범위 | 파트너 기관 단위 발급 — API Key로 기관 범위 자동 적용 |
| 만료 | 백오피스에서 수동 만료 처리 |
| 갱신 | 신규 발급 후 구키 만료 처리 (동시에 두 개 운용 가능, 전환 기간) |

#### Pull API 스펙

**Base URL**: `https://api.picklass.com`

**공통 Query Parameters** (3개 엔드포인트 동일):

| 파라미터 | 타입 | 필수 | 설명 |
|---------|------|:----:|------|
| `startDate` | string (ISO 8601) | 필수 | 기간 시작일 |
| `endDate` | string (ISO 8601) | 필수 | 기간 종료일 |
| `userId` | string | 선택 | 특정 회원 필터 (파트너 로그인 ID) |
| `courseId` | UUID | 선택 | 특정 과정 필터 |

> API Key로 파트너 기관 범위 자동 적용 — 타 기관 데이터 접근 불가.  
> `userName`은 제공하지 않음 — 파트너가 `userId` · `userPkId` 기준으로 자체 매핑.

```
  ├─ partner-api.service.ts    ← partner_api_configs 조회

```

### 4-2. PartnerApiClientService 인터페이스

```typescript
// packages/core/src/partner-api/partner-api-client.service.ts

export interface PartnerAuthResult {
  institutionId: string;
  user_pk_id: string;
  userId: string;
  status: string;
}

export interface FrtOptions {
  termination_mode: 'TIME' | 'TOKEN';
  termination_value: number;   // TIME: 초(sec), TOKEN: 개수
  mic_mode: 'PTT' | 'HYBRID' | 'ALWAYS_ON';
}

export interface EnrollmentOptions {
  course_type: 'MANDATORY_COURSE' | 'TOTAL_LESSON_COUNT';
  completion_criteria: {
    utterance_goal: number;           // 목표 발화 횟수
    lesson_completion_rate: number;   // 레슨 이수율 (0–1)
  };
  free_learning_enabled: boolean;
  frt: FrtOptions | null;             // null → FRT 모듈 없는 과정
}

export interface PartnerEnrollment {
  enrollmentId: string;               // 파트너 수강신청 고유 ID (이수 완료 Push echo-back용)
  enrolledAt: string;
  expiresAt: string | null;
  status: string;
  courseScope: 'SPECIFIC' | 'ALL';
  picklassCourseIds: string[];        // ALL이면 빈 배열
  options: EnrollmentOptions | null;  // null → 픽클래스 기본 설정 적용
}

export interface PartnerHistoryRecord extends PartnerEnrollment {
  completedAt: string | null;         // 이수 완료일 (status: "completed"이면 있음)
}

export interface PartnerHistoryResponse {
  total: number;
  page: number;
  limit: number;
  history: PartnerHistoryRecord[];
}

export interface CompletionAchievement {
  utteranceCount: number;
  lessonCompletionRate: number;
}

export interface PartnerCompletionPayload {
  institutionId: string;
  userPkId: string;
  userId: string;
  enrollmentId: string;
  completedAt: string;
  achievement: CompletionAchievement;
}

export class PartnerApiClientService {
  // 로그인 Step 1: 파트너 로그인 페이지 redirect URL 생성
  async buildLoginRedirectUrl(
    institutionId: string,
    callbackUrl: string,
    state: string
  ): Promise<string>
  // {login_page_url}?callback=...&institutionId=...&state=... 반환

  // 로그인 Step 2: callback 토큰 검증 → 사용자 정보 추출
  async verifyAuthCallback(
    institutionId: string,
    token: string,
    state: string,
    expectedState: string
  ): Promise<PartnerAuthResult>
  // state·서명(HS256)·만료·institutionId 검증
  // partner_auth_logs 기록. 실패 시 PartnerAuthException throw

  // 수강목록: 파트너 수강목록 API 호출 (status: "active"만 반환)
  async getEnrollments(
    institutionId: string,
    user_pk_id: string
  ): Promise<PartnerEnrollment[]>
  // 실패 시 PartnerApiException throw

  // 이수 완료 Push: 파트너 completion_endpoint 호출
  async notifyCompletion(
    institutionId: string,
    payload: PartnerCompletionPayload
  ): Promise<void>
  // completion_endpoint 미설정 기관은 no-op. 실패 시 partner_completion_logs에 기록 후 종료 (학습 흐름 차단 안 함)

  // 이전 학습내역: 파트너 history_endpoint 호출 (status: "completed" | "expired")
  async getHistory(
    institutionId: string,
    user_pk_id: string,
    page: number,
    limit: number
  ): Promise<PartnerHistoryResponse>
  // 실패 시 PartnerApiException throw

  // 내부: partner_api_configs 조회
  private async getConfig(institutionId: string): Promise<PartnerApiConfig>
}
```

### 4-3. 오류 처리 전략

| 상황 | 동작 |
|------|------|
| 파트너 API 응답 없음 (timeout) | 로그 기록 후 `ServiceUnavailableException` |
| 파트너 응답 4xx | 로그 기록 후 적절한 HTTP 오류로 변환 |
| partner_api_configs 없음 | 로그 기록 후 `NotFoundException` |
| 수강목록 응답 빈 배열 | 정상 처리 (빈 배열 반환) |
| `verifyAuthCallback()` 검증 실패 (state·서명·만료·institutionId) | `partner_auth_logs`에 `success: false` 기록 후 `PartnerAuthException` throw — HTTP 출처 없음 (로컬 검증) |
| `notifyCompletion()` 실패 (1회 재시도 후 timeout / 4xx / 5xx) | `partner_completion_logs`에 `success: false` 기록 후 **정상 반환** — 학습 흐름 차단 없음 (silent fail) |

**필터**:

| 필터 | 내용 |

| 파트너 기관 | `institution_id` 검색 |
| 파트너 회원 PK | `partner_user_pk_id` 검색 |
| 결과 | 성공 / 실패 |

**목록 컬럼**:

| 컬럼 | 내용 |

### 6-1. POST /auth/login/b2b

```json
{
  "sub": "session_uuid",
  "institutionId": "institution_uuid",
  "user_pk_id": "partner-user-pk",
  "loginScope": "institution"
}
```

### 6-2. getEnrolledCourses() — INTERNAL + B2B 통합

#### INTERNAL 수강 목록 — DB 쿼리 (Phase E 완료 후 기준)

```sql
SELECT c.* FROM access_codes ac
JOIN courses c ON c.id = ac.course_id
WHERE ac.user_id = :userId
  AND ac.status_code = 'active'
  AND (ac.usage_end_date IS NULL OR ac.usage_end_date > NOW())
```

> `source_type` 컬럼 삭제로 필터 조건에서 제거됨.  
> Phase E 전 임시 조건: `status_code = 'inactive' AND user_id IS NOT NULL`

#### B2B 수강 목록 — 파트너 API 실시간 호출

기존 B2B UNION 쿼리 (access_codes/access_code_options 조회) 방식은 **파트너 소유 데이터를 픽클래스 DB에 저장하는 구조**이므로 제거한다.

```typescript
// 변경 후 (tutoring lessons.service.ts)
async getEnrolledCourses(studentId: string, loginScope: string, institutionId?: string, user_pk_id?: string) {
  // ① INTERNAL 수강 목록 (기존 DB 쿼리)
  const internalCourses = await this.getInternalCourses(studentId);

  // ② B2B 수강 목록 (파트너 API 실시간 호출)
  let b2bCourses: Course[] = [];
  if (loginScope === 'institution' && institutionId && user_pk_id) {
    const partnerCourses = await this.partnerApiClient.getEnrollments(institutionId, user_pk_id);
    b2bCourses = await this.mapPartnerCoursesToLocal(partnerCourses);
    // partner_enrollment_logs 자동 기록 (PartnerApiClientService 내부 처리)
  }

  return [...internalCourses, ...b2bCourses];
}
```

## 7. access_codes B2B 역할 재정의

기존 설계에서 B2B access_codes는 **수강권 레코드**였으나, 픽클래스가 수강 데이터를 소유하지 않으므로 **세션 로그 용도**로 재정의한다.

| 항목 | 기존 설계 | 변경 후 |
|------|---------|---------|
| 생성 시점 | 파트너 API 인입 시 자동 생성 | 학습자가 B2B 로그인 시 세션 기록용 생성 |
| source_type='B2B' 역할 | 수강권 (source of truth) | 로그인·학습 세션 이력 |
| 수강 데이터 출처 | access_codes + access_code_options (DB) | 파트너 API 실시간 조회 |
| access_code_options | B2B 다중 과정 연결용 | 불필요 (파트너 API가 과정 정보 보유) |

> **결론**: `source_type='B2B'` access_codes 레코드와 access_code_options는 이번 범위에서 생성하지 않는다.  
> B2B 수강 이력이 필요하면 `partner_enrollment_logs`를 사용한다.

## 11. 의도적 제외

| 항목 | 이유 |
|------|------|
| 파트너 API 응답 캐싱 | 수강목록 실시간성 보장 우선 — 캐싱은 성능 이슈 발생 시 별도 검토 |
| 파트너 API 재시도 (retry) | **로그인 인증·수강목록·이전 학습내역 API**: 재시도 없음 — 실패 로그 기록 후 사용자가 재시도하는 흐름으로 처리. **이수 완료 Push만 예외**: 비동기 처리 특성상 1회 재시도 적용 (§3-3) |
| 수강 데이터 DB 동기화 | 픽클래스가 수강 데이터 소유 안 함 — 로그만 기록 |
| access_code_options B2B 사용 | B2B 수강 데이터는 파트너 API가 source of truth — DB 복제 불필요 |
| 파트너 측 API 인증 방식 강제 | 파트너마다 인증 방식 다름 — api_key 선택적으로 처리 |
| `partner_api_configs.api_key` 암호화 저장 | 현재 평문 저장 — 운영 보안 강화 필요 시 별도 검토 (AES 암호화 또는 Secrets Manager) |
| Webhook Push 방식 | Pull 방식만으로 충분 — 실시간성 요구 없고 파트너 endpoint 관리 복잡도 불필요 |
