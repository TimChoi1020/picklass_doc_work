## 0. 배경 및 목표

### 배경

`/report` 페이지는 강사가 수강생의 학습 현황을 조회하는 화면이다.  
현재 구현의 주요 문제점:

| 문제 | 현황 |
|------|------|
| 데이터 소스 미연결 | `student_learning_records` 레거시 테이블 사용 — `lesson_results` / `module_histories` 미사용 |
| 학습자 이름 미노출 | `name` 필드에 UUID 그대로 노출 |
| 레슨 현황 고정 구조 | `unit1~unit8` 하드코딩 — 과정마다 레슨 수가 다름 |
| KPI 값 추정 | `module_histories.kpis` 실제값 대신 CEFR 기반 추정치 사용 |
| 필터 미연결 | 모든 select가 빈 `<option>선택</option>` 상태 |
| Mock 데이터 의존 | API 응답이 빈 경우 `mockStudentReports`로 폴백 |

### 목표

`access_codes → lesson_results → module_histories` 데이터 계층을 실제로 연결하여:

- 검색 필터(과정·학습시작일·학습종료일·아이디/이름)를 실제 데이터 기반으로 동작
- 레슨별 실제 진도·점수·학습시간을 정확하게 표시
- `module_histories.kpis`의 실제 값(Voca·Reading·Speaking)을 반영
- 수강기간 노출 및 만료 임박 강조
- 상세 페이지(`/report/[studentId]`)와의 역할 분담 명확화

## 1. 데이터 소스

### 1-1. 관련 테이블

| 테이블 | 용도 | 주요 필드 |
|--------|------|-----------|
| `access_codes` | 학습자-과정 연결 + 수강기간 | `course_id`, `user_id`, `usage_start_date`, `usage_end_date`, `status_code` |
| `users` | 학습자 이름 | `id`, `name`, `email` |
| `courses` | 과정 기본 정보 | `id`, `name` |
| `course_lessons` | 레슨 목록 + 순서 | `course_id`, `lesson_order`, `topic` |
| `lesson_results` | 레슨별 완료여부·점수·소요시간 | `course_lesson_id`, `student_id`, `average_score`, `total_duration`, `completed_at` |
| `module_histories` | 모듈별 KPI | `course_lesson_id`, `student_id`, `kpis` (JSONB) |

### 1-2. 데이터 계층

```
Course (과정)
  └── AccessCode (수강 학습자, usage_start_date ~ usage_end_date)
        └── Users (학습자 이름)
        └── lesson_results (레슨별 완료 여부, average_score, total_duration)
              └── module_histories (모듈별 kpis, started_at, completed_at)
                    └── kpis: { vocaSize, readingWPM, pronunciationAccuracy,
                                speakingWPM, avgSentenceLength, correctAnswerRate, ... }
```

### 1-3. 핵심 필드 매핑

| 현재 컬럼 | 현재 소스 | 변경 후 소스 |
|----------|----------|-------------|
| 학생 이름 | UUID 노출 | `users.name` |
| 로그인 ID | 없음 | `users.user_id` (VARCHAR 로그인 ID) |
| 진도율 | `progress_rate` (추정) | `완료 레슨 수 / 전체 레슨 수` |
| 레슨 현황 | `unit1~unit8` 고정 8개 | `course_lessons` 기반 동적 배열 |
| Voca | CEFR 추정 | `module_histories.kpis.vocaSize` 평균 |
| Reading WPM | CEFR 추정 | `module_histories.kpis.readingWPM` 평균 |
| 발화 정확도 | CEFR 추정 | `module_histories.kpis.pronunciationAccuracy` 평균 |
| Speaking WPM | CEFR 추정 | `module_histories.kpis.speakingWPM` 평균 |
| 수강기간 | 없음 | `access_codes.usage_start_date ~ usage_end_date` |
| 누적 학습시간 | 없음 | `SUM(lesson_results.total_duration)` |
| 마지막 학습일 | 없음 | `MAX(lesson_results.completed_at)` |

## 2. 검색 필터 설계

### 2-1. 필터 항목

| 필터 | 바인딩 필드 | 동작 |
|------|------------|------|
| 과정 | `course_id` (optional) | select — 학습종료일이 오늘 이후인 과정만 표시 |
| 학습시작일 | `start_date_from` | date input — `access_codes.usage_start_date >= ?` |
| 학습종료일 | `end_date_to` | date input — `access_codes.usage_end_date <= ?` |
| 아이디(이름) | `student_search` | text input — `users.name ILIKE ?` 또는 `users.email ILIKE ?` |

> **`course_id`는 필수가 아니다.** 선택하지 않으면 모든 과정의 수강생을 조회한다.  
> 단, 과정 select에 노출되는 목록은 `access_codes.usage_end_date >= TODAY`인 과정으로 제한한다.

### 2-2. 과정 목록 쿼리 (select 옵션용)

```sql
-- 현재 기관(institution_id)에서 학습종료일이 오늘 이후인 과정만 노출
-- courses 테이블의 실제 컬럼명은 title (name 아님)
SELECT DISTINCT c.id, c.title AS name
FROM courses c
JOIN access_codes ac ON ac.course_id = c.id
WHERE ac.institution_id = :institutionId
  AND (ac.usage_end_date IS NULL OR ac.usage_end_date >= CURRENT_DATE)
  AND (ac.user_id IS NOT NULL OR ac.generated_user_id IS NOT NULL)
ORDER BY c.title;
```

### 2-3. 필터 조합 규칙

- 모든 필터는 AND 조건으로 적용
- `start_date_from`만 입력 시: `usage_start_date >= start_date_from`
- `end_date_to`만 입력 시: `usage_end_date <= end_date_to`
- 둘 다 입력 시: 수강기간이 해당 범위와 겹치는 학습자 조회
- `student_search`: `users.name ILIKE '%검색어%'` OR `users.user_id ILIKE '%검색어%'` (로그인 ID 검색)

## 4. 백엔드 API 변경

### 4-1. `GET /reports` — 집계 쿼리 재설계

기존 `student_learning_records` 기반 쿼리를 **전면 교체**한다.  
복잡한 다단계 조인 + JSONB 집계가 필요하므로 **Prisma `$queryRawUnsafe`** 사용.

> **`$queryRaw` → `$queryRawUnsafe` 변경 이유**  
> 필터 조합에 따라 WHERE절이 동적으로 달라지므로, tagged template literal인 `$queryRaw`로는
> 조건절을 동적으로 구성할 수 없다. 파라미터 배열 방식인 `$queryRawUnsafe`를 채택하고,
> 동적 파라미터는 positional placeholder(`$1`, `$2`, …)로 처리한다.

> **`access_codes` 이중 user 경로**  
> `access_codes`에서 학습자를 참조하는 경로가 두 가지 존재한다:
> - `user_id` (UUID FK) — 학생 생성 시 `students.service.ts`에서 직접 설정
> - `generated_user_id` (VARCHAR) — 일부 경로에서 UUID 없이 로그인 ID만 기록
>
> → 두 경로를 모두 처리하는 JOIN 설계:
> ```sql
> JOIN users u ON (
>   u.id = ac.user_id
>   OR (ac.user_id IS NULL AND u.user_id = ac.generated_user_id)
> )
> ```

> **UUID 캐스팅 필수**  
> `$queryRawUnsafe`에서 PostgreSQL이 문자열을 UUID로 자동 캐스팅하지 않는다.
> `institution_id`, `course_id` 등 UUID 컬럼은 반드시 `$1::uuid` 형태로 명시해야 한다.

> **`courses.name` → `courses.title`**  
> `courses` 테이블의 과정명 컬럼 실제 이름은 `title`이며 `name`은 존재하지 않는다.
> Raw SQL 작성 시 혼동 주의.

**집계 흐름:**

```
1. access_codes (institution_id 기준 + 필터 적용)
   → users JOIN (이름, 이메일)
   → courses JOIN (과정명)

2. course_lessons WHERE course_id IN (위 과정 목록)
   → total_lesson_count 계산

3. lesson_results WHERE student_id IN (...) AND course_lesson_id IN (...)
   → completed_lesson_count, SUM(total_duration), MAX(completed_at)
   → lesson_statuses 배열 생성

4. module_histories WHERE student_id IN (...) AND course_lesson_id IN (...)
   → AVG((kpis->>'vocaSize')::numeric)
   → AVG((kpis->>'readingWPM')::numeric)
   → AVG((kpis->>'pronunciationAccuracy')::numeric)
   → AVG((kpis->>'speakingWPM')::numeric)
   → AVG((kpis->>'avgSentenceLength')::numeric)
   → AVG((kpis->>'correctAnswerRate')::numeric)
```

## 5. 프론트엔드 변경

### 5-1. 필터 바 재설계

```
[현재]
업체명(본사) | 캠퍼스 | 담당(강사) | 과정 | 클래스(반) | 개인(학생 검색) | 학습기간(1/3/6개월)

[변경]
과정 (optional) | 학습시작일 | 학습종료일 | 아이디(이름) | 정렬 | [초기화]
```

**과정 select:**
- `GET /reports/active-courses` 로 옵션 로드
- 첫 번째 옵션: `전체 과정` (course_id = undefined)
- 이후: 학습종료일이 오늘 이후인 과정만 표시

**날짜 필터:**
```tsx
<Input type="date" value={startDateFrom} onChange={...} placeholder="학습시작일" />
<span>~</span>
<Input type="date" value={endDateTo} onChange={...} placeholder="학습종료일" />
```

**아이디(이름) 검색:**
- 기존 `searchTerm` → `studentSearch`로 변수명 변경
- `users.name` OR `users.user_id`(로그인 ID) 검색

### 5-2. 테이블 컬럼 재설계

```
[현재]
이름(ID) | 진도율 시각화 | 레슨 현황(8개 고정) | Voca | Reading | Speaking | Writing/Listen | AI진단

[변경]
이름 | 과정명 | 수강기간 | 진도 | 레슨 현황(동적) | 누적시간 | Voca | Reading | Speaking | AI진단
```

**각 컬럼 상세:**

- **이름**: `users.name` / `users.user_id`(로그인 ID)
- **과정명**: `courses.title` (course_id 미선택 시 유용)
- **수강기간**: `usage_start_date ~ usage_end_date`. 만료 7일 이내 시 빨간색 강조
- **진도**: `completed_lesson_count / total_lesson_count` + 프로그레스 바
- **레슨 현황**: `lesson_statuses` 배열 동적 렌더링

```tsx
<div className="flex gap-0.5 justify-center">
  {student.lesson_statuses.map((status, i) => (
    <span key={i} title={`레슨 ${i + 1}`}>
      {getUnitStatusEmoji(status)}
    </span>
  ))}
</div>
```

- **누적시간**: `total_duration_sec`을 `Xh Ym` 형식으로 변환
- **Voca / Reading / Speaking**: `kpis` 실제값 (CEFR 추정 로직 제거)
- **AI 진단**: 입력값만 실제 kpis로 교체, 로직 유지

### 5-3. 수강기간 만료 임박 강조

```tsx
const daysLeft = differenceInDays(new Date(student.usage_end_date!), new Date());
const isExpiringSoon = daysLeft >= 0 && daysLeft <= 7;

<span className={isExpiringSoon ? 'text-red-500 font-semibold' : 'text-gray-600'}>
  {formatDate(student.usage_start_date)} ~ {formatDate(student.usage_end_date)}
</span>
```

## 8. 주요 설계 결정

| 결정 사항 | 선택 | 이유 |
|-----------|------|------|
| `course_id` 필수 여부 | **선택 사항** | 강사가 전체 수강생을 먼저 볼 수 있어야 함 |
| 과정 select 목록 범위 | `usage_end_date >= TODAY` | 종료된 과정은 일반적으로 조회 불필요 |
| 집계 방식 | `$queryRawUnsafe` | 동적 WHERE절 조합 필요 — tagged template인 `$queryRaw` 불가 |
| 기존 `student_learning_records` | **완전 교체** | 새 데이터 모델과 구조적으로 호환 불가 |
| `period` 필터 | **제거** | `start_date_from` / `end_date_to`로 대체 |
| 검색 대상 | `users.name` OR `users.user_id` | 이름과 로그인 ID 모두 검색 허용 |
| `access_codes` user 참조 경로 | **이중 경로** | `user_id`(UUID) 없으면 `generated_user_id`(로그인ID)로 fallback JOIN |
| `courses` 과정명 컬럼 | `title` | DB 실제 컬럼명. `name`으로 기술했던 계획 오류 수정 |
| UUID 파라미터 캐스팅 | `$N::uuid` 명시 | `$queryRawUnsafe`에서 PostgreSQL 자동 캐스팅 미지원 |
