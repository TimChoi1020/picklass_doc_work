## 1. backoffice와의 연결 구조 (가장 중요)

### 1-1. 두 시스템은 같은 데이터베이스를 공유한다

- studio와 backoffice는 **동일한 PostgreSQL DB**를 사용합니다 (`DATABASE_URL` 동일, `institutions` 테이블 공유).
- 단, **코드 저장소(repo)는 분리**되어 있고, 각자 자기 `prisma/schema.prisma`를 가집니다.
- 따라서 **DB 컬럼 추가(DDL)는 공유 DB에 딱 1번만 실행**하고, **양쪽 repo가 각각 `prisma db pull`로 스키마를 동기화**해야 합니다.

### 1-2. 역할 분담 — 누가 주인이고 누가 소비자인가

| 시스템 | 기관설정에 대한 역할 | 필요한 작업 |
|--------|---------------------|------------|
| **backoffice** | **설정의 주인** (관리자가 학원별 한도를 정함) | 읽기 + **쓰기** API, 설정 UI 연동 |
| **studio** | **설정의 소비자** (강사 과정생성 시 한도를 참고만) | **읽기** API, stub 제거 후 연동 |

### 1-3. 결론: 선행 작업이 존재한다 ⚠️

> **studio 과정 생성이 "진짜로" 동작하려면, 먼저 backoffice 쪽에서 학원별 설정값이 DB에 저장될 수 있어야 합니다.**
>
> 즉 **`[공통 DB 작업]` → `[backoffice 설정 저장 기능]` → `[studio 연동]`** 순서가 강제됩니다.
> (studio만 먼저 만들면, 읽어올 설정값이 DB에 없어서 항상 "제한 없음" 기본값으로만 동작 → 반쪽짜리)

## 3. Phase A — 공통 기반 (선행 필수)

### A-1. institutions 테이블에 설정 컬럼 추가

> **결정 권장: Option A (institutions 테이블에 컬럼 직접 추가)**
> 별도 `institution_settings` 테이블(Option B)보다 조인이 없어 단순하고, backoffice UI가 이미 통합 관리하는 방향과 맞습니다.

```sql
-- 공유 DB에 1회만 실행 (DBeaver/pgAdmin)
-- 파일: prisma/manual-sql/20260530_add_institution_settings.sql
ALTER TABLE institutions
  ADD COLUMN max_class_minutes      INTEGER,           -- 전체 수업 최대시간 (null=제한없음)
  ADD COLUMN max_frt_module_minutes INTEGER,           -- 프리토킹 최대시간 (null=제한없음)
  ADD COLUMN default_mic_mode       VARCHAR(20) DEFAULT 'push_to_talk',
  ADD COLUMN allowed_mic_modes      JSONB DEFAULT '["push_to_talk","hybrid","always_on"]',
  ADD COLUMN mic_mode_user_change   BOOLEAN DEFAULT true,
  ADD COLUMN free_learning_enabled  BOOLEAN DEFAULT false,
  ADD COLUMN completion_defaults    JSONB;             -- {"lessonRate":70,"sentences":200,"minutes":null}
-- 기존 레코드는 NULL 또는 DEFAULT로 자동 세팅 → studio는 null이면 "제한 없음"으로 폴백
```

### A-2. courses 테이블에 설정 컬럼 추가

```sql
-- 파일: prisma/manual-sql/20260530_add_course_options.sql
ALTER TABLE courses
  ADD COLUMN course_type       VARCHAR(20) DEFAULT 'tutoring',  -- tutoring|speaking|integrated
  ADD COLUMN max_class_minutes INTEGER,                          -- 강사가 정한 전체 수업 최대시간
  ADD COLUMN course_options    JSONB,                            -- 이수조건 + 자유학습 (모든 유형 공통)
  ADD COLUMN speaking_options  JSONB;                            -- FRT 설정 (speaking|integrated + FRT 포함 시)
-- course_options 예: {"completion_lesson_rate":70,"completion_sentences":200,"completion_minutes":null,"free_learning_enabled":false}
-- speaking_options 예: {"frt_minutes":10,"mic_mode":"push_to_talk","mic_mode_user_change":true}
```

> **기존 과정 처리**: `course_type` 기본값을 `'tutoring'`으로 부여 (기준문서 §9 열린이슈 5번 권장안). 나머지 옵션 컬럼은 NULL 허용 — 편집 진입 시 기관 기본값으로 pre-fill.

### A-3. 양쪽 repo 스키마 동기화

```bash
# studio.picklass.com 와 picklass-backoffice 각각에서 실행
pnpm prisma:pull          # DB → schema.prisma 역동기화
git diff prisma/schema.prisma   # courses/institutions 변경 확인
pnpm prisma:generate      # 클라이언트 재생성
# core/shared 패키지 재빌드
```

**산출물**: 2개 SQL 파일, 양쪽 schema.prisma 갱신
**완료 기준**: 양쪽 repo에서 새 컬럼이 Prisma 타입에 노출됨

- 규칙: `courseType === 'integrated'`일 때 회차 내 스피킹 모듈을 **항상 맨 마지막**으로 정렬 (기준문서 §3-1).
- 구현 위치 확인 필요: `LessonModuleSection.tsx` 내부 시퀀싱 결과 렌더링부 또는 백엔드 lesson-plan 서비스. (현재 `sequence.sort` 미발견 → 신규 추가)

```ts
sequence.sort((a, b) => {
  const aS = a.skill === 'speaking' ? 1 : 0;
  const bS = b.skill === 'speaking' ? 1 : 0;
  if (aS !== bS) return aS - bS;
  return a.order - b.order;
});
```

## 9. 작업 전 확정이 필요한 열린 이슈

1. **DB 구조**: institutions 컬럼 추가(Option A, 권장) vs 별도 institution_settings 테이블(Option B) — 본 플랜은 A 가정.
2. **필드명/프리셋 통일**: backoffice(`maxTotalClassMinutes`, `[5..50]`) ↔ studio(`maxClassMinutes`, `[10,20,30,40,60]`) 불일치 해소.
3. **FRT 섹션 show/hide 시 저장값 처리**: 회차에서 FRT 제거 시 저장된 `speaking_options` 초기화 여부 (기준문서 §9 7번).
4. **기존 과정 마이그레이션**: `course_type` 일괄 `'tutoring'` 부여 정책 확정.
5. **설정 API 소유권**: studio는 읽기 전용 / backoffice는 읽기·쓰기 — 각 backend에 별도 구현 (같은 DB, 다른 repo).
