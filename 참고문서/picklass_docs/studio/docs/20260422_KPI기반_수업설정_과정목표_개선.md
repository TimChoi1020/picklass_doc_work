## 1. 사용자 흐름 (User Flow)

### lesson-setup `/class/lesson-setup/[passageId]`

1. 교사가 `/class` 지문 목록에서 지문 선택 → `/class/lesson-setup/[passageId]` 진입
2. **지문 정보 카드** 표시 (제목, 레벨, 단어수, 장르, 지문 타입 배지)
3. **[신규] KPI 선택 섹션** — `KPI_CATEGORY`에서 로드한 목표 칩 목록 표시
   - 복수 선택 가능 (멀티셀렉트)
   - 선택 시 초록 강조(`border-[#18c37e] bg-[#e9f9f3]`), 재클릭 시 해제
   - 선택 안 해도 수업 진행 가능 (필수 아님)
4. **[신규] 수업 시간 선택 섹션** — 15 / 20 / 25 / 30분 버튼 중 하나 토글 선택
   - 미선택 상태도 허용
5. **모듈 그리드** — 카테고리별 모듈 토글 버튼 (기존 유지)
6. "수업 들어가기" 클릭 (최소 1개 모듈 선택 필수)
   - URL: `/class/lesson/[passageId]?modules=…&kpis=…&duration=30`

### course `/course` (과정 생성 마법사 Step 1/2)

1. "새 과정 만들기" 클릭 → 마법사 Step 1/2 열림
2. **과정 목표 섹션** — `KPI_CATEGORY` goal 칩 목록 표시 (코드 미노출)
   - Before: `ai_modules.learning_objectives` flat 목록
   - After: `KPI_CATEGORY.extraData.goal` distinct 목록
   - 선택값은 내부적으로 KPI **코드** 배열로 저장
3. "다음" 클릭 → Step 2/2에서 AI 주제 생성
   - `course_goal`: 선택한 코드 → goal 텍스트로 변환하여 AI 프롬프트에 전달
   - KPI 미선택 시: `'일반 영어 학습'` 폴백
4. 과정 저장 시 `description`: KPI 코드를 `, ` 구분 문자열로 저장

## 3. 정책 (Policy / Business Rules)

### KPI 선택 공통 정책 (lesson-setup + course 양쪽 적용)

- **데이터 소스**: 백오피스 `KPI_CATEGORY` 코드 그룹 단일 소스 — `ai_modules.learning_objectives`, `KPI_ITEMS`, `KPI_ROLLUP` 불사용
- **표시 값**: `extraData.goal` 텍스트만 노출. 코드는 UI에 미표시
- **중복 제거**: `extraData.goal` 기준 distinct (동일 goal의 첫 번째 코드 항목만 유지)
- **정렬**: `sort_order ASC` (백오피스 설정 순서 존중)
- **필터**: `is_active = true` 인 항목만 표시
- **선택 저장**: 내부 state는 KPI **코드** 배열 (`string[]`)로 관리

### lesson-setup 정책

- KPI 및 수업 시간은 **선택 사항** — 미선택 상태로 수업 진입 가능
- 수업 시간 옵션: **15 / 20 / 25 / 30분** (5분 간격) — 단일 선택, 재클릭 시 해제
- URL 파라미터 전달 규칙:
  - `modules`: 쉼표 구분 코드 문자열 (필수)
  - `kpis`: 선택된 KPI 코드 쉼표 구분 (선택 시만 포함)
  - `duration`: 숫자 문자열 (선택 시만 포함)

### course 정책

- **과정 저장**: `selectedObjectives` (KPI 코드 배열) → `courses.description`에 `', '` 구분 문자열로 저장
- **AI 주제 생성 `course_goal`**: 코드 → goal 텍스트 변환 후 전달 (AI가 코드를 이해하지 못하므로)
  - KPI 미선택 → `'일반 영어 학습'` 폴백 (400 에러 방지)
- **`course_focus` 컬럼**: 현재 미사용 (`undefined` 전달) — 추후 AI 생성 `courseFocus` 값 저장 예정

### 정책 변경 사항 (기존 대비)

| 항목 | 기존 (2026-04-12) | 변경 (2026-04-22) |
|------|-------------------|-------------------|
| 과정 목표 소스 | `ai_modules.learning_objectives` | `KPI_CATEGORY.extraData.goal` |
| 선택 값 저장 방식 | goal 텍스트 배열 | KPI 코드 배열 |
| `description` 저장 내용 | goal 텍스트 쉼표 문자열 | KPI 코드 쉼표 문자열 |
| AI `course_goal` 값 | 텍스트 그대로 | 코드 → 텍스트 변환 |

## 4. 개발자 추가 작업 사항

### 4-0. [완료] `learning_objectives` → `KPI_CATEGORY` 통합

#### 배경 및 결정 근거

`ai_modules`의 `learning_objectives` 필드와 `KPI_CATEGORY` 코드 그룹이 **동일한 개념**("이 모듈이 어떤 학습 목표를 다루는지")을 이중으로 관리하고 있었음.

- **개념 중복**: 두 필드 모두 모듈의 학습 목표를 표현하며, 코드 그룹과 DB 컬럼 두 곳에 분산 관리
- **LEARNING_OBJECTIVES 사실상 미사용**: 오늘 Studio 과정 목표를 KPI_CATEGORY로 전환하면서 `learning_objectives`를 소비하는 코드가 없어짐
- **KPI_CATEGORY의 우월성**: `code`(측정 가능한 식별자) + `extraData.goal`(UI 텍스트)를 이미 갖추고 있어 `LEARNING_OBJECTIVES`의 역할을 완전히 대체 가능

### 4-2. [필수] `courses.description` 마이그레이션 전략 결정

`description`이 goal 텍스트(기존)와 KPI 코드(신규)가 혼재하게 됨.  
아래 중 하나 선택 필요:

**Option A**: `kpi_codes VARCHAR[]` 컬럼 별도 추가 (권장)
```sql
ALTER TABLE courses ADD COLUMN kpi_codes TEXT[] DEFAULT '{}';
```
```typescript
// createCourse payload에 추가
kpi_codes: selectedObjectives,
```

**Option B**: 기존 `description` 유지, 코드 패턴으로 파싱 (임시)
- 현재 코드는 Option B 상태 — 추후 Option A로 이전 권장

### 4-3. [필수] `course_focus` 컬럼 활용

AI 주제 생성 응답의 `courseFocus`(camelCase) 또는 `course_focus`(snake_case) 불일치 수정 및 저장 연결:

// TopicsResult.courseFocus (camelCase) → courses.course_focus 저장 미구현

lesson-setup 페이지의 KPI + duration 입력이 완성되었으므로, 실제 자동 시퀀싱 API 구현 준비 완료. `lesson-plan-update.md` 참조.

## 5. 코드 규칙 (Coding Rules)

### KPI 관련

- KPI 데이터는 항상 `useKpiItems()` 훅 사용 — `commonCodesApi.getItemsByGroupCode('KPI_CATEGORY')` 직접 호출 금지
- 선택값 state는 **코드 배열** (`string[]`) — goal 텍스트 배열 사용 금지
- UI 표시 시 goal 텍스트 필요: `kpiItems.find(k => k.code === code)?.goal ?? code` 패턴 사용
- AI 프롬프트 전달 시 코드 → 텍스트 변환 필수 (코드 문자열 그대로 전달 금지)
- `KPI_CATEGORY` 미선택 시 폴백 문자열 제공 (`@IsNotEmpty()` 검증 통과 필요)

### 수업 시간

- `DURATION_OPTIONS` 상수는 페이지 파일 최상단 컴포넌트 외부에 선언
- `as const` 타입 단언 사용: `[15, 20, 25, 30] as const`
- 단일 선택 토글: 같은 값 클릭 시 `null`로 해제

### 공통

- 칩/버튼 선택 색상 통일:
  - 선택: `border-2 border-[#18c37e] bg-[#e9f9f3] text-[#008c5b]`
  - 미선택: `border-transparent bg-white text-gray-700 hover:bg-gray-50`
- `any` 타입, `@ts-ignore`, `alert()` 직접 사용 금지 — `toast.error()` 사용
- API 호출은 `src/lib/api.ts`의 함수 경유 필수 (fetch 직접 호출 금지, `generateAndSavePassage` 예외)
- 타입 정의: `packages/shared/src/types/` 또는 훅 파일 내 `export interface`로 선언

## 8. DB / API 구조 (Data Contract)

### 신규: `useKpiItems` 훅

**파일**: `apps/web/src/hooks/use-modules.ts`

```typescript
export interface KpiItem {
  code: string;   // KPI_CATEGORY.code (내부 식별자, UI 미노출)
  goal: string;   // KPI_CATEGORY.extraData.goal (UI 표시 텍스트)
}

export function useKpiItems() {
  return useQuery({
    queryKey: queryKeys.commonCodes.items('KPI_CATEGORY'),
    queryFn: async () => {
      const items = await commonCodesApi.getItemsByGroupCode('KPI_CATEGORY');
      return items
        .filter((item) => item.is_active)
        .sort((a, b) => a.sort_order - b.sort_order)
        .map((item): KpiItem => ({
          code: item.code,
          goal: (item.extra_data?.goal as string) || item.name,
        }))
        .filter((item, idx, arr) => arr.findIndex((x) => x.goal === item.goal) === idx); // goal distinct
    },
    staleTime: 5 * 60 * 1000,
  });
}
```
