## 1. 한 줄 요약

> **"KPI + 수업 시간이 둘 다 선택되는 순간 시퀀싱 API를 호출하고, 사용자가 모듈을 선택하면 분석 결과 순서대로 번호가 매겨져 표시된다."**

---

## 2. 비유로 이해하기

**음식 코스 메뉴 만들기**에 비유하면:

| 음식 | KPI 시퀀싱 |
|------|-----------|
| 손님이 알레르기/식단 목표 알려줌 | KPI 선택 |
| 식사 시간 정함 (런치 1시간) | 수업 시간 선택 |
| 셰프가 머릿속으로 코스 순서를 짜둠 | analyzer가 시퀀스 계산 (UI에 안 보임) |
| 손님이 메뉴판에서 음식을 고름 | 사용자가 모듈 선택 |
| 고른 음식이 셰프의 코스 순서대로 1, 2, 3 번호 매겨짐 | 선택된 모듈에 시퀀스 번호 표시 |

핵심: **메뉴판(모듈 리스트) UI는 그대로**, **선택된 항목의 번호만 셰프(analyzer) 순서로 정렬**

## 3. 사용자 흐름 (User Flow)

### 3-1. 진입 직후

```
[lesson-setup 페이지]
─────────────────────────
[지문 정보 카드]

[수업 목표 KPI 선택]
  □ 말하기 유창성 향상
  □ 발음 정확도
  □ 독해 속도

[수업 시간]
  [15분] [20분] [25분] [30분]

[모듈 리스트]
  □ 단어 인식
  □ 단어 학습
  □ 음독
  □ 발음 연습
  □ 독해
```

→ analyzer 미호출. 모듈 클릭해도 번호 없음 (또는 클릭 차단 검토).

### 3-2. KPI만 선택 (duration 미선택)

```
[KPI]
  ☑ 발음 정확도
  
[수업 시간]
  [15분] [20분] [25분] [30분]   ← 미선택
```

→ analyzer 미호출. 트리거 조건 미충족.

### 3-3. KPI + duration 모두 선택 → 트리거 발동

```
[KPI]
  ☑ 발음 정확도
  
[수업 시간]
  [●20분]
```

이 순간 자동 실행:
```
1. POST /lesson-plan
   { kpis: ['PRONUNC'], duration: 20, passageId, ... }
   
2. 모듈 리스트에 로딩 인디케이터 표시
   (전체 그레이아웃 또는 스피너 오버레이)

3. 응답 도착 → 시퀀스 내부 저장
   sequence: ['WRD', 'ORL', 'PWR', 'WSD', 'READ']
   
4. 로딩 해제 → 모듈 클릭 가능
```

### 3-4. 사용자가 모듈 선택

```
[클릭 1] "음독" 선택
─────────────────────────
☑ 음독         [1]      ← 분석 순서에서 첫 번째 (선택된 것 중)

[클릭 2] "단어 학습" 추가
─────────────────────────
☑ 단어 학습    [1]      ← analyzer 순서: WRD가 ORL보다 앞
☑ 음독         [2]      ← 자동 재정렬

[클릭 3] "발음 연습" 추가
─────────────────────────
☑ 단어 학습    [1]
☑ 음독         [2]
☑ 발음 연습    [3]
```

### 3-5. 옵션 재변경 → 재호출

```
[KPI 변경] "발음 정확도" 해제 + "독해 속도" 추가

→ 즉시 POST /lesson-plan 재호출
→ 로딩 표시
→ 새 시퀀스 도착 → 선택 모듈 번호 재계산
```

### 3-6. 분석 실패 (503 등)

```
[모듈 리스트]
  ⚠ 시퀀싱 분석에 실패했습니다. 옵션을 다시 선택하거나 잠시 후 시도하세요.
  
  [모듈 클릭 차단 — 선택 불가]
```

→ "수업 들어가기" 버튼도 비활성. 사용자는 KPI/duration 변경 또는 재시도해야 함.

## 4. 정책 (Policy)

### 4-1. 트리거 조건

| 조건 | analyzer 호출 |
|------|--------------|
| KPI 미선택 + duration 미선택 | ❌ |
| KPI만 선택 | ❌ |
| duration만 선택 | ❌ |
| KPI ≥ 1개 **AND** duration ∈ {15,20,25,30} | ✅ 호출 |
| 위 상태에서 옵션 변경 | ✅ 재호출 |

### 4-2. 모듈 리스트 표시 정책

| 항목 | 정책 |
|------|------|
| 모듈 표시 범위 | **전체 모듈 표시** (analyzer 결과로 필터링하지 않음) |
| 미선택 모듈 | 번호 없음, 토글 가능 |
| 선택 모듈 | 번호 표시 (analyzer 순서 기반 자동 정렬) |
| 클릭 순서 | **무관** — 분석 순서가 우선 |

### 4-3. 번호 계산 규칙

분석 결과 시퀀스: `[A, B, C, D, E]`

선택된 모듈을 분석 순서대로 정렬한 인덱스 + 1을 번호로 부여.

```
선택: {C, A}    → 표시: A=[1], C=[2]
선택: {B, D, A} → 표시: A=[1], B=[2], D=[3]
선택: {E}       → 표시: E=[1]
```

### 4-4. 분석 결과에 없는 모듈을 선택할 때 (현재: 풀어둠)

**현 정책: 선택 허용** — 번호 부여 방식은 아래 §6 메모 참조하여 추후 결정.

> **임시 처리**: 선택은 가능하나 번호 표시 방식은 미정. 우선 마지막 번호로 추가하되, 시각적 구분(예: 회색 또는 ★ 마크) 검토.

### 4-5. 로딩 상태

| 시점 | 표시 |
|------|------|
| analyzer 호출 시작 | 모듈 리스트 영역에 스피너 + 그레이아웃 |
| 응답 도착 | 로딩 해제 + 번호 재계산 |
| 호출 중 사용자가 옵션 변경 | 이전 호출 abort + 새 호출 시작 (race condition 방지) |
| 호출 중 모듈 클릭 | 클릭 비활성 |

### 4-6. 분석 실패 시

| 상황 | 동작 |
|------|------|
| HTTP 503 (analyzer DB 끊김) | 모듈 선택 **차단** + 에러 메시지 |
| HTTP 4xx (검증 실패) | 모듈 선택 차단 + 메시지 (실제론 클라 검증으로 차단됨) |
| 네트워크 오류 | 재시도 버튼 + 차단 |
| Timeout | 차단 + 재시도 안내 |

차단 = 모듈 토글 불가 + "수업 들어가기" 버튼 비활성

### 4-7. "수업 들어가기" 진입 조건

```
analyzer 호출 성공 ✅
+ 모듈 1개 이상 선택 ✅
+ KPI ≥ 1개 + duration ∈ {15,20,25,30} ✅ (이미 트리거 조건)
```

## 7. API 입출력 변경 (제안)

### 7-1. 현재 (4/23 구현)

**요청:**
```typescript
POST /lesson-plan
{
  passageId: string,
  modules: string[],     // 사용자가 선택한 모듈
  kpis: string[],
  duration: 15 | 20 | 25 | 30,
}
```

**응답:**
```typescript
{
  sequence: { module_code, name, duration }[],
  total_duration: number,
  filtered_from: number,
  warnings: string[],
}
```

### 7-2. 변경 제안

**요청에서 `modules` 제거** (모듈은 출력이지 입력이 아님):

```typescript
POST /lesson-plan
{
  passageId: string,
  kpis: string[],         // 필수, ≥ 1
  duration: 15 | 20 | 25 | 30,  // 필수
}
```

**응답:** (기존과 동일, 단 `sequence`는 추천 모듈 전체 + 순서)

```typescript
{
  sequence: [
    { module_code: 'WRD', name: '단어 학습', recommended_duration: 7 },
    { module_code: 'ORL', name: '음독',      recommended_duration: 8 },
    ...
  ],
  total_duration: 20,
  filtered_from: 21,      // 전체 중 KPI 매칭 모듈 수
  warnings: [...],
}
```

> 클라이언트는 `sequence` 배열의 인덱스를 참조해서 선택된 모듈에 번호 부여.

**예시:**
```typescript
const sequence = ['WRD', 'ORL', 'PWR', 'WSD'];
const selected = new Set(['ORL', 'WRD']);

// UI 표시
sequence
  .filter(code => selected.has(code))
  .forEach((code, idx) => {
    moduleNumber[code] = idx + 1;
  });
// 결과: WRD = 1, ORL = 2
```
