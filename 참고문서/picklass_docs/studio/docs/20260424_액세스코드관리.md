## 1. 사용자 흐름 (User Flow)

### 액세스코드 목록 조회
1. 강사/기관관리자가 좌측 CourseSidebar에서 "액세스코드 관리" 진입
2. 소속 기관(`institution_id`) 기준으로 전체 액세스코드 목록 로드
3. 상단 통계 (전체 / 수강 중 / 미사용) 표시
4. 기관명 검색 / 코드 검색 / 상태 필터 적용 가능
5. 목록 컬럼 구성 (Option B — 병합 레이아웃):

| 컬럼 | 내용 | 비고 |
|------|------|------|
| # | 일련번호 | `(page-1) × limit + idx + 1` |
| 코드 · 상태 | 액세스코드 + 상태 배지 (2줄 병합) | |
| 역할 | 역할 배지 | `student=학생`, `teacher=강사` |
| 과정명 | 연결 과정명 | |
| 등록만료일 | 코드 등록 가능 기한 | |
| 학습기간 | 사용기간 + 시작일~종료일 (2줄 병합) | |
| 사용자아이디 | 등록한 학생 로그인 ID | |
| 활성일 | `activated_at` | |

### 액세스코드 등록
1. "액세스코드 등록" 버튼 클릭 → 모달 열림
2. 입력 항목:
   - 과정 선택 (선택사항)
   - 생성 개수 (1~1,000)
   - 등록 만료일
   - 사용 기간 (1개월 / 3개월 / 6개월 / 1년 / 2년)
   - **사용 시작일/종료일 직접 설정** (체크박스 토글, 기본값: 미체크)
     - 미체크: 학습자 등록 시점에 자동 계산
     - 체크 시: 시작일 입력 → 종료일 자동 계산 (`startDate + usagePeriodDays`)
     - 사용 기간 변경 시 종료일 재계산
     - 종료일 수동 수정 시 불일치 → 경고 배너 표시
3. 생성 → `POST /access-codes` 호출 → `inactive` 상태로 생성
4. 성공 시 목록 자동 갱신

### 상태 전환 (활성화 ↔ 비활성화)
1. 목록 행 클릭 → 오버레이 노출 (활성화 또는 비활성화 버튼)
2. 다시 클릭 시 오버레이 닫힘
3. 버튼 노출 조건:

| 현재 상태 | 버튼 | 색상 |
|----------|------|------|
| `inactive` | **활성화** | `#4CAF50` (초록) |
| `active` | **비활성화** | `#FF9800` (주황) |
| `completed` / `expired` | 없음 (최종 상태) | — |

4. 버튼 클릭 → 확인 AlertDialog → `PATCH /access-codes/:id/status` 호출
5. `active` 전환 시 `activated_at` 자동 설정, `inactive` 전환 시 `activated_at = null`

> **삭제 기능은 UI에서 제거됨.** 코드 삭제는 백오피스 관리자 화면에서만 가능.

### 과정 리스트에서의 액세스코드 생성
1. 과정 목록 페이지에서 개별 과정의 "액세스코드 생성" 버튼 클릭
2. `POST /courses/:id/access-code` 호출
3. 해당 과정에 연결된 `inactive` 상태 코드 1건 생성
4. 생성된 코드는 액세스코드 관리 목록에 표시됨

## 3. 정책 (Policy / Business Rules)

### 2026-04-24 변경 정책

| # | 정책 | 이전 | 변경 후 |
|---|------|------|---------|
| P1 | 발행 가능 역할 | teacher / student 선택 | **student 고정** |
| P2 | 코드 표시 형식 | `ST-XXXXXX` / `TC-XXXXXX` | **코드 원문 그대로** (`XXXXXX`) |
| P3 | 과정 리스트 생성 코드 초기 상태 | `active` | **`inactive`** |
| P4 | 소유권 판단 기준 | `created_by = user.id` | **`institution_id = user.institutionId`** |
| P5 | 과정 연결 | 없음 | **course_id 연결 가능** (선택사항) |

### 2026-05-26 변경 정책

| # | 정책 | 이전 | 변경 후 |
|---|------|------|---------|
| P6 | 코드 상태 종류 | `active`, `inactive` 2종 | **`inactive`, `active`, `completed`, `expired`** 4종 |
| P7 | UI 상태 전환 범위 | active ↔ inactive (양방향) | **inactive → active (활성화), active → inactive (비활성화)** 만 허용. completed/expired는 최종 상태 |
| P8 | UI 삭제 기능 | 있음 (행 클릭 → 삭제 버튼) | **제거** — 백오피스에서만 관리 |
| P9 | 학습 시작일/종료일 | 학습자 등록 시 자동 계산만 지원 | **코드 생성 시 직접 지정 가능** (미지정 시 기존 자동 계산 유지) |
| P10 | 기관명 검색 필터 | 없음 | **추가** (기관명 부분 검색) |

### 유지되는 정책
- 코드는 6자리 영대문자+숫자 랜덤 생성, 전역 유니크
- 등록 만료일 이후에는 학생이 코드 등록 불가 (tutoring 측 검증)
- `status_code = active` 전환 시 `activated_at` = 현재 시각 자동 기록
- `status_code = inactive` 전환 시 `activated_at = null` 초기화

### 미결 정책 (Tutoring 측 작업 필요)
- **[Tutoring 작업 필요]** 학생이 tutoring에서 액세스코드를 입력하여 등록할 때:
  - `access_codes.status_code` → `'active'`로 업데이트
  - `access_codes.activated_at` → 등록 시각으로 업데이트
  - `access_codes.user_id` → 등록한 학생의 users.id(UUID)로 연결
  - 사전 설정된 `usageStartDate` / `usageEndDate`가 있으면 그대로 사용, 없으면 등록 시점 기준 자동 계산

## 8. DB/API 구조 (Data Contract)

### API 엔드포인트

| Method | Path | 설명 | Auth |
|--------|------|------|------|
| GET | `/access-codes` | 목록 조회 | JWT 필수 |
| POST | `/access-codes` | 코드 생성 | JWT 필수 |
| PATCH | `/access-codes/:id/status` | 상태 변경 | JWT 필수 |
| POST | `/courses/:id/access-code` | 과정 연결 코드 생성 | JWT 필수 |

> `DELETE /access-codes/:id` 는 Studio UI에서 제거됨. 백오피스에서만 사용.

### POST /access-codes — Request Body
```json
{
  "count": 10,
  "registrationExpiry": "2026-12-31",
  "usagePeriodDays": 365,
  "courseId": "uuid-optional",
  "usageStartDate": "2026-01-01",
  "usageEndDate": "2026-12-31"
}
```
> `usageStartDate`, `usageEndDate`는 선택사항. 미입력 시 학습자 등록 시점에 자동 계산.

### GET /access-codes — Query Params
```
institution?: string   // 기관명 부분 검색
search?: string        // 코드 부분 검색
status?: 'inactive' | 'active' | 'completed' | 'expired'
role?: string          // 백엔드 DTO에 존재하나 UI에서 미노출 — D4 참조
page?: number
limit?: number
```

### AccessCodeListResponse
```typescript
{
  data: AccessCode[];
  total: number;
  page: number;
  totalPages: number;
  activeCount: number;
  inactiveCount: number;
  // completedCount, expiredCount 미포함 — 4종 상태 도입 후에도 백엔드에서 미반환, 추후 추가 필요
}
```

### AccessCode 타입 (2026-05-26 기준)
```typescript
// packages/shared/src/types/access-code.ts
export type AccessCodeStatusCode = 'inactive' | 'active' | 'completed' | 'expired';
export type AccessCodeRoleCode = 'teacher' | 'student';

export interface AccessCode {
  id: string;
  code: string;
  institution_id: string;
  institution_name: string | null;         // 서비스 레이어에서 조회 후 첨부
  role_code: AccessCodeRoleCode;           // 항상 'student'로 생성
  user_id: string | null;                  // 학생 등록 후 연결 (UUID)
  course_id: string | null;
  course_title: string | null;             // JOIN 결과 (DB 컬럼 아님, 응답 전용)
  status_code: AccessCodeStatusCode;
  registration_expiry: string;
  usage_period_days: number;
  usage_start_date: string | null;
  usage_end_date: string | null;
  generated_user_id: string | null;
  generated_password: string | null;
  registered_user_login: string | null;    // JOIN 결과 (users.user_id) 응답 전용
  activated_at: string | null;
  created_at: string;
  updated_at: string;
```
