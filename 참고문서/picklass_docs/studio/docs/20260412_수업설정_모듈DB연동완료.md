**작성일**: 2026-04-12  
**버전**: 1.0  
**관련 계획**: `module-db-integration-plan-20260407.md`

---

## 1. User Flow

1. 교사가 수업 설정 페이지(`/class/lesson-setup/[passageId]`) 진입
2. 지문 정보(제목, 레벨, 단어수, 장르) 표시
3. 모듈 그리드가 **Backoffice ai_modules 테이블** 기반으로 렌더링 (로딩 중 spinner)
4. 카테고리별(vocabulary, reading, speaking, writing…) 모듈 표시
5. 모듈 클릭 → 선택/해제, 상단 선택 순서 뱃지 표시
6. "수업 만들기" 클릭 → 선택된 모듈 코드 배열로 수업 생성

---

## 2. IA (정보 구조)

```
/class/lesson-setup/[passageId]
├── 지문 정보 카드 (passageId → useText 조회)
└── 모듈 선택 그리드
    ├── 카테고리 헤더 (vocabulary, reading, speaking …)
    └── 모듈 토글 버튼 (선택 순서 뱃지 포함)
        ├── 아이콘 (MODULE_ICON_MAP에 있으면 표시, 없으면 생략)
        ├── 모듈 코드 (굵게)
        └── 모듈 이름 (작은 글씨)
```

---

## 3. Policy (정책/규칙)

- 모듈 목록은 Backoffice `ai_modules` 테이블에서 `status = 'active'` 인 것만 표시
- Studio에서는 모듈 생성/수정/삭제 불가 (읽기 전용)
- 모듈 아이콘: `MODULE_ICON_MAP`에 코드가 있으면 표시, 없으면 아이콘 없이 텍스트만
- 새 모듈이 Backoffice에 추가되면 `MODULE_ICON_MAP`에 수동으로 아이콘 경로 추가 필요
- 카테고리 색상/아이콘 경로: `vocab` 및 `vocabulary` 둘 다 처리 (API skill 이름 차이 대응)
- API 응답 캐시: 5분 (`staleTime: 5 * 60 * 1000`)

## 4. Dev Tasks (구현 내용)

### 4-1. 하드코딩 모듈 배열 제거

**파일**: `apps/web/src/app/class/lesson-setup/[passageId]/page.tsx`

- 기존 `ModuleItem[]` 타입 + 10개 모듈 하드코딩 배열 완전 삭제
- `useModuleCategories` import 추가 → `const { moduleCategories } = useModuleCategories()`
- `allModules` useMemo 추가: 카테고리 맵을 `{ code, name, skill }[]` flat 리스트로 변환

```typescript
const allModules = useMemo(
  () =>
    Object.entries(moduleCategories).flatMap(([skill, categoryData]) =>
      categoryData.modules.map((m) => ({ code: m.code, name: m.name, skill })),
    ),
  [moduleCategories],
);
```

## 5. Coding Rules

- `allModules`는 `moduleCategories`에 의존하는 `useMemo` — 직접 state 관리 금지
- `MODULE_ICON_MAP`은 페이지 파일 최상단 상수로 선언 (컴포넌트 외부)
- `vocabulary` / `vocab` 양쪽을 항상 switch/case에서 처리할 것
- 모듈 고유 키: `module.code` (기존 `module.id` 아님)
- 로딩 조건: `isLoading || allModules.length === 0` — 둘 다 체크

## 6. Known Issues

- **아이콘 없는 신규 모듈**: Backoffice에서 모듈이 추가되어도 `MODULE_ICON_MAP`에 없으면 아이콘 없이 표시됨. 아이콘 파일 추가 + Map 등록 필요.
- **카테고리 순서**: API가 반환하는 `categories` 객체의 키 순서에 의존. 명시적 순서 보장이 필요하면 정렬 로직 추가 필요.

## 8. DB / API

### GET /modules

**응답 타입**:
```typescript
interface ModuleListResponse {
  data: AiModuleItem[];
  categories: Record<string, AiModuleItem[]>;
}

interface AiModuleItem {
  id: string;
  skill: string;
  code: string;
  name: string;
  priority: number;
  suitable_level_min: string;
  suitable_level_max: string;
  prerequisites: string[];
  incompatible_with: string[];
  learning_objectives: string[];
}
```

**필터**: `status = 'active'`, `deleted_at IS NULL`  
**정렬**: `skill ASC`, `priority ASC`

### Studio Prisma schema 변경

**파일**: `apps/api/prisma/schema.prisma`

`ai_modules` 모델에 `learning_objectives` 필드 추가 (Backoffice 마이그레이션 `20260412000000_add_learning_objectives`와 동기화):

```prisma
learning_objectives  String[] @default([])
```

> 컬럼은 Backoffice 마이그레이션으로 이미 존재 → Studio에서는 `prisma generate`만 실행 (마이그레이션 불필요)

**실행 명령**: `cd apps/api && npx prisma generate`
