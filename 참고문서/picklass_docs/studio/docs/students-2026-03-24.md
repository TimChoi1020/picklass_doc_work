## 1. 사용자 흐름 (User Flow)

### 1-1. 목록 조회
1. 좌측 사이드바(Course Hub) → **학생 아이디 관리** 클릭 → `/course/students` 진입
2. 역할 / 소속 / 이름 / 아이디 / 상태 필터로 목록 검색
3. 초기화 버튼으로 필터 전체 리셋
4. 페이지당 10건, `SimplePagination` 으로 페이지 이동

### 1-2. 학생 단건 등록 (학생 등록)
1. 우상단 **학생 등록** 버튼 클릭 → Dialog 모달 열림
2. 학생 아이디 직접 입력 **또는** 랜덤생성 버튼으로 자동 생성
   - 생성 규칙: `{STUDIO_CODE}{serial:3자리}@{STUDIO_CODE}.pick` (예: `pkls013@pkls.pick`)
3. **중복확인** 버튼 필수 → 통과 전까지 등록 불가
4. 초기 임시 비밀번호, 이름 입력
5. 등록 → `toast.success` 알림, 목록에 즉시 반영

### 1-3. 학생 정보 수정
1. 목록의 행 클릭 → 오버레이에 **수정** 버튼 노출
2. **수정** 클릭 → Dialog 모달 열림
3. 이름, 상태 변경 가능 (아이디는 읽기 전용)
4. 비밀번호 초기화 체크박스 선택 시 새 비밀번호 입력 필드 활성화
5. 저장 → `toast.success` 알림, 목록 즉시 반영

### 1-4. 학생+액세스코드 일괄 등록
1. 우상단 **학생+액세스코드 등록** 버튼 클릭 → Dialog 모달 열림
2. 사용자 유형 고정 (학생만)
3. 생성할 아이디 개수 입력 → 일련번호 이어서 자동 생성
4. 액세스코드도 함께 생성 체크박스 선택 시 등록만료일 + 사용기간 추가 입력
5. 생성 → `toast.success` 알림, 목록에 즉시 반영

## 3. 정책 (Policy / Business Rules)

### 아이디 생성 규칙
- 형식: `{STUDIO_CODE}{serial:3자리}@{STUDIO_CODE}.pick`
- `STUDIO_CODE` = `pkls` (현재 하드코딩)
- 일련번호는 기존 목록에서 최대값 + 1 로 계산
- 아이디 변경 불가 (등록 후 읽기 전용)

### 중복 확인
- 단건 등록 시 중복확인을 완료하지 않으면 등록 버튼 제출 차단
- 중복 확인은 **현재 클라이언트 목록** 기준으로만 검사 (→ 미구현: 서버 실시간 확인)

### 상태 정책
| 상태 코드 | 표시명 | 의미 |
|-----------|--------|------|
| `active` | 활성 | 정상 이용 중 |
| `suspended` | 정지 | 이용 정지 상태 |
| `withdrawn` | 탈퇴 | 탈퇴 처리됨 |

### 일괄 등록 정책
- 사용자 유형은 **학생(`student`)만** 허용
- 이름은 `신규학생{serial}` 형태로 자동 생성 (이후 수정 가능)
- 액세스코드 함께 생성 옵션은 선택 사항이나, 선택 시 만료일·사용기간 모두 필수

### 정책 변경 이력
| 날짜 | 변경 내용 |
|------|-----------|
| 2026-03-24 | 테이블 컬럼에 역할/소속 추가, 번호 컬럼 제거 |
| 2026-03-24 | 필터에 역할/소속 검색 추가 |
| 2026-03-24 | 학생+액세스코드 일괄 등록 기능 추가 |
| 2026-03-24 | 일괄 등록 사용자 유형을 학생 전용으로 고정 |

## 8. DB/API 구조 (Data Contract)

### 현재 목표 API 엔드포인트 (미연동, 설계 기준)

#### GET `/users`
```typescript
// Request Query
{
  page: number;
  limit: number;
  role?: 'student' | 'teacher';
  institutionId?: string;
  name?: string;
  userId?: string;
  status?: 'active' | 'suspended' | 'withdrawn';
}

// Response
{
  data: UserResponse[];
  pagination: {
    total: number;
    totalPages: number;
    page: number;
    limit: number;
  };
}
```

#### POST `/users`
```typescript
// Request Body
{
  roleCode: 'student' | 'teacher';
  institutionId: string;
  userId: string;          // 지정 아이디
  tempPassword: string;    // 초기 임시 비밀번호
  name: string;
}

// Response
UserResponse
```

#### POST `/users/bulk`
```typescript
// Request Body
{
  roleCode: 'student';     // 학생 전용
  institutionId: string;
  count: number;           // 생성 개수 (1~1000)
  withAccessCode: boolean;
  registrationExpiry?: string;  // withAccessCode=true 시 필수
  usagePeriodDays?: number;     // withAccessCode=true 시 필수
}

// Response
{
  users: UserResponse[];
  accessCodes?: AccessCodeResponse[];  // withAccessCode=true 시 포함
}
```

#### PUT `/users/:id`
```typescript
// Request Body
{
  name?: string;
  status?: 'active' | 'suspended' | 'withdrawn';
  newPassword?: string;    // 비밀번호 초기화 시
}

// Response
UserResponse
```

#### GET `/users/check-duplicate`
```typescript
// Request Query
{ userId: string; }

// Response
{ available: boolean; }
```

### 인터페이스/타입 정의

```typescript
interface UserResponse {
  id: string;
  role: 'student' | 'teacher';
  name: string;
  userId: string;          // 이메일 형식 아이디 (예: pkls001@pkls.pick)
  institution: string;     // 기관명 (표시용)
  institutionId: string;   // 기관 ID (연동용)
  status: 'active' | 'suspended' | 'withdrawn';
  createdAt: string;       // ISO 8601 또는 YYYY-MM-DD
}

// 단건 등록 폼
interface RegisterForm {
  userId: string;
  tempPassword: string;
  name: string;
}

// 수정 폼
interface EditForm {
  userId: string;          // 읽기 전용
  name: string;
  status: 'active' | 'suspended' | 'withdrawn';
  newPassword: string;     // 비밀번호 초기화 선택 시
}

// 일괄 등록 폼
interface BulkRegisterForm {
  roleCode: 'student';     // 학생 고정
  idCount: string;
  withAccessCode: boolean;
  registrationExpiry: string;
  usagePeriodCode: '1m' | '3m' | '6m' | '1y' | '2y';
}

type UserStatus = 'active' | 'suspended' | 'withdrawn';
type UserRole = 'student' | 'teacher';
```
