## 1. 배경 및 목표

backoffice에서 관리되는 과정 카테고리(L1/L2)를 studio에서:
1. **CourseSidebar**: 폴더 UI로 탐색·필터링
2. **과정 편집 페이지**: 과정에 카테고리 배정

강사는 카테고리를 **선택**만 한다. 생성·수정·삭제는 backoffice 전담.

### 역할 분리 요약

| 주체 | 행위 | 위치 |
|------|------|------|
| 파트너 관리자 | 파트너 L1/L2 생성·수정·삭제 | backoffice |
| backoffice 관리자 | 모든 파트너 카테고리 열람·관리 | backoffice |
| **기관 강사** | **과정에 카테고리 배정** | **studio** |

카테고리는 파트너가 소유한다. platform 공통 카테고리는 없다.
파트너에 소속되지 않은 독립 기관은 카테고리를 사용할 수 없으며, studio에서 카테고리 UI가 표시되지 않는다.

---

## 2. 과정 생성 모달과의 관계

**과정 생성 모달에 카테고리 연동은 현재 보류.**
카테고리 배정은 과정 생성 후 **편집 페이지(`/course/[id]`)** 에서 수행한다.
추후 생성 모달에 추가할 경우 별도 플랜으로 분리.

## 3. API 연동

### 3.1 카테고리 목록 조회

```
GET /course-categories          ← studio 자체 API (apps/api)
```

- **✅ 구현 완료 (2026-06-05)**: backoffice API 경유 없이 studio 자체 `apps/api`에 `GET /course-categories` 엔드포인트를 신설
- JWT의 `institutionId` → `institutions` 재귀 CTE로 최상위 파트너 resolve → `course_categories` 직접 조회
- 파트너 없는 기관이면 빈 배열 반환 (카테고리 UI 미표시)
- 구현 위치: `apps/api/src/course-categories/course-categories.service.ts`

```ts
// hooks/use-course-categories.ts (신규)
export function useCourseCategories() {
  // authFetch 사용 — institutionId는 JWT에서 추출
  return useQuery({
    queryKey: ['course-categories'],
    queryFn: () => courseCategoriesApi.list(),
  });
}
```

### 3.2 과정 카테고리 배정

```
PATCH /courses/:id
body: { title, course_focus, l1_category_id: number | null, l2_category_id: number | null }
```

- **✅ 구현 완료 (2026-06-05)**: studio 자체 API (`apps/api/src/courses/`) — backoffice API와 다른 서버
- `UpdateCoursePayload`에 두 필드 추가 완료
- `CourseEditModal` 기본 정보 탭에서 L1/L2 Select → 저장 버튼으로 반영

**⚠ 버그 수정 (2026-06-07) — 총 2차 수정**

초기 구현에서 카테고리 저장이 반영되지 않는 버그 발견 및 수정.

#### 1차 수정 — 프론트엔드 (CourseEditModal.tsx)

| 구분 | 기존 (버그) | 수정 후 |
|------|------------|---------|
| 저장 방식 | `updateMutation`(제목/설명) + 조건부 `updateCategoryMutation`(카테고리) 2-step | `updateMutation` 단일 호출에 `l1_category_id`·`l2_category_id` 포함 |
| 문제 | `updateMutation.onSuccess`의 `invalidateQueries` 타이밍으로 조건 비교가 오작동. 에러 발생 시 toast.success가 먼저 표시됨 | — |
| 에러 처리 | 없음 (unhandled rejection) | try/catch + `toast.error` 추가 |
| 제거된 코드 | `useUpdateCourseCategory` hook 사용 | import 제거, `updateCategoryMutation` 선언 제거 |

수정 파일: `apps/web/src/components/CourseEditModal.tsx` — `BasicInfoTab.handleSave`

#### 2차 수정 — 백엔드 (근본 원인)

1차 수정 후에도 저장되지 않아 추가 확인한 결과, **백엔드 DTO와 서비스에 해당 필드가 누락**된 것이 실제 원인이었다.

| 위치 | 문제 | 수정 |
|------|------|------|
| `apps/api/src/courses/dto/courses.dto.ts` | `UpdateCourseDto`에 `l1_category_id`·`l2_category_id` 필드 없음 → NestJS ValidationPipe(`whitelist: true`)가 요청 바디에서 두 필드를 제거 | `@IsNumber() @IsOptional()` 데코레이터로 두 필드 추가 |
| `apps/api/src/courses/courses.service.ts` | `update()` 메서드의 `updateData` 빌드 로직에 두 필드 처리 없음 | `if (dto.l1_category_id !== undefined)` 등 처리 로직 추가 |

> `null` 전달 시 카테고리 배정 해제도 정상 동작 (`updateData` 타입이 `null` 허용).

## 5. 과정 목록 필터 연동

`course/page.tsx`의 `useCoursesList` 쿼리에 카테고리 필터 파라미터 추가.

```ts
// 추가할 state
const [filterL1Id, setFilterL1Id] = useState<number | null>(null);
const [filterL2Id, setFilterL2Id] = useState<number | null>(null);

// useCoursesList 호출 시 추가
const { data: coursesData } = useCoursesList({
  ...
  l1_category_id: filterL1Id ?? undefined,
  l2_category_id: filterL2Id ?? undefined,
});
```

L1 선택 시 → L2 필터 초기화.
"전체 보기" 선택 시 → L1, L2 모두 null.

## 6. 과정 편집 페이지 — 카테고리 배정 UI

`/course/[id]` 편집 페이지에 카테고리 섹션 추가.

```
[카테고리]  ───────────────────────────────────

  대카테고리 (L1)          중카테고리 (L2)
  ┌───────────────────┐   ┌──────────────────────┐
  │ 생활영어       ▾  │   │ 패턴영어 1권       ▾ │
  └───────────────────┘   └──────────────────────┘

  ※ L1 선택 후 L2 목록이 활성화됩니다.
  ※ L2는 선택하지 않아도 됩니다.
```

- L1 Select → L2 Select 활성화 (L1 미선택 시 L2 비활성)
- L2는 선택 사항 (필수 아님)
- 저장: 기존 과정 저장 버튼과 통합 (`PATCH /courses/:id` 호출)
