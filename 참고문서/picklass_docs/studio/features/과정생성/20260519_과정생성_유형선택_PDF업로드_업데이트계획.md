## 3. 과정 유형별 모듈 범위

| 과정 유형 | 코드 | 허용 모듈 카테고리 |
|---|---|---|
| 튜터링과정 | `tutoring` | **Speaking을 제외한 모든 스킬** (현재: V/R/W, 향후 스킬 추가 시 자동 포함) |
| 스피킹과정 | `speaking` | Speaking(S) 전용 |
| 통합과정 | `integrated` | 전체 스킬 |

> **튜터링 모듈 범위 설계 원칙**: `speaking` 스킬을 명시적으로 제외하는 방식으로 구현.  
> 향후 새 스킬(`grammar`, `listening` 등)이 추가되더라도 별도 코드 수정 없이 튜터링에 자동 포함된다.  
>
> 과정 유형(`course_type`)은 `courses` 테이블 컬럼으로 관리한다.  
> 회차별 모듈 선택 UI 및 KPI 목표 선택 UI에서 `courseType`에 맞지 않는 항목은 비활성화 또는 숨김 처리한다.  
>
> **구현 완료** (2026-05-19): KPI 목표 필터링 — `ai_modules.selected_kpi_codes` 역방향 매핑으로 KPI ↔ skill 연결. `kpiSkillFilter()` 함수로 과정 유형별 필터 적용.

### 3-1. 시퀀싱 로직 변경 — 스피킹 모듈 배치 순서

**규칙**: 스피킹 모듈(`skill === 'speaking'`)은 동일 회차 내 다른 모든 스킬 모듈보다 **후순위**로 배치한다.

```
회차 내 모듈 배치 순서 (예시)
────────────────────────────────
1. Vocabulary
2. Reading
3. Writing
4. (기타 비스피킹 스킬)
...
N. Speaking   ← 항상 마지막
────────────────────────────────
```

**적용 대상**: `courseType === 'integrated'` (스피킹과 비스피킹 모듈이 혼재하는 경우).  
`courseType === 'speaking'` 단독 과정은 스피킹 모듈만 존재하므로 해당 없음.

**구현 위치**: 시퀀싱 엔진 결과 정렬 로직 (백엔드 lesson-plan 서비스 또는 프론트엔드 시퀀싱 결과 렌더링 시 재정렬).

```ts
// 정렬 예시 (프론트엔드 또는 백엔드 공통 적용 가능)
sequence.sort((a, b) => {
  const aIsSpeaking = a.skill === 'speaking' ? 1 : 0;
  const bIsSpeaking = b.skill === 'speaking' ? 1 : 0;
  if (aIsSpeaking !== bIsSpeaking) return aIsSpeaking - bIsSpeaking;
  return a.order - b.order;
});
```

**작업 항목**: Phase 2-A 순서 테이블에 추가 (순서 5-1).

## 4. 교재 PDF 업로드 과정 생성 — 상세 설계

### 4-0. 요구사항 정의 (Phase 2)

| 구분 | 현재 (Phase 1) | 확장 (Phase 2) |
|---|---|---|
| 진입 방식 | 주제 입력 (Step 1) | 교재 PDF 업로드 추가 (Step 0-B 분기) |
| 콘텐츠 출처 | 주제 기반 LLM 생성 | 교재 유닛 추출 → DB 저장 → 모듈에 주입 |
| 회차 단위 | 강사 직접 설정 | 교재 유닛 1개 = 회차 1개 (자동 매핑) |
| LLM 사용 | 모듈 첫 진입 시 content_generation → module_questions | textbook 데이터 있으면 LLM 호출 0회 |

**요구사항 ③-1 유닛 단위 회차 자동 생성**

| 항목 | 내용 |
|---|---|
| 업로드 포맷 | PDF (DOC/DOCX는 향후 확장 가능) |
| 유닛 분할 | PDF → 유닛 자동 분할 → 각 유닛 = 1 회차로 매핑 |
| 진입점 | Step 0-B → 교재 PDF 업로드 선택 시 Step 1-P로 분기 |

**요구사항 ③-2 textbook 테이블** — 유닛별 콘텐츠 사전 저장 (§4-2 참조)

**요구사항 ③-3 module_questions 생성 로직 갱신** — textbook 데이터 우선 활용 (§5 참조)

### 4-2. textbook 테이블 DDL (안)

```sql
CREATE TABLE textbooks (
  id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  course_id           UUID        REFERENCES courses(id) ON DELETE CASCADE,
  text_id             UUID        REFERENCES texts(id) ON DELETE SET NULL,
  unit_number         INTEGER     NOT NULL,
  unit_title          VARCHAR(500),
  source_filename     VARCHAR(1000),           -- 원본 PDF 파일명
  keywords            JSONB,                   -- [{word, definition, example}]
  key_expressions     JSONB,                   -- [{expression, meaning, example}]
  dialogues           JSONB,                   -- [{speaker, line}]
  comprehension_items JSONB,                   -- [{question, options[], answer, explanation}]
  raw_content         TEXT,                    -- 원본 유닛 전체 텍스트 (파싱 원문 보존)
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  CONSTRAINT uq_textbooks_course_unit UNIQUE (course_id, unit_number)
);

CREATE INDEX idx_textbooks_course_id ON textbooks(course_id);
CREATE INDEX idx_textbooks_text_id   ON textbooks(text_id);
```

## 5. module_questions 생성 시 textbook 데이터 활용

### 5-1. 현재 흐름

```
학생 첫 진입 → module_questions 없음
    → content_generation 프롬프트로 LLM 호출
    → module_questions 저장

학생 재진입 → module_questions 있음 → DB에서 로드 (LLM 미사용)
```

### 5-2. 변경 후 흐름

```
학생 첫 진입 → module_questions 없음
    → textbooks에 해당 text_id 데이터 존재?
        ┌── YES ──→ textbooks 데이터로 module_questions 직접 생성
        │            (LLM 호출 없음 or 최소화)
        └── NO  ──→ 기존 content_generation 프롬프트 → LLM 생성
    → module_questions 저장

학생 재진입 → module_questions 있음 → DB에서 로드 (변경 없음)
```

### 5-3. 모듈 유형별 textbook → module_questions 매핑

| 모듈 유형 | textbook 소스 필드 | 비고 |
|---|---|---|
| Vocabulary | `keywords` | word/definition → 뜻 확인해서 저장(교재에 있는 경우만) |
| Reading Comprehension | `comprehension_items` | 직접 사용 (Q&A 그대로) |
| Writing | `key_expressions` | 핵심 표현 그대로 저장(교재에 있는 경우만)  |
| Speaking | `dialogues` | 대화문 그대로 저장(교재에 있는 경우만) |

> 변환 로직은 기존 `content_generation` 프롬프트 구조를 유지하되,  
> 프롬프트 입력에 textbook 데이터를 컨텍스트로 주입하는 방식으로 구현.  
> LLM 호출이 완전 제거되지 않더라도 입력이 명확하므로 토큰/비용이 크게 감소.

### Option B — 마이크 모드

| 모드 | 동작 | 권장 사용 |
|---|---|---|
| **Push to talk (PTT)** | 학습자가 버튼을 누른 동안만 녹음 | 공공장소·소음 환경 / **기본값** |
| **Hybrid** | 기본 자동 인식, 학습자가 PTT로 강제 끄기 가능 | 일반 환경 |

- **기관설정 연동**:

```ts
type MicMode = 'push_to_talk' | 'hybrid' | 'always_on';
const [micMode, setMicMode] = useState<MicMode>('push_to_talk');
const [micModeUserChange, setMicModeUserChange] = useState(true);
```

### Option C — 과정 이수 조건

- 결합 방식: **체크한 조건만 AND로 적용**. 체크 해제한 조건은 무시됨. OR 결합은 Phase 2 (v1.15+) 검토.

| 지표 | 단위 | 기본 임계값 | 활성 조건 | 적용 범위 |
|---|---|---|---|---|
| 레슨이수율 | % | ≥ 70% | 항상 활성 | 전체 레슨 중 완료 비율 |
| 발화량 (sentences) | 누적 문장 수 | ≥ 200 | **Speaking 모듈 포함 시에만 활성** (`courseType === 'speaking' \|\| 'integrated'`). 비해당 시 `disabled`+툴팁("Speaking 모듈이 없는 과정은 설정 불가") | 전 모듈 발화 누적 |
| 누적 수업시간 (minutes) | 분 | 기관 `completionDefaults.minutes` (미설정 시 미적용) | 항상 활성 | 학습자 총 수업 참여 시간 |

```ts
const [completionLessonRate, setCompletionLessonRate] = useState(70);           // %
const [completionSentences, setCompletionSentences] = useState<number | null>(200); // null = 미적용
```

4. **textbook 콘텐츠 수정 권한**: PDF 파싱 후 콘텐츠 수동 편집 UI 필요 여부.
