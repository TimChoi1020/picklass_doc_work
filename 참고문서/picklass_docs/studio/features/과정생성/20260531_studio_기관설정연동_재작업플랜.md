## 1. 팀 컨트랙트 (정확 명세 — studio가 맞춰야 할 대상)

### 1-1. 테이블 `institution_settings` (institution과 1:1, `type='institution'`만)

| 컬럼 (DB) | Prisma 필드 | 타입 | 의미 | null 의미 |
|---|---|---|---|---|
| `max_total_class_minutes` | maxTotalClassMinutes | Int? | 전체 수업시간 상한(분) | **무제한** |
| `max_frt_module_minutes` | maxFrtModuleMinutes | Int? | FRT 시간 상한(분) | **무제한** |
| `default_completion_sentences` | defaultCompletionSentences | Int? | 발화량 기본값(문장) | **이수조건 미체크** |
| `default_completion_lesson_rate` | defaultCompletionLessonRate | Int? | 레슨이수율 기본값(%) | **이수조건 미체크** |
| `default_completion_minutes` | defaultCompletionMinutes | Int? | 누적 수업시간 기본값(분) | **이수조건 미체크** |
| `free_learning_enabled` | freeLearningEnabled | Boolean | 자유학습(나만의수업) 허용 | (기본 false) |
| `allowed_mic_modes` | allowedMicModes | text[] | 허용 마이크 모드 (**최소 1**) | — |
| `mic_mode_user_change` | micModeUserChange | Boolean | 학습자 마이크 변경 허용 | (기본 true) |

### 1-2. backoffice API (참고 — studio가 호출하지는 않음, 1-4 참조)

```
GET  /institutions/:id/settings  → InstitutionSettingsResponse  (없으면 기본값 행 자동 생성 후 반환)
PUT  /institutions/:id/settings  → 저장 (backoffice 관리자 전용)
```
- **getSettings는 행이 없으면 기본값 레코드를 lazy 생성**한다 → 모든 기관은 항상 설정을 가진다고 봐도 됨.

### 1-3. 설정값이 studio 과정 생성에 적용되는 방식

| 설정 | studio 동작 | 성격 |
|---|---|---|
| maxTotalClassMinutes | 초과하는 수업시간 프리셋 **비활성** | 하드 제한 |
| maxFrtModuleMinutes | 초과하는 FRT 프리셋 **비활성** | 하드 제한 |
| allowedMicModes | 목록에 없는 마이크 모드 버튼 **비활성** | 하드 제한 |
| freeLearningEnabled=false | 자유학습 "허용" **잠금** | 하드 제한 |
| defaultCompletion*(null=미체크) | 이수조건 체크상태·값 **초기 pre-fill** (강사 수정 가능) | 소프트 |
| micModeUserChange | "학습자 변경 허용" 체크박스 **초기값** (강사 수정 가능) | 소프트 |

> 핵심: 과정 저장 후 값은 과정에 **독립 복사**되어, 이후 기관설정이 바뀌어도 기존 과정엔 영향 없음.

### 1-4. studio가 설정을 읽는 방법 — **DB 직접 읽기 (권장)**

- studio는 이미 `institutions`를 자기 Prisma로 직접 읽는다(공유 DB). 동일 패턴으로 `institution_settings`를 **studio Prisma로 직접 조회**한다.
- 대안(B: backoffice API 호출)은 백엔드 간 호출·인증이 얽혀 복잡 → 채택하지 않음.
- studio는 **읽기 전용**. 쓰기는 backoffice만.

## 4. 단계별 작업 플랜

### Step 1 — studio 스키마 동기화
- `apps/api/prisma/schema.prisma`:
  - `institutions` 모델에서 내가 넣은 `class_settings Json?` **제거**.
  - **`InstitutionSettings` 모델 추가** (팀 테이블 미러, `@@map("institution_settings")`, 필드 1-1 그대로, `institutionId @unique`).
  - `institutions` 모델에 `settings InstitutionSettings?` 관계 추가(선택).
- `pnpm prisma:generate` 로 클라이언트 갱신.
> ⚠️ studio `institutions` 모델은 팀 마이그레이션으로 **이미 드리프트**(branch_count 등 드롭, member_status_code→status_code 등). 이번 범위(설정 읽기)는 영향 없지만, 별도로 studio institutions 모델 전체를 팀 DB에 맞추는 정리가 필요(§7 참조).

### Step 2 — 공유타입 정렬
- `packages/shared/src/types/class-settings.ts`의 `InstitutionClassSettings`를 **팀 shape**로 교체:
  ```ts
  export interface InstitutionClassSettings {
    maxTotalClassMinutes: number | null;
    maxFrtModuleMinutes: number | null;
    defaultCompletionSentences: number | null;   // null = 미체크
    defaultCompletionLessonRate: number | null;  // null = 미체크
    defaultCompletionMinutes: number | null;      // null = 미체크
    freeLearningEnabled: boolean;
    allowedMicModes: MicMode[];
    micModeUserChange: boolean;
  }
  ```
  (`*Enabled` 불리언 제거). `CourseOptions`/`SpeakingOptions`/`CourseType`/`MicMode`는 유지.
- `pnpm --filter @classsnap/shared build`.

### Step 3 — studio 읽기 서비스 교체
- `apps/api/src/institutions/institutions.service.ts`:
  - `prisma.institutions.findFirst({select:{class_settings}})` → **`prisma.institutionSettings.findUnique({ where:{ institutionId } })`**.
  - 없으면 기본값(제한 없음/미체크) 폴백 반환. (백오피스가 lazy 생성하지만 studio는 읽기 전용이므로 안전하게 폴백.)
  - `select`만 사용해 드리프트된 institutions 컬럼은 건드리지 않음.

### Step 4 — 과정 생성 화면 로직 정렬 (`apps/web/src/app/course/page.tsx`)
- 설정 → 폼 초기화 매핑을 **null=미체크** 기준으로:
  - `completionLessonCheck = settings.defaultCompletionLessonRate !== null`
  - `completionLessonRate  = settings.defaultCompletionLessonRate ?? 70`
  - `completionSentEnabled = settings.defaultCompletionSentences !== null`
  - `completionSentences   = settings.defaultCompletionSentences ?? 200`
  - `completionMinEnabled  = settings.defaultCompletionMinutes !== null`
  - `completionMinutes     = settings.defaultCompletionMinutes`
- 하드 제한 그대로: 수업시간/ FRT 프리셋 `> max → 비활성`, `allowedMicModes` 미포함 비활성, `freeLearningEnabled=false`면 "허용" 잠금, `micModeUserChange` 초기값.

### Step 5 — 서버 한도 재검증 정렬 (`apps/api/src/courses/courses.service.ts`)
- `assertWithinInstitutionLimits`가 **institution_settings 테이블**을 읽도록 교체(Step 3 서비스 재사용 또는 동일 조회).
- 검증 항목 동일: max_total_class_minutes 초과 / max_frt_module_minutes 초과 / allowed_mic_modes 미포함 / freeLearningEnabled=false인데 자유학습 ON → 400.

### Step 6 — 빌드 + 런타임 재검증
- 빌드: shared / api(nest) / web(tsc) 전부 통과.
- 런타임(이전 JSONB 기준 검증은 무효 → 재실행):
  - teacher 로그인 → `GET /institutions/settings`가 **institution_settings 테이블 값** 반환.
  - 한도 초과/비허용 마이크/자유학습 위반 과정 생성 → 400.
  - 정상 생성 → course_type/course_options/speaking_options 저장.
  - (analyzer 가동 시) 스피킹 후순위 정렬 유지 확인.

## 7. 주의 / 열린 이슈
1. **studio institutions 모델 드리프트(별건, 범위 밖)**: 팀 마이그레이션이 institutions 컬럼을 다수 드롭/이름변경했다. studio의 institutions 모델은 아직 옛 컬럼을 가진다. 이번 설정 연동은 `select` 한정으로 영향 없지만, studio가 institutions 전체 컬럼을 읽는 다른 경로가 있으면 깨질 수 있음 → **studio prisma의 institutions 모델을 팀 DB에 맞추는 정리 작업을 별도 진행 권장.**
2. **잔재 컬럼 `institutions.class_settings`**: 내가 추가했던 컬럼이 공유 DB에 남아 있을 수 있음(무해). 정리하려면 backoffice와 협의해 DROP.
3. **설정 읽기 방식 확정**: 본 플랜은 §1-4 (A) studio Prisma 직접 읽기를 채택. backoffice API 경유(B)를 원하면 Step 3 변경.
4. **계층(partner/group) 설정 없음**: 설정은 institution 레벨만. studio 강사는 자기 institution의 설정만 사용.
