## 2. 신규 테이블: `user_login_logs`

### DDL 파일

```
tutoring.picklass.com/apps/api/prisma/manual-sql/2026-05-27_user_login_logs.sql
```

> **⚠️ Supabase Studio에서 직접 실행 필수** — `prisma migrate` / `prisma db push` 사용 금지.

### 스키마

```sql
CREATE TABLE user_login_logs (
  id              UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID         NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  institution_id  UUID         REFERENCES institutions(id) ON DELETE SET NULL,
  logged_in_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

### 인덱스

| 이름 | 컬럼 | 용도 |
|---|---|---|
| `idx_ull_user_id` | `user_id` | 학습자별 단순 조회 |
| `idx_ull_logged_in_at` | `logged_in_at DESC` | 날짜 범위 필터 |
| `idx_ull_user_date` | `(user_id, logged_in_at DESC)` | 학습자 × 기간 복합 조회 |
| `idx_ull_inst_date` | `(institution_id, logged_in_at DESC)` | 기관별 출석 집계 핵심 |

## 3. 코드 변경: `auth.service.ts`

**파일**: `apps/api/src/auth/auth.service.ts`  
**위치**: `login()` 메서드 — `last_login_at` UPDATE 직후

### 변경 내용

```typescript
// ─── 기존 코드 (유지) ────────────────────────────────────────────
const rows = await this.prisma.$queryRawUnsafe<UserRow[]>(
  `SELECT id, email, name, role_code, institution_id, password_hash, status_code
   FROM users WHERE user_id = $1 AND deleted_at IS NULL LIMIT 1`,
  userId,
);
const user = rows[0];

// 마지막 로그인 + 활동 시간 업데이트 (기존)
await this.prisma.$executeRawUnsafe(
  `UPDATE users SET last_login_at = NOW(), last_active_at = NOW() WHERE id = $1::uuid`,
  user.id,
);

// ─── 신규 추가 ───────────────────────────────────────────────────
// 로그인 이력 기록 (출석률 집계용 + 앱 구분)
await this.prisma.$executeRawUnsafe(
  `INSERT INTO user_login_logs (user_id, institution_id, app_code, logged_in_at)
   VALUES ($1::uuid, $2::uuid, $3, NOW())`,
  user.id,
  user.institution_id ?? null,  // users.institution_id — 미소속(관리자 등)은 NULL
  'tutoring',
);
```

### 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| Prisma 모델 추가 여부 | ❌ 추가 안 함 | `user_login_logs`는 INSERT 전용 — raw SQL로 충분 |
| `institution_id` 출처 | `users.institution_id` (동일 SELECT에서 조회) | 별도 쿼리 없이 로그인 흐름 그대로 활용 |
| `institution_id` NULL | 허용 — `users.institution_id`가 NULL이면 NULL 저장 | 관리자 계정 등 미소속 사용자 포함 |
| 오류 처리 | INSERT 실패 시 로그인 자체는 중단하지 않음 | 출석 기록은 부가 기능, 로그인 UX 영향 없어야 함 |

> **주의**: 현재 코드는 INSERT 실패 시 로그인 전체가 실패한다. 향후 try/catch로 분리를 고려할 수 있다.

tutoring 앱에서 로그인 후 Supabase Studio에서 확인:

## 6. 알려진 제약

- **소급 불가**: `user_login_logs` 기록 시작일 이전 로그인 이력 없음. backoffice 출석률 UI에 "이전 데이터 없음" 안내 표시.
- **INSERT 오류 시**: 현재 로그인 트랜잭션 전체 실패. 향후 분리 고려.
- **tutoring schema.prisma**: `UserLoginLog` 모델 없음 (의도적). 필요 시 추가 가능.
- **speaking.picklass.com**: 동일 DB를 공유하며 speaking의 로그인에도 INSERT 추가 완료 (app_code='speaking').
