## 증상

CLR 모듈에서 "완료하기" 버튼을 누르면 KPI 결과 카드가 표시되지 않고 즉시 다음 모듈로 전환된다.

---

## 근본 원인 (이중 구조)

### 원인 1: backoffice에서 `selected_kpi_codes` 미설정
`buildKpis()` (`GenericAdapter`)는 `this.moduleConfig.selectedKpiCodes.map(...)` 을 반환하므로,
CLR 모듈의 `selected_kpi_codes`가 비어 있으면 kpis 배열이 `[]`가 되어 KPI 카드 블록이 스킵된다.

**해결**: backoffice에서 CLR 모듈에 `READING_COMPLETE` KPI 코드를 추가 (DB 작업, 코드 변경 아님).

### 원인 2: embedded 콜백이 `onModuleComplete`를 즉시 호출 (코드 버그) ← 주 원인
`LessonSession.tsx`의 embedded 완료 콜백에서 `onModuleSave`와 `onModuleComplete`를 연속 호출했다.

```
완료하기 클릭
→ handleManualComplete() [useEmbeddedMode]
  → completedRef.current = true
  → onComplete(explainedCount, totalCount)
    → [embedded callback]
      → onModuleSave(result, ...)     ← fire-and-forget (결과 무시)
      → onModuleComplete(result, ...) ← 즉시 페이지 전환
```

`onModuleComplete` 호출이 즉시 다음 모듈로 이동시키므로 FeedbackPanel이 KPI 카드를
렌더링할 시간이 없었다. 또한 `handleModuleNext`는 `completedRef.current === true`(이미 설정됨)
+ `!moduleResult`(CLR에서는 orchestrator가 설정 안 함) 조건으로 bail out되어 "다음" 버튼도 동작 안 했다.

## 수정 내용 (`LessonSession.tsx`)

### 1. `embeddedResult` 상태 추가 (line ~608)

```typescript
const [embeddedResult, setEmbeddedResult] = useState<ModuleResult | null>(null);
```

### 2. embedded 콜백 변경 (line ~785)

Before:
```typescript
onModuleSave(result, messages, currentPlannedModule.order);
onModuleComplete(result, messages, currentPlannedModule.order);
```

After:
```typescript
onModuleSave(result, messages, currentPlannedModule.order)
  .then((finalKpis) => { if (finalKpis) setSavedKpis(finalKpis); });
setEmbeddedResult(result);  // FeedbackPanel 표시용 — 즉시 이동하지 않음
```

`onModuleComplete` 제거 → `setEmbeddedResult`로 KPI 결과 카드 표시.
`onModuleSave` 반환값(LLM KPI 평가 결과)을 `.then`으로 받아 `savedKpis` 업데이트.

### 3. `handleModuleNext` 수정 (line ~700)

Before:
```typescript
const handleModuleNext = useCallback(() => {
  if (completedRef.current || !moduleResult) return;  // CLR: 둘 다 true → bail out
  completedRef.current = true;
  ...
}, [...]);
```

After:
```typescript
const handleModuleNext = useCallback(() => {
  const result = moduleResult ?? embeddedResult;  // CLR: embeddedResult 사용
  if (!result) return;
  completedRef.current = true;
  const resultToComplete = savedKpis ? { ...result, kpis: savedKpis } : result;
  onModuleComplete(resultToComplete, messages, currentPlannedModule.order);
}, [moduleResult, embeddedResult, savedKpis, ...]);
```

### 4. `isCompleted`, `displayModuleResult`, `onNext` 수정

```typescript
// isCompleted: embedded 완료도 포함
const isCompleted = !!(moduleResult || embeddedResult || replanSignal);

// displayModuleResult: embedded 결과도 표시
const effectiveResult = moduleResult ?? embeddedResult;
const displayModuleResult = savedKpis && effectiveResult
  ? { ...effectiveResult, kpis: savedKpis }
  : effectiveResult;

// onNext/onModuleNext props: embedded 완료 후 "다음" 버튼 활성화
onNext={(moduleResult ?? embeddedResult) ? handleModuleNext : undefined}
onModuleNext={(moduleResult ?? embeddedResult) ? handleModuleNext : undefined}
```

## 수정 후 CLR 흐름

```
완료하기 클릭
→ handleManualComplete()
  → completedRef.current = true
  → embedded callback
    → onModuleSave(result, ...).then(setSavedKpis)  ← KPI 평가 결과 수신
    → setEmbeddedResult(result)                     ← FeedbackPanel 렌더링 트리거

FeedbackPanel 표시:
  → displayModuleResult = effectiveResult (embeddedResult)
  → KPI 카드 렌더링
  → "다음" 버튼 활성화 (onNext prop이 handleModuleNext로 설정됨)

다음 클릭
→ handleModuleNext()
  → result = moduleResult ?? embeddedResult  → embeddedResult 사용
  → onModuleComplete(result, ...)             → 다음 모듈 전환
```
