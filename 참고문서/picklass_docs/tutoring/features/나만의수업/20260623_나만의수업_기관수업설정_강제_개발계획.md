## 1. 한 줄 요약

> **기관에 소속된 학생이 "나만의 수업"을 만들 때, 소속 기관의 수업설정(전체 수업 최대시간·자유학습 허용)을 초과하는 선택을 못 하게 막는다. studio 과정생성에 이미 있는 `GET /institutions/settings` 패턴을 tutoring에 이식하고, 프론트는 초과 프리셋을 비활성화, 서버는 초과 요청을 거부한다. 기관 미소속(B2C) 학생과 설정 미적용 기관은 현행대로 제약 없이 동작한다.**

---

## 2. 목표 / 배경

### 2.1 목표

`backoffice`에서 기관 관리자가 정한 수업설정(전체 수업 최대시간, 자유학습 허용 여부)을 **나만의 수업 생성 단계에서 강제**한다. 강사용 studio 과정생성에는 이미 적용돼 있으나, 학생용 tutoring "나만의 수업"에는 미적용 상태다.

### 2.2 적용 대상 설정

나만의 수업 옵션 폼([custom/page.tsx](../../../../tutoring.picklass.com/apps/web/src/app/class/lesson-setup/custom/page.tsx))이 노출하는 입력은 **학습목표 · 학습시간 · 레벨** 3가지뿐이다. 기관설정과 맞물리는 항목은 둘:

| 기관설정 필드 (`institution_settings`) | 나만의 수업에 미치는 영향 | 적용 |
|---|---|---|
| `max_total_class_minutes` | **학습 시간** 프리셋(15·20·25·30) 중 초과값 차단 | ✅ |
| `free_learning_enabled` | `false`면 **나만의 수업 생성 자체 차단** | ✅ |
| `max_frt_module_minutes` / `allowed_mic_modes` / `mic_mode_user_change` | 나만의 수업 UI에 FRT시간·마이크모드 **입력 없음** | ❌ 범위 밖 |
| `default_completion_*` (이수조건) | 과정 단위 운영 설정, 단발 나만의 수업과 무관 | ❌ 범위 밖 |

### 2.3 비목표

- FRT시간·마이크모드·이수조건의 나만의 수업 반영 (해당 입력 자체가 없음)
- `institution_settings` 테이블/스키마 변경 (backoffice 소유, 조회만)
- 기관 계층(institution→group→partner) 상속 조회 — settings는 institution 단위 직접 조회 (studio와 동일)

## 3. 핵심 전제 — 제약은 "기관 소속 + 명시적 설정"에만

요구사항이 "**기관 소속**의 사용자"로 한정되고, 결정사항(§ 결정 1)에 따라 **설정 행이 없으면 허용**이므로 다음과 같이 분기한다.

| 사용자 / 설정 상태 | 동작 |
|---|---|
| `institutionId == null` (B2C·개인 학생) | **제약 없음** (현행 유지) |
| `institutionId != null`, `institution_settings` 행 **없음** | **제약 없음** (허용 — 결정 1) |
| `institutionId != null`, 설정 행 **있음** | 행의 `free_learning_enabled` / `max_total_class_minutes` 적용 |

→ **오직 명시적 설정 행이 있는 기관 소속 학생만 제약**을 받는다. 따라서 차단은 기관 관리자가 의도적으로 설정했을 때만 발생한다.

> **studio와의 의도적 차이**: studio `getSettings`는 미소속·미설정 시 `DEFAULT_CLASS_SETTINGS`(`free_learning_enabled=false`)를 적용하지만, tutoring은 학생 대상이라 **permissive 기본값**(무제한·허용)을 쓴다. 이 분기 정책이 본 작업의 핵심 결정이다.

---

## 4. 결정 사항 (확정)

| # | 항목 | 결정 |
|---|------|------|
| 1 | 설정 행 없는 기관의 기본값 | **허용(permissive)** — 무제한 + 자유학습 허용. 명시적 행이 있을 때만 제약 |
| 2 | 학습시간 상한 초과 요청 처리 | **서버에서 거부** (`400`). 프론트는 사전 비활성화, 서버가 최종 권위 |
| 3 | `institutionId` 조달 방식 | **tutoring JWT에 `institutionId` 캐싱 도입** — 로그인 시 1회 리졸브해 토큰 payload에 포함, refresh 시 carry-forward |

## 5. 아키텍처

```
[로그인]                                   [나만의 수업 생성]
  │ users.institution_id 리졸브               │ POST /lessons/create-custom
  │ → JWT payload에 institutionId 캐싱  ──────▶│  (Authorization: Bearer ...)
  │   (결정 3)                                 │
                                              │ 1) 토큰에서 institutionId 추출 (DB 조회 없음)
                                              │ 2) institutionId 있으면
                                              │    GET settings (institution_settings 조회)
                                              │ 3) free_learning_enabled=false → 403

                                              │ 4) 통과 시 기존 흐름(지문→analyzer→레슨)

[프론트 custom/page.tsx]
  진입 시 GET /institutions/settings 동시 fetch
   → 학습시간 프리셋: max 초과값 disabled
```

## 6. 백엔드 구현

### 6.1 신규 모듈 — `institutions` (studio 미러)

`apps/api/src/institutions/`

| 파일 | 역할 |
|------|------|
| `institutions.module.ts` | NestJS 모듈, `InstitutionsService` export |
| `institutions.service.ts` | `getSettings(institutionId)` — `institution_settings` 조회, **permissive 폴백** |
| `institutions.controller.ts` | `GET /institutions/settings` (JWT 필수) — 로그인 사용자 institutionId로 조회 |
| `dto/institution-settings.dto.ts` | `InstitutionClassSettings` (studio `packages/shared/.../class-settings.ts` 호환) |

studio [institutions.service.ts:26-49](../../../../studio.picklass.com3/apps/api/src/institutions/institutions.service.ts) 이식하되, **폴백만 permissive로 교체**(결정 1):

```ts
// tutoring 전용 permissive 기본값 (결정 1)
const PERMISSIVE_SETTINGS: InstitutionClassSettings = {
  maxTotalClassMinutes: null,        // 무제한
  freeLearningEnabled: true,         // 허용
  maxFrtModuleMinutes: null,
  defaultCompletionSentences: null,
  defaultCompletionLessonRate: null,
  defaultCompletionMinutes: null,
  allowedMicModes: ['push_to_talk', 'hybrid', 'always_on'],
  micModeUserChange: true,
};

async getSettings(institutionId: string | null): Promise<InstitutionClassSettings> {
  if (!institutionId) return { ...PERMISSIVE_SETTINGS };          // 미소속 → 허용
  const s = await this.prisma.institution_settings.findUnique({
    where: { institution_id: institutionId },
  });
  if (!s) return { ...PERMISSIVE_SETTINGS };                      // 행 없음 → 허용 (결정 1)
  return {
    maxTotalClassMinutes: s.max_total_class_minutes,
    freeLearningEnabled: s.free_learning_enabled,
    maxFrtModuleMinutes: s.max_frt_module_minutes,
    defaultCompletionSentences: s.default_completion_sentences,
    defaultCompletionLessonRate: s.default_completion_lesson_rate,
    defaultCompletionMinutes: s.default_completion_minutes,
    allowedMicModes: s.allowed_mic_modes as MicMode[],
    micModeUserChange: s.mic_mode_user_change,
  };
}
```

> `GET /institutions/settings` 컨트롤러는 인증 사용자의 `institutionId`(§6.3 JWT)를 그대로 `getSettings`에 넘긴다. 미소속이어도 `200` + permissive 응답(프론트 분기 단순화).

### 6.3 Auth — JWT에 `institutionId` 캐싱 (결정 3)

현재 tutoring JWT payload는 `{ userId, email, roleCode }`로 institutionId가 없다([auth.service.ts:192-222](../../../../tutoring.picklass.com/apps/api/src/auth/auth.service.ts)). speaking의 [JWT 캐싱 결정](../../../speaking/architecture/2026-06-22_로그인-JWT-partnerId-institutionId-캐싱.md)과 동일 전략을 도입:

- **로그인(토큰 발급) 시**: `users.institution_id`를 1회 읽어 payload에 `institutionId` 포함
- **refresh 시**: 재계산하지 않고 기존 payload의 `institutionId`를 **carry-forward** (요청당 DB 조회 방지)
- `verifyToken()` 반환 타입에 `institutionId: string | null` 추가
- 기존 토큰(institutionId 미포함) 호환: payload에 없으면 `null`로 처리 → permissive(제약 없음). 토큰 자연 만료 후 신 토큰에 채워짐.

> partnerId까지 담는 speaking 결정과 달리, 본 작업은 `institutionId`만 필요(설정은 institution 단위). partnerId는 범위 밖.

### 6.4 `createCustomLesson()` 서버 검증 (결정 2)

[lessons.service.ts:609~](../../../../tutoring.picklass.com/apps/api/src/lessons/lessons.service.ts) `createCustomLesson()`에 검증 추가. institutionId는 컨트롤러가 JWT에서 추출해 전달(또는 service가 AuthUser 수신).

```ts
// durationMin 정규화 직후
if (institutionId) {
  const s = await this.institutionsService.getSettings(institutionId);
  if (!s.freeLearningEnabled) {
    throw new ForbiddenException('소속 기관에서 나만의 수업을 허용하지 않습니다.');
  }
  if (s.maxTotalClassMinutes != null && durationMin > s.maxTotalClassMinutes) {
    throw new BadRequestException(`학습 시간은 최대 ${s.maxTotalClassMinutes}분까지 가능합니다.`);
  }
}
```

- 프론트가 비활성화로 막아도, **조작·우회 요청은 서버가 거부**(결정 2).
- `create-custom` 엔드포인트([lessons.controller.ts:101-126](../../../../tutoring.picklass.com/apps/api/src/lessons/lessons.controller.ts))에서 `institutionId`를 JWT로부터 추출해 service에 전달.
- `durationMin` 허용 집합은 기존 `ALLOWED_DURATIONS`([lesson-plan.dto.ts:7-8](../../../../tutoring.picklass.com/apps/api/src/lesson-plan/dto/lesson-plan.dto.ts)) 유지.

### 7.1 설정 fetch

진입 시 KPI·레벨추정과 함께 `GET /institutions/settings`를 `authFetch`로 호출(인증 필요). 응답을 `settings` state에 저장. 실패 시 permissive로 폴백(제약 없음).

### 7.2 학습 시간 프리셋 비활성화

studio [course/page.tsx:1045-1071](../../../../studio.picklass.com3/apps/web/src/app/course/page.tsx) 패턴:

```tsx
{DURATION_OPTIONS.map((min) => {
  const isDisabled = settings?.maxTotalClassMinutes != null && min > settings.maxTotalClassMinutes;
  return (
    <button key={min} type="button" disabled={isDisabled}
      onClick={() => !isDisabled && setDurationMin(min)}
      className={isDisabled ? 'opacity-30 cursor-not-allowed ...' : (durationMin === min ? '...선택...' : '...')}>
      {min}분
    </button>
  );
})}
```

**디폴트 하향**: `settings` 로드 후 기본 `durationMin`(30)이 상한을 넘으면, **허용되는 최대 프리셋으로 자동 설정**(`useEffect`).
**전 프리셋 비활성 엣지케이스**(`maxTotalClassMinutes < 15`): 안내 문구 노출 + CTA 비활성(서버도 어차피 거부).

### 7.3 자유학습 게이트

`settings.freeLearningEnabled === false`면 옵션 폼 대신 **차단 안내 화면**(`step='error'` 재사용: "소속 기관에서 나만의 수업을 허용하지 않습니다") 노출, "수업 만들기" 비활성.

> **명시적으로 설정한 기관의 소속 학생만, 그 기관의 전체 수업 최대시간·자유학습 허용 범위 안에서 나만의 수업을 만들 수 있다. JWT에 institutionId를 캐싱해 매 요청 DB 조회 없이 institution_settings를 조회하고, 프론트는 사전 차단·서버는 최종 거부의 이중 방어로 강제한다. 미소속·미설정은 현행대로 제약 없이 동작한다.**
