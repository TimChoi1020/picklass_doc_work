## 1. 한 줄 요약

> **"나만의 수업" 옵션 폼의 학습목표(KPI) 선택을 학생이 간결·명확하게 고를 수 있도록, 칩의 구성(스킬 배지)과 순서(스킬 순 정렬)를 studio 과정생성 화면과 동일하게 맞춘다. 같은 KPI 카탈로그·같은 그룹핑 로직을 쓰므로 프론트 한 파일 수정으로 양 화면의 학습목표 UX parity를 확보한다.**

## 2. 개발 목표 / 배경

### 2.1 목표 — 간결하고 명확한 학습목표 선택

학생이 "나만의 수업"을 만들 때 마주하는 학습목표 칩 목록은 현재 **goal 텍스트만** 나열되어 있어 다음이 불명확하다.

- **이 목표가 어떤 영역(어휘/읽기/쓰기/듣기/말하기)인지** 한눈에 안 보인다.
- 칩 순서가 DB `sort_order`(goal 첫 등장 순)라 **영역이 섞여 나열**되어, 학생이 "내가 무엇을 고르는지"를 빠르게 판단하기 어렵다.

목표는 학생이 **(1) 각 목표의 영역을 즉시 인지**하고 **(2) 영역 순서대로 정렬된 목록에서 빠르게 선택**할 수 있게 하는 것이다. 이를 위한 검증된 기준이 이미 studio 과정생성 화면(강사용 "과정 목표")에 존재하므로, 그 **구성과 순서를 그대로 차용**한다. 결과적으로 강사(studio)와 학생(tutoring)이 동일한 형태의 학습목표 UI를 보게 되어 조직 전체의 일관성도 올라간다.

### 2.2 배경 — 두 화면은 이미 대부분 같다

| 공통점 | 내용 |
|--------|------|
| KPI 데이터 소스 | `GET /common-codes/KPI_CATEGORY/items` (studio·tutoring 동일 Supabase) |
| 그룹핑 | `extra_data.goal` 기준으로 같은 goal의 코드들을 하나의 칩으로 묶음 |
| 토글 | 칩 1개 클릭 → 같은 goal에 묶인 모든 코드 일괄 선택/해제 |

차이는 **"스킬(skill) 차원을 다루느냐" 하나**다. studio는 `extra_data.skill`을 읽어 칩에 영역 배지를 달고 영역 순으로 정렬하지만, tutoring custom은 이 필드를 사용하지 않는다.

### 2.3 비목표

- KPI 카탈로그 데이터/스키마 변경 (양 화면 공유 자원, 변경 없음)
- studio의 `courseType` 필터(`kpiSkillFilter`) 이식 — §6 참조 (해당 개념 없음)
- React Query 도입 등 데이터 페칭 인프라 변경 (tutoring custom의 raw fetch 구조 유지)
- 선택 결과(`selectedKpiCodes`)·레슨 생성 흐름 변경

## 4. 변경 설계 (4단계)

대상 파일은 [custom/page.tsx](../../../../tutoring.picklass.com/apps/web/src/app/class/lesson-setup/custom/page.tsx) **하나뿐**. 같은 DB라 `extra_data.skill`이 이미 응답에 포함되므로 API 변경이 없다.

### 4.1 스킬 상수 도입 (studio와 1:1)

studio의 3개 상수를 그대로 가져온다. 단일 소비처이므로 page 상단 인라인으로 둔다 (재사용이 늘면 `apps/web/src/lib/skills.ts`로 분리 — `lib/cefr.ts` 선례와 동일 패턴).

```ts
const SKILL_CODE_MAP: Record<string, string> = { r: 'reading', l: 'listening', s: 'speaking', w: 'writing', v: 'vocabulary' };
const SKILL_SORT_ORDER: Record<string, number> = { vocabulary: 0, reading: 1, writing: 2, listening: 3, speaking: 4 };
const SKILL_ABBR: Record<string, string> = { vocabulary: 'V', reading: 'R', writing: 'W', listening: 'L', speaking: 'S' };
```

### 4.2 `KpiItem`에 `skills[]` 추가 (구성)

```ts
interface KpiItem {
  code: string;
  goal: string;
  codes: string[];
  skills: string[]; // ← 추가: 이 goal에 묶인 스킬들 (배지 표시 + 정렬 기준)
}
```

### 4.3 `loadKpiItems()`에서 skill 수집 (구성)

goal 그룹마다 `skills: Set<string>`을 두고 `extra_data.skill`을 `SKILL_CODE_MAP`으로 매핑해 모은다 (studio `useKpiItems`와 동일).

```ts
// grouped 타입: Record<string, { goal: string; codes: string[]; skills: Set<string> }>
for (const item of active) {
  const rawGoal = item.extra_data?.goal;
  const goal = (typeof rawGoal === 'string' ? rawGoal : item.name).trim();
  if (!goal) continue;

  const skillChar = item.extra_data?.skill as string | undefined;
  const skill = skillChar ? (SKILL_CODE_MAP[skillChar] ?? skillChar) : undefined;

  if (!grouped[goal]) {
    grouped[goal] = { goal, codes: [], skills: new Set() };
    groupOrder.push(goal);
  }
  if (!grouped[goal].codes.includes(item.code)) grouped[goal].codes.push(item.code);
  if (skill) grouped[goal].skills.add(skill);
}

const items = groupOrder.map((goal): KpiItem => ({
  code: grouped[goal].codes[0],
  goal,
  codes: grouped[goal].codes,
  skills: Array.from(grouped[goal].skills),
}));
```

### 4.4 스킬 순 정렬 + 칩 배지 렌더 (순서 + 구성)

정렬은 상태 추가 없이 파생값(`useMemo`)으로 처리한다. V8 stable sort라 동순위는 기존 `sort_order` 순이 유지되어 studio와 동일한 결과가 된다.

```ts
const sortedKpiItems = useMemo(() => {
  const minOrder = (skills: string[]) => Math.min(...skills.map((s) => SKILL_SORT_ORDER[s] ?? 99));
  return [...kpiItems].sort((a, b) => minOrder(a.skills) - minOrder(b.skills));
}, [kpiItems]);
```

칩 렌더는 `kpiItems.map` → `sortedKpiItems.map`으로 바꾸고, `{kpi.goal}` 뒤에 스킬 배지(V/R/W/L/S, `SKILL_SORT_ORDER` 순)를 추가한다. 색상 토큰(`#18c37e` 계열)은 양 화면이 이미 동일하므로 그대로 매칭된다.

```tsx
<span className="flex items-center gap-1.5">
  {kpi.goal}
  <span className="flex gap-0.5">
    {[...kpi.skills]
      .sort((a, b) => (SKILL_SORT_ORDER[a] ?? 99) - (SKILL_SORT_ORDER[b] ?? 99))
      .map((skill) => (
        <span key={skill} className={`rounded px-1 text-[9px] font-bold leading-4 ${
          selected ? 'bg-[#18c37e]/20 text-[#008c5b]' : 'bg-white/80 text-gray-400'
        }`}>
          {SKILL_ABBR[skill] ?? skill[0].toUpperCase()}
        </span>
      ))}
  </span>
</span>
```

## 6. courseType 필터 — 의도적 제외

studio의 `kpiSkillFilter`(tutoring/speaking/integrated 별 KPI 필터)는 **이식하지 않는다.** "나만의 수업"은 학생 단일 흐름이라 과정 유형 선택 개념이 없고, studio의 `integrated`(전체 표시)와 동일하게 모든 KPI를 노출하면 된다.

> **단서**: 만약 "나만의 수업"이 스피킹 모듈을 포함할 수 없는 정책이라면 `speaking` 스킬 KPI를 숨겨야 하므로, 그 경우에만 `kpiSkillFilter`의 tutoring 분기를 추가 이식한다. (현재 결정: 전체 표시)
