## 1. 한 줄 요약

> **`createCustomLesson()`이 지문을 먼저 DB에 저장한 뒤 analyzer를 호출하는 구조라, analyzer(시퀀싱 엔진) 실패 시 어느 레슨에도 연결되지 않은 고아(orphan) 지문이 매번 쌓였다. 외부 호출(지문 생성·analyzer)을 전부 앞으로 빼 DB 쓰기 전에 끝내고, `texts·courses·course_lessons` 세 쓰기만 하나의 짧은 트랜잭션으로 묶어 원자화한다. 느린 외부 호출은 트랜잭션 밖에 둔다.**

---

## 2. 배경 / 문제

운영 중 "수업 생성 실패 — 시퀀싱 엔진에 연결할 수 없습니다"(analyzer 연결 오류, `BadGatewayException`)가 발생하면서, 그 시점에 DB에 무엇이 남는지 점검한 결과:

현재 순서(실패 지점 = analyzer):

| 순서 | 작업 | DB 영향 | analyzer 실패 시 |
|---|---|---|---|
| 1 | Gemini 지문 생성 | — | 수행됨 |
| 2 | **`texts` INSERT (지문)** | ✅ 저장 | **남음 (orphan)** |
| 2-1 | 스피킹 지문 변환 (fire-and-forget) | texts.update | 백그라운드 진행 |
| 2-2 | 핵심표현·대화문 (fire-and-forget) | 별도 테이블 | 백그라운드 진행 |
| 3 | 지문 분석 `runDefaults` | ✅ `text_analyses` 저장 | **남음 (orphan)** |
| 4 | **analyzer 시퀀싱** | — | ❌ **throw** |
| 5 | `courses` 조회/생성 | ⛔ 도달 못 함 | — |
| 6 | `course_lessons` 생성 | ⛔ 도달 못 함 | — |

→ analyzer 실패마다 **레슨에 연결되지 않은 `texts`(+`text_analyses`, 스피킹 코어데이터) 행이 누적**된다. 함수가 트랜잭션으로 감싸여 있지 않아 부분 데이터도 가능하다.

---

## 3. 핵심 원칙 — 외부 호출을 트랜잭션에 넣지 않는다

"전체를 트랜잭션으로 감싼다"를 문자 그대로 `$transaction`으로 모든 단계를 감싸면 **안 된다.** Gemini·analyzer 같은 수 초짜리 외부 HTTP를 트랜잭션 안에 두면 DB 커넥션을 그동안 점유하고 Prisma 인터랙티브 트랜잭션 기본 타임아웃(5초)을 초과해 오히려 실패한다.

올바른 트랜잭션화:
1. **외부 호출을 먼저 전부 끝낸다** (DB 미기록). 여기서 실패하면 DB에 아무것도 안 남는다 → orphan 0.
2. **빠른 로컬 DB 쓰기만 하나의 짧은 트랜잭션**으로 묶는다 → 원자성.
3. `text.id`가 필요한 **비핵심 부수작업(분석·스피킹 변환)은 커밋 후**로 미룬다.

---

## 4. 재배치된 흐름

```
1. 검증 (topic / auth / 기관설정)            ← 그대로
2. 옵션 정규화 (duration / level)
3. generatePassage (외부)                    ┐ DB 미기록
4. analyzer 시퀀싱 (외부) → moduleSequence    ┘ 실패 시 남는 것 0  ← texts 저장보다 앞으로 이동
────────────────────────────────────────────
5. $transaction {                            ← 빠른 로컬 쓰기만, 원자적
     texts.create
     courses find / create
     course_lessons.create
   }
────────────────────────────────────────────
6. (커밋 후) runDefaults → analysis (응답용 await)
   (커밋 후) 스피킹 지문/코어데이터 fire-and-forget
7. return (응답 shape 불변)
```

**analyzer를 앞으로 옮길 수 있는 근거**: `lessonPlanService.generate`는 `passageText`(=`passage.content`)·`passageLevel`·KPI·duration만 필요하고 **`text.id`를 요구하지 않는다.** 따라서 texts 저장 전에 호출 가능.

---

## 5. 트랜잭션 경계

| 단계 | 트랜잭션 | 이유 |
|---|---|---|
| generatePassage, analyzer 시퀀싱 | **밖 (앞)** | 외부 HTTP·느림. 먼저 실패시켜 DB 무변경 |
| **texts + courses + course_lessons** | **안** | 빠른 로컬 쓰기 3건, 함께 커밋/롤백 |
| `runDefaults`(text_analyses), 스피킹 변환/코어데이터 | **밖 (뒤)** | 외부 호출 + `text.id` 필요 + **비핵심**(부분 실패 허용, `refreshAllForUser`로 재생성 가능) |

---

## 6. 의도적 결정

1. **`text_analyses`는 트랜잭션 밖(커밋 후) 유지** — 외부 LLM 호출이며 본질적으로 비핵심. 레슨은 분석 성패와 무관하게 보장. 분석 실패 시 추후 재분석 가능.
2. **`analysis`는 커밋 후 계산하되 응답에 그대로 포함** — `runDefaults`를 await하므로 응답 shape·필드 변화 없음.
3. **스피킹 fire-and-forget은 커밋 후 시작** — `text.id` 확정 상태에서 실행(기존과 동일하게 비차단).
4. **과정 중복 레이스는 본 작업 범위 밖** — `(title, created_by)`에 unique 제약이 없어 같은 사용자의 동시 생성 시 "나만의 수업" 과정이 중복될 수 있음. 이는 트랜잭션화와 무관한 선존재 이슈. 필요 시 부분 유니크 인덱스 추가로 별도 처리.

## 7. 구현 (단일 파일)

[lessons.service.ts](../../../../tutoring.picklass.com/apps/api/src/lessons/lessons.service.ts) `createCustomLesson()` 본문만 재배치:

- 기존 "4. 모듈 시퀀스(analyzer)" 블록을 "2. texts 저장" 앞으로 이동.
- `texts.create` + `courses` 조회/생성 + `course_lessons.create`를 `this.prisma.$transaction(async (tx) => { ... })`로 묶고, 각 쓰기를 `tx.*`로 호출 후 `{ text, customCourse, lesson }` 반환.
- `runDefaults`(+`analysis` 추출), 스피킹 `fire-and-forget` 2건을 트랜잭션 뒤로 이동. 커밋 후 작업은 `this.prisma`/서비스 그대로 사용.

```ts
// 3~4: 외부 호출 먼저 (DB 미기록)
const passage = await this.aiService.generatePassage({ topic, targetLevel: effectiveTargetLevel, wordCount });
const planResp = await this.lessonPlanService.generate({
  passageLevel: targetCefrLevel, passageText: passage.content, selectedKpiCodes, durationMin,
});
const moduleSequence = mapAnalyzerSequenceToPlanned(planResp.sequence);
const totalEstimatedMinutes = computeTotalMinutes(planResp.sequence);

// 5: 빠른 DB 쓰기만 원자적으로
const { text, customCourse, lesson } = await this.prisma.$transaction(async (tx) => {
  const text = await tx.texts.create({ data: { user_id: targetUserId, title: passage.title, content: passage.content, word_count: passage.wordCount, text_type: 'A', topic } });
  let customCourse = await tx.courses.findFirst({ where: { title: '나만의 수업', created_by: targetUserId, deleted_at: null } });
  if (!customCourse) customCourse = await tx.courses.create({ data: { institution_id: '00000000-0000-0000-0000-000000000000', title: '나만의 수업', description: '학생이 직접 주제를 선택하여 생성한 수업', level_code: `L${effectiveTargetLevel}`, genre_code: 'custom', created_by: targetUserId } });
  const existing = await tx.course_lessons.count({ where: { course_id: customCourse.id } });
  const lesson = await tx.course_lessons.create({ data: { course_id: customCourse.id, text_id: text.id, lesson_order: existing + 1, topic, topic_source: 'ai', skill_modules: moduleSequence, status_code: 'active' } });
  return { text, customCourse, lesson };
});

// 6: 커밋 후 — 분석(응답용 await) + 스피킹(fire-and-forget)
const analyzed = await this.textAnalyses.runDefaults(text.id, passage.content, { title: passage.title, wordCount: passage.wordCount });
const analysis = /* gemini-passage settled 추출 (기존 로직 그대로) */;
void this.speakingPassageService.generate(passage.content).then(/* texts.update */).catch(/* log */);
void this.speakingCoreDataService.generateAll(text.id, passage.content, targetCefrLevel).catch(/* log */);
```

## 8. 효과

- **Orphan 완전 제거**: 지문 생성·analyzer 중 어느 하나라도 실패하면 DB에 **아무것도 안 남음**. 재시도해도 누적 없음.
- **원자성**: `texts·courses·course_lessons`가 한꺼번에 커밋되거나 전부 롤백.
- **성능 안전**: 느린 외부 호출이 트랜잭션 밖 → 커넥션 점유/타임아웃 없음.
