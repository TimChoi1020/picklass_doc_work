# 외부 API 원타임 URL 개발 플랜

> 작성일: 2026-04-09
> 프로젝트: tutoring.picklass.com

---

## 1. 개요

외부 시스템에서 Picklass 튜터링 플랫폼의 레슨 모듈 정보를 안전하게 조회할 수 있도록
**원타임(One-Time) URL 토큰 기반 외부 API**를 제공한다.

### 핵심 흐름

```
[학생] 메인페이지 "시작" 버튼 클릭 → /modules/{lessonId} 진입
       ↓
[Picklass API] 레슨 플랜 조회 시 SNR/FRT 모듈 감지 → 원타임 토큰 자동 생성
       ↓
[외부 시스템] → 토큰 + 모듈코드로 API 호출 (헤더 전달)
       ↓
[Picklass API] → 토큰 검증 → 사용자 정보 + 모듈 데이터 응답
       ↓
[Picklass API] → 레슨 완료 또는 수동 호출 시 토큰 만료 처리
```

### 토큰 생성 트리거

- **시점**: 학생이 메인페이지(`/`)에서 "현재 수강중인 과정"의 **시작** 버튼 클릭
- **경로**: `handleGoToLesson()` → `/modules/{lessonId}` → `GET /lessons/{lessonId}/plan` 호출
- **조건**: 레슨의 `skill_modules` 시퀀스에 **SNR(스피킹) 또는 FRT** 모듈이 포함된 경우에만 토큰 자동 생성
- **외부 연동 대상 모듈**: `SNR`, `FRT` (확장 시 동일한 자동 발급 로직 재사용)
- **생성 주체**: 시스템 자동 (학생 JWT 토큰에서 userId 추출)

## 2. DB 스키마 설계

### 2.1 신규 테이블: `external_access_tokens`

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | UUID (PK) | 토큰 레코드 ID |
| `token` | VARCHAR(255), UNIQUE | 원타임 토큰 값 (crypto randomUUID 또는 nanoid) |
| `user_id` | UUID (FK → users.id) | 매핑된 사용자 |
| `course_lesson_id` | UUID (FK → course_lessons.id) | 레슨 ID |
| `module_code` | VARCHAR(10) | 모듈 코드 (ai_modules.code 참조) |
| `is_expired` | BOOLEAN | 만료 여부 (기본값: false) |
| `expires_at` | TIMESTAMPTZ | 만료 시간 |
| `used_at` | TIMESTAMPTZ | 사용(조회)된 시간 (nullable) |
| `created_at` | TIMESTAMPTZ | 생성 시간 |
| `created_by` | UUID | 토큰 생성자 ID (= 학생 본인, 시스템 자동 생성) |

### 2.2 Prisma 모델

```prisma
model external_access_tokens {
  id              String    @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  token           String    @unique @db.VarChar(255)
  userId          String    @map("user_id") @db.Uuid
  courseLessonId  String    @map("course_lesson_id") @db.Uuid
  moduleCode      String    @map("module_code") @db.VarChar(10)
  isExpired       Boolean   @default(false) @map("is_expired")
  expiresAt       DateTime  @map("expires_at") @db.Timestamptz
  usedAt          DateTime? @map("used_at") @db.Timestamptz
  createdAt       DateTime  @default(now()) @map("created_at") @db.Timestamptz
  createdBy       String    @map("created_by") @db.Uuid

  @@index([token])
  @@index([userId])
  @@index([expiresAt])
  @@map("external_access_tokens")
}
```

## 3. API 엔드포인트 설계

### 3.1 원타임 토큰 자동 생성 (레슨 플랜 조회 시)

> 별도 API 엔드포인트가 아닌, 기존 `GET /lessons/{lessonId}/plan` 응답에 토큰 정보를 포함하는 방식.
> 레슨의 모듈 시퀀스에 스피킹 모듈이 포함된 경우에만 토큰을 자동 생성한다.

**기존 엔드포인트 확장:** `GET /lessons/:lessonId/plan`

**변경 사항:**
- 레슨 플랜 조회 시 `skill_modules`에 외부 연동 모듈(SNR/FRT)이 존재하는지 확인
- 외부 연동 모듈이 있으면 해당 모듈별로 원타임 토큰 자동 생성
- 응답에 `externalTokens` 필드 추가

**Response 추가 필드:**
```json
{
  "lessonId": "lesson-uuid",
  "moduleSequence": [...],
  "externalTokens": [
    {
      "moduleCode": "SNR",
      "token": "generated-onetime-token-value",
      "url": "https://tutoring.picklass.com/api/external/verify",
      "expiresAt": "2026-04-09T15:00:00Z"
    }
  ]
}
```

**내부 처리 로직 (LessonsService.getLessonPlan 확장):**
1. 기존 레슨 플랜 조회 로직 수행
2. `skill_modules`에서 외부 연동 모듈 코드 필터링 (`SNR`, `FRT`)
3. 매칭 모듈이 있으면:
   - JWT에서 userId 추출
   - 동일 사용자+레슨+모듈에 유효한(미만료) 토큰이 있으면 재사용
   - 없으면 crypto.randomUUID()로 신규 생성 → `external_access_tokens` 저장 (만료시간 기본 60분)
4. 응답에 `externalTokens` 배열 포함 (매칭 모듈 없으면 빈 배열)
   - 한 레슨에 SNR과 FRT가 동시에 포함되면 모듈별 토큰이 각각 발급되어 배열에 병렬로 담긴다

---

### 3.2 토큰 검증 + 데이터 조회 (외부 시스템 호출용)

**`GET /external/verify`**

> 외부 시스템이 헤더에 토큰과 모듈ID를 전달하여 검증 + 데이터를 받는다.

**Request Headers:**
```
X-Access-Token: generated-onetime-token-value
X-Module-Code: WRD
```

**Response (200):**
```json
{
  "user": {
    "userId": "student01",
    "name": "홍길동"
  },
  "module": {
    "code": "WRD",
    "name": "Word Definition",
    "skill": "vocabulary",
    "uiTemplate": "standard",
    "answerType": "multiple_choice",
    "scoringMode": "exact",
    "passageExposureMode": "full",
    "feedbackStyle": "immediate",
    "questionCount": "multi",
    "questionMinCount": 3,
    "questionMaxCount": 5
  },
  "lesson": {
    "id": "lesson-uuid",
    "topic": "Environmental Issues",
    "lessonOrder": 3,
    "text": {
      "title": "Climate Change Effects",
      "content": "지문 본문...",
      "level": "B1",
      "category": "science",
      "wordCount": 350
    }
  }
}
```

**처리 로직:**
1. `X-Access-Token` 헤더에서 토큰 추출
2. `X-Module-Code` 헤더에서 모듈 코드 추출
3. DB에서 토큰 조회
4. 검증 체크:
   - 토큰 존재 여부
   - `is_expired === false`
   - `expires_at > now()`
   - `module_code`가 헤더의 모듈 코드와 일치
5. 검증 성공 시:
   - `used_at`에 현재 시간 기록
   - 사용자 정보 조회 (users 테이블)
   - 모듈 메타데이터 조회 (ai_modules 테이블)
   - 레슨 + 지문 정보 조회 (course_lessons + texts 테이블)
   - 통합 응답 반환

**에러 응답:**
| 상태 코드 | 설명 |
|-----------|------|
| 401 | 토큰 없음 / 유효하지 않은 토큰 |
| 403 | 토큰 만료됨 |
| 404 | 모듈 또는 레슨 데이터 없음 |

---

### 3.3 토큰 만료 처리

**`POST /external/tokens/expire`**

> 원타임 토큰을 수동으로 만료 처리한다.

**Request Body:**
```json
{
  "token": "generated-onetime-token-value"
}
```

**Response (200):**
```json
{
  "token": "generated-onetime-token-value",
  "isExpired": true,
  "expiredAt": "2026-04-09T14:30:00Z"
}
```

**처리 로직:**
1. JWT 인증 (기존 JwtAuthGuard)
2. 토큰 조회
3. `is_expired = true` 업데이트
4. 결과 반환

## 8.1 FRT 모듈 추가 (2026-04-25)

### 변경 요약

기존 자동 토큰 생성은 `moduleCode === 'SNR'`만 매칭했으나, **FRT** 모듈도 동일한 외부 연동 흐름을 사용하므로 매칭 대상에 추가한다.

### 변경 항목

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| `LessonsService.createSpeakingModuleTokens()` | `m.moduleCode === 'SNR'` | `EXTERNAL_TOKEN_MODULE_CODES.includes(m.moduleCode)` |
| 외부 연동 모듈 코드 | `SNR` 단일 | `SNR`, `FRT` (배열 상수로 일원화) |
| 임시 발급 엔드포인트 (`POST /external/tokens/issue`) | `TEMP_ISSUE_MODULE_CODE = 'SNR'` 고정 | (별도 변경 없음 — 테스트 고정값 유지) |
| `/external/gateway` 분기 | `'SNR'` 케이스 | `'SNR'`, `'FRT'` 모두 동일하게 `/my-classes`로 리다이렉트 (분기 구조 일반화) |

### 사이드 이펙트 방지

- 한 레슨에 SNR/FRT가 **둘 다** 존재하면 모듈별로 토큰 2개가 발급되어 `externalTokens` 배열에 병렬로 담긴다 (기존 재사용 로직은 `userId+lessonId+moduleCode` 단위라 충돌 없음)
- 외부 시스템은 헤더의 `X-Module-Code`로 발급된 토큰의 모듈 코드와 정확히 일치해야 검증 통과 → 토큰 혼용 불가
- FRT 매칭은 모듈 코드 문자열 비교일 뿐, `ai_modules` 테이블의 FRT 행이 active 상태가 아니면 `/external/verify` 단계에서 404 반환 (기존 동작 유지)
