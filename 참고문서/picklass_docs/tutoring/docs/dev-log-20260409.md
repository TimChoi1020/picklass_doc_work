## 1. retryAnswer 버그 수정

### 증상
WRD 모듈에서 문항을 틀리고 "다시 시도"를 눌렀을 때 "잘했어요! 이제 Q4번 차례예요." 메시지가 중복 발화되는 현상.

### 원인
`retryAnswer(questionId)`가 답안을 삭제한 뒤 `orchestrate()`를 호출하면, 삭제된 문항 이전에 정답 처리된 문항(예: Q3)이 `getLastAnsweredQuestionId()`의 마지막 답변으로 재선택된다.

```
Q3 정답 → ruleCorrectAnswer → "잘했어요! 이제 Q4번 차례예요." (정상)
Q4 오답 → ruleWrongAnswerFeedback → "아쉽네요!"
retryAnswer(Q4) → answers[Q4] 삭제 → orchestrate() 재호출
  getLastAnsweredQuestionId() = Q3 (Q4 삭제됨)
  ruleCorrectAnswer(Q3): 정답 → "잘했어요! 이제 Q4번 차례예요." ← 중복 발화
```

### 수정
`retryAnswer`에서 `orchestrate()` 호출 제거 → 해당 문항을 직접 재제시.

```ts
// 변경 전
setTimeout(() => orchestrateRef.current(), 0);

// 변경 후
setActiveQuestionId(questionId);
setQuestionGuidance(null);
```

재시도는 "같은 문항으로 돌아가는 것"이므로 Orchestrator 재평가가 불필요하다.

## 2. ruleIdleHint — 20초 무응답 선제적 힌트 추가

### 배경
학습자가 문항을 보고 오래 멈춰 있을 때 선제적으로 힌트를 제공한다.
유휴 체크(120초)와 별개로, 20초 무응답 시 즉시 subtle 힌트를 발화한다.

### 설계 결정
- Orchestrator가 스스로 재호출을 예약하는 `scheduleCheck` 패턴 대신 유휴 타이머에 20초 임계값을 추가하는 방식으로 구현 (현 단계).
- `scheduleCheck` 패턴은 추후 모듈별 동적 타이밍이 필요할 때 전환 예정 (주석으로 TODO 기록).

### 변경 사항

#### `ModuleOrchestratorAgent.ts` — `ruleIdleHint` 추가
- 위치: `ruleRepeatWrongAnswer` 바로 뒤
- 조건:
  - `idleSeconds >= 20`
  - `scoringMode !== 'pronunciation'` (SHR/RRD 전용 룰 제외)
  - `audio-record`, `sentence-write` 타입 제외 (전용 피드백 룰 존재)
  - `eventFiredIds['hintGiven']`에 미포함 (중복 방지)
  - `exact` 모드: 미답변 또는 오답인 문항
  - `holistic` 모드: 미답변인 문항만 (답변 후에는 `ruleHolisticFeedback`이 처리)

#### `useModuleOrchestrator.ts` — 유휴 타이머 20초 임계값 추가
```ts
// 추가된 임계값
const idleThreshold20FiredRef = useRef(false);

// 20초 초과 시 orchestrate() 호출
} else if (idleSec >= 20 && !idleThreshold20FiredRef.current) {
  idleThreshold20FiredRef.current = true;
  orchestrateRef.current();
}
```
- `submitAnswer`, `submitVoiceAnswer`, `submitUserMessage` 3곳에서 `idleThreshold20FiredRef` 리셋 추가.

#### `useModuleOrchestrator.ts` — `giveHint` 발화 추적 추가
```ts
// giveHint 실행 시 hintGiven에 questionId 기록
eventFiredIdsRef.current = {
  ...eventFiredIdsRef.current,
  hintGiven: [...(eventFiredIdsRef.current['hintGiven'] ?? []), toolCall.params.questionId],
};
```
- `ruleRepeatWrongAnswer`와 `ruleIdleHint` 모두 동일한 `hintGiven` 키를 공유하므로 어느 룰에서 힌트가 발화되든 중복 방지.

## 3. 주요 설계 결정 기록

### QuestionType vs scoringMode 구분
`QuestionType`은 **입력 방식** (short-text, essay, multiple-choice 등),
`scoringMode`는 **채점 방식** (exact, holistic, pronunciation).
같은 `short-text` 타입이라도 WRD는 `exact`, GMN은 `holistic`이다.
`ruleIdleHint`의 필터는 타입이 아닌 `scoringMode`로 판별해야 한다.

### holistic 모듈 힌트 전략
정해진 정답이 없는 holistic 모듈(PRD, SUM 등)은 힌트가 "작성 시작 촉진" 역할을 한다.
- 미답변 상태: 힌트 발화 O
- 답변 후: 힌트 발화 X (`ruleHolisticFeedback`에 위임)

현재 유휴 타이머는 Hook에 임계값이 하드코딩되어 있다.
추후 Orchestrator가 `scheduleCheck { delaySeconds: N }` Tool을 반환하여
스스로 재호출 타이밍을 결정하는 방식으로 전환 가능.
전환 시 `idleThreshold20FiredRef` 및 20초 임계값 블록 제거 가능.
