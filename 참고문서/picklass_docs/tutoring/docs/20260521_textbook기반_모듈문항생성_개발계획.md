## 1. 배경 및 목적

### 현재 문제

교재 PDF 업로드로 생성된 과정(studio Phase 2-B)에서도 학생이 모듈에 처음 진입할 때 LLM이 지문만 보고 학습 대상(단어, 표현, 대화문)을 자유롭게 선정한다.

| 항목 | 현재 | 문제 |
|------|------|------|
| 문항 생성 소스 | 지문에서 LLM이 자유 선정 | 교재가 지정한 학습 어휘·표현과 다른 항목이 문항으로 나올 수 있음 |
| 교재 데이터 활용 | 미활용 | textbooks 테이블에 저장된 keywords/expressions/dialogues가 문항 생성에 반영되지 않음 |
| LLM 호출 | 항상 발생 | 교재 데이터가 있어도 지문만으로 LLM 재실행 |

### 개선 목표

교재에서 미리 선정된 학습 대상(어휘, 핵심 표현, 대화문, 독해 문항)이 textbooks 테이블에 있을 경우, 해당 데이터를 LLM 프롬프트에 컨텍스트로 주입하여:
1. 교재의 학습 의도가 module_questions에 반영되도록
2. contentGenerationInstruction은 변경 없이 재사용
3. textbook 없는 기존 과정(주제 입력 방식)에 영향 없음

## 2. 설계 원칙

### 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| 직접 매핑(LLM 0회) 경로 | **제거** | textbook 데이터(단어·표현·대화문)는 module_questions 형식과 달라 직접 변환 불가 |
| LLM 경로 | **항상 유지** | hint 생성·question text 포맷·answer 형식은 contentGenerationInstruction이 담당 |
| textbook 주입 방식 | **컨텍스트 주입** | 기존 prompt 구조를 유지하고 [교재 데이터] 블록만 추가 |
| 소스 지시문 | **단일 통일 상수** | 모듈마다 분기 불가 — 모듈은 무한 확장됨 |
| 소스 지시문 위치 | contentGenerationInstruction **앞에 삽입** | LLM이 contentBlock 처리 전 소스 판단 기준을 먼저 인지 |
| 주입 대상 필드 선택 | **별도 설정 없음** | 소스 지시문의 조건부 구조("있다면")가 관련성 판단을 LLM에 위임 |

### 역할 분리

| 구성 요소 | 역할 |
|-----------|------|
| `passageText` | 지문 — 문맥·의미 참조 (양쪽 경로 공통) |
| `textbookContext` | 교재 미리 선정 데이터 — textbook 있을 때만 주입 |
| `TEXTBOOK_SOURCE_DIRECTIVE` | "교재 데이터 있으면 우선 활용" — 단일 상수, 모든 모듈 공통 |
| `contentGenerationInstruction` | 문항 형식·구조·힌트·채점 방식 — 모듈별 고유, 변경 없음 |

## 3. 변경된 문항 생성 흐름

### 현재 (2단계)

```
모듈 진입
  → 캐시 확인 (module_questions)
       ├── HIT  → DB 반환
       └── MISS → buildQuestionGenerationPrompt({ aiModule, passageText })
                → LLM (Gemini) → 저장 → 반환
```

### 변경 후 (3단계)

```
모듈 진입
  → 캐시 확인 (module_questions)
       ├── HIT  → DB 반환
       └── MISS
              → textbook 조회 (text_id + course_id 기준)
                   ├── textbook 있음
                   │     → buildTextbookContext(textbook)
                   │          ├── 데이터 있음 (non-null)
                   │          │     → buildQuestionGenerationPrompt({ aiModule, passageText, textbookContext })
                   │          │     → [지문] + [교재 데이터] + [소스 지시문] + [contentGenerationInstruction]
                   │          │     → LLM → 저장 → 반환   ← 교재 학습 의도 반영
                   │          └── 데이터 없음 (모든 필드가 빈 값)
                   │                → buildQuestionGenerationPrompt({ aiModule, passageText })
                   │                → LLM → 저장 → 반환   ← 기존 경로
                   └── textbook 없음
                         → buildQuestionGenerationPrompt({ aiModule, passageText })
                         → LLM → 저장 → 반환   ← 기존 경로 그대로
```

## 4. 프롬프트 구조

### textbook 없을 때 (기존 그대로)

```
[지문]
{passageText}

[문항 생성 지시문]
{contentGenerationInstruction}
```

### textbook 있을 때

```
[지문]
{passageText}

[교재에서 선정된 학습 어휘]
[
  { "word": "indigenous", "definition": "originating in a particular place", "example": "..." },
  { "word": "canopy",     "definition": "the upper layer of a forest", "example": "..." }
]

[교재에서 선정된 핵심 표현]
[
  { "expression": "in the wake of", "meaning": "~의 결과로", "example": "..." }
]

[문항 생성 지시문]
콘텐츠 생성 대상을 추출하기 전에 제공되는 교재 데이터에 추출하려는 콘텐츠가 있다면
해당 콘텐츠를 활용하여 아래 지시에 따라 필요한 나머지 콘텐츠를 생성하세요.

{contentGenerationInstruction}    ← 변경 없음
```

> **소스 지시문 동작 원리**
> - "있다면" → 조건부. 교재 데이터가 LLM이 추출하려는 항목과 관련 없으면 기존 방식(지문 추출)으로 자동 대체
> - "활용하여" → 교재 항목(단어, 표현, 대화문)을 생성 대상으로 사용
> - "나머지 콘텐츠를 생성하세요" → hint·question text·options 등 교재에 없는 부분은 LLM이 생성
> - "아래 지시에 따라" → 형식·구조는 contentGenerationInstruction에 위임

## 5. 신규 개발 항목

### 5-1. textbook-context-builder.ts (신규)

textbook 레코드에서 비어있지 않은 모든 필드를 레이블 블록으로 직렬화합니다.  
어느 필드를 주입할지 별도 설정 없이, LLM이 소스 지시문에 따라 관련 데이터를 판단합니다.

```typescript
// apps/api/src/textbooks/textbook-context-builder.ts

const TEXTBOOK_FIELDS: { key: keyof TextbookRecord; label: string }[] = [
  { key: 'keywords',           label: '교재에서 선정된 학습 어휘' },
  { key: 'keyExpressions',     label: '교재에서 선정된 핵심 표현' },
  { key: 'dialogues',          label: '교재 대화문' },
  { key: 'comprehensionItems', label: '교재 독해 문항' },
  { key: 'rawContent',         label: '교재 추가 지문' },
];

export function buildTextbookContext(textbook: TextbookRecord): string | null {
  const blocks: string[] = [];

  for (const { key, label } of TEXTBOOK_FIELDS) {
    const data = textbook[key];
    if (!data) continue;
    if (Array.isArray(data) && data.length === 0) continue;

    const body = typeof data === 'string' ? data : JSON.stringify(data, null, 2);
    blocks.push(`[${label}]\n${body}`);
  }

  return blocks.length > 0 ? blocks.join('\n\n') : null;
}
```

### 5-2. buildQuestionGenerationPrompt 수정

```typescript
// apps/api/src/ai/prompts/question-generation.ts

const TEXTBOOK_SOURCE_DIRECTIVE =
  '콘텐츠 생성 대상을 추출하기 전에 제공되는 교재 데이터에 추출하려는 콘텐츠가 있다면 ' +
  '해당 콘텐츠를 활용하여 아래 지시에 따라 필요한 나머지 콘텐츠를 생성하세요.';

interface QuestionGenerationParams {
  contentGenerationInstruction?: string | null;  // 변경 없음
  strategy?: 'extract' | 'instruct';             // 변경 없음
  answerType?: string;                            // 변경 없음
  passageText: string;                            // 변경 없음
  textbookContext?: string | null;                // 신규
}

export function buildQuestionGenerationPrompt(params: QuestionGenerationParams): string {
  const contentBlock = params.contentGenerationInstruction?.trim()
    ? params.contentGenerationInstruction.trim()
    : params.strategy === 'extract'
      ? buildExtractRules(params.answerType)
      : buildInstructRules();

  if (params.textbookContext?.trim()) {
    return [
      `[지문]\n${params.passageText}`,
      params.textbookContext.trim(),
      `[문항 생성 지시문]\n${TEXTBOOK_SOURCE_DIRECTIVE}\n\n${contentBlock}`,
    ].join('\n\n');
  }

  // 기존 경로 — 변경 없음
  return `[지문]\n${params.passageText}\n\n[문항 생성 지시문]\n${contentBlock}`;
}
```

### 5-3. lessons.service.ts 수정

```typescript
// apps/api/src/lessons/lessons.service.ts

async getOrGenerateQuestions(
  lessonId: string,
  moduleCode: string,
  textId: string | null,
  courseId: string,
  aiModule: AiModuleData,
  passageText: string,
): Promise<ModuleQuestion[]> {

  // 1단계: 캐시 (변경 없음)
  const cached = await this.prisma.moduleQuestion.findMany({
    where: { lessonId, moduleCode },
  });
  if (cached.length > 0) return cached;

  // 2단계: textbook 조회 (신규)
  let textbookContext: string | null = null;

  if (textId) {
    const textbook = await this.prisma.textbooks.findFirst({
      where: { textId, courseId },
    });
    if (textbook) {
      textbookContext = buildTextbookContext(textbook);
    }
  }

  // 3단계: LLM 생성 (textbookContext 유무만 다름, 경로는 동일)
  const prompt = buildQuestionGenerationPrompt({
    contentGenerationInstruction: aiModule.contentGenerationInstruction,
    strategy:   aiModule.questionGenerationStrategy,
    answerType: aiModule.answerType,
    passageText,
    textbookContext,  // null이면 기존 동작 그대로
  });

  const generated = await this.geminiService.generate(prompt);
  return this.saveAndReturn(lessonId, moduleCode, parseGeneratedQuestions(generated));
}
```

## 8. 의도적 제외

| 항목 | 이유 |
|------|------|
| 직접 매핑 경로 (LLM 0회) | textbook 데이터는 module_questions 형식과 달라 직접 변환 불가 |
| 모듈별 소스 지시문 분기 | 모듈은 무한 확장 — 코드 분기 대신 단일 통일 지시문으로 처리 |
| 주입 필드 선택 설정 (textbookDataKey 등) | 소스 지시문의 조건부 구조가 LLM에 관련성 판단을 위임하므로 불필요 |
| textbookContext 완전 대체 | passageText는 문맥 참조용으로 항상 필요 |
| 기존 contentGenerationInstruction 수정 | 소스 판단은 인프라 레벨(sourceDirective)이 담당 — 지시문 재작성 불필요 |
