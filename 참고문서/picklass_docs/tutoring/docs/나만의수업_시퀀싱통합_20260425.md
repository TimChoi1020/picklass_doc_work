## 1. 한 줄 요약

> **나만의 수업의 모듈 시퀀스 결정을 Gemini → analyzer로 일원화하고, 학생이 KPI/시간/레벨을 직접 선택할 수 있는 옵션 폼을 도입했다. 학생 학습 이력 기반 레벨 추정 시스템을 신설해 디폴트로 노출한다. studio.picklass.com 의 시퀀싱과 동일한 결과(parity)가 보장된다.**

## 2. 배경 / 의사결정

studio.picklass.com에 이미 구축된 **KPI + duration 기반 2단계 시퀀싱 로직**(① 모듈 선정 → ② 순서 정렬)을 tutoring의 **나만의 수업**(`/class/lesson-setup/custom`) 흐름에도 통합한다. 시퀀싱의 단일 진실 원천은 **analyzer 서버**이며, studio와 tutoring이 같은 analyzer를 호출함으로써 **결과 동일성(parity)** 이 보장된다.

### 2.1 흐름 변화

| 단계 | 변경 전 (Gemini 기반) | 변경 후 (analyzer 기반) |
|------|----------------------|--------------------------|
| 1 | 학생이 주제 입력 → `POST /lessons/create-custom` | (동일) |
| 2 | `aiService.generatePassage()` — Gemini가 지문 생성 | (동일) |
| 3 | `texts` 테이블 저장 | (동일) |
| 4 | `aiService.analyzePassage()` — Gemini가 지문 분석 | (동일) |
| 5 | **`aiService.generateLesson()` — Gemini가 모듈 시퀀스 생성** ← 교체 대상 | **`lessonPlanService.generate()` — analyzer가 시퀀스 결정** |
| 6 | "나만의 수업" 과정에 `course_lessons` 행 생성 | (동일) |

§5단계만 바뀌고 나머지는 유지. analyzer는 KPI 합집합 + 시간 조정 + before/middle/after stage + 인지 레벨 정렬을 수행.

### 2.2 통합 옵션 비교 / 선택

| 옵션 | 설명 | 채택 |
|------|------|------|
| 1 | 전체 흐름 이식 — KPI 선택 + duration 선택 UI 추가하고 별도 시퀀싱 API 호출 | 부분 채택 (옵션 UI는 추가) |
| **2** | **백엔드 통합형 — `POST /lessons/create-custom`이 내부적으로 analyzer 호출, UI 변경 최소화** | **✓ 1차** |
| 3 | passage 생성 → 시퀀싱 분리 흐름 | 미채택 |

초기엔 Option 2(UI 변경 최소화)로 시작했으나, 진행 중 옵션 UI(KPI/시간/레벨)도 함께 도입 → **Option 2 + 학생용 옵션 폼**의 결합. studio의 강사용 모듈 칩 번호 배지 같은 UI는 이식하지 않음 (학생 단일 사용자 경험 우선).

### 2.3 목표

1. 모듈 시퀀스 결정을 **analyzer로 일원화**
2. studio의 lesson-setup / course 흐름과 **동일 입력 → 동일 시퀀스** parity 보장
3. analyzer 장애 시 **명확한 에러** (Gemini 폴백 두지 않음 — studio가 2026-04-23 폐지한 정책과 동일)
4. 학생이 KPI/시간/레벨을 **직접 선택** 가능, 추정 레벨이 디폴트로 노출
5. 추정 레벨이 학생 override 비율 < 30% (운영 KPI)

### 2.4 비목표

- studio의 ModuleChipList / 번호 배지 UI 그대로 이식 (학생용 미리보기는 결과만 표시)
- analyzer 자체 로직 수정
- `course_lessons.skill_modules` JSON 스키마 변경
- 학생 프로필 페이지에서 레벨 변경/잠금
- KPI 자동 약점 추천 (Phase 2 후속)

## 3. API 변경

### 3.1 `POST /lessons/create-custom` 요청 확장

```json
{
  "topic": "string",
  "targetLevel": 10,                          // 기존 (number 1~18, optional)
  "wordCount": 150,                           // 기존 (optional)
  "selectedKpiCodes": ["VOCAB_RECOG"],        // 신규 — analyzer KPI (optional, 기본값 폴백)
  "durationMin": 30,                          // 신규 — 15|20|25|30 (optional)
  "targetCefrLevel": "B1"                     // 신규 — 사용자 선택 CEFR (optional)
}
```

기본값 (백엔드):
- `DEFAULT_CUSTOM_KPI_CODES = ['VOCAB_RECOG']`
- `DEFAULT_CUSTOM_DURATION_MIN = 30`
- `DEFAULT_CUSTOM_CEFR_LEVEL = 'B1'`

### 3.2 응답 확장

기존 응답에 `sequencing` 메타 추가:

```json
{
  "lessonId": "uuid",
  "courseId": "uuid",
  "passage": { "title": "...", "wordCount": 200 },
  "analysis": { "estimatedLevel": 11, "type": "expository", ... },
  "moduleSequence": [
    { "order": 1, "moduleCode": "WSD", "role": "warming", "passageExposed": false, "estimatedMinutes": 7, "rationale": "..." }
  ],
  "totalEstimatedMinutes": 30,
  "sequencing": {
    "source": "analyzer",
    "passageLevel": "A2",
    "selectedKpiCodes": ["VOCAB_RECOG"],
    "durationMin": 30,
    "summary": { /* analyzer summary */ },
    "meta":    { /* analyzer meta */ }
  }
}
```

`moduleSequence`는 기존 `PlannedModule[]` 스키마 유지 — 프론트엔드 호환.

## 6. 학습자 레벨 추정 시스템

### 6.1 데이터 소스

| 테이블 | 필드 | 의미 |
|--------|------|------|
| `lesson_results` | `student_id`, `course_lesson_id`, `average_score` (Decimal 5,2), `total_duration` (초), `completed_at` | 레슨별 종합 점수 |
| `course_lessons.text_id → texts.level` | CEFR or "1"~"18" | 학생이 풀어본 지문의 난이도 |

핵심 시그널: **풀어본 지문의 레벨 + 점수**.
- A2 지문 90점 → A2가 너무 쉽다 → 학생은 ≥ A2+
- B1 지문 50점 → B1이 어렵다 → 학생은 ≤ B1-

### 6.2 알고리즘 (가중 점수 보정)

```
INPUT: studentId

1. lesson_results 조회 (student_id, completed_at >= 30일 전, ORDER BY DESC LIMIT 10)
   JOIN course_lessons → texts (level)
   필터: text_id IS NOT NULL, texts.level 파싱 가능, completed_at IS NOT NULL

2. 각 결과:
   - levelIdx = parseLevelToIndex(text.level)  // CEFR 또는 정수 문자열
   - score = clamp(0, 100, Number(average_score))
   - scoreAdjust = (score - 50) / 50 × 1.5     // ±1.5단계 보정
   - adjustedLevel = clamp(0, 18, levelIdx + scoreAdjust)
   - daysSince = (now - completed_at) / 86400000
   - recencyWeight = exp(-daysSince / 14)       // 14일 반감기
   - durationWeight = clamp(0.3, 1.0, 0.3 + 0.7 × duration/300)  // 5분 기준
   - weight = recencyWeight × durationWeight

3. inferredIndex = round(가중평균(adjustedLevel, weight))
4. inferredCefr = INDEX_TO_CEFR[inferredIndex]

5. confidence:
   sampleScore = min(1, n/5)
   stdScore    = max(0, 1 - σ/4)         // σ=adjustedLevel 표본 표준편차
   recencyScore = mean(weights)
   confidence  = clamp(0,1, sample×0.5 + std×0.4 + recency×0.1)
   if n < 3: confidence = min(confidence, 0.4)   // sample-bound cap

OUTPUT: { inferredCefr, inferredIndex, sampleSize, confidence, isColdStart, sourceLessons[] }
```

### 6.3 Cold start 처리

| 데이터 양 | 처리 |
|-----------|------|
| 0건 | `B1`(idx=8), confidence=0, isColdStart=true, sourceLessons=[] |
| 1~2건 | 산출하되 confidence ≤ 0.4 (cap) |
| ≥ 3건 | 정상 산출, cap 미적용 |

### 6.4 알고리즘 파라미터 (한 곳에서 조정)

| 파라미터 | 값 | 위치 |
|---------|----|------|
| `RECENT_DAYS` | 30 | [level-estimate.service.ts](../apps/api/src/level-estimate/level-estimate.service.ts) |
| `SAMPLE_LIMIT` | 10 | 동일 |
| 점수 보정 폭 | ±1.5단계 (50점 기준) | [level-estimate.util.ts](../apps/api/src/level-estimate/level-estimate.util.ts) — `scoreToLevelAdjust` |
| recency 반감기 | 14일 | 동일 — `recencyWeight` |
| duration 가중 (0.3~1.0, 5분 기준) | 동일 — `durationWeight` |
| confidence 가중치 | sample×0.5 + std×0.4 + recency×0.1 | 동일 — `computeConfidence` |
| cold-start 디폴트 | `B1` (index=8) | 동일 |

## 8. CEFR 일관성 — 사용자 옵션 → 지문 → 시퀀싱

이전엔 **frontend가 `targetLevel:10` 하드코딩**해서 보냈고, 사용자 슬라이더 선택은 `targetCefrLevel`로만 흘러 analyzer에만 반영. 결과: 지문은 항상 B1로 생성, 화면 "레벨"은 Gemini의 사후 분석값(때로 13/B2-).

수정 후: `effectiveLevelIndex` 단일 진실원천 도입. `targetCefrLevel` 우선 → 0~18 인덱스 변환 → `effectiveTargetLevel`(1~18 clamp)을 generatePassage에, `targetCefrLevel`을 analyzer에 일관 전달. course `level_code`도 동일.

→ 사용자가 슬라이더로 "A2"를 고르면 **지문도 A2 수준으로 시도** + analyzer도 A2 모듈 후보로 시퀀싱.

## 15. 추후 개선 사항

### 15.1 미리보기 표시값 정확도 (학습자 친화도)

`수업 준비 완료!` 화면의 `유형: expository`, `읽기: 1.1분`은 `aiService.analyzePassage()`(별도 Gemini 호출)의 결과. 사용자 선택과 무관하고 다음 한계가 있음:

- **읽기 분**: Gemini 자체 어림 (≈220 wpm) — 영어 **학습자**의 실제 속도(100~150 wpm)보다 빠르게 추정될 수 있음
- **유형 4분류**: `narrative / expository / argumentative / descriptive` 중 단일 라벨, 혼합형 지문도 한 라벨
- **결정성**: 같은 지문 재호출 시 흔들릴 수 있음

| ID | 조치 | 효과 / 비용 |
|----|------|------------|
| FW-A | 읽기 분을 **결정 계산**으로 — `wordCount ÷ levelWpm` (A1-A2=100, B1=140, B2=170, C1+=200) | 일관성↑, 학습자 현실 반영. LLM 추가 호출 없음 |
| FW-B | 읽기 분 LLM 추정 + 학생 레벨 보정의 가중평균 | 둘의 절충 |
| FW-C | 유형 라벨을 한국어로 표시 (`expository → 설명문`) | 매핑 1줄 |
| FW-D | analyzePassage 프롬프트에 wpm 기준 명시 (예: "학습자 130wpm 기준") | LLM 출력 안정화 |

권장 우선순위: **FW-A** (결정성 + 학습자 현실), **FW-C** (국문 친화). FW-B/FW-D는 보조.

### 15.2 옵션 UI 확장

| 항목 | 설명 |
|------|------|
| 추천 KPI 자동 prefil | 학생의 약점 KPI 1개 자동 선택. `GET /lessons/me/recommended-kpis` 신설 또는 `level-estimate` 응답에 합치기 |
| Per-skill 레벨 추정 | 리딩/스피킹 별도. `module_histories.module_code → ai_modules.skill` 조인 → skill별 점수 집계 → 종합 + 스킬별 표시 |
| 슬라이더 위젯 개선 | 19단계 → 세그먼트 4단계(초급/중급/상급) + 마이크로 조정. 모바일 친화 |

### 15.3 Frontend 데이터 페칭 인프라

현재 `custom/page.tsx`는 raw fetch + useState. studio처럼 React Query 도입 시:
- KPI / 레벨 추정 캐싱 일관성
- 디바운스 / 재시도 / 로딩 표준화

### 15.4 자동 재시도 모니터링

`isPassageOnTopic` 미스매치 발동률을 메트릭으로 수집. >5%면 프롬프트 재튜닝 신호.

### 15.5 ELO-style 레벨 갱신

매 레슨 완료마다 ELO 갱신 (`R' = R + K(S - E)`). 단발 점수가 아닌 상대적 성취 평가. 운영 모니터링 후 도입 검토. `K값` 튜닝 필요.

### 15.6 추정 레벨 사용자 피드백 루프

옵션 폼에 "추정 레벨 어떠셨어요? 👍 👎" 미니 피드백 → 알고리즘 정확도 측정 + 가중치 재튜닝.

### 15.7 코드 정리

- `aiService.generateLesson()` + `buildGenerateLessonPrompt()` 사용처 0 확인 후 삭제
- `analysis.estimatedLevel` 필드는 미리보기 미사용 — 응답에 남겨둘지 정리할지 결정

### 15.8 운영 데이터 검증

- `texts.level` 형식 일관성 (`"A2"` vs `"7"`) 운영 DB 샘플 조회로 확인
- `lesson_results.average_score` 스케일 (0~100 가정) 검증
- 4주 운영 후 추정 레벨 override 비율 / cold-start 비율 모니터링 → 알고리즘 가중치 재튜닝
- 추천 레벨이 학생이 override한 비율 < 30% 목표 (운영 KPI)

### 15.9 추천 콘텐츠

진입 시 "${name}님 수준에 맞는 추천 주제 3개" 카드 — 학생이 주제 입력 부담 자체를 줄임. 가벼운 LLM 호출 또는 정적 카탈로그.
