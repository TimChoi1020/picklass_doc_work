// apps/api/src/lessons/lessons.controller.ts:128-136
@Post('register-accesscode')
async registerAccessCode(
  @Headers('authorization') authHeader: string | undefined,
  @Body() body: { accessCode: string },
) {
  const userId = this.extractUserId(authHeader);
  return this.lessonsService.registerAccessCode(body.accessCode, userId);
}

## 6. 인증 시스템 목표 설계

### 6.1 AuthContext / useAuth 훅 (구현 완료)

MOCK_USER 하드코딩 제거 완료. `apps/web/src/lib/hooks/useAuth.ts`에 구현됨.

```typescript
// apps/web/src/lib/hooks/useAuth.ts (구현 완료)

export interface AuthUser {
  id:            string;
  email:         string | null;   // null 가능
  name:          string;          // nickname이 아닌 name 필드
  roleCode:      string;          // 필수
  institutionId: string | null;   // null 가능
}

interface AuthContextValue {
  user:            AuthUser | null;
  isAuthenticated: boolean;
  isLoading:       boolean;
  login:           (userId: string, password: string) => Promise<{ success: boolean; error?: string }>;
  signup:          (email: string, password: string, nickname: string) => Promise<{ success: boolean; error?: string }>;
  logout:          () => Promise<void>;
}

export function useAuth() {
  return useContext(AuthContext);
}
```

**StudioHeader 현재 구현:**
```typescript
// StudioHeader.tsx:12 — 현재 코드
const { user, isAuthenticated, isLoading, logout } = useAuth();
// 표시 필드: user.name, user.email (nickname 아님)
```

### 6.2 JWT 흐름 (현재 구현)

```
로그인 성공
  → 서버: 단일 JWT 발급 (JWT_EXPIRES_IN env, 기본 1h)
  → 클라이언트: localStorage('picklass_auth_token')에 저장
               (httpOnly cookie 아님)

API 요청
  → Authorization: Bearer {token} 헤더 첨부 (authFetch wrapper)
  → GET /auth/me 호출 시 touchActivity() 실행:
      - 활동 시간 갱신 + 응답의 refreshToken 필드로 새 토큰 반환
      - IDLE_TIMEOUT_SECONDS(기본 3600s) 초과 → 401 → 로그아웃

로그아웃
  → POST /auth/logout → 서버 last_active_at = NULL 초기화
  → 클라이언트: localStorage 토큰 삭제 + user 상태 null 설정
```

> `/auth/refresh` 별도 엔드포인트 없음 — `/auth/me` 응답의 `refreshToken` 필드로 갱신 처리.

### 6.3 Next.js middleware 보호 경로 (미구현)

> ⚠️ 현재 토큰을 **localStorage**에 저장하므로 서버 사이드인 middleware에서 직접 읽을 수 없음.
> 구현 전에 토큰을 쿠키로 이중 저장하거나, 별도 쿠키 플래그를 두는 방식을 먼저 결정해야 함.

```typescript
// apps/web/src/middleware.ts (신규 생성 필요 — 토큰 저장 방식 변경 선행 필요)

export function middleware(request: NextRequest) {
  // localStorage는 서버에서 읽을 수 없으므로 쿠키 기반 플래그 필요
  const token = request.cookies.get('picklass_auth_flag');
  const protectedPaths = ['/modules', '/report', '/my-classes'];

  if (!token && protectedPaths.some(p => request.nextUrl.pathname.startsWith(p))) {
    return NextResponse.redirect(new URL('/?login=required', request.url));
  }
}
```

### 6.4 소셜 OAuth 연동 계획

```
Google OAuth 흐름:
  [프론트] 버튼 클릭 → window.location.href = /auth/social/google
  [NestJS] PassportStrategy(GoogleStrategy) → Google 리디렉션
  [Google] 인증 완료 → NestJS /auth/social/google/callback
  [NestJS] 사용자 조회/생성 → JWT 발급 → 프론트 리디렉션 + cookie 설정

필요 패키지:
  @nestjs/passport, passport, passport-google-oauth20
  passport-kakao, passport-naver
  (카카오/네이버는 별도 개발자 등록 필요)
```
