## 1. 사용자 흐름 변화

### 1-1. WRD (exact 모듈) 오답 흐름 수정

**변경 전:**
```
학생 오답 제출
→ ruleHolisticFeedback 발동 (short-text가 HOLISTIC_TYPES에 포함 → 정답인 척 피드백)
→ "딩동댕! urban 정말 완벽해요!" (오답인데 정답 피드백)
```

**변경 후:**
```
학생 1회 오답 제출
→ ruleWrongAnswerFeedback 발동 (exact 모듈 + 틀림)
→ "아쉽네요! 다시 한번 생각해볼까요?" 피드백

학생 2회 오답 제출 (questionMaxAttempts=3 기준)
→ ruleOfferHint → hints.direct 즉시 표시
→ 힌트 메시지 후 최종 재시도

학생 3회 오답 (마지막 시도 후)
→ revealAnswer → "정답은 urban입니다" 정답 공개
→ ruleCorrectAnswer (정답 비교 기반) → celebrate
→ ruleCompleteAfterCelebrate → 모듈 완료
```

### 1-2. CLR 모듈 완료 흐름 변경

**변경 전:** 문장 80% 이상 탐색 시 자동 완료 (학생 인지 없음)

**변경 후:** 80% 탐색 달성 시 FeedbackPanel에 완료 버튼 표시
```
"수고했어요! 지문의 80% 이상을 탐색했어요."
[완료하기 ✓] ← 학생이 직접 클릭
→ 모듈 완료 처리 (점수 계산 후 다음 모듈 이동)
```

### 1-3. AI 피드백 형식 자유화

**변경 전:** `feedbackStyle` 값에 따라 형식 고정
- `'holistic'` → 반드시 "잘한 점 / 개선할 점" 두 섹션 강제
- `'correct-wrong'` → 정답/오답 여부 + 이유 형식 고정
- `'wpm-pronunciation'` → WPM + 발음 형식 고정

**변경 후:** `pedagogyInstruction`이 형식과 내용을 모두 결정
- 각 모듈의 `pedagogyInstruction`에 맞는 자유로운 형식
- 모듈마다 다른 톤, 구조, 강조점 가능

## 3. 정책 / 비즈니스 규칙

### 3-1. scoringMode가 피드백 룰의 진실의 원천

`scoringMode = 'exact'`인 모듈(WRD, QAR 등)은 `q.type`이 `HOLISTIC_TYPES`에 속하더라도 exact 처리를 강제한다.

```
WRD: scoringMode='exact', answerType='short-text'
→ short-text ∈ HOLISTIC_TYPES이지만 exact 우선 적용
→ ruleHolisticFeedback 완전 제외
→ ruleWrongAnswerFeedback / ruleCorrectAnswer 실제 정답 비교 적용
```

### 3-2. exact 모듈 룰 적용 표

| 오케스트레이터 룰 | exact 모듈 | holistic 모듈 |
|---|---|---|
| `ruleHolisticFeedback` | ❌ 항상 skip | ✅ 적용 |
| `ruleWrongAnswerFeedback` | ✅ short-text 포함 적용 | ❌ skip |
| `ruleCorrectAnswer` 정답 판정 | ✅ `answer === q.answer` | ✅ `!!answer` |
| `ruleCompleteAfterCelebrate` holistic 체크 | ❌ (빈 배열, 체크 불필요) | ✅ 전체 문항 체크 |

### 3-3. giveHint — `/ai/hint` API 제거

힌트는 `module_questions.hints.direct`(사전 생성)만 사용. API 실시간 호출 경로 제거.

```
staticHint 있음 → "💡 힌트: {hints.direct 값}"
staticHint 없음 → buildHintMessage() (범용 폴백)
```

### 3-4. feedbackStyle 필드 완전 제거

`pedagogyProfile.feedbackStyle`은 API 파라미터, 프롬프트 템플릿 모두에서 삭제됨.  
`pedagogyInstruction`이 형식 지침을 포함해야 한다 (각 모듈 profile에서 관리).

## 4. 개발자 작업 내역

### 4-1. ModuleOrchestratorAgent.ts — 4개 룰 수정

#### Fix 1: `ruleHolisticFeedback` — exact 모듈 완전 제외

```typescript
// 변경 전
if (!isHolisticType(q.type) && hasRightWrongConcept(context)) return null;

// 변경 후
if (hasRightWrongConcept(context)) return null;
```

#### Fix 2: `ruleWrongAnswerFeedback` — short-text 제외 조건 삭제

```typescript
// 변경 전
if (q.type === 'essay' || q.type === 'short-text' || q.type === 'sentence-write') return null;

// 변경 후 (short-text 제거)
if (q.type === 'essay' || q.type === 'sentence-write') return null;
```

#### Fix 3: `ruleCorrectAnswer` — exact 모듈 정답 비교 분기

```typescript
// 변경 전: q.type 기반 단순 분기
const isAnsweredCorrectly =
  isHolisticType(q.type) || q.type === 'audio-record' || q.type === 'sentence-write'
    ? !!state.answers[lastId]
    : state.answers[lastId] === q.answer;

// 변경 후: scoringMode 우선
const isAnsweredCorrectly = hasRightWrongConcept(context)
  ? state.answers[lastId] === q.answer
  : isHolisticType(q.type) || q.type === 'audio-record' || q.type === 'sentence-write'
    ? !!state.answers[lastId]
    : state.answers[lastId] === q.answer;

// holistic 피드백 대기 조건도 exact 제외
if (!hasRightWrongConcept(context) && isHolisticType(q.type) && ...) return null;
```

#### Fix 4: `ruleCompleteAfterCelebrate` — exact 모듈 holistic 체크 제거

```typescript
// 변경 전
const holisticQuestions = !hasRightWrongConcept(context)
  ? questions
  : questions.filter((q) => isHolisticType(q.type));

// 변경 후
const holisticQuestions = hasRightWrongConcept(context)
  ? []           // exact 모듈: holistic 피드백 없음 → 즉시 완료 가능
  : questions;
```

## 5. 코딩 규칙 및 설계 원칙

### scoringMode 우선 원칙

`q.type`이 `HOLISTIC_TYPES`에 속하더라도 `scoringMode`가 `'exact'`면 exact 처리를 강제한다.  
`hasRightWrongConcept(context)` 함수가 이를 추상화하며, 모든 피드백 룰에서 이 함수로 판단한다.

### pedagogyInstruction 책임 범위 확장

기존 `feedbackStyle`이 담당하던 "피드백 형식 지시"를 `pedagogyInstruction`이 흡수.  
각 모듈 profile의 `pedagogyInstruction`에 형식 지침을 포함하는 것이 원칙.

### 힌트 제공 단계

```
Level 0: hints.button  → 학생이 [힌트 요청] 버튼 클릭 시 (FeedbackPanel 표시)
Level 1: hints.direct  → 오답 누적 시 오케스트레이터 자동 표시 (giveHint)
Level 2: answer        → 최대 시도 초과 시 정답 공개 (revealAnswer)
```
