## 1. 배경 및 문제

현재 `GenericAdapter.buildKpis()`는 모든 KPI를 **단순 완료율 (answeredCount / totalCount × 100)** 로 계산한다.

```typescript
// 현재 — KPI 종류와 무관하게 동일한 값
kpis.push({ kpi_code: kpiCode, value: completionRate, unit: '%' });
```

백오피스 `code_items` 테이블의 `extra_data`에는 각 KPI별로 `measureTool`, `measureMethod`, `measureUnit`이 이미 정의되어 있지만, 프론트에서 이 정보를 읽지 않아 실측값이 `module_kpi_results`에 전혀 저장되지 않는다.

---

## 2. 목표

`code_items.extra_data.measureMethod` 필드를 **실행 가능한 수식 문자열**로 전환하여, 코드 변경 없이 DB 등록만으로 KPI 계산 로직을 추가·수정할 수 있게 한다.

```json
// 변경 전 (설명 문자열)
{ "measureMethod": "TTR 순수 계산" }

// 변경 후 (실행 수식)
{ "measureMethod": "Math.round(new Set(Object.values(ctx.answers).join(' ').split(' ')).size / Math.max(Object.values(ctx.answers).join(' ').split(' ').length, 1) * 100)" }
```

---

## 3. 핵심 결정 사항

### 3.1 measureMethod 재용도

- `extra_data.measureMethod`를 **새 필드 추가 없이** 수식/프롬프트로 재사용
- `measureTool` 값으로 실행 방식 분기:

| measureTool | measureMethod 형식 | 실행 주체 |
|---|---|---|
| `측정` | JS 수식 문자열 (`ctx.XXX` 참조) | 프론트엔드 (동기) |
| `ASR` | JS 수식 문자열 (`ctx.pronunciationScores` 참조) | 프론트엔드 (동기) |
| `STT` | JS 수식 문자열 (`ctx.sttWpm` 등 참조) | 프론트엔드 (동기) — 데이터는 `pronunciation-eval` 응답에서 수집 |
| `LLM` | Gemini 프롬프트 템플릿 (`{{ctx.XXX}}` 보간) | 백엔드 (동기, `saveModuleHistory` 내) |
| `STT+LLM` | Gemini 프롬프트 + STT ctx 보간 | 백엔드 (동기, STT 메트릭 포함 후 Gemini 평가) |

### 3.2 LLM KPI 처리 방식

LLM KPI는 프론트에서 계산 불가 → `module_kpi_results`에 `kpi_value = 0`으로 일단 INSERT, 백엔드 `saveModuleHistory` 내 동기 Gemini 호출 후 UPDATE. (단계 4 참고)

### 3.3 STT KPI 처리 방식

STT KPI는 **ASR과 동일한 데이터 수집 경로**를 사용하지만, 추출 메트릭이 다르다.

```
[ASR]
발화 → POST /ai/pronunciation-eval
  → overallScore, fluencyScore, accuracyScore 반환
  → pronunciationScores[qId] 누적
  → KpiCtx.pronunciationScores → new Function() 수식 실행

[STT]
발화 → POST /ai/pronunciation-eval (기존 엔드포인트 확장)
  → (기존 점수) + sttMetrics { wpm, mlu, silenceRatio } 반환
  → sttMetricsRef[qId] 누적 → 모듈 완료 시 평균값 계산
  → KpiCtx.sttWpm / sttMlu / sttSilenceRatio → new Function() 수식 실행
  → pending 없음 (측정과 동일 처리)

[STT+LLM]
발화 → sttMetricsRef 누적 (동일)
  → buildKpis(): pending=true 마킹 (LLM과 동일)
  → saveModuleHistory body에 sttMetrics 포함
  → 백엔드: {{ctx.sttWpm}}, {{ctx.sttMlu}} 보간 후 Gemini 평가
```

**ASR과의 결정적 차이**: Azure SDK 응답의 `NBest[0].Words`에서 단어 offset/duration을 파싱해 WPM·MLU·silence ratio를 계산해야 한다. 현재 `pronunciation.service.ts`는 이 타이밍 데이터를 버리고 있어 파싱 확장이 선결 과제.

## 4. ctx 표준 객체 정의

수식이 참조하는 변수 집합. 모든 `측정` / `ASR` 수식은 이 객체만 사용한다.

```typescript
interface KpiCtx {
  // 문항·답변
  answers: Record<string, string>;         // questionId → 학습자 답변
  questions: QuestionData[];
  correctCount: number;                    // 정답 수 (정답 일치 비교)
  totalCount: number;                      // 전체 문항 수
  answeredCount: number;                   // 답변한 문항 수

  // 발음 (ASR 모듈)
  pronunciationScores: Record<string, number>;  // questionId → 0~100 (종합 발음 점수)
  prosodyScores: Record<string, number>;        // questionId → 0~100 (Azure Prosody 세부 점수)

  // 시간
  timeSpentSeconds: number;               // 모듈 실측 소요 시간(초)
  turnLatencies: number[];                // 턴별 반응 지연 시간(ms) — RPB·RPF 전용

  // 힌트·시도
  attemptCounts: Record<string, number>;  // questionId → 시도 횟수
  hintUsedIds: string[];

  // 지문
  passageWordCount: number;               // passage.content 단어 수
  passageCharCount: number;               // passage.content 글자 수
  passageContent: string;                 // passage 원문 전체 (LLM 프롬프트 보간용)
  answersText: string;                    // ctx.answers 줄글 직렬화 (LLM 프롬프트 보간용)

  // STT 전용 — pronunciation-eval 응답에서 수집 (⬜ 단계 4-B 구현 예정)
  sttWpm: number;                         // Words Per Minute — 발화 속도
  sttMlu: number;                         // Mean Length of Utterance — 평균 발화 길이 (단어 수)
  sttSilenceRatio: number;                // 0–100 — 침묵 비율 %
}
```

> **STT 전용 필드** (`mlU`, `wpm`, `silenceRatio` 등)는 Azure Speech SDK 결과를 백엔드에서 파싱한 후 별도 ctx로 전달. 이 계획의 단계 4에서 다룬다.

#### 초기 구현 (2026-06-30) — fire-and-forget (폐기)

> **문제**: LLM KPI가 AI 패널에 항상 0으로 표시되고, `module_histories.kpis`에도 0이 영구 저장됨.
> 2026-07-02에 동기 방식으로 교체됨.

초기 구현은 `evaluateLlmKpisAsync()` private 메서드를 fire-and-forget으로 호출했으며,
`module_kpi_results`만 비동기 UPDATE하고 `module_histories.kpis`는 업데이트하지 않아
두 가지 문제가 발생했다:

1. **AI 패널 표시 오류**: 프론트는 API 응답 없이 메모리의 kpis(value=0)를 그대로 렌더링
2. **DB 불일치**: `module_histories.kpis`에 LLM KPI가 영구적으로 0으로 저장

#### 재구현 (2026-07-02) — 동기 방식 ✅ 현재 구현

**목적**: `saveModuleHistory` 내에서 LLM KPI 평가를 동기 완료 후 최종값을 API 응답에 포함.
프론트가 응답값으로 FeedbackPanel을 업데이트하여 사용자에게 실제 KPI 점수를 표시한다.

**처리 흐름** (현재 구현 — 2026-07-02 최종):

```
POST /lessons/:id/modules/:code/history
  ── $transaction ────────────────────────────────────────────────────────────
  → module_histories INSERT (LLM KPI kpis[].value = 0 초기값)
  → module_kpi_results createMany (kpi_code 있는 KPI, LLM pending 포함)
  → module_histories.findMany + course_lessons.findUnique → lesson_results upsert
  ── 트랜잭션 외부 (kpi_code 있는 KPI가 하나라도 있으면) ─────────────────────
  → 지문·답변 내용 조회 (passageContent, answersText)
  → LLM KPI(pending=true)가 있으면:
        → measureMethod 프롬프트 보간 → Gemini API → 정수 파싱
        → module_kpi_results UPDATE kpi_value (실제값)
        → finalKpis에 pending→false, value→실제값 반영
  → kpi_code 있는 전체 KPI (측정+LLM 통합) description 일괄 생성:
        → generateLlmKpiDescriptions(kpis, passageContent, answersText)
        → finalKpis에 description 반영
  → module_histories.kpis UPDATE (finalKpis — 값+description 통합, 1회)
  → LLM 값 변경이 있었으면 → lesson_results 재집계 UPDATE
  → 응답: { success, id, kpis: finalKpis }

프론트:
  → API 응답의 finalKpis로 setSavedKpis()
  → FeedbackPanel: displayModuleResult = { ...moduleResult, kpis: savedKpis }
  → handleModuleNext: savedKpis로 completedResults 업데이트
```

### 단계 4-B — STT KPI 처리 ⬜ 설계 완료 / 미구현

**목적**: `STT` measureTool KPI(`SPEAKING_RATE`, `MLU_LENGTH` 등)를 실제값으로 측정.
현재 `pending=true`로 마킹만 되고 값은 항상 0.

#### 선결 과제 — Azure SDK offset/duration 확인

`pronunciation.service.ts`의 `NBest[0].Words` 파싱에서 `Offset`(100ns 단위), `Duration` 필드 포함 여부 확인.

```typescript
// pronunciation.service.ts — 현재 파싱 (타이밍 정보 누락)
words: nBest?.Words?.map(w => ({
  word: w.Word,
  accuracyScore: w.PronunciationAssessment?.AccuracyScore ?? 0,
  errorType: w.PronunciationAssessment?.ErrorType ?? 'None',
}))

// 확인 필요: Azure가 Offset/Duration을 반환하는지
const words = nBest?.Words ?? [];
const lastWord = words[words.length - 1];
const totalSpeechMs = lastWord ? (lastWord.Offset + lastWord.Duration) / 10000 : 0;
const wpm = Math.round(words.length / Math.max(totalSpeechMs / 60000, 0.001));
```

Azure가 타이밍 데이터를 반환하지 않을 경우 대안: 프론트에서 녹음 길이(`recordingDurationMs`)를 함께 전달.

#### 처리 흐름

```
[단계 4-B 구현 후]

1. pronunciation.service.ts 확장
   → sttMetrics { wpm, mlu, silenceRatio } 계산 후 응답에 추가

2. useModuleOrchestrator: sttMetricsRef 추가
   → submitVoiceAnswer() 응답에서 sttMetrics 누적
   → completeModule 시 평균값 → KpiCtx.sttWpm / sttMlu / sttSilenceRatio 전달

3. GenericAdapter.buildKpis(): STT → pending 필터 제거
   → new Function()으로 ctx.sttWpm 등 수식 실행 (측정과 동일)

4. STT+LLM (PRESENT_FLUENCY):
   → buildKpis(): pending=true 유지
   → saveModuleHistory body에 sttMetrics 포함
   → 백엔드: {{ctx.sttWpm}}, {{ctx.sttMlu}} 보간 후 Gemini 평가
   → LLM 처리 루프에 STT+LLM 분기 추가
```

### 단계 5 — 백오피스 관리 UI 개선 (선택) ⏸ 대기 중

**목적**: `code-management` 화면에서 `측정 도구`(measureTool) 값에 따라 `측정 방법` 입력창의 동작을 달리하여 어드민이 올바른 형식을 쉽게 입력할 수 있게 한다.

#### 현재 상태

`KPI_CATEGORY` 그룹의 `측정 방법` 컬럼이 고정 placeholder만 보여줌:

```typescript
// code-management/page.tsx line 132
{ key: 'extraData.measureMethod', label: '측정 방법', type: 'text', width: '17%',
  placeholder: 'Step별 문장 길이 추적 자동 측정' },
```

`측정 도구` 값과 무관하게 항상 동일한 placeholder → 어드민이 어떤 형식을 입력해야 하는지 알기 어렵다.

#### 변경 목표

| measureTool | 변경 후 |
|---|---|
| `측정` | JS 수식 예시 placeholder: `Math.round(ctx.correctCount / Math.max(ctx.totalCount, 1) * 100)` |
| `ASR` | ASR 수식 예시 placeholder: `Math.round(Object.values(ctx.pronunciationScores).reduce((a,b)=>a+b,0)/...)` |
| `LLM` | 프롬프트 예시 placeholder + **textarea로 전환** (프롬프트가 한 줄을 초과하는 경우 많음) |
| `STT` | STT 수식 예시 placeholder |

#### 구현 방향 결정 필요

현재 `CodeGroupTable` / `ColumnDef`는 정적 placeholder만 지원한다. 두 방향 중 선택 후 구현 진행.

**방향 A — 정적 교체 (간단)**
- `측정 방법` placeholder를 `측정 도구별 형식 안내 문자열`로 고정 교체
- 동적이 아닌 정적이지만 어드민에게 형식을 알려줌
- 추가 컴포넌트 수정 없음

**방향 B — 동적 + textarea 지원 (제대로)**
- `ColumnDef`에 `placeholderFn: (row: LocalItem) => string` 콜백 추가
- `CodeGroupTable` 셀 렌더 로직에서 `placeholderFn` 우선 적용
- `ColumnDef`에 `type: 'textarea'` 추가 및 셀 렌더러 분기
- `측정 도구 = LLM`이면 자동으로 textarea로 전환

**파일** (방향 B 기준):
- `apps/admin/frontend/src/app/(admin)/admin/ai-modules/code-management/page.tsx`
- `apps/admin/frontend/src/app/(admin)/admin/system/_components/code-group-table.tsx`
