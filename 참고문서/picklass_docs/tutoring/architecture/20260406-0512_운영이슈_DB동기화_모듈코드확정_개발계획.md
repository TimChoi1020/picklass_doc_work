## 3. ai_modules 필드 체계

### 3.1 AiModuleFlags — 설계 원칙

Orchestrator 규칙에서 `context.pedagogyProfile.xxx` 직접 비교 대신 `context.flags.xxx`를 참조하는 것이 원칙이다. 필드명 변경이나 타입 확장 시 규칙 코드 수정 없이 `buildModuleFlags()`만 수정하면 된다.

```typescript
// ✅ 권장 — flags 참조
function ruleXxx(context: OrchestratorContext) {
  if (context.flags.isVoiceModule) return null;
  if (!context.flags.hasRightWrongConcept) return null;
}

// ❌ 지양 — 프로파일 직접 비교 (점진적 교체 대상)
// context.pedagogyProfile.answerType === 'audio-record'
// context.pedagogyProfile.scoringMode !== 'holistic'
```

**현재 구현된 AiModuleFlags** (`agent-types.ts`):

```typescript
interface AiModuleFlags {
  // passageMode(DB) → passageExposureMode(브릿지, GenericAdapter.ts:120) → flags 계산
  // 브릿지 제거 후에는 passageMode를 직접 참조
  isPassageHidden:      boolean;  // passageMode === 'hidden'
  isPassagePreview:     boolean;  // passageMode === 'preview'
  isPassageTimedBlur:   boolean;  // passageMode === 'timed-blur'
  isVoiceModule:        boolean;  // answerType === 'audio-record'
  isMultiQuestion:      boolean;  // questionCount !== 'single'
  hasRightWrongConcept: boolean;  // scoringMode === 'exact'
  hasRetry:             boolean;  // questionMaxAttempts > 1
  hasHints:             boolean;  // hintTypes.length > 0 && !includes('none')
}
```

`buildModuleFlags(profile)` 호출 위치: `useModuleOrchestrator.ts:755`

**미구현 플래그** (§5.2 참조):
- `isPassiveModule` — 학생 답안 제출 없는 모듈 (CLR 등)
- `isHolisticScoring` — scoringMode === 'holistic'
- `isPronunciationScoring` — scoringMode === 'pronunciation'
- `isSingleQuestion` — questionCount === 'single'
- `isContentDriven` — questionCount === 'content-driven'

### 5.1 🔴 자동화 미구현 (운영 위험)

**DB 자동 동기화 미구현**

백오피스 AI 모듈 저장 API(`PUT /ai-modules/:id`)에서 튜터링 Supabase로 자동 PATCH 호출하는 로직이 없다.

```typescript

  const updated = await this.prisma.aiModule.update({ ... });

  // 자동 동기화 (미구현)
  await this.tutoringSupabaseService.syncAiModule(updated);

  return updated;
}
```
