# 외부 API 인증 — 두 패턴 통합

- 날짜: 2026-06-28
- 맥락: `api.picklass.com` 은 기존에 흩어진 두 외부 API 패턴을 한 서비스로 통합 호스팅한다.

## 기존 두 패턴 (출처)

| | backoffice `b2b-external` | tutoring `external` |
|---|---|---|
| 인증 | 장기 **API Key** (`partner_api_keys`, `pk_live_...`) | **원타임 토큰** (`external_access_tokens`, UUID, ~60분) |
| 헤더 | `Authorization: Bearer {apiKey}` | `X-Access-Token` + `X-Module-Code` |
| 스코프 | 파트너 기관 단위 | 단일 사용자+레슨+모듈 |
| 발급 | backoffice 화면(system_admin) | tutoring(일부 한시적·하드코딩) |
| 에러 | `{code, message}` | NestException 기본 |
| 용도 | 파트너가 학습결과 **pull** | 외부→픽클래스 학습모듈 **핸드오프** |

## api.picklass.com 의 통합 방식

- 두 가드를 **분리 배치**하고 컨트롤러별로 선택한다.
  - `ApiKeyGuard` → `partner_api_keys(active)` 조회 → `req.partnerInstitutionId` 주입. (backoffice `B2bApiKeyGuard` 이식)
  - `AccessTokenGuard` → `X-Access-Token`/`X-Module-Code` 헤더 검증, 실제 유효성은 서비스에서 DB 조회. (tutoring `ExternalTokenGuard` 이식)
- **에러 envelope 통일**: 전 라우트 `{code, message}` (backoffice 포맷 기준).
- **발급 로직 미이식**: 키/토큰 발급은 기존 소유 서비스(backoffice/tutoring)에 둔다. 본 서비스는 **검증/조회 전용**.
- tutoring 의 **한시적 엔드포인트**(`tokens/issue` 하드코딩, `gateway` 리다이렉트)는 운영 API 가 아니므로 **이식하지 않음**.

## 공유 테이블 (read-only)

- `partner_api_keys` — backoffice 소유. 컬럼: `api_key`, `institution_id`, `status_code(active|revoked)`, `revoked_at`.
- `external_access_tokens` — tutoring/speaking 공유. 컬럼: `token`, `user_id`, `course_lesson_id`, `module_code`, `is_expired`, `expires_at`, `used_at`.
