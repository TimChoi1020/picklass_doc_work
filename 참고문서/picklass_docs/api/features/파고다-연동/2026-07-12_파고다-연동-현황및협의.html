기준 명세 파고다–오이지 연동 API 명세서 v1.2 (2026-07-07)
본 문서는 파고다–오이지 연동 명세(v1.2)의 10개 API에 대해 픽클래스가 ‘오이지’ 역할을 직접 수행하여 구현한 현황과, 실연동을 위해 파고다 측에 요청드리는 협의 사항을 정리한 것입니다.

1. 연동 구조

파고다(LMS) ──#1~6 수신──▶ 픽클래스(오이지 역할)
            ◀──#7 로그인 인증──
            ◀──#8~10 결과 송신──
  • #1~6: 파고다 → 픽클래스 (수강신청·기수변경·환불·기간조정·종료일·설문공지) 수신
  • #7: 픽클래스 → 파고다 (학습자 로그인 인증)
  • #8~10: 픽클래스 → 파고다 (출석완료·수료완료·평가)

2. API별 구현 현황

#API방향메서드픽클래스 현황
1학습자 수강신청파고다→픽클래스POST구현 완료 수신·적재
2기업 기수정보 변경파고다→픽클래스PATCH구현 완료
3환불·수업취소파고다→픽클래스PATCH구현 완료
4기간조정·서비스티켓파고다→픽클래스PATCH구현 완료
5기업 종료일 일괄변경파고다→픽클래스PATCH구현 완료
6설문·공지 등록파고다→픽클래스POST구현 완료
7로그인 인증픽클래스→파고다POST엔드포인트 대기 인증 후 학습자 자동 프로비저닝 로직 완료
8출석 완료픽클래스→파고다POST엔드포인트 대기 송신 파이프라인(아웃박스) 구현
9수료 완료픽클래스→파고다POST엔드포인트 대기 수료 AND/OR 판정 + 송신 구현
10레벨테스트·평가픽클래스→파고다POST엔드포인트 대기

#1~6 수신은 실동작 검증까지 완료했습니다. #7~10 송신은 로직·판정·송신 파이프라인을 구현했으나, 파고다 측 실제 엔드포인트·인증 정보가 명세상 “미정”이라 대기 중입니다.

4. 파고다 측 협의·제공 요청

A. #7~10 엔드포인트 및 인증 (최우선)

명세상 Request URI가 “미정”입니다. 아래를 확정해 주세요.

  • #7(로그인)·#8(출석)·#9(수료)·#10(평가) 각각의 운영/테스트 실제 URL
  • 인증 방식(예: Authorization Bearer 토큰, auth_secret 등) 및 값 발급
  • #7 응답의 classStatus·classInfo(active/completed) 반환 규격 재확인

B. processId / detailId ↔ 콘텐츠 대응

#1의 processes[].detailIds(예 "Y2GK7B")는 파고다 자체 콘텐츠 코드로 확인됩니다. 픽클래스 과정/차시와 연결하려면 대응 관계가 필요합니다.

  • 파고다 detailId(및 processId) 코드 목록과 그 의미(어떤 과정/차시 단위인지)
  • 또는 파고다가 픽클래스 콘텐츠 코드를 수용해 동봉해 줄 수 있는지
  • 이 대응이 확정되어야 수강(classId)이 픽클래스 과정으로 연결되어 학습·수료 판정이 개통됩니다.

C. processId / detailId 그레인(단위) 확정

#1은 process(상위) → details[](하위) 계층인데, #8·#9·#10 예시는 processId가 #1의 detail 레벨 코드(R2GK7B)로 표기되어 있습니다. 결과 송신 시 어느 단위를 processId/detailId로 보내야 하는지 확정 부탁드립니다.

D. 데이터 형식

  • 일시(bgnDttm/endDttm) 타임존(KST/UTC) 기준
  • #10 응답 필드명 recommand(표) vs recommend(예시) 표기 확정

5. 참고 — 수신(#1~6) 엔드포인트·인증

Base URL — 라이브 https://api.picklass.com · 개발 https://api-picklass-com.vercel.app (경로 /pagoda/*). 파고다에서 #1~6 호출 시 이 주소로 전송합니다.

현재 #1~6 수신은 파트너 API Key(Authorization: Bearer) 대조로 보호하고 있습니다. 파고다에서 호출 시 사용할 키 발급/교환 방식을 함께 협의하면 됩니다.

본 문서는 픽클래스 내부 구현 현황 기준의 협의용 초안입니다. 회신 주시면 #7~10 실연동 및 콘텐츠 대응을 즉시 진행하겠습니다.
