## 1. 컬럼 = `module_question` 테이블 구조 (snake_case)

| 엑셀 컬럼 | API 응답(camelCase) | 설명 |
|---|---|---|
| code | (module.code) | 모듈 코드 |
| name | (module.name) | 모듈 이름 |
| skill | (module.skill) | speaking |
| question_id | questionId | 문항 UUID |
| question_number | questionNumber | 문항 번호 |
| type | type | audio-listen / audio-record |
| instruction | instruction | 지시문(한글) |
| text | text | 화면 본문 |
| options | options | 모듈별 JSON(또는 SMK는 string) |
| answer | answer | 모듈별 JSON(listen 모듈은 null) |
| hints | hints | SMK 객체 / SFB 연계표현 string / 그 외 null |
| source | source | RPB·RPF 시나리오·페르소나 / SFB 정답문장 / 그 외 null |
| sort_order | sortOrder | 0부터 |
| question_status | questionStatus | active |

> **DB는 snake_case, 외부 API 응답은 camelCase로 변환.** options/answer/hints/source는 파싱된 JSON으로 전달(문자열 이중 인코딩 금지). SMK의 `options`와 SFB의 `hints`/`source`는 예외적으로 string.

## 2. 샘플 구성 — 1개 레슨(식당 음식 주문하기), 8개 모듈

| 모듈 | name (엑셀 정본) | type | 행수 | 문항수 형태 |
|---|---|---|---|---|
| LRN | Learn & Study | audio-listen | 3 | (표현 3개를 행으로) |
| VLM | Vocabulary Listening & Meaning | audio-listen | 5 | 단어당 1행 (question_number 2~6) |
| SHD | Shadowing Drill | audio-record | 3 | 문장당 1행 |
| SFB | Sentence Fill-in Blank | audio-record | 3 | 문장당 1행 |
| SMK | Sentence Making Drill | audio-record | 3 | 표현당 1행 |
| RPB | Role-Play Basic | audio-record | 1 | 대화 전체 1행 |
| RPF | Role-Play Free | audio-record | 1 | 미션 전체 1행 |
| OMP | One Minute Presentation | audio-record | 1 | 토픽 1행 |

> PDF 대비 정정: **SMK = "Sentence Making Drill"**, **VLM = "Vocabulary Listening & Meaning"** (엑셀 정본). LRN은 `options.videoUrl` 없이 `expressionList` + `readCompletionThreshold:70`만.

## 3. 표현 연계 확인 (LRN→SHD→SFB→SMK 동일 세트)

레슨의 **3개 핵심 표현**이 네 모듈에 동일하게 흐른다:
1. `ask for one's order` (~의 주문을 받다/요청하다)
2. `have with no sauce` (소스 없이 먹다/주문하다)
3. `ensure a smooth dining experience` (원활한 식사 경험을 보장하다)

- LRN: 3 표현을 `expressionList`로 소개 · SHD: 3 문장 따라말하기 · SFB: 3 문장 빈칸 · SMK: 3 표현으로 문장 만들기.
- VLM: 관련 어휘(politely, confirm, ensure, smooth, experience …).

## 5. 구현 메모

- 엑셀 행 = `module_questions` 행. verify는 (모듈코드, 레슨/text) 기준으로 행을 모아 camelCase 변환 후 `lesson.text.moduleQuestions[]`에 동봉.
- `evalRubric`·`measures` 키에 측정 코드(LOGIC_STRUCT, RE_UTTERANCE, MISSION_USAGE, EXPRESSION_APPROP, INTERACTION_ACT, STAY_TIME, READ_COMPLETION)가 포함 — 결과 송신(results)·내부 측정값과 연결.
- OMP `text`·`description`에 `_x000D_`(캐리지리턴) 포함 — 줄바꿈 정규화 필요.
- VLM `question_number`가 2부터 시작(엑셀 그대로) — 운영 데이터 정합 시 확인.
- 원본 엑셀(.xlsx)은 본 문서 hub로 정식 편입 권장(현재 Desktop 위치).
