## 1. 3자 아키텍처

```
 파고다(Pagoda)            우유랩스                 픽클래스(Picklass)=우리
 B2B LMS/기관       ←→     AI 스피킹 앱(외부 고객사)  ←→    콘텐츠·AI 채점 엔진
 학습자·수강·결제·결과       학습자에게 앱 제공               studio(콘텐츠) + api(런타임)
        └── Doc A: 10 API ──┘          └── Doc B: 3 API ──┘
```

- **픽클래스 = 우리.** **우유랩스 = 픽클래스의 외부 고객사**. 우유랩스 앱이 픽클래스 API 호출(`앱 → 픽클래스`).
- 우유랩스는 별도로 **파고다(LMS)** 와 연동(Doc A). 픽클래스는 Doc A의 직접 당사자가 **아님**.
- 단, 우유랩스가 파고다에 보내는 데이터(출석 총평/교정, 평가 점수/추천과정, Monthly Report)의 **원천이 픽클래스 AI 산출물** → Doc B의 `results`/`verify` 설계가 이를 공급해야 함.

## 2. 서비스 제공 플로우 (PPTX slide 8~13)

1. ① 우유랩스 → 스튜디오: AI 콘텐츠 생성 (파톡 어드민에 과정 생성·등록)
2. ② 파고다 → 과정관리: 우유랩스 과정코드 연동
3. ③ 파고다 → 제휴사별 AI 상품관리: 업체별 AI 제공 과정 설정 (기수 복사 시 AI 과정도 복사)
4. ④ 파고다 → 학습자: 수강신청
5. ⑤ 파고다 → 학습자 → 나의 학습현황: **'상세보기'에서 우유랩스 앱 연결(핸드오프)**. 앱 설치 시 앱으로, 미설치 시 브라우저+스토어 안내. 리스트엔 수업진도만(발화량 미노출)
6. ⑥ 파고다 → 수강중인 강의: 수업 진행

## 3. Doc A — 파고다 ↔ 우유랩스 (우선 범위: 8·9, 10 추후)

> **범위 조정(2026-06-28)**: 파고다↔우유랩스 10개 API 중 **8(출석완료)·9(수료완료)만 우선** 다룬다. **10(레벨테스트/월말평가)은 추후** 진행, **1~7은 본 분석 범위에서 제외**. (모든 API 호출 주체는 우유랩스이며, 픽클래스는 데이터 공급원)

개발 `https://tpwww.npagodatalk.com/`, 운영 `https://www.pagodatalkool.com/` (경로 "미정"). 응답 표준 `{ result: { code(200/400), message } }`. 일시 형식 `YYYY-MM-DD HH24:MI:00`.

| # | API | 방향 | 메서드 | 핵심 필드 / 픽클래스 의존 |
|---|---|---|---|---|
| 8 | **출석 완료** | 우유랩스→파고다 | POST | userInfo(comCd/loginId/userId, **totSpeechCnt** 누적발화량), classInfo(classId, **speechCnt** 발화량, bgnDttm, endDttm, **comment**(총평), **todayExpression**{idiom,example}, **corrections**{grammer[]{wrong,correct}, pronunciation[]{wrong,correct}}), processes{processId, detailId} |
| 9 | **수료 완료** | 우유랩스→파고다 | POST | userInfo, classInfo(classId), processes{processId, detailId} |

> **10(추후)**: evalInfo(evalType=LT\|MR, evalLevel 1~10, comment, scores{listen/speak/pronun/voca/gram 10점}, memos{영역별}, corrections(LT만), recommend[]{process,detailId}). 화면 확정 후 정리 예정(현재 초안).

**픽클래스가 공급해야 할 데이터(8·9)**: 발화량(speechCnt/totSpeechCnt), 총평(comment), todayExpression(idiom/example), corrections(문법·발음 wrong/correct), 들은 과정(processId/detailId). (출석 인정 = PPTX 정책상 해당 수업 미션 전부 완료)

> **구현 방식 확정(2026-06-28)**: 8·9는 **이벤트 push가 아니라 파고다가 호출해 가져가는 Pull API**로 제공.
> `GET /external/attendance`(#8)·`GET /external/completion`(#9) — **파트너 API Key**(`partner_api_keys`→기관 스코프) + `startDate`/`endDate`/`page`/`limit`. backoffice `b2b-external`(GET /b2b/results) 패턴 준용.
> 현재 데이터로 채우는 필드: `userId`(users.user_id), `classId`(=course_lessons.id), `bgnDttm`/`endDttm`(module_histories), `totSpeechCnt`(utterance_logs 합), `score`/`averageScore`. **미보유 → null(협의)**: `comCd`, `loginId`, 수업별 `speechCnt`, `comment`, `todayExpression`, `corrections`, `processes(processId/detailId)`. (10번 평가는 추후)

## 5. PPTX — 사업/운영 정책

- **기본 옵션(제휴사별 상품관리)**: 수업 20분 고정, 대상 B2B/B2C, 방식 AI 스피킹, 횟수 상품별(8/12회 등), 기간 업체별(1·3개월), 종류 정규(Regular)/무제한(Free). 무제한이면 '나만의 수업' 월 최대 20회. 대화모드(Push-to-Talk/Hybrid/Always-On) 전부 제공·학습자 선택.
- **기타 옵션(기수관리)**: 서브웨이모드(발화 어려운 환경에서 듣기모드 전환), 나만의 수업(교재 외 자체 수업 생성, 제공 횟수 내).
- **수료 기준**: 출석율(출석수/교육횟수×100 ≥ 수료율) 또는/그리고 지정 발화 문장 수. **출석 인정 = 해당 수업 미션 전부 완료**. (Doc A completion.criteria `sentences|attendance`)
- **티켓**: 소진 후 당일 23:59까지 학습, 미사용 이월 불가.
- **재학습**: 기간 종료 후 이력·코멘트 조회만, 재학습 불가(업체별 조건 택일/동시).
- **Monthly Report**: 마지막 수업/기간종료 시 자동 생성. 데이터=최초 AI 레벨(레벨테스트 대체)+영역별 평가. 앱·파고다 모두 노출, 명칭 통일. 전화/화상 레벨과 AI 학습 레벨 상이 가능.
- **설문/공지**: AI 학습자는 전화/화상과 별개 노출·집계, 파고다 어드민 반영.
