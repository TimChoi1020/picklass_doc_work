# Doc B — 스피킹앱 ↔ 픽클래스 구현 규격

- 날짜: 2026-06-28
- 구현 호스트: `api.picklass.com` (경로 **`/external/*`**, 인증 원타임 토큰)
- 원문(API 규격): `스피킹앱__픽클래스_연동_규격_(8개_모듈).pdf`
- **데이터 정본**: `스피킹모듈 데이터 샘플_최종.xlsx` → [모듈데이터-샘플-엑셀](./2026-06-28_모듈데이터-샘플-엑셀.md). 콘텐츠 값·모듈명·필드 형태는 **엑셀이 우선**(PDF 예시는 참고).

## 0. 픽클래스가 할 일 (문서 0.1)

| 작업 | 내용 | 우선순위 |
|---|---|---|
| **A. verify 확장** | `/external/verify`가 8개 모듈코드 수신 + 응답 `lesson.text.moduleQuestions[]` 동봉 | 운영 진입 전 |
| **B. 모듈 콘텐츠 생성·전달** | 레벨·차시별 `module_question`을 모듈별 형태로 생성해 A에 실어 전달. 표현연계 4종 동일 표현세트 | 핵심(모듈개발 입력) |
| **C. 결과 수신** | `POST /external/results` 신설(엔드포인트·페이로드 협의) | 협의 후 |
| tokens/expire | FRT 그대로 재사용, 변경 없음 | — |

## 1. API 목록

| # | 방향 | 엔드포인트 | 메서드 | 인증 | 상태 |
|---|---|---|---|---|---|
| 1 | 앱→픽클래스 | `/external/verify` | GET | X-Access-Token | 구현 |
| 2 | 앱→픽클래스 | `/external/tokens/expire` | POST | X-Access-Token | 구현 |
| 3 | 앱→픽클래스 | `/external/results` | POST | X-Access-Token | 구현 |
| 4 | 시스템→픽클래스 | `/external/tokens/issue` | POST | **X-Admin-Secret** | 구현(발급) |

학습자용 공통 헤더: `X-Access-Token`(진입 토큰), `X-Module-Code`(8개 중 하나).
발급(4)은 `X-Admin-Secret`(=`EXTERNAL_TOKEN_ISSUE_SECRET`) 보호. 본문 `{ userId(외부 user_id), courseLessonId(uuid), moduleCode, expiresInMinutes? }` → `{ moduleCode, token, expiresAt, reused }`. 동일 (학습자·레슨·모듈) 유효 토큰은 재사용.

## 2. 8개 모듈

| 코드 | 이름 (엑셀 정본) | type | 문항수 | 비고 |
|---|---|---|---|---|
| LRN | Learn & Study | audio-listen | single | 강의영상+표현카드(탭) |
| VLM | Vocabulary Listening & Meaning | audio-listen | multi | 단어 듣기(탭) |
| SHD | Shadowing Drill | audio-record | multi | 따라말하기(발화) |
| SFB | Sentence Fill-in Blank | audio-record | multi | 빈칸 완성 발화 |
| SMK | Sentence Making Drill | audio-record | multi | 새 문장 + AI 코칭 |
| RPB | Role-Play Basic | audio-record | single | 대본 역할극 |
| RPF | Role-Play Free | audio-record | single | 자유 역할극 |
| OMP | One Minute Presentation | audio-record | single | 30초준비+1분발표, AI채점, 재도전없음 |

**표현 연계(중요)**: LRN→SHD→SFB→SMK는 같은 핵심 표현 세트를 단계만 바꿔 반복 → 한 세션 안에서 **같은 표현세트로 묶어** 전달.

## 3. #1 verify — 응답 규격

요청: `GET /external/verify` + 헤더(X-Access-Token, X-Module-Code).
변경점 2가지: (가) X-Module-Code를 8개 모듈로 확장, (나) 응답 `lesson.text.moduleQuestions[]`에 해당 모듈 문항배열 동봉(FRT의 speakingContent 자리).

`module` 메타 — 모듈별로 다른 것: `answerType, uiTemplate, questionCount, questionMin/MaxCount`. 나머지(scoringMode 등)는 FRT 규칙 그대로.

```jsonc
{
  "lessonId": "lesson-restaurant-01",
  "user": { "userId": "u_12345", "name": "홍길동" },
  "module": {
    "code": "SHD", "name": "Shadowing Drill", "skill": "speaking",
    "uiTemplate": "voice",            // standard(듣기) | voice(발화)
    "answerType": "audio-record",     // audio-listen(탭) | audio-record(발화)
    "scoringMode": "absolute",
    "passageExposureMode": "sentence",
    "feedbackStyle": "encouraging",
    "questionCount": "multi",         // single | multi
    "questionMinCount": 3, "questionMaxCount": 7
  },
  "lesson": {
    "id": "lesson-restaurant-01", "topic": "식당에서 음식 주문하기", "lessonOrder": 1,
    "text": {
      "title": "식당에서 음식 주문하기",
      "content": "", "speakingContent": null,   // FRT만 사용
      "level": "B1", "category": "daily", "wordCount": null,
      "moduleQuestions": [ /* 3.2 형태의 문항 원소들 */ ]
    }
  }
}
```

## 3.2 moduleQuestions[] 공통 봉투 (module_question)

| 필드(camelCase) | 타입 | 필수 | 설명 |
|---|---|---|---|
| questionId | string | O | 문항 고유 ID |
| questionNumber | number | O | 문항 번호(1부터) |
| type | enum | O | audio-listen(탭) / audio-record(발화) |
| instruction | string(한글) | O | 학습자 지시문 |
| text | string | O | 화면 본문(문장·단어·블랭크·토픽) |
| options | JSON(모듈별) | O | 콘텐츠 본체 |
| answer | JSON(모듈별) | 발화모듈 | 정답·채점기준. listen 모듈(LRN·VLM)은 null |
| hints | JSON/string | 일부 | SMK(객체)·SFB(연계표현 string), 그 외 null |
| source | JSON/string | 일부 | RPB·RPF(시나리오·페르소나), SFB(정답문장), 그 외 null |
| sortOrder | number | O | 정렬 |
| questionStatus | string | O | active 등 |

전달 주의: ① options/answer/hints/source는 **파싱된 JSON**으로(문자열 이중 인코딩 금지). ② 필드명 camelCase. ③ threshold(`asrThreshold`/`exprApropThreshold`/`missionUsageThreshold`, 보통 70)는 합격 기준값 — 미만이면 자동 1회 재도전(OMP 제외).

## 3.3 모듈별 options/answer/hints 스키마

> 실제 값·완전 예시는 [모듈데이터-샘플-엑셀](./2026-06-28_모듈데이터-샘플-엑셀.md) 참조(정본). 아래는 형태 요약.

| 모듈 | text | options | answer | hints |
|---|---|---|---|---|
| LRN | 표현 요약 | `{expressionList[]{expression,meaningKr,usage,exampleEn,exampleKr}, readCompletionThreshold, videoUrl?}` | — | — |
| VLM | 단어 | `{word, sampleEn, sampleKr, meaningKr, audioUrl?, sampleAudioUrl?}` | — | — |
| SHD | 영어 문장 | `{meaningKr}` | `{sentence, asrThreshold, phoneticGuide, pronunciationPoints[], passSpeeds[]}` | — |
| SFB | 블랭크 문장 | `{meaningKr}` | `{fullSentence, blankAnswer, asrThreshold, pronunciationPoints[]}` | 연계표현(string) / source=정답문장 |
| SMK | 한글 가이드 | `modelEnglish(string)` | `{targetExpression, modelEnglish, alternativeAnswers[], evalCriteria{}, exprApropThreshold}` | `{button, direct}` |
| RPB | 안내문 | `{dialogue[]{turnNo,speaker(persona\|learner),role,en,meaningKr}}` | `{learnerTargetLines[], missionExpressions[], asrThreshold}` | source=`{scenario,persona{name,role,tone}}` |
| RPF | 미션 안내 | `{branchPool[]{branchType,promptEn,meaningKr,targetMission}, missionChecklist[]{expression,meaningKr}}` | `{missionExpressions[], interactionActCriteria{}, missionUsageThreshold}` | source=`{scenario,persona}` |
| OMP | 토픽+안내 | `{topicEn, topicKr, description}` | `{topic{en,kr}, keywords[], memoTemplate[], modelKeyPoints[], evalRubric{fiveAxis[],ompFour{}}, prepSeconds, speakSeconds}` | — |

> 문항수: multi=단어/문장마다 1문항, single=리스트·대화·토픽 전체가 1문항. 완전 예시(레스토랑 주제)는 원문 3.3 참조.

## 4. #2 tokens/expire (재사용)

`POST /external/tokens/expire` + 헤더. 응답 `{ token, isExpired, expiredAt }`. 409 = 이미 만료(멱등). → **현재 handoff에 구현됨, 그대로 사용.**

## 5. #3 results — 학습 결과 수신 (신규)

세션 종료 시 1회 집계 송신(제안). 호스트/엔드포인트명/시점/페이로드 **협의 대상**.

```jsonc
POST /external/results
// headers: X-Access-Token, X-Module-Code
{
  "lessonId": "lesson-restaurant-01", "userId": "u_12345", "moduleCode": "SHD",
  "level": 8,
  "passRate": 0.83,        // 정답률(재도전 판정, 0~1)
  "retakeCount": 0,        // 자동 재도전(0|1)
  "scores": { "pronunciation":78,"fluency":72,"grammar":80,"appropriateness":75,"volume":70 }, // 5축
  "measures": { /* 모듈별 내부 측정값 - 6절, 키·범위 협의 */ },
  "results": [             // 문항별 상세(선택)
    { "questionId":"shd-restaurant-001","seq":0,"passed":true,"attempt":1,"retakeCycle":0,"durationMs":4200,
      "pronunciation": { "accuracy":82,"fluency":74,"completeness":90,"prosody":70,"score":79,"errorWords":1 } } // 발화모듈만
  ]
}
```

### 6. 모듈별 내부 측정값(measures)

5축(발음·유창·문법·상황적절성·발화량) 외:

| 모듈 | 측정 지표 |
|---|---|
| LRN | 영상 머문시간(STAY_TIME) · 완독률(READ_COMPLETION) |
| VLM | 없음(자기보고 — 측정·저장 제외) |
| SHD | 5축 |
| SFB | 5축 · 미션사용(MISSION_USAGE) |
| SMK | 5축 · 표현적절성(EXPRESSION_APPROP) |
| RPB | 미션사용 · 5축 |
| RPF | 미션사용 · 상호작용(INTERACTION_ACT) · 5축 |
| OMP | 5축 · 논리구조 · 재발화 · 키워드사용률 · OMP 4영역 · 공인시험 환산 |

## 7. 레벨별 표현/어휘 수 (CEFR)

| CEFR | 핵심 표현 수 | 핵심 어휘 수 |
|---|---|---|
| Pre-A1~A1 | 3 | 5 |
| A2 | 4 | 6 |
| B1 | 5 | 8 |
| B2 | 6 | 10 |
| C1~C2 | 7 | 12 |

표현연계 4모듈(LRN→SHD→SFB→SMK)은 이 N개 동일 표현 공유. verify의 `module.questionMin/MaxCount`도 이 수에 맞춤.

## 8. 현재 스캐폴드(api.picklass.com) GAP

| 항목 | 현재(handoff) | 필요 | 작업 |
|---|---|---|---|
| 경로 | `/api/v1/handoff/verify` | **`/external/verify`** | 경로 변경(글로벌 prefix/버전 예외 또는 별도 라우트) |
| verify 응답 | module 기본 + text 기본 | **`moduleQuestions[]` + `passageExposureMode`** | verify 서비스 확장 |
| `module_questions` | 스키마 미포함 | 모델 추가 + (module,text) 조회 | prisma 서브셋에 추가(tutoring 소유 테이블) |
| `/external/results` | 없음 | **신설** | 컨트롤러/서비스 + 저장 대상 결정 |
| DB 쓰기 | read-only 전제 | results는 **쓰기** 필요 | module_histories/lesson_results 쓰기 권한·소유 협의 |
| tokens/expire | ✅ 구현됨 | 그대로 | 경로만 `/external/tokens/expire`로 |
| 8개 모듈 데이터 | 없음 | ai_modules + module_questions 콘텐츠(작업 B) | **엑셀 정본 존재** → studio/콘텐츠 생성과 연계 |

## 9. 협의 필요 (문서 §5)

- results: 호스트(픽클래스 제공?)·엔드포인트명·호출시점(세션종료 1회 vs 문항별)·measures 포함범위·문항별 상세 포함여부
- 추가 학습자 정보 수신 필요여부 (현재 verify: user{userId,name}, level, module 메타)
- 콘텐츠 형식: A.LRN 영상(URL/videoUrl/자막) · B.오디오 출처(앱 TTS vs 음원파일) · C.레벨·차시 콘텐츠 선택주체(픽클래스) · D.표현세트 연계 보장 · E.OMP 공인시험 환산식
