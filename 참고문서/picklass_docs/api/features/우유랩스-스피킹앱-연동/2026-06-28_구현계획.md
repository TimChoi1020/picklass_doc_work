## 0. 전제·핵심 사실

- **토큰이 신원의 정본**: `external_access_tokens`에 `user_id`(uuid)·`course_lesson_id`(uuid)·`module_code`가 바인딩됨. verify/results 모두 토큰 기준으로 내부 식별자를 얻는다(body의 외부 ID는 검증·참고용).
- **module_questions 컬럼 타입**: `options`·`hints`=JsonB(파싱됨), `answer`·`source`=Text(JSON 문자열 또는 평문). → 출력 규칙: **JSON 파싱 시도 → 성공하면 객체, 실패하면 평문, 빈 값이면 null**.
- DB는 snake_case, 외부 응답은 camelCase. 마이그레이션은 본 서비스가 두지 않음(read는 그대로, write는 §4 협의).

## 1. 구조 변경 — 경로 `/external/*`

현재 `main.ts`는 글로벌 prefix `api` + URI 버저닝(`/api/v1/...`). 계약은 `/external/verify` 등 **prefix 없음**.

- [main.ts]: `setGlobalPrefix`·`enableVersioning` **제거**. (helmet·CORS·ValidationPipe·Swagger·ThrottlerGuard·AllExceptionsFilter·LoggingInterceptor 유지)
- `handoff/` 모듈 → **`external/`** 로 재편, `@Controller('external')`.
- 라우트: `GET /external/verify`, `POST /external/tokens/expire`, `POST /external/results`, `GET /health`, `GET /docs`.
- 기존 `partners/`(API Key 샘플)·`ApiKeyGuard`는 본 범위 밖 → **제거 또는 보류**(향후 파트너 pull용으로 남길 수 있음). `AccessTokenGuard`는 그대로 사용.

## 2. Prisma 스키마 추가

기존 서브셋에 다음 추가 후 `pnpm prisma:generate` (실값 정합은 `prisma db pull`로 확인).

- **`module_questions`** (신규): `id, module_id(uuid), text_id(int), question_number, type, instruction?(text), source?(text), text, options?(jsonb), answer(text), hints?(jsonb), sort_order, status, created_at, updated_at`. 인덱스 module_id/text_id/status. `@@map("module_questions")`.
- **`ai_modules`**에 필드 보강: `passageExposure`(`@map("passage_exposure")`) — verify의 `passageExposureMode`로 노출. (필요 시 feedbackStyle 등 기존 유지)
- `module_histories`(신규, results 저장용): `id, course_lesson_id(uuid), student_id(uuid), module_code, answers?(jsonb), chat_messages?(jsonb), score?(int), kpis?(jsonb), started_at?, completed_at?, created_at`.
- (선택) `lesson_results`: `id, course_lesson_id, student_id, average_score(decimal), module_results?(jsonb), total_duration?, completed_at?, created_at`.

## 3. `GET /external/verify` 확장

### 3.1 처리 흐름 (기존 handoff 확장)
1. AccessTokenGuard: `X-Access-Token`·`X-Module-Code` 헤더 주입.
2. 토큰 조회·만료·`module_code == X-Module-Code` 검증 → `usedAt` 기록 (기존 로직).
3. `users`(id=token.userId), `ai_modules`(code=moduleCode, active), `course_lessons`(id=token.courseLessonId, include text).
4. **신규**: `module_questions` where `module_id = aiModule.id AND text_id = lesson.text_id` order by `sort_order` → camelCase 변환 + answer/source 파싱.
5. 응답 조립.

### 3.2 응답 필드 매핑 (API ← DB)

| 응답 경로 | 출처 |
|---|---|
| `module.code/name/skill` | ai_modules.code/name/skill |
| `module.uiTemplate/answerType/scoringMode/feedbackStyle` | ai_modules 동일 필드 |
| `module.passageExposureMode` | ai_modules.passage_exposure |
| `module.questionCount/questionMinCount/questionMaxCount` | ai_modules 동일 |
| `lesson.text.moduleQuestions[]` | module_questions (3.1-4) |
| `moduleQuestions[].questionId/questionNumber/sortOrder/questionStatus` | question_id/question_number/sort_order/status |
| `moduleQuestions[].type/instruction/text` | 동일 |
| `moduleQuestions[].options/hints` | JsonB 그대로 |
| `moduleQuestions[].answer/source` | Text → **파싱(객체\|문자열\|null)** |

> FRT 호환: FRT 토큰이면 기존대로 `speakingContent`만, `moduleQuestions`는 빈 배열/생략. 8개 모듈이면 `speakingContent: null` + `moduleQuestions[]`.

### 3.3 X-Module-Code 검증
허용값 = ai_modules에 존재하는 active 코드(LRN/VLM/SHD/SFB/SMK/RPB/RPF/OMP + FRT). 미존재 시 `NOT_FOUND`.

## 4. `POST /external/results` 신설

### 4.1 인증·검증
- AccessTokenGuard + 토큰 유효성(verify와 동일 검증 재사용).
- DTO(class-validator): `lessonId, userId, moduleCode, level, passRate(0~1), retakeCount, scores{pronunciation,fluency,grammar,appropriateness,volume}, measures(obj), results[]?`.
- body.moduleCode == token.moduleCode 검증(불일치 `MODULE_MISMATCH`).

### 4.2 저장 매핑 (토큰 uuid 기준)
`module_histories` 1행 upsert/insert:
| 컬럼 | 값 |
|---|---|
| course_lesson_id | **token.courseLessonId** |
| student_id | **token.userId** |
| module_code | token.moduleCode |
| score | 대표 점수(협의: scores 평균 또는 passRate·100) |
| kpis | `{ level, passRate, retakeCount, scores, measures }` |
| answers | body.results[] |
| completed_at | now |

(선택) `lesson_results`에 요약(average_score, module_results=body) 병행 기록.

### 4.3 멱등성
동일 세션 재전송 대비: (course_lesson_id, student_id, module_code) 기준 최신 1건 갱신 또는 append 정책 — **협의 후 확정**.

## 5. `POST /external/tokens/expire` (유지)
기존 handoff 구현 그대로, 경로만 `/external/tokens/expire`. 응답 `{token,isExpired,expiredAt}`, 이미 만료 시 409(`ALREADY_EXPIRED`).

## 6. 검증 방법

- **엑셀 대조**: 샘플 레슨(식당 주문)의 module_questions를 DB(또는 시드)에 넣고 모듈별 verify 호출 → 응답 `moduleQuestions[]`가 [엑셀 정본](./2026-06-28_모듈데이터-샘플-엑셀.md) 값과 일치하는지(특히 SMK options=string, SFB hints/source, RPB/RPF source 객체, OMP evalRubric) 확인.
- **curl 예시**: `GET /external/verify -H "X-Access-Token: <t>" -H "X-Module-Code: SHD"`, `POST /external/results -d @sample.json`.
- 로컬: `pnpm build && pnpm start`. Docker: `docker compose up -d --build`(가상화 활성 후).

## 8. 결정 사항 (2026-06-28 확정) + 잔여 미정

**확정**
- **module_histories 쓰기**: 본 서비스가 직접 insert — **허용 확정**.
