## 1. 기관 스킨·브랜딩 시스템 (master-plan §5.1)

### 개요

기관(institution) 단위로 로고와 메인 컬러를 앱에 동적 적용. 백오피스에서 설정하면 학습자 앱에 즉시 반영. 픽클래스 기본 브랜드는 유지하면서 B2B 파트너사 화이트라벨을 지원.

### 구현 단계

| 작업 | 범위 | 상태 |
|------|------|------|
| DB 테이블 생성 | Supabase에 `institution_brands` 테이블 추가 (migration) | ⬜ |
| API — GET /config/brand DB 연동 | `config.controller.ts` hardcode → DB 조회로 교체 | ⬜ |
| 백오피스 연동 검토 | `picklass-backoffice` 기관관리 화면 브랜드 설정 섹션 설계 | ⬜ |
| Supabase Storage 연동 | 로고 업로드 → Storage URL → `institution_brands.logo_url` 저장 | ⬜ |
| 백오피스 PUT /admin/institutions/:id/brand | Admin Auth 포함 엔드포인트 구현 | ⬜ |
| 프론트 미리보기 | PhoneFrame 축소 렌더링 컴포넌트 (백오피스용) | ⬜ |
| 통합 테스트 | 기관 브랜드 설정 → 앱 반영 E2E 확인 | ⬜ |

## 3. 동적 수료조건 시스템 (master-plan §12)

### 개요

향후 고객사의 요청에 대비하기 위해 구현한다. 파트너사마다 수료 기준이 다르다. 백오피스에서 수료조건을 설정하면 앱의 홈 통계·학습 탭 진행바가 동적으로 변경. 조건이 없으면 기본 통계(스트릭·레슨 수) 유지.

### 구현 단계

| 작업 | 범위 | 상태 |
|------|------|------|
| DB 테이블 생성 | `program_configs`, `user_program_enrollments` | ⬜ |
| GET /config/program MVP | 기본값 응답 (completionRules 빈 배열) | ⬜ |
| lesson_count / course_completion_pct 집계 | `lesson_results` 기반 ON-DEMAND 계산 | ⬜ |
| useProgramConfig 훅 | 세션 캐시 + `completionRules.length === 0` 분기 | ⬜ |
| CompletionProgressBar 컴포넌트 | 재사용 가능 단일 조건 진행 바 | ⬜ |
| 홈 StatsRow 동적 변경 | 수료조건 유무에 따라 표시 내용 분기 | ⬜ |
| 학습 탭 InProgressCourseCard 변경 | course_completion_pct 표시 + D-day 뱃지 | ⬜ |
| utterance_sentences / utterance_words 집계 | `module_histories.kpis` 합산 | ⬜ |
| D-day 칩 | endDate 30일 이내 StatsRow 상단 노출 | ⬜ |
| 백오피스 프로그램 생성 UI | POST /admin/programs + 등록 | ⬜ |
| 통합 테스트 | 수료조건 설정 → 앱 반영 E2E | ⬜ |

### 개발 상세

#### Phase 1 — DB

```sql
CREATE TABLE program_configs (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id        UUID REFERENCES institutions(id) NOT NULL,
  product_code          TEXT,
  program_name          TEXT NOT NULL,
  completion_rules      JSONB NOT NULL,
  daily_goal_minutes    INTEGER DEFAULT 20,
  start_date            DATE,
  end_date              DATE,
  created_at            TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE user_program_enrollments (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             UUID REFERENCES users(id) NOT NULL,
  program_config_id   UUID REFERENCES program_configs(id) NOT NULL,
  enrolled_at         TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, program_config_id)
);
```

`completion_rules` JSONB 구조:
```json

  { "type": "utterance_sentences", "target": 3000, "unit": "문장", "label": "발화량" },

]
```

## 4. 발화량 챌린지 (master-plan §4.4) 🆕

### 개요

VLM·DRILL·FRT·RPL·OMP 등 **전 모듈에서 발화한 문장**을 통합 집계하는 발화량 챌린지를 챌린지 탭의 독립 서브페이지로 구현.
시간(분)이 아닌 **문장 수**를 1차 KPI로 사용. 학습자가 4종 미터를 챌린지 탭에서 일괄 확인·관리.

### 4종 미터

| 미터 | 기간 | 기본 목표 | 비고 |
|------|------|---------|------|
| 일일 발화량 | 24h | 30문장 | 탭 모드(마이크 OFF) 인정 (×0.6 가중치) |
| 주간 발화량 | 월~일 | 200문장 | 주간 챌린지와 별도 추적 |

## 5. 마이 탭 알림 설정 세분화 (master-plan §4.5) 🆕

### 개요

기존 마이 → 앱 설정의 단일 알림 토글을 **5개 서브 메뉴**로 세분화.
백엔드 알림 발송 시스템(푸시 서버·알림톡·이메일)은 장기 과제로 연기하고,
**프론트 설정 UI + 사용자 선택값 DB 저장만 우선 구현**.

### 5개 서브 메뉴

| # | 메뉴명 | UI 타입 | 내용 |
|---|--------|---------|------|
| 1 | 푸시 알림 | 펼침 목록 (9종 토글) | 오늘의 미션 / 스트릭 보호 / 챌린지 마감 / 친밀도 게이트 / 1MP 리마인더 / 발화량 부족 / AI 캐릭터 메시지 / 관리자 공지(B2B) / 복귀 캠페인 |
| 2 | 방해 금지 시간대 | 시간 범위 선택 | 기본 22:00~08:00, 사용자 변경 |
| 3 | 알림톡 수신 동의 | 단일 토글 + 법적 고지 | B2C 한정, 법적 옵트인 |
| 4 | 이메일 캠페인 수신 동의 | 단일 토글 + 법적 고지 | 법적 필수 이메일은 항상 발송 |
| 5 | 마케팅 정보 수신 동의 | 단일 토글 + 법적 고지 | 프로모션·할인 카테고리 |
