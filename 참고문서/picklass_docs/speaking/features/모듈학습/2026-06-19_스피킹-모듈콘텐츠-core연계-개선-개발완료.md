## 1. 배경 — 발견된 연계 구조 허점

파이프라인 Stage 1(Studio 사전 생성)과 Stage 2~3(Speaking API Cache-Aside) 구현은 완료됐다.
그러나 Stage 2~3 구현을 실제 코드 기준으로 검토한 결과 다음 4가지 구조 문제가 확인됐다.

### 문제 1 — 문항 수가 `core_expressions.length`와 무관하게 계산됨

`apps/api/src/lessons/lessons.service.ts` `getModuleData()`에서 문항 수를 결정하는 로직:

```typescript
const recommendedCount = questionCount === 'content-driven'
  ? 0
  : calcRecommendedCount(passageLevel, min, max);  // ← 지문 레벨 기반 계산
```

LRN·SHD·SFB·SMK·RPF는 `core_expressions` N개를 1:1로 문항에 매핑해야 한다.
그런데 `recommendedCount`는 CEFR 레벨 기반 계산이라 `core_expressions.length`와 다를 수 있다.

**예시**: CEFR B1 지문 → `core_expressions` 4개 생성 → `calcRecommendedCount` 결과 3 → Gemini에 "3개 생성" 전달 → 4번째 표현 누락.

RPB도 동일 문제: 문항 수가 `core_dialog.turns.length`가 아닌 레벨 기반 값으로 계산된다.

---

### 문제 2 — SHD·SFB의 `contentGenerationInstruction`이 필드를 명시적으로 지정하지 않으면 Gemini가 임의로 재생성할 수 있음

| 모듈 | `core_expressions`에 이미 있는 것 | Gemini 임의 재생성 시 위험 |
|------|----------------------------------|--------------------------|
| **SHD** | `sentence` (낭독 원문, 완성형) | 다른 문장 선택 가능성 |
| **SFB** | `blank_version` + `blank_answer` (빈칸 위치 확정) | Studio에서 공들여 만든 빈칸 위치가 바뀔 수 있음 |

시스템 일관성을 위해 모든 모듈은 Gemini 경로를 유지한다.
대신 SHD·SFB의 `contentGenerationInstruction`에 참조할 필드명을 명시적으로 지정하여
Gemini가 재해석 없이 매핑만 수행하도록 제어한다.

---

### 문제 3 — `contentGenerationInstruction`이 주입 데이터를 명시적으로 참조하지 않으면 Gemini가 무시할 수 있음

프롬프트 구조:
```
[핵심문장·핵심표현 — N개]   ← JSON 데이터 주입됨
[콘텐츠 생성 지시문]         ← ai_modules.content_generation_instruction
```

지시문에 "위의 데이터를 사용하라"는 명시적 언급이 없으면
Gemini는 `[지문]` 블록만 보고 독립적으로 문항을 생성할 수 있다.

---

### 문제 4 — `core_expressions`·`core_dialog` null 시 폴백 경로가 일관성을 해침

Studio 등록 시 Gemini 오류, 소급 생성 누락, 개발/테스트 환경 등의 이유로
`texts.core_expressions`·`texts.core_dialog`가 null인 지문이 존재할 수 있다.

이 상태에서 학생이 모듈에 진입하면 `contentGenerationInstruction`만으로
지문 전체에서 Gemini 자율 추출하는 폴백 경로를 타게 된다.
모듈 간 표현 불일치 및 SFB `blank_version` 불일치가 발생할 수 있다.

**결정**: null인 경우 Speaking API가 **온디맨드로 직접 생성**하고 완료 후 진행한다.

## 3. 구현 상세

### 3-A·B. 문항 수 고정 (`lessons.service.ts`) ✅

`getModuleData()` 내 `coreExpressions`·`coreDialog` 추출 후 `coreCount` 오버라이드.

```typescript
const coreCount = coreExpressions?.length ?? (coreDialog ? coreDialog.turns.length : null);
const recommendedCount = coreCount
  ?? (questionCount === 'content-driven' ? 0 : calcRecommendedCount(passageLevel, min, max));
```

---

### 3-C. `contentGenerationInstruction` 최상단 문구 추가 (backoffice DB) ✅

모든 대상 모듈의 `ai_modules.content_generation_instruction` **최상단**에 모듈별 문구 추가.
backoffice AI 모듈 관리 페이지에서 직접 편집 완료.

| 모듈 | 참조 필드 |
|------|-----------|
| LRN | `sentence`, `translation`, `expression`, `expression_meaning` |
| SHD | `sentence` → `text`·`answer` 동일 (수정 금지) |
| SFB | `blank_version` → `text`, `blank_answer` → `answer`, `sentence` → `source` (수정 금지) |
| SMK | `sentence` |
| RPB | `core_dialog.turns[].role`, `line`, `translation` |
| RPF | `expression`, `expression_meaning`, `sentence` |

---

### 3-D. core 데이터 온디맨드 생성 🔄

#### 3-D-1. `AiService` — `generateJson<T>()` 추가

```typescript
async generateJson<T>(prompt: string): Promise<T> {
  const text = await this.callWithFallback(prompt, { responseMimeType: 'application/json', temperature: 0.3 });
  return JSON.parse(text) as T;
}
```

#### 3-D-2. 신규 서비스 — `CoreDataService` (`apps/api/src/ai/core-data.service.ts`)

- `speaking_passage_prompts` 테이블에서 프롬프트 조회 (`core-expressions`, `core-dialog`)
- `generateIfMissing(textId, passageContent, level, needDialog)`:
  1. `core_expressions` null → Gemini 생성 → `texts` UPDATE
  2. `needDialog && core_dialog` null → Gemini 생성 → `texts` UPDATE
- 생성 실패 시 에러 로그만 남기고 null 반환 (graceful)

#### 3-D-3. `lessons.service.ts` — null 체크 + 온디맨드 생성 호출

`coreExpressions`·`coreDialog` 추출 전, `getModuleData()` 진입 시 체크:

```typescript
const needCoreExpressions = CORE_EXPRESSIONS_MODULES.has(moduleCode);
const needCoreDialog = moduleCode === 'RPB' || moduleCode === 'RPF';

if ((needCoreExpressions && !text.core_expressions) || (needCoreDialog && !text.core_dialog)) {
  const generated = await this.coreDataService.generateIfMissing(
    text.id, text.content ?? '', text.level, needCoreDialog,
  );
  // text 객체 갱신 (let으로 선언 변경 필요)
  if (!text.core_expressions && generated.coreExpressions) {
    text = { ...text, core_expressions: generated.coreExpressions };
  }
  if (!text.core_dialog && generated.coreDialog) {
    text = { ...text, core_dialog: generated.coreDialog };
  }
}
```

#### 3-D-4. `AiModule` — `CoreDataService` 등록

```typescript
providers: [AiService, QuestionGeneratorService, CoreDataService],
exports:   [AiService, QuestionGeneratorService, CoreDataService],
```

#### 3-D-5. `schema.prisma` — `speaking_passage_prompts` 추가

`prisma:pull` 후 자동 반영 → `prisma:generate` 실행.

## 5. 각 모듈별 최종 생성 방식 정리

| 모듈 | 생성 방식 | 주입 데이터 | 문항 수 기준 |
|------|-----------|------------|------------|
| LRN | Gemini (`core_expressions` 주입) | `sentence` + `expression` + `translation` | `core_expressions.length` (고정) |
| SHD | Gemini (`core_expressions` 주입) | `sentence` → 필드 그대로 매핑 지시 | `core_expressions.length` (고정) |
| SFB | Gemini (`core_expressions` 주입) | `blank_version` + `blank_answer` → 필드 그대로 매핑 지시 | `core_expressions.length` (고정) |
| SMK | Gemini (`core_expressions` 주입) | `sentence` → 한국어 보고 영문 생성 | `core_expressions.length` (고정) |
| RPB | Gemini (`core_dialog` 주입) | `core_dialog.turns` → 필드 그대로 매핑 지시 | `core_dialog.turns.length` (고정) |
| RPF | Gemini (`core_expressions` 주입) | `expression` 미션 목록 | `core_expressions.length` (고정) |
| OMP | Gemini (지문 전체) | 지문 텍스트 | 레벨 기반 |
| VLM | Gemini (지문 전체) | 지문 텍스트 | 레벨 기반 |

## 6. 검증 항목

| 항목 | 확인 방법 |
|------|-----------|
| SHD 문항 수 = `core_expressions.length` | GET `/lessons/:id/module-data?moduleCode=SHD` 응답 `questions.length` 확인 |
| SHD 문항 `text`·`answer`가 `core_expressions[].sentence`와 동일 | 응답 JSON 대조 |
| SFB 문항 `text`가 `blank_version`, `answer`가 `blank_answer`와 동일 | 응답 JSON 대조 |
| LRN 문항 수 = `core_expressions.length` | 응답 `questions.length` 확인 |
| RPB 문항 수 = `core_dialog.turns.length` | 응답 `questions.length` 확인 |
| `core_expressions` null 지문 + SHD 진입 시 자동 생성 후 문항 반환 | null 지문으로 GET → 응답 정상 + texts 테이블 값 확인 |
| `core_dialog` null 지문 + RPB 진입 시 `core_dialog`만 생성 | null 지문으로 RPB GET → texts 테이블 확인 |
| `speaking_passage_prompts` 미존재 시 graceful 처리 | 프롬프트 없는 환경에서 에러 미발생 확인 |
| `core_expressions` null 지문에서 기존 레벨 기반 폴백 유지 (프롬프트 없을 때) | 로그 확인 |
| `pnpm typecheck` 통과 | `apps/api` 타입 에러 없음 |
