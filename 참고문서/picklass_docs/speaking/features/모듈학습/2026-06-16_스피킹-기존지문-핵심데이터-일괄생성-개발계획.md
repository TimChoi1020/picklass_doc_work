## 1. 배경

신규 지문은 등록 시 `SpeakingCoreDataService.generateAll()`이 자동 실행된다 (fire-and-forget).
그러나 해당 기능이 추가되기 **이전에 등록된 기존 지문**은 `core_expressions`, `core_dialog`가 `null`인 상태다.

이 기능은 기존 지문을 대상으로 핵심데이터를 소급 생성하는 두 가지 수단을 제공한다.

- **2-A**: 지문 1개 단위 개별 재생성 (Studio UI 버튼)
- **2-B**: null 지문 전체 일괄 처리 (백오피스 운영 도구)

기존 `/passages/:textId/analyses/:type/refresh` 엔드포인트 패턴을 그대로 차용한다.

**이전 결정 (2026-06-19)**:
- 2-A API는 Studio에서 구현 완료. UI 버튼은 Backoffice 관리 페이지로 통합.
- 2-B 전체 일괄 처리는 Backoffice에서 전담 구현.
- Backoffice 상세 계획: [`backoffice/features/2026-06-19_speaking-핵심데이터-관리-페이지-개발계획.md`](../../../backoffice/features/2026-06-19_speaking-핵심데이터-관리-페이지-개발계획.md)

## 2. 2-A — 개별 재생성

### API

```
POST /passages/:textId/core-data/generate
Body: { "force": boolean }
```

| `force` | 동작 |
|---------|------|
| `false` | `core_expressions`가 이미 있으면 skip (`status: "skipped"` 반환) |
| `true`  | 기존 값 덮어쓰기 (null 초기화 후 재생성) |

**응답**

```json
{ "textId": 42, "status": "started" | "skipped" }
```

### 동작 흐름

```
POST /passages/42/core-data/generate  { force: false }
  ├── force=false + core_expressions 존재 → { status: "skipped" } 반환
  └── 생성 필요 시
        └── void speakingCoreData.generateAll(42, content, level)  ← fire-and-forget
              ├── Step 1: generateCoreExpressions() → texts.core_expressions 저장
              └── Step 2: generateCoreDialog()      → texts.core_dialog 저장
```

### Studio UI 연결

- 지문 상세 페이지에 **"핵심데이터 생성"** 버튼 추가
- `force: false` 호출 → 이미 있으면 skip이므로 중복 호출 안전
- 재생성이 필요한 경우에만 `force: true` 버튼 별도 제공 (또는 confirm 다이얼로그)

### 구현 범위 (Studio)

| 파일 | 작업 | 상태 |
|------|------|------|
| `apps/api/src/passages/passages.controller.ts` | `POST /passages/:textId/core-data/generate` 엔드포인트 추가 | ✅ 완료 |
| `apps/api/src/passages/speaking-core-data.service.ts` | `force` 플래그 처리 로직 (null 초기화 분기) | ✅ 완료 |
| UI 버튼 | Backoffice 관리 페이지에서 대체 — Studio 상세 페이지 버튼은 보류 | ➡️ Backoffice |

## 3. 2-B — 일괄 재생성 (➡️ Backoffice로 이전)

> **이전 완료 (2026-06-19)**: 이 섹션의 Studio 구현 계획은 **Backoffice로 이전**되었다.
> Backoffice가 같은 Supabase DB에 직접 접근하는 방식으로 구현하며, Studio API 크로스 콜 없이 독립적으로 동작한다.
> 상세 계획: [`backoffice/features/2026-06-19_speaking-핵심데이터-관리-페이지-개발계획.md`](../../../backoffice/features/2026-06-19_speaking-핵심데이터-관리-페이지-개발계획.md)

### (참고) 당초 Studio 구현 계획 API

```
POST /passages/core-data/generate-missing
```

별도 body 없음. `core_expressions IS NULL`인 지문 전체를 대상으로 한다.
(선택적으로 `user_id` 필터 파라미터 추가 가능)

**응답**

```json
{ "taskId": "uuid", "totalCount": 15 }
```

### 동작 흐름

```
POST /passages/core-data/generate-missing
  ↓
  1) SELECT id, content, level FROM texts
        WHERE core_expressions IS NULL
        (AND user_id = ? — 선택적 필터)

  2) AsyncTaskManager로 태스크 등록
        async_tasks INSERT → taskId 반환 (200 즉시 응답)

  3) 백그라운드: 순차 처리
        for each textId (concurrencyLimit = 3):
          speakingCoreData.generateAll(textId, content, level)
          → async_tasks.progress 업데이트
          → 완료 시 notifications INSERT (Studio의 기존 패턴)
```

### 동시성 제한 (concurrencyLimit = 3)

- Gemini API 동시 호출이 많으면 429 (quota) 발생
- `p-limit` 또는 수동 세마포어로 최대 3개 병렬 처리
- 실패한 개별 지문은 로그만 남기고 나머지 계속 진행 (`Promise.allSettled` 패턴)

### async_tasks 테이블 활용

Studio에 이미 `AsyncTaskManager` + `async_tasks` + `notifications` 인프라가 구현되어 있으므로
추가 인프라 없이 진행률 UI를 연결할 수 있다.

```
async_tasks 레코드:
  type: 'core-data-generate-missing'
  status: 'running' | 'completed' | 'failed'
  progress: { done: 7, total: 15, failed: 1 }
  result: { generatedIds: [...], skippedIds: [...], failedIds: [...] }
```

### (참고) 당초 Studio 구현 범위 — 이전됨

| 파일 | 작업 | 상태 |
|------|------|------|
| `apps/api/src/passages/passages.controller.ts` | `POST /passages/core-data/generate-missing` 엔드포인트 | ➡️ Backoffice 이전 |
| `apps/api/src/passages/speaking-core-data.service.ts` | `generateMissing(userId?)` 메서드 | ➡️ Backoffice 이전 |
| `apps/api/src/tasks/task-manager.ts` | AsyncTaskManager 재사용 | ➡️ Backoffice 불필요 (단순 폴링 방식) |
| Studio UI (운영 페이지) | 진행률 표시 UI | ➡️ Backoffice 이전 |

## 4. 우선순위 및 의존성

| 항목 | 의존 | 우선순위 |
|------|------|---------|
| 2-A 엔드포인트 | `SpeakingCoreDataService` 기구현 | 높음 (Studio UI 버튼 필요) |
| 2-A Studio UI 버튼 | 2-A 엔드포인트 | 높음 |

| 2-B Studio UI | 2-B 엔드포인트 | 낮음 |
