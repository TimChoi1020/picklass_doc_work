## 0. 확정 사항 (Locked, 2026-07-10)

| 항목 | 결정 |
|---|---|
| 마스터 발화 목표 | **8회** (Lv4 = 누적 발화 8+). 난이도별 차등은 운영 튜닝(§6 후속) |
| Quiz 문장 출처 | **A. 과정 데이터 직접** — 이미 `texts.core_expressions`(지문별 핵심표현). 학습 완료 시 `source='learning'` 편입. **추가 구축 불필요** |

| 게임성 축 | **L1 순간 피드백(Juice) + L4 수집·완성(Collection)** 채택(§3.4). L2 발음 스킬 별점·L3 스트릭/상실회피는 **후속 유보** |

> A/B는 경쟁이 아니라 **서로 다른 문장 유형**을 담당한다: Quiz(학습 종속 문장)=과정 콘텐츠, preset(상시·필수 문장)=운영 카탈로그.

## 1. 한 줄 정의

> **Quiz와 표현노트는 이름은 다르지만, "문장 하나를 발화 반복으로 마스터한다"는 동일 엔진을
> 공유하는 하나의 학습 시스템이다.** 데이터는 한 곳(`user_expressions`)에 저장하고,
> **문장별 누적 발화수만큼 리워드(레벨)를 올리는 게임화 섀도잉 학습**을 지향한다.

- **Quiz** = *시스템이 제공*. 스피킹 과정에서 학습한 **핵심표현 문장**을 **망각곡선 주기**로 **적정량씩** 복습(섀도잉).
- **표현노트** = *사용자/사전 제공*. 직접 입력하거나 미리 탑재된 **필수·상시 학습 문장**. Quiz 큐가 비어도 **항상 학습 가능**.
- 두 진입점이 **같은 마스터리 엔진**(발화수 → 레벨 → 리워드)을 쓴다.

---

## 2. 역할 분리 (Quiz vs 표현노트)

| 구분 | Quiz (복습 섀도잉) | 표현노트 |
|---|---|---|
| 문장 출처 | 학습 완료 레슨의 **핵심표현**(`texts.core_expressions`) 자동 편입 | 사용자 직접 입력 + **사전 탑재 필수 문장** |
| 제공 방식 | 망각곡선 스케줄로 **오늘 도래분만** 자동 큐 | 사용자가 목록에서 선택, 상시 접근 |
| 제공량 | **적정량 제한**(세션당 N문장) — 과다 금지 | 제한 없음(사용자 주도) |
| 존재 이유 | 배운 것을 잊기 전에 되살림(정착) | Quiz가 비어도 **끊김 없는 학습** + 필수 문장 보장 |
| `source` 값 | `learning` | `note`(사용자) / `preset`(사전 탑재) |

> **핵심**: 둘 다 최종적으로 `user_expressions`의 한 행이 되고, **동일한 발화수 기반 마스터리**를 따른다.
> "Quiz에서 마스터한 문장"과 "표현노트에서 마스터한 문장"은 같은 레벨 체계를 공유한다.

## 3. 마스터리 엔진 (공통 핵심)

### 3.1 발화수 → 레벨
한 문장의 **누적 발화수(utterance_count)**로 레벨과 마스터를 판정한다.
(기존 [BATCH1 §3](../발화량-표현노트-학습설정/2026-06-21_BATCH1-API-구현.md) 레벨 체계 재사용·재해석)

| 레벨 | 누적 발화수 | 색상 | 상태 |
|---|---|---|---|
| Lv0 | 0 | 회색 | 미학습 |
| Lv1 | 1~2 | 연파랑 | 시작 |
| Lv2 | 3~4 | 파랑 | 익숙 |
| Lv3 | 5~7 | 보라 | 능숙 |
| **Lv4** | **8+** | 초록 | **마스터** |

- **마스터 발화 목표(mastery_target) = 8회** (✅ 확정, §0). → "한 문장을 유창하게 만드는 데 필요한 발화 횟수"를 8회로 정의.
- 난이도/길이별 차등 목표는 운영 데이터 확보 후 튜닝(§6 후속). 기본값 8은 고정.

### 3.2 리워드 시각화 (발화마다)
> 사용자가 요청한 "각 발화 시마다 리워드를 시각적으로 제공".

- **발화 1회 = 진행 pip 1칸 채움**. 문장 카드에 `●●●○○○○○` (8칸) 게이지.
- 매 발화 시 **+1 마이크로 애니메이션**(pip 팝 + 색 점등). 발음 점수 우수 시 **보너스 이펙트**(별/불꽃).
- **레벨업 순간**: 카드 색 전환(회→파→보→초) + 축하 토스트.
- **마스터(Lv4) 순간**: 트로피/별 연출 + **배지 갤러리 연동**(예: "표현마스터" 배지 진척).
- **세션 종료 요약**: 오늘 총 발화수 · 레벨업 M개 · 신규 마스터 K개.

### 3.3 마스터 이후 (유지 복습)
- 마스터 문장은 `status='mastered'`로 이동, 목록 상단 "마스터" 필터.
- 장기 망각곡선 간격(예: 35일+)으로 **가끔 유지 복습** 재등장(정착 유지). 실패 시 레벨 소폭 하향(선택).

### 3.4 게임성 설계 (채택: L1 · L4)
게임성을 포인트·배지 같은 **장식이 아니라 두 축의 구조**로 확보한다. (발화수 = 성실도 축을 유지하되, 아래로 "느낌"과 "완성 욕구"를 얹음)

**L1 — 순간 피드백 (Juice)**: *발화하는 순간이 기분 좋아야 한다.*
- 발화 즉시(0.1s 내) **3-감각 반응**: 시각(pip 팝 + `+1` 숫자 튀어오름) · 청각(짧은 성공 사운드) · 촉각(햅틱).
- 마스터 근접/도달 시 파티클(별·불꽃) 강도 상승. 반응 **지연 최소화**가 핵심(느리면 게임감 소멸).
- 저비용·고효과. 상세 연출은 [화면 기획 §3.3](./2026-07-10_문장마스터리-화면기획.md).

**L4 — 수집·완성 (Collection)**: *채우고 싶은 컬렉션이 있어야 돌아온다.*
- **마스터 컬렉션**: 마스터한 문장이 쌓이는 갤러리(배지 갤러리와 연결).
- **세트/과정별 완성도 %**: "이 과정 표현 20개 중 15 마스터 (75%)" 진행바 → 100% 채우려는 동기.
- 배지는 **완성의 결과로만** 부여(배지 자체가 목적이 되면 다시 장식).

> **유보(후속)**: L2(발음 점수를 별점·콤보·품질게이트로 = 실력 도전축), L3(스트릭·"잊기 전에" 상실회피)는
> 1차 범위 밖. 단, **발화수만으로는 그라인드 위험**이 있으므로 운영 데이터로 재도입 여부 판단(§8·§9 P6).

## 4. 망각곡선 스케줄링 (Quiz 제공 주기·수량)

> 사용자 강조점: **"어떤 주기로 몇 개씩"** + **"너무 많은 양보다 적절한 양"**.

### 4.1 주기 (언제 다시 나오나)
- 문장별 `next_review_at`로 관리. 성공 세션 시 다음 간격으로 전진.
- **간격 = `[1, 2, 4, 7, 16, 35]`일** (기존 BATCH1 망각곡선 재사용).
  - 오늘 학습 → 내일(1) → 2일 → 4일 → 7일 → 16일 → 35일 → (마스터/유지).

### 4.2 수량 (한 번에 몇 개)
| 파라미터 | 기본값 | 근거/비고 |
|---|---|---|
| **세션당 제공 문장 수** | **6문장** (5~8 범위) | 인지 부하·완주율. due 문장이 많아도 상한 |
| **문장별 세션 내 발화** | **1~2회** | 섀도잉 반복. 최소 1회로 pip 전진 |
| **하루 세션 수** | 1회 권장 | due 소진 시 종료. 더 하려면 표현노트로 |
| **due 초과분** | 다음날로 이월 | 밀린 문장 우선순위 상향 |
| **due 부족분** | 표현노트/신규 학습 유도 | Quiz 카드에 "오늘 복습 없음 → 표현노트" |

- **적정량 원칙**: 세션당 6문장 × 1~2발화 ≈ **6~12발화 / 2~4분** 목표. "짧고 자주".
- 누적 마스터 경로 예시: 6회 스케줄 등장 × 평균 1.3발화 ≈ 8발화 → Lv4. (간격·목표 정합은 §7 튜닝)

## 5. 통합 데이터 모델 (`user_expressions` 확장)

기존 컬럼(id·user_id·expression·meaning·example_sentence·category·source·source_lesson_id·level·review_count·last_reviewed_at·next_review_at·status)에 **마스터리 필드 추가**(차후 DDL, §6.4):

| 컬럼 | 용도 |
|---|---|
| `utterance_count` (신규) | 누적 발화수 → 레벨/마스터 판정 (기존 `review_count`와 분리 or 재해석) |
| `mastery_target` (신규, default 8) | 마스터 목표 발화수 (난이도별 차등 여지) |
| `mastered_at` (신규, ts?) | 마스터 도달 시각 |
| `last_score` (신규, int?) | 최근 발음 점수(Azure) — 보너스/게이팅용 |
| `status` (기존) | `active` / `mastered` |
| `source` (기존) | `learning`(Quiz) / `note`(사용자) / `preset`(사전 탑재) |
| `next_review_at` (기존) | 망각곡선 다음 등장일 |

- **단일 저장 원칙 유지**: Quiz·표현노트·필수문장 전부 이 테이블 1곳. `source`로만 구분.
- 사전 탑재 필수 문장(`preset`)의 원본 카탈로그(과정/기관별)는 별도 seed 소스 필요 → §6.3.

## 6. 연동 · 아키텍처

### 6.1 발화량 챌린지와의 시너지 ★
**각 발화는 발화량 로그로도 기록된다.**
- Quiz/표현노트 발화 1회 → `utterance_logs` insert(`source_module='QUIZ'` 또는 `'EXPR'`).
- 결과: **문장 마스터리(개별 문장) + 발화량 미터/차트(총량)** 이중 리워드.
- **부수효과**: 앞서 [발화량 검토](./2026-07-10_챌린지-탭-재디자인.md#7-후속)에서 지적된 "발화량 쓰기 경로 미연결"을,
  Quiz/표현노트 발화가 **실제 데이터 유입원**이 되어 일부 메운다.

### 6.2 Quiz 문장 편입 파이프라인
- 레슨 학습 완료 시 → 해당 지문 `texts.core_expressions`(핵심표현 Json)를
  `user_expressions`(source='learning', source_lesson_id=…)로 **upsert 편입**.
- 이미 있는 표현(동일 user_id+expression)은 `@@unique`로 중복 방지(기존 제약 활용).

### 6.3 사전 탑재 필수 문장(preset) — backoffice 카탈로그 (✅ 확정)
과정과 **무관한 공통·필수 문장**을 backoffice에서 큐레이션·배정한다. (Quiz의 과정직접 방식과 분리)

- **관리 주체/위치**: picklass-backoffice — 신규 카탈로그 엔티티(예: `preset_expression_sets` + items). 기관/레벨/과정에 매핑.
- **배정(seed)**: 가입·수강 등록 훅에서 매핑된 세트 → `user_expressions`(source='preset')로 upsert seed.
- **왜 backoffice인가**: (1) 과정 안 들어도 **상시 제공**(표현노트 취지) (2) 여러 과정·기관 **재사용** (3) **B2B 기관별 필수문장 차등**(화이트라벨) (4) 콘텐츠 배포 없이 운영이 문장만 독립 수정.
- **공유DB 주의**: 카탈로그 테이블·매핑은 tutoring과 공유 인스턴스 → 스키마 신설 시 사전 정렬(CLAUDE §15.4). speaking 전용이면 speaking 스키마에 둔다.
- **구현 비용이 크므로 로드맵상 P5**(엔진·Quiz·표현노트 본체 이후). P1~P4 동안 표현노트는 사용자 입력(`note`)만으로도 동작.

### 6.4 API 설계 (제안)
| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/expressions/quiz?limit=6` | 오늘 **due**(next_review_at ≤ now, source='learning') 문장 세트 (망각곡선 큐) |
| `GET` | `/expressions?filter=all\|unlearned\|master` | 표현노트 목록 (기존) |
| `POST` | `/expressions/:id/utterance` | **발화 1회 기록** `{score?, tapMode?}` → utterance_count++, level 재계산, `utterance_logs` insert |
| `POST` | `/expressions/:id/complete-session` | 세션 종료 → `next_review_at` 망각곡선 전진, 요약 반환 |
| `POST` | `/expressions` | 사용자 수동 추가 (기존, source='note') |
| (차후) | preset seed | 수강 등록 훅에서 필수 문장 편입 |

> 기존 `POST /:id/review`는 **`/:id/utterance` + `/complete-session`으로 의미 분리**(발화 단위 리워드를 위해). 마이그레이션 시 정합.

### 6.5 발음 평가 연동
- 섀도잉 발화 → 기존 Azure 발음 평가(tutoring `pronunciation.service` 패턴 차용) → `last_score`.
- **저점수 발화도 pip은 카운트**(학습 지속성), 단 **보너스 이펙트는 고득점만**(질 유도). — 게이팅 정책 §7.

## 7. 화면 흐름

> 📐 **상세 와이어프레임·상태·연출은 [문장 마스터리 화면 기획](./2026-07-10_문장마스터리-화면기획.md) 참조.** 본 절은 개요.

### 7.1 Quiz (챌린지 탭 → `/player/quiz`)
- 챌린지 Quiz 카드: "오늘 복습 **N문장**"(due 카운트). due=0이면 "표현노트로 학습" 유도.
- 세션: 문장별 **① TTS 듣기 → ② 따라 발화 → ③ 발음 평가 → ④ 리워드(pip+애니)** → 다음 문장.
- 진행바(6문장) + 종료 요약(발화수·레벨업·마스터).

### 7.2 표현노트 (챌린지 탭 → `/player/expressions`)
- 목록/필터(전체·미학습·마스터) + 직접 추가(기존) + 각 문장 카드에 **마스터리 게이지**.
- 카드 탭 → **동일 섀도잉 엔진**으로 발화(Quiz와 같은 리워드).
- "도전하기" → 필터된 세트 일괄 섀도잉 세션(마스터플랜 §4.7의 미구현분).

---

## 8. 미결 / 튜닝 항목 (착수 전·운영 중 검증)

> ✅ 확정(§0): 마스터 목표 8회 · Quiz=과정직접 · preset=backoffice 카탈로그.

남은 튜닝 항목:
1. **세션당 제공 수(6) · 문장별 발화(1~2)** — 완주율·체감 기준 A/B.
2. **발음 점수 게이팅** — 저점수 발화 카운트 정책, 보너스 임계 점수.
3. **Quiz due 소진 시 fallback** 우선순위(표현노트 vs 신규 학습).
4. **망각곡선 실패 처리** — 발화 실패/저점수 시 간격 후퇴(step down) 여부.
5. **마스터 후 유지 복습** 간격·다운그레이드 정책.
6. **preset 카탈로그 스키마 위치** — speaking 전용 vs 공유(tutoring 정렬 필요, §6.3).

## 9. 단계별 로드맵 (제안)

| 단계 | 내용 | 선행 |
|---|---|---|
| **P0 기획 확정** | ✅ 핵심 결정 완료(§0). 남은 튜닝값(§8)은 운영 중 조정 | 본 문서 |
| **P1 데이터·엔진** | `user_expressions` 마스터리 컬럼 DDL + `/utterance`·`/complete-session` API + `utterance_logs` 연동 | 공유DB DDL(§15) |
| **P2 Quiz 큐** | 레슨 완료 → `texts.core_expressions` 편입 파이프라인(과정직접) + `GET /expressions/quiz` 망각곡선 큐 | P1 |
| **P3 섀도잉 화면** | `/player/quiz` 세션(듣기·발화·평가·리워드) + 진행/요약. 발음 평가 연동 | P1·P2 |
| **P4 표현노트 통합** | `/player/expressions` 마스터리 게이지 + 동일 엔진 + "도전하기" 세션 (사용자 `note` 입력만으로 동작) | P1·P3 |
| **P5 preset 카탈로그·배지** | **backoffice 카탈로그** 신설 + 매핑/seed 훅 + 마스터 배지 연동 | P4 · backoffice |
| **P6 튜닝** | 운영 데이터로 주기·수량·목표 조정 | 운영 |

> **챌린지 탭 반영**: [재디자인 문서](./2026-07-10_챌린지-탭-재디자인.md)의 Quiz 카드("N문제")·표현노트 카운트는
> 본 시스템 완성 시 **due 문장 수·표현 개수 실데이터**로 대체된다(현재 Mock).
