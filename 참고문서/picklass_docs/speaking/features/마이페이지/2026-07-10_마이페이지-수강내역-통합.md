## 1. 배경

my 페이지 섹션2 "수강내역"과 `/my/history` 목록이 **하드코딩(목 데이터)** 상태다.

- my 페이지: "수강 중 **1개**" / "종료된 수업 **3개**" 두 행이 고정 ([my/page.tsx:208-243](../../../../speaking.picklass.com/apps/web/src/app/(tabs)/my/page.tsx)).
- `/my/history`: `ENROLLMENTS` 배열 4건이 고정이고 `status`가 날짜와 무관하게 박제됨.

**설계 방향(개정):** 수강중/종료된 수업을 **화면·섹션으로 나누지 않고 하나의 "수강내역"
목록으로 통합**한다. 상태(수강중/종료)는 각 카드의 **배지로만** 구분한다.
튜터링의 날짜 기반 상태 판정 로직은 차용하되, 튜터링처럼 섹션을 분할하지는 않는다.

> **왜 통합인가**: speaking my의 수강 규모는 사용자당 소수(수 건)이며, 상태별 개수를
> 별도 카운트로 노출할 실익보다 **한 목록에서 최신순으로 훑는 UX**가 단순하고 명확하다.
> split 로직(active/expired 2배열·2섹션·filter 쿼리)이 사라져 구현·유지보수도 가벼워진다.

## 2. 수강 상태 정의 (배지 판정용)

| 상태 | 기준 (`usage_end_date` = 계약 종료일) | 배지 |
|------|------|------|
| 수강중 | `usage_end_date IS NULL`(무제한) **또는** `usage_end_date >= 오늘` | 초록 "수강 중" |
| 종료 | `usage_end_date < 오늘` | 회색 "종료" |

> DB `status_code`는 변경하지 않는다. 만료는 **조회 시점 계산**으로만 판정한다
> (튜터링 §8 "의도적 제외" 정책과 동일). 상태는 목록 분할이 아니라 **카드 배지**에만 쓰인다.

### 2.1 카드 단위 = "수강(access_code)" — 결정 #2

한 사용자가 **같은 과정을 두 번 수강**할 수 있다(예: 재수강). 목 데이터도 동일 과정
"Business Presentation Skills"를 수강중(2026.06–08) / 종료(2026.03–05) **두 건**으로 표시한다.

→ 카드의 정체성은 **course가 아니라 access_code(1회 수강 계약)** 이다.
현재 백엔드 쿼리는 `SELECT DISTINCT c.id`(course 단위)라 **수강 단위 식별자(`enrollmentId`)가
없다.** §5에서 이를 보강한다. 통합 목록에서도 재수강 건은 **각각 한 카드**로 나열된다.

## 5. 백엔드 변경 (`apps/api/src/lessons/lessons.service.ts`)

> access_codes 테이블은 speaking `schema.prisma`에 **미등록**이며 `$queryRawUnsafe`
> raw SQL로만 접근한다. 따라서 컬럼 추가는 SELECT 목록 수정만으로 끝난다(모델 등록 불필요).

### 5.1 `enrollment_id` 추가 (결정 #2)

`getEnrolledCourses()` INTERNAL 쿼리 SELECT에 `ac.id AS enrollment_id` 추가.
custom(나만의 수업) UNION 절은 access_code가 없으므로 `NULL AS enrollment_id`.

```sql
-- INTERNAL 절
SELECT DISTINCT
  ac.id           AS enrollment_id,   -- 추가 (수강 단위 식별자)
  c.id            AS course_id,
  c.title         AS course_title,
  c.level_code,
  c.total_lessons,
  ac.usage_start_date,
  ac.usage_end_date,
  c.course_type,
  c.genre_code
FROM access_codes ac
JOIN courses c ON ac.course_id = c.id
WHERE ac.status_code = 'active'
  AND ac.course_id IS NOT NULL
  AND ac.user_id = '${studentId}'
  AND (c.course_type IN ('speaking', 'integrated') OR c.course_type IS NULL)
  AND c.deleted_at IS NULL
```

> **주의(현행 버그 소지)**: 현재 매핑([lessons.service.ts:132-133](../../../../speaking.picklass.com/apps/api/src/lessons/lessons.service.ts))이
> `id: course.course_id`로 반환하므로, 같은 과정을 2회 수강하면 **동일 `id`를 가진 카드가 2장**
> 생겨 통합 목록에서 React key 충돌이 난다. `enrollmentId`를 별도 식별자/React key로 사용해 회피한다.
> (`id`는 레슨 진입용 course_id로 유지, `enrollmentId`는 카드 정체성)

### 5.2 CEFR 배지 = `level_code` 직접 사용 (결정 #1 — 조사 후 확정)

> **조사 결과(2026-07-10)**: `courses.level_code`는 숫자가 아니라 **이미 CEFR 문자열**이다
> (`"B1"` 등). 근거: 과정 생성 시 리터럴 저장([courses.service.ts:204](../../../../speaking.picklass.com/apps/api/src/courses/courses.service.ts) `level_code: 'B1'`),
> explore 화면이 가공 없이 배지로 렌더([explore/page.tsx:214](../../../../speaking.picklass.com/apps/web/src/app/(tabs)/learn/explore/page.tsx) `{course.levelCode}`).

따라서 **백엔드에 `cefr` 파생 필드는 불필요**하다. 기존 응답 필드 `level`(= `level_code`)이 곧 CEFR 배지 값이다.
프론트는 `EnrolledCourse.level`을 그대로 배지로 표시한다(빈값이면 미표시).

> ⚠️ **초기 오설계 정정**: 최초 계획은 `cefrForLevel(Number(level_code))`로 파생하려 했으나,
> ① `level_code`가 이미 CEFR라 변환이 불필요하고 ② `Number('B1')=NaN`이라 오히려 배지가 전부
> `null`이 되며 ③ `cefrForLevel` 함수 자체가 폐기됨(현재는 `labelForRank`, 사용자 1~18 레벨 전용
> — 과정 `level_code`와 무관). → **파생 로직 없이 `level` 직접 사용**으로 확정.

### 5.3 반환 필드 요약 (추가분)

```ts

// cefr 필드 추가 없음 — 기존 level(= level_code, CEFR 문자열)을 배지로 사용
```

## 6. 프론트 변경

### 6.1 공용 훅 신설 — `lib/hooks/useEnrolledCourses.ts`

my 페이지(총계)와 history 페이지(목록)가 동일 API를 쓰므로 중복 방지를 위해 훅으로
캡슐화한다(CLAUDE §11.1 재사용, §6.4 authFetch→서비스 경유 유지).
**split은 하지 않고**, 카드별 상태(`isActive`)를 부여해 **최신순으로 정렬한 단일 목록**을 만든다.

```ts
const today = new Date(); today.setHours(0, 0, 0, 0);
const isActive = (c: EnrolledCourse) =>
  !c.usageEndDate || new Date(c.usageEndDate) >= today;

// 수강내역 대상(custom 제외), 상태 부여 후 통합 정렬:
// 수강중 먼저 → 그 안에서 종료일 늦은 순 → 종료분은 종료일 최근 순
const enrollments = courses
  .filter((c) => !c.isCustom)
  .map((c) => ({ ...c, active: isActive(c) }))
  .sort((a, b) => {
    if (a.active !== b.active) return a.active ? -1 : 1;
    return (b.usageEndDate ?? '9999').localeCompare(a.usageEndDate ?? '9999');
  });
// 반환: { enrollments, loading, error }
```

> **custom(나만의 수업) 제외 이유**: speaking my 요구는 수강내역뿐이다. 튜터링의
> "내가 만든 과정" 섹션은 speaking 범위 밖(§11 의도적 제외).
> 정렬·무제한 처리 세부는 구현 시 조정 가능(무제한 과정을 최상단에 둘지 등).

### 6.5 카드 클릭 이동 (2026-07-10 추가)

카드 **전체를 클릭 대상**으로 하고 상태별로 목적지를 분기한다.

| 카드 상태 | 클릭 시 이동 | 이유 |
|---|---|---|
| 수강중(`active`) | `/learn?courseId={id}` — 수업 페이지에서 **그 과정 선택** | "수강중 과정 → 수업 계속" 동선 |
| 종료(`!active`) | `/feedback?enrollmentId={enrollmentId ?? id}` — 리포트 | 종료 후 리포트 열람 |

- `/learn`은 **course 단위**로 과정을 선택하므로 이동 파라미터는 `id`(= course_id), 리포트는 **수강 단위** `enrollmentId`(결정 #2).
- `/learn` 초기 선택 로직이 `?courseId=`를 우선 반영(있고 activeCourses에 존재할 때) → 없으면 기존 자동 선택. 파라미터는 `window.location.search`로 1회 읽어 Suspense 경계 요구 회피(`useAuth` 패턴).
- **중첩 인터랙션 회피**: 카드 전체가 `<button>`이므로 내부 리포트/수업 액션은 별도 버튼이 아니라 **시각적 pill**(수강중=초록 "수업 계속" · 종료=파랑 "리포트")로 표기. hover 배경으로 탭 가능 표시.

### 6.6 마이페이지 "수강권" 드롭다운 (2026-07-10 추가)

계정 섹션의 행을 단일 링크에서 **인라인 드롭다운(아코디언)** 으로 전환한다. 헤더 라벨은 **"수강권"**.
`components/ui`에 드롭다운 프리미티브가 없어 로컬 state 기반 인라인 펼침으로 구현(코드베이스 Tailwind 패턴).

- **표시 대상**: `enrollments.filter(e => e.active)` (수강중만). `useEnrolledCourses` 재사용, 추가 API 없음.
- **접힘**: 헤더 서브텍스트 = 수강중 첫 과정의 **과정명 + 수강일정(기간)** + `ChevronDown`. **펼침**: 서브텍스트 = `N개` + `ChevronUp`, 아래 패널에 각 과정 **과정명 + 수강일정**을 나열.
- **수강일정** = 과정기간(`formatEnrollmentPeriod`, 시작~종료·무제한)에 `수강일정` 라벨을 붙여 표기. 별도 스케줄 데이터 없음(계약 기간이 곧 수강일정). 예: `수강일정 2026.06.01 – 2026.08.31`.
- **항목 탭 → 수업 이동**: `/learn?courseId={id}`(§6.5 동선 재사용). 각 항목은 course 단위이므로 `id`(course_id) 전달.
- **수강중 0개**: 토글 `disabled` + "수강 중인 강의 없음" 표시(펼침 없음).
- **기간 포맷 공용화**: history 페이지의 `periodLabel`/`fmtDate`를 `useEnrolledCourses.ts`의 **`formatEnrollmentPeriod(e)`** 로 추출·export 하여 my·history 양쪽에서 재사용(§11.1 중복 제거 — 실제 2회 사용).
