## 1. 배경

my 페이지가 표시·편집하는 값들이 대부분 **하드코딩(로컬 state)** 상태였고, 특히
사용자의 **현재 레벨**과 그 **변화 이력**을 저장할 곳이 없었다.

레벨은 다음 세 경로로 바뀌며, 이 변화를 모두 추적해야 한다.

- **PT (Placement Test)** — 최초 자동 진단 + 원하면 재응시
- **AT (Achievement Test)** — 학습 사이클 후 성장 확인 (직전 진단 대비)
- **학습 중 조정** — 세션이 없는 런타임 레벨 보정

→ PT/AT 결과는 `alt_results`에 세션별로 남지만, **학습 중 조정(무세션)** 은 담을 곳이 없고,
"현재 레벨 단일 소스"도 부재했다.

순수 취향값은 클라이언트/JSONB(볼륨).

## 3. 저장 설계 결정 (2026-07-09 확정)

### 3.1 레벨 = "원장(ledger) + 스냅샷(snapshot)" 패턴

레벨 변화는 본질적으로 이벤트 스트림(PT → 학습조정 → AT → …)이다.

- **스냅샷 (현재값)**: `user_learning_profiles.picklass_level` — my 페이지·콘텐츠 난이도 서빙이
  PK 1행으로 O(1) 조회. speaking 소유 테이블 재사용(신규 테이블 안 만듦).
- **원장 (이력)**: `alt_level_history` — 모든 변화 1행씩 append-only. 궤적 차트·성장 리포트 원천.

| 대안 | 기각 사유 |
|---|---|
| `users`에 컬럼 추가 | 공유 테이블 + 이력 소실 (DB 설계 §1) |
| `alt_results`만 사용 | 학습 조정(무세션) 못 담음, 현재값을 두 소스 union 필요 |
| JSONB 배열 이력 | 궤적 정렬·집계 불리 (DB 설계 §15 위반) |
| 원장만 두고 매번 MAX 조회 | my 페이지·서빙이 매 요청 스캔 → 스냅샷 1컬럼으로 회피 |

### 3.2 영어 닉네임

- 용도: **영어 수업에서 원어민이 호명** + 챌린지 랭킹 표시.
- 영문 전용 → DB CHECK `^[A-Za-z0-9 ]+$` + 앱 입력 검증. 최대 16자.
- **유일성 제약 없음** (리더보드 중복 허용).
- `users.name`(가입명, 공유)과 별개. NULL이면 앱에서 `users.name` 폴백.

### 3.3 학습 알림 vs 광의 알림 설정 (경계 분리)

my 페이지에 알림 설정이 두 종류이며 성격이 다르다.

- **(A) 섹션3 "학습 알림 설정"** — 매일 지정 시각 리마인더 + 전화모드.
  → `user_learning_profiles`의 컬럼(`reminder_enabled`/`reminder_time`/`reminder_phone_mode`)으로 **분리**.
  이유: 스케줄러가 "지금 시각에 알림 받을 사용자"를 **인덱스 조회**해야 함(정규화). 공유 users 재변경 회피.
- **(B) 섹션5 "알림 설정"** — 카테고리별 on/off + 카카오·이메일 수신동의 + DND 윈도우.
  → 기존 `users.notification_settings`(JSONB, 공유) 유지.

> **註 (2026-07-09) — 섹션5 "알림"(알림 설정·알림 내역) UI 진입 잠정 숨김**: 알림 생성 파이프라인
> 미구현으로 실동작이 없어 `my/page.tsx` 섹션5 블록을 주석 처리했다(라우트 페이지·저장 스키마는 유지).
> 복원·상세: [알림 생성 파이프라인](../알림/2026-07-09_알림-생성-파이프라인.md).

### 3.4 사운드 볼륨 = 클라이언트 로컬 저장

볼륨은 기기별 취향(새 기기에서 기본값 리셋이 자연스러움)이라 계정 동기화 실익이 없다.
DB 컬럼·API 없이 **클라이언트 localStorage**에 저장. (동기화 요구 발생 시 `app_prefs JSONB`로 승격)

## 5. 읽기 / 쓰기 흐름

### 5.1 읽기 (my 페이지 헤더)

`user_learning_profiles` PK 1행으로 헤더 전체 렌더:

```
표시 이름  = english_nickname ?? users.name
레벨 배지  = 'L{picklass_level} · {picklassLabel} · {파트너 레벨명}'  (§5.1.1)
학습 시간  = daily_goal_min
학습 알림  = reminder_enabled ? reminder_time : '꺼짐'
페르소나   = persona_code
```
볼륨만 클라이언트 localStorage.

#### 5.1.1 레벨 배지 = 18변형 라벨 + 파트너 레벨매핑 (2026-07-09 개정)

레벨 표시는 단순 CEFR 6밴드가 아니라 **18변형 라벨**(`A1-`~`C2+`)과 **파트너별 레벨명**을 병기한다.

- `picklassLabel` = `labelForRank(picklass_level)` — 정수 1~18 → 18변형 라벨.
  `getLearningProfile` 응답에 포함(`apps/api/src/users/users.service.ts`).
- 파트너 레벨명 = `GET /config/level-mappings`(institution 기준)의 `picklassLabel → displayLevel` 매핑.
  파트너 매핑이 없으면 라벨 그대로 표시(수업 탭과 동일 패턴).
- 조합(`apps/web/src/app/(tabs)/my/page.tsx`): `picklass_level == null`이면 `'레벨 미진단'`,
  아니면 `L{n}` + 라벨 + (파트너명 != 라벨일 때) 파트너명을 ` · `로 연결.
  예) 기본 `'L12 · B2+'` / 파트너 `'L12 · B2+ · Lower Advanced'`.
- 상세·결정·as-built는 **§10(레벨 표현·파트너 레벨매핑 연동)** 참조. 커밋 `7e3a135`(파트너레벨매핑 Phase C).

### 5.2 쓰기 (레벨 변화 발생 시 — 트랜잭션 1개)

1. `INSERT alt_level_history (... source, session_id 또는 ref_id, previous_level, delta ...)`
2. `UPDATE user_learning_profiles SET picklass_level, cefr_level, level_source, level_updated_at`

- **PT/AT 완료**: `source='PT'|'AT'`, `session_id` = 완료 세션, `level` = `alt_results.final_level`.
  헤드라인 레벨만 원장에 두고 루브릭 상세는 `alt_results` 유지(중복 없음).
- **학습 중 조정**: `source='learning'`, `ref_type/ref_id` = 근거 lesson/module, `session_id` NULL.
- AT baseline은 여전히 `alt_sessions.previous_session_id` 체인으로 리졸브(DB 설계 §5.1) — 원장이 이 로직을 건드리지 않음.

## 6. API 구현 계획 (2026-07-09)

### 6.1 방침 — 기존 `users` 모듈 확장 + 신규 `levels` 모듈

기존 `apps/api/src/users`에 이미 `GET/PATCH /users/learning-profile`(= `user_learning_profiles` upsert)과
`GET/PATCH /users/notification-settings`(= `users.notification_settings` deep-merge)이 존재한다(§11.1 재사용).

| 관심사 | 배치 |
|---|---|
| 닉네임·학습알림·레벨 조회/설정 | **기존 `users` 모듈 확장** |
| 레벨 변화 이력·트랜잭션 헬퍼 | **신규 `levels` 모듈** (`recordLevelChange`를 PT/AT·학습조정이 주입) |

닉네임 표시는 프론트에서 `englishNickname ?? user.name`으로 조합(`useAuth`가 `name` 보유) → 이름 조인 엔드포인트 불필요.

### 6.3 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/users/learning-profile` | 기존 + `englishNickname, picklassLevel, picklassLabel, cefrLevel, levelSource, levelUpdatedAt, reminderEnabled, reminderTime, reminderPhoneMode` |
| PATCH | `/users/learning-profile` | 기존 + `englishNickname`(영문 검증)·`reminder*` 부분 업데이트. **레벨 필드 불허** |
| GET | `/levels/status` | 진단 상태(레벨테스트 진입·게이팅). [게이팅 문서](../레벨테스트/2026-07-09_레벨테스트-진입-게이팅.md) |
| GET | `/levels/history` | `alt_level_history` 시간순 궤적 |

- 닉네임 검증(서비스 내 수동, 기존 컨벤션): `^[A-Za-z0-9 ]+$` + ≤16자 위반 시 `BadRequestException`.
- **레벨은 PATCH로 변경 불가** — 오직 `LevelService.recordLevelChange`(트랜잭션)로만.
- 프론트는 CLAUDE §6.4대로 `authFetch` → `lib/services/*` 경유. 볼륨은 API 없이 localStorage.

### 6.4 `LevelService.recordLevelChange` — 트랜잭션 헬퍼 (핵심)

PT/AT 완료·학습조정 공통 진입점. `prisma.$transaction`(interactive)으로 원장 INSERT + 스냅샷 UPDATE 원자 처리.

```ts
type LevelChangeInput = {
  level: number;                          // 결과 레벨 (AT는 이미 하한보호 적용된 값)
  source: 'PT'|'AT'|'learning'|'manual'|'onboarding';
  sessionId?: number;                     // PT/AT일 때
  refType?: string; refId?: string;       // 학습조정 참조(lesson/module)
  reason?: string;
};
// 1) 현재 스냅샷 picklass_level 읽어 previous·delta 계산
// 2) alt_level_history.create(...)
// 3) user_learning_profiles.upsert(picklass_level·cefr_level·level_source·level_updated_at)
```

- `previous_level` = 변경 시점의 현재 스냅샷(학습조정 반영 running 값) → delta 정확.
- **하한 보호는 헬퍼가 강제하지 않음**: AT 채점이 `previous_session_id` 체인으로 baseline을 구해 floored `final_level`을 전달(§4-2/§10-1). 스냅샷 기준 재-floor는 학습조정분과 충돌하므로 분리.
- `cefr` 컬럼 값은 `labelForRank(level)`로 파생 — 정수 1~18 → **18변형 라벨**(`A1-`~`C2+`, `apps/api/src/levels/level.util.ts`의 `PICKLASS_LABELS`). 파트너 레벨매핑·수업 탭 배지가 이 라벨을 키로 사용하므로 밴드(6단계)가 아니라 18변형으로 저장한다(§5.1.1).
  > **개정 이력**: 초기 설계는 `cefrForLevel()`(6밴드 CEFR)로 파생하려 했으나, 파트너 레벨매핑(Phase C)이 18변형 라벨을 키로 요구해 `labelForRank()`로 교체했다. `cefrForLevel()` 함수는 폐기(현재 코드베이스 미존재).

### 6.5 결정 사항 (2026-07-09 확정)

| 항목 | 결정 |
|---|---|
| PATCH 통합 vs 전용 | 기존 `learning-profile` PATCH에 **통합** (닉네임 검증만 추가) |
| 레벨 이력 위치 | 신규 **`levels` 모듈** (크로스모듈 주입) |
| cefr 파생 | `labelForRank()` → 18변형 라벨(`A1-`~`C2+`). 파트너 레벨매핑 키 (초기 `cefrForLevel()` 6밴드 안은 폐기) |
| 레벨 배지 표시 | `L{n} · 18라벨 · 파트너레벨명`, 파트너 매핑은 `/config/level-mappings` (§5.1.1) |
| history 페이지네이션 | 초기 **전량 반환** (사용자당 수십 행) |

## 10. 레벨 표현·파트너 레벨매핑 연동 (2026-07-09 후속)

[파트너 레벨매핑](../../../backoffice/features/파트너레벨매핑/20260605_파트너레벨매핑_개발계획.md)과 대조해 레벨 표현을 정합화했다.

### 10.1 세 가지 레벨 표현

| 표현 | 값 | 역할 |
|---|---|---|
| 정수 1~18 | `picklass_level`(SMALLINT) | 내부 계산·서빙 단일 소스. `== words_18levels_6000.picklass_rank` |
| **18변형 라벨** | `A1-`~`C2+` | CEFR 세분 표기 + **파트너 매핑 키**. `labelForRank(level)` |
| 파트너 레벨명 | 예 'Lower Advanced' | 파트너 학습자 표시. `displayLevel(라벨)` (`GET /config/level-mappings`) |

### 10.2 결정 (2026-07-09)

- **배지 = `L{n} · {18라벨}` 병행 표기** — 픽클래스 레벨(L-number)과 CEFR 직관성(18라벨)을 동시 표기.
  파트너 매핑이 있으면 **18라벨 뒤에 파트너 레벨명을 추가 병기**(잠정, §10.4 미결).
  - 기본: `L12 · B2+`
  - 파트너: `L12 · B2+ · Lower Advanced`
- **`cefr_level`·`alt_level_history.cefr` = 18라벨 저장** — `recordLevelChange`가 `labelForRank(level)` 기록.
  (기존 6밴드 `cefrForLevel`은 제거)

### 10.3 구현 (as-built)

- `apps/api/src/levels/level.util.ts` — `PICKLASS_LABELS`(18) + `labelForRank()` (기존 `cefrForLevel` 대체)
- `levels.service.recordLevelChange` — `cefr`에 18라벨 저장
- `users.service` — 프로필 응답에 `picklassLabel = labelForRank(picklass_level)` 파생 필드 추가
- web `usersService.LearningProfile.picklassLabel` 추가
- web `my/page.tsx` — `getLevelMappings()`로 `levelMap` 구성, 배지 `L{n} · displayLevel(picklassLabel)`

검증: api typecheck·lint·nest build ✅ / web typecheck·변경파일 lint ✅.

### 10.4 미결

- ⏸️ **파트너 학습자 배지 표기 방식(잠정)** — 현재 **병기**(`L12 · B2+ · Lower Advanced`)로 구현. 차후 대체/축약 등 UX 최종 확정 필요.
- `displayLevel` 로직이 수업 탭·마이페이지에 중복 — 공유 헬퍼 추출(선택).
- 파트너 매핑 규칙 변경 시 speaking `config.service.getLevelMappings`와 동기화 주의(파트너 문서 주1).
