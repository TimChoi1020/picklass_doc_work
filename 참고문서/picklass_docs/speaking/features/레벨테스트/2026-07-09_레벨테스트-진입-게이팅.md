## 1. 개요

닉네임·레벨이 없는 사용자를 **레벨테스트(PT)로 유도**하고, 신규 회원은 완료 전까지 **수업을 하드 블록**한다.
PT/AT 진입은 홈 위 팝오버로 안내한다.

핵심: 진입 조건은 닉네임·레벨 유무만으로 결정되지 않는다(PT/AT 구분, 하드/소프트, 재노출). 따라서
**서버가 단일 "진단 상태"를 계산**하고, **홈 팝오버**와 **수업 진입 가드**가 이를 공유한다.

---

## 2. 진단 상태 모델

`GET /levels/status` 응답:

```ts
{
  requiresTest: boolean,
  testType: 'PT' | 'AT' | null,
  reason: 'new_user' | 'renewal' | 'after_lesson' | null,
  enforcement: 'hard_block' | 'soft_prompt' | null,   // 신규 PT만 hard_block
  hasNickname: boolean,   // PT 플로우 내 닉네임 수집 필요 판단
  hasLevel: boolean,
}
```

---

## 3. 판정 규칙 (우선순위 순)

| 우선 | 조건 | testType | enforcement | reason |
|:---:|---|:---:|:---:|:---:|
| 1 | **신규회원**(완료 진단 0건) & `picklass_level` 없음 | PT | **hard_block** | new_user |
| 2 | 기존회원 & **수강권 갱신 후** & 갱신 이후 PT 미완료 | PT | soft_prompt | renewal |
| 3 | 기존회원 & **마지막 수업 완료 > 마지막 진단 완료** | AT | soft_prompt | after_lesson |
| 4 | 그 외 | — | — | — |

- **신규 판정** = 완료된 `alt_sessions`(status='completed', test_type='PT') 0건.
  - **Phase 1 구현 주의**: `alt_sessions`는 `user_id` 타입 불일치(§13)·무데이터 상태라, 현재 구현은 **`picklass_level` 부재를 new_user 프록시**로 사용한다(`LevelService.getStatus`). `alt_sessions` 기반 정밀 판정은 Phase 2(타입 정리 + PT 플로우 이후).
- **하드 블록은 신규 PT에만** 적용(기획: "신규 회원은 레벨테스트 미진행 시 수업 불가").
- 갱신 PT·AT는 soft_prompt(수업 허용, '나중에 하기' 가능).

---

## 4. 게이팅 — 하드 블록

프론트만 막으면 우회 가능하므로 **서버가 최종 방어**한다. 수업 시작 엔드포인트에 가드 부착.

```
LessonAccessGuard → LevelService.getStatus(userId)
  if (requiresTest && enforcement === 'hard_block')
     → 403 { code: 'LEVEL_TEST_REQUIRED', testType: 'PT' }
```

프론트는 `LEVEL_TEST_REQUIRED` 수신 시 수업 진입을 막고 팝오버로 유도한다.

---

## 5. 팝오버 진입 흐름 (홈, PKS-HM-001)

1. 홈 로드 → `GET /levels/status`
2. `requiresTest === true` → 팝오버 노출. 안내 문구는 `reason`별 분기
   - `new_user`: 첫 진단 환영 / `renewal`: 재배치 안내 / `after_lesson`: 학습 후 성장 확인
3. **[시작하기]** → `/onboarding/level-test`(PKS-LV-002)
4. **[나중에 하기]** → 팝오버 닫기. 단 `hard_block`이면 수업 카드/버튼은 계속 잠금 유지

노출 시점(기획):
- 신규회원 PT: 온보딩 후
- 기존회원 PT: 수강권 갱신 후 첫 로그인부터 레벨테스트 완료 전까지
- AT: 마지막 수업 완료 후

## 6. 재노출 빈도 (스누즈) — 확정: 클라이언트 localStorage

| 유형 | 재노출 정책 |
|---|---|
| hard_block(신규 PT) | **매 홈 진입 노출** (스누즈 무의미 — 수업 자체 잠김) |
| soft_prompt(갱신 PT·AT) | **스누즈**: `localStorage.levelPromptSnoozeUntil = now + 24h`. 만료 전 재노출 안 함 |

> 결정(2026-07-09): 스누즈는 **클라이언트 localStorage**(간단). 기기 간 일관성이 필요해지면
> `user_learning_profiles.level_prompt_snoozed_until` 서버 컬럼으로 승격.

## 7. 닉네임 수집 통합 — 확정: PT 플로우 내 수집

> 결정(2026-07-09): 별도 온보딩 단계 대신 **PT 플로우(PKS-LV-002)에서 닉네임을 수집**한다.

- PT 완료 시 **닉네임 + 레벨을 동시 확보** → 원어민 호명·수업 진입 전 필수값 보장.
- `hasNickname=false`인데 `hasLevel=true`인 엣지: 플로우가 닉네임만 받는 단계로 진입.
- 저장: 닉네임 → `user_learning_profiles.english_nickname`(영문 검증), 레벨 → `LevelService.recordLevelChange(source='PT')`.

## 8. 데이터 소스 & 단계화

| 입력 | 소스 | 가용성 |
|---|---|---|
| hasLevel / hasNickname | `user_learning_profiles.picklass_level` / `english_nickname` | ✅ 지금 |
| 신규 여부 / 마지막 진단 완료 | `alt_sessions`(completed) | ✅ 지금 |
| 마지막 수업 완료 | `lesson_results.completed_at`(student_id) | ✅ 지금 |
| **수강권 갱신** | backoffice `access_codes.usage_start_date` | ⚠️ speaking 미보유 — READ 연동 필요 |

- **Phase 1**(지금 가능): 규칙 1(신규 PT·하드블록) + 규칙 3(AT·after_lesson).
- **Phase 2**: 규칙 2(기존회원 갱신 PT) — `access_codes` READ 연동 후.

## 9. API 스펙

| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | `/levels/status` | 진단 상태 계산 (§2 응답) | JwtAuthGuard |
| GET | `/levels/history` | 레벨 궤적 (`alt_level_history`) | JwtAuthGuard |
| (내부) | `LevelService.getStatus(userId)` | 가드·컨트롤러 공용 | — |
| (내부) | `LessonAccessGuard` | 수업 시작 엔드포인트 하드블록 | — |

수업 시작 엔드포인트 하드블록 응답: `403 { code: 'LEVEL_TEST_REQUIRED', testType }`.

프론트는 CLAUDE §6.4대로 `authFetch` → `lib/services/*` 경유 호출.

## 10. 테스트 항목

### 10.1 상태 판정 (`GET /levels/status`)

- [ ] 신규(진단 0건)·레벨 없음 → `{requiresTest, testType:'PT', enforcement:'hard_block', reason:'new_user'}`
- [ ] PT 1회 완료 사용자 → 즉시 `requiresTest:false` (수업 완료 전)
- [ ] 마지막 수업 완료 > 마지막 진단 → `testType:'AT', enforcement:'soft_prompt', reason:'after_lesson'`
- [ ] 레벨 있음 & 닉네임 없음 → `hasLevel:true, hasNickname:false`
- [ ] (Phase 2) 갱신 후 PT 미완료 → `testType:'PT', reason:'renewal', soft_prompt`

### 10.2 하드 블록 가드

- [ ] 신규·PT 미완료가 수업 시작 호출 → `403 LEVEL_TEST_REQUIRED`
- [ ] PT 완료 후 동일 호출 → 정상 진입(200)
- [ ] soft_prompt 상태(AT 대기)는 수업 진입 허용

### 10.3 팝오버 / 스누즈 (프론트)

- [ ] 홈 진입 시 `requiresTest`면 팝오버 노출, `reason`별 문구 분기
- [ ] [시작하기] → `/onboarding/level-test` 이동
- [ ] soft: [나중에 하기] → 24h 스누즈, 만료 전 재노출 안 함
- [ ] hard_block: [나중에 하기]해도 수업 카드 잠금 유지 + 매 진입 재노출
- [ ] 스누즈 값이 localStorage에만 저장(서버 무호출) 확인

### 10.4 닉네임 통합

- [ ] PT 완료 시 `english_nickname` + `picklass_level` 동시 저장
- [ ] 닉네임 영문 검증 실패 케이스(한글/기호/17자) 반려
