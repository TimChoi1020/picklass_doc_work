## 6. 작업 5 — 듣기·섀도잉 집계 API (신규)

리포트 Quantity 섹션의 **듣기·섀도잉**을 채우기 위한 신규 백엔드. **새 데이터 유입원 불필요** — `module_histories`에 이미 모듈별 완료 행이 있고, 5축 KPI(pron/flu/gram/prag/vol)에 안 들어가는 모듈 카운트만 집계하면 됨.

### 백엔드
**파일**: `apps/api/src/feedback/feedback.{controller,service}.ts`
- `GET /feedback/quantity?period=7d|30d` 신규.
- `module_histories`를 모듈 코드별로 그룹 집계 → 듣기·섀도잉(및 발화) 수량 반환.
- 모듈 코드 매핑은 모듈 시퀀싱 데이터([2026-06-05 등록완료](../../operations/2026-06-05_스피킹-모듈-시퀀싱-데이터-등록-완료.md)) 기준 확정 필요.
- P2 연계: KPI 카탈로그 `LISTEN_COMPLETE`·`EXPRESSION_COM` code_items 미등록 → 본 작업 시 함께 등록.

응답(안):
```jsonc
{ "period": "30d",
  "utterance": { "sentences": 0 },   // 발화 = 문장 수
  "listening": { "minutes": 0 },     // 듣기 = 분 (리포트 Mock 단위: 분)
  "shadowing": { "count": 0 } }      // 섀도잉 = 회 (리포트 Mock 단위: 회)
```

> ⚠️ 단위 정합: 리포트 Quantity Mock(`feedback/page.tsx:24-28`)은 발화=`문장`·듣기=`분`·섀도잉=`회`. API 응답 단위를 이에 맞춰야 함. `module_histories`에 듣기 분(min)·섀도잉 횟수 집계 가능 필드가 있는지 모듈 시퀀싱 기준으로 먼저 확인 필요(없으면 횟수 단위로 통일).

### 프론트
- `feedbackService.getQuantity(period)` 추가 → 리포트 Quantity 섹션(작업 3) 듣기·섀도잉 바인딩.

- [ ] `GET /feedback/quantity` 컨트롤러/서비스
