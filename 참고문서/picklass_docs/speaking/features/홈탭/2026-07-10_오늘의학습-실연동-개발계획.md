## 1. 배경 / 목표

홈 탭 재디자인(2026-07-10) 후 **"오늘의 학습" 카드 2종이 여전히 Mock**(`MISSIONS` 상수).
이를 실데이터로 연동한다.

- **① 정규 카드** — "마지막 학습 기준 이어하기" 과정 + 진행률 + 다음 레슨 진입
- **② FRT 카드** — 자유 주제 스피킹(수업 탭과 동일 동작)

핵심 결론: **정규 카드는 기존 화면(수업 탭)의 검증된 로직을 재사용**해 신규 API 없이도 가능하나,
"진짜 마지막 학습" 정밀도를 위해 기존 `GET /courses/in-progress`를 **소폭 확장**한다(Phase 2 채택).

## 3. 사용 가능한 데이터 소스 (신규 엔드포인트 불요)

| 엔드포인트 | 보유 필드 | 정규 카드 적합성 |
|---|---|---|
| `GET /lessons/enrolled-courses` (`getEnrolledCourses`) | `nextLessonId`·`nextLessonTitle`·`nextLessonRound`·`completed/totalLessons`·기간 | ✅ navigable(lessonId 有), ⚠️ `lastCompletedAt` 無 |
| `GET /courses/in-progress` (`getInProgress`) | `lastCompletedAt`·`nextLessonOrder/Topic`·`progress`·`lastScore` | ✅ 진짜 "마지막 학습" 정렬(completed_at desc), ⚠️ `nextLessonId` 無 |

→ 두 API가 서로 하나씩 결핍. enrolled-courses는 이동 가능하나 최근순 정렬 불가,
in-progress는 최근순이나 이동 불가(`courses.service.ts:87-167`에서 `nextLessonId` 미select).

**중요**: 프론트 `coursesService.getInProgress`는 **현재 어느 화면도 소비하지 않음**(정의만 존재)
→ 확장해도 기존 화면 부작용 0 (CLAUDE §5.6 안전).

## 5. 작업 계획

### A. 백엔드 — `getInProgress` 확장
파일: `apps/api/src/courses/courses.service.ts` (`getInProgress`, 87-167)

1. 과정별 집계 후, 각 과정 `nextLessonOrder`의 레슨 id **배치 조회**:
   ```ts
   const list = Array.from(courseMap.values());
   const nextRows = await this.prisma.course_lessons.findMany({
     where: { OR: list.map(c => ({ course_id: c.id, lesson_order: c.nextLessonOrder })) },
     select: { id: true, course_id: true, lesson_order: true },
   });
   const nextIdMap = new Map(nextRows.map(l => [`${l.course_id}:${l.lesson_order}`, l.id]));
   ```
2. 반환에 `nextLessonId: nextIdMap.get(`${c.id}:${c.nextLessonOrder}`) ?? null` 추가
3. **`lastCompletedAt desc` 명시 정렬**(nulls last) → `[0]` = 진짜 마지막 학습
   - Postgres `ORDER BY … DESC` 기본 NULLS FIRST 함정 회피 목적(반환 배열에서 재정렬)
4. 과정 전부 완료(다음 레슨 없음) 시 `nextLessonId=null`

> DB 스키마 변경 아님(select 확장만) → 마이그레이션 불요.
> 반영: `pnpm --filter @speaking/api build`(prisma generate 포함) + api 재시작 (CLAUDE §7.1).

### B. 프론트 서비스 — 타입 확장
파일: `apps/web/src/lib/services/coursesService.ts` (`InProgressCourse`, 7-19)
- `nextLessonId: string | null` 필드 추가 (소비처 없어 안전)

### C. 홈 페이지 — 정규 카드 실연동 + FRT 게이팅
파일: `apps/web/src/app/(tabs)/home/page.tsx`

- **fetch 추가**: `getInProgress()`(정규) + `getEnrolledCourses()`(FRT 잠금 판정 active 과정)
- **정규 카드(동적)** — `inProgress[0]` 기준
  - 제목 = `title`, 부제 = `Lesson {nextLessonOrder} · {nextLessonTopic}`, 진행바 = `progress`
  - href = `nextLessonId ? '/learn-flow/pick?lessonId=' + id : '/learn'`
  - in-progress 0건(수강했으나 미학습/비로그인) → 정규 카드 숨김
- **FRT 카드(수업탭 동일)** — `canUseCustom = active 과정 존재`
  - 잠금 시 비활성 + "수강 중인 과정 없음" 안내
  - 활성 시 탭 → `addCurriculumLesson()`(자유주제 기본) → `/player/frt?lessonId=`
  - 주제 입력 시트는 홈에서 생략(수업 탭 유지)
- **남는 Mock**: `분(minutes)` — 두 API 미제공 → 정적 유지
