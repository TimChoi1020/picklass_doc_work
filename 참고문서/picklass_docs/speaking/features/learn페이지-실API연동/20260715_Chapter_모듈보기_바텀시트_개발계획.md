## 1. 배경 및 목적

speaking learn 페이지는 tutoring "나의 수업(my-classes)" 페이지와 개념적으로 동일하다. 차이는 노출 과정 유형뿐이다.

| | tutoring my-classes | speaking learn |
|---|---|---|
| 노출 과정 | 튜터링 + 통합 | 스피킹 + 통합 |
| 레슨 단위 명칭 | 레슨 | **Chapter** (동일 개념) |
| 레슨 목록 위치 | "레슨 보기" → **CourseDrawer**(우측 드로어) 안에 나열 | **페이지 본문에 직접 나열** (Chapter 섹션) |
| 모듈 분해 | 드로어에서 레슨을 아코디언으로 펼치면 모듈 표시 → 모듈 클릭 진입 | **없음** — Chapter 클릭 시 곧바로 이탈 |

**목적**: tutoring에서 "레슨 보기"를 눌렀을 때 보이는 화면(레슨의 모듈 목록 → 모듈 선택 진입)을, speaking learn에서 **Chapter를 눌렀을 때 나오는 화면**으로 재구성한다. learn의 Chapter 목록이 이미 tutoring 드로어의 "레슨 목록" 역할을 하고 있으므로, 부족한 것은 **선택한 Chapter의 모듈 분해 화면**뿐이다.

### 1-1. 요구사항 (추가 2026-07-15)

Chapter → 모듈 보기 화면(ChapterSheet)은 단순 진입 버튼이 아니라 **수업 진입 전 확인 + 이어하기**를 지원해야 한다.

1. **모듈 내용 확인 후 진입**: 학습자는 수업 진입 시 **오늘 수업할 모듈의 내용을 먼저 확인**하고 수업에 들어갈 수 있어야 한다. 즉 ChapterSheet는 그 챕터에 포함된 모듈이 무엇인지(구성·순서·간단 설명)를 보여주어, 학습자가 무엇을 학습할지 인지한 뒤 시작하도록 한다.
2. **이어하기(resume)**: 앞서 진행하던 내용이 있으면 **중단 지점에서 이어서** 진행할 수 있어야 한다. 완료한 모듈은 완료로, 진행 중이던 모듈은 "이어하기" 진입점으로 표시하고, 미시작 모듈과 구분한다.

> **설계 영향**:
> - (1)은 ChapterSheet가 모듈 **목록/구성 미리보기** 역할을 겸해야 함을 의미한다(§4). tutoring CourseDrawer는 모듈명만 나열하므로, "내용 확인" 수준(모듈 설명/스킬)을 어디까지 노출할지 결정 필요.
> - (2) 이어하기는 **모듈 단위 진행 상태**를 요구한다(§1-2·§8·§5와 연동).

### 1-2. 이어하기 — tutoring 선례 조사 (2026-07-15)

"이어하기가 tutoring에 이미 있지 않나?"를 코드로 확인한 결과: **부품은 있으나 자동 이어하기 기능은 tutoring에도 없다.** speaking 신규 구현이 필요하며, 아래 부품은 재사용할 수 있다.

**재사용 가능한 부품 (tutoring 기존 구현)**

| 부품 | 위치 | 재사용 |
|---|---|---|
| 특정 모듈로 딥링크 진입 | `modules/[lessonId]/page.tsx:14,62` (`?module={idx}` → `initialModuleIdx`), `LessonSession.tsx:46` | 이어하기 = "중단 모듈 idx로 진입". §5 라우트 규격에 idx 파라미터 포함 |
| 모듈별 이력 서버 저장 | `LessonSession.tsx:93-104` `saveModuleHistory()` → `POST /lessons/{lessonId}/modules/{moduleCode}/history` | speaking도 동일 패턴 존재([FRT 문서 §5-3](./20260619_FRT섹션_개발계획.md) `saveModuleHistory`). 완료 데이터는 이미 DB에 쌓임 |

**비어 있는 것 (tutoring도 미구현 → 신규 작업)**

1. **재진입 시 자동 복원 없음** — `LessonSession`은 마운트마다 `completedResults = []`로 초기화하고 저장된 이력을 되불러오지 않음(`LessonSession.tsx:47,54-55`).
2. **module 파라미터는 사용자 선택, 계산 아님** — 페이지 기본값 `module=0`, CourseDrawer는 클릭한 모듈 idx만 전달. "첫 미완료 모듈로 점프" 로직 없음.
3. **LessonPlan에 모듈 완료 상태 필드 없음** — `PlannedModule`/`moduleSequence`에 completed/진행중 필드 부재(`agent-types.ts:388-404`).
4. **런처(CourseDrawer)는 레슨 단위 `isCompleted`만 표시** — 모듈 단위 완료를 못 보여줌.

> **결론**: 이어하기의 병목은 원시 데이터가 아니라 **① 모듈 완료 상태 조회 API + ② 클라이언트 복원/점프 로직**이다. tutoring에서 통째로 이식할 완성품이 없으므로, speaking에서 이 둘을 새로 만들되 위 딥링크·`saveModuleHistory` 부품은 그대로 활용한다.

## 4. 설계 — ChapterSheet (바텀시트)

> **표현 방식 결정(2026-07-15)**: 바텀시트 채택. speaking은 모바일 우선이고 learn 페이지가 이미 `BottomSheet`를 FRT 주제 입력·수강 과정 선택에 사용 중이므로(`learn/page.tsx:427,454`), tutoring의 우측 드로어보다 바텀시트가 앱 패턴에 부합한다. "Chapter를 누르면 나오는 화면"이라는 요구 표현과도 일치.

### 4-1. 진입 흐름

ChapterSheet는 §1-1 요구사항을 반영해 **(1) 모듈 구성 확인**과 **(2) 이어하기 진입점**을 함께 제공한다.

```
[learn 페이지 Chapter 목록]
  Chapter 클릭
     │  (router.push 제거)
     ▼
  setSelectedChapter(lesson)  → ChapterSheet 열림
     │
     ▼
[ChapterSheet 바텀시트]  ← 오늘 수업할 모듈 "내용 확인" 역할 겸함
  · 챕터 제목(textTitle ?? topic) + 상태 뱃지
  · 모듈 목록(구성·순서 확인용):
      [스킬색 moduleCode] 모듈명   상태(완료 / 이어하기 / 미시작)
  · 주 CTA: 이어하기 진행 중 모듈 있으면 "이어하기",
            없으면 "수업 시작하기"(첫 미완료 모듈)
     │  모듈 클릭 or CTA
     ▼
  모듈 진입 라우트 (§5 — 결정 필요) — 이어하기 시 중단 지점으로 진입
```

> **이어하기 진입점 계산**: tutoring CourseDrawer는 열릴 때 "첫 미완료 레슨"을 자동 확장한다(`CourseDrawer.tsx:46-51`). 동일 패턴을 **모듈 단위**로 적용해 "첫 미완료(=진행 중 또는 미시작) 모듈"을 이어하기 진입점으로 삼는다. 단, 모듈 단위 완료 상태 데이터가 선행되어야 한다(§8).

### 4-2. 컴포넌트 구조

신규 컴포넌트 `ChapterSheet`를 `BottomSheet` 위에 구성. tutoring `CourseDrawer`의 **모듈 렌더 블록(`CourseDrawer.tsx:158-186`)** 을 단일 챕터 기준으로 이식한다(레슨 아코디언 부분은 불필요 — 이미 단일 챕터로 진입).

```tsx
// 신규: components 또는 learn 하위 _components
function ChapterSheet({
  open, onClose, chapter, onSelectModule,
}: {
  open: boolean;
  onClose: () => void;
  chapter: CourseLesson | null;
  onSelectModule: (lessonId: string, moduleIdx: number) => void;
}) {
  return (
    <BottomSheet open={open} onClose={onClose} title={chapter?.textTitle ?? chapter?.topic ?? '레슨'}>
      <div className="p-4 space-y-2">
        {(!chapter || chapter.modules.length === 0) ? (
          <p className="py-6 text-center text-sm text-gray-400">모듈 정보가 없습니다.</p>
        ) : (
          chapter.modules.map((mod, idx) => (
            <button
              key={`${mod.moduleCode}-${idx}`}
              onClick={() => onSelectModule(chapter.id, idx)}
              className="w-full flex items-center gap-3 rounded-lg px-3 py-2.5 hover:bg-gray-50 transition-colors"
            >
              <span className={`shrink-0 rounded-md px-2 py-0.5 text-[11px] font-bold ${skillBadge(mod.skill)}`}>
                {mod.moduleCode}
              </span>
              <span className="flex-1 text-left text-sm text-gray-700">{mod.name}</span>
              <ChevronRight className="w-4 h-4 shrink-0 text-gray-300" />
            </button>
          ))
        )}
      </div>
    </BottomSheet>
  );
}
```

### 4-3. 모듈 스킬 색상 — 상수 이식 필요

tutoring은 `@/lib/constants/moduleLabels`의 `SKILL_COLORS`를 사용하지만 **speaking에는 해당 상수가 없다**(확인: 2026-07-15 grep 결과 0건). 두 가지 선택:

- **(권장) 최소 매핑 이식**: speaking에 `moduleLabels.ts`(또는 인라인 `skillBadge()` 헬퍼)를 만들어 `reading/writing/speaking/general` → Tailwind 클래스 매핑. tutoring 상수를 그대로 복제.
- 색상 없이 중립 뱃지로 시작(`bg-gray-100 text-gray-600`) 후 후속 개선.

### 4-4. learn/page.tsx 상태·핸들러 변경


## 5. 모듈 진입 라우트 — 🏗️ 외주개발 진행 (차후 구현)

> **진행 구분**: 모듈 진입 라우트 및 그 대상 화면(모듈 플레이어/`/learn-flow/pick` 등)은 **외주개발로 진행되는 부분**이다. 본 문서의 내부 구현 범위(ChapterSheet)에서는 **임시 배선만** 유지하고, 정식 라우트·플레이어는 외주 산출물로 차후 통합한다.

tutoring은 모듈 클릭 시 `/modules/{lessonId}?module={idx}`로 이동하나, **speaking에는 `/modules/`도 `/learn-flow/pick`도 라우트 파일이 없다.** 모듈 단위 진입 경로 정의가 이 작업의 선행 과제이며, **외주개발 범위로 이관**한다.

**현재 임시 배선 (내부)**: `handleSelectModule` → `/learn-flow/pick?lessonId={id}&module={idx}`. 외주 산출물 확정 시 이 한 줄만 교체한다.

**외주개발 결정 대상 (후보)**

| 후보 | 설명 | 고려사항 |
|---|---|---|
| A. `/learn-flow/pick?lessonId=&module=` | 기존 Chapter 클릭 라우트를 모듈 파라미터까지 받도록 확장 | 해당 라우트 자체가 미구현 — 함께 정의 필요 |
| B. speaking `/modules/{lessonId}?module={idx}` 신설 | tutoring과 라우트 규격 통일 | speaking 플레이어(예: FRT `/player/frt`)와의 관계 정리 필요 |
| C. 모듈 스킬별 분기 | 스피킹 모듈→FRT/스피킹 플레이어, 그 외→일반 모듈 플레이어 | speaking 과정은 모듈 구성이 스피킹 위주라 분기 단순할 수 있음 |

> **참고**: [FRT 섹션 개발계획 §5](./20260619_FRT섹션_개발계획.md)에서 FRT 플레이어는 `/player/frt?lessonId=`로 진입한다. 스피킹 모듈이 곧 FRT 세션이라면 C안이 자연스럽다.
>
> **외주 인계 시 명시할 것**: ① 진입 라우트 규격(A/B/C), ② 모듈 idx 기반 진입 + 이어하기(중단 지점) 진입 방식, ③ 모듈 단위 완료 상태 조회 API(§1-2·§8). ChapterSheet는 `onSelectModule(lessonId, moduleIdx)` 계약만 노출하므로, 외주 라우트가 이 시그니처만 맞추면 내부 변경은 `handleSelectModule` 1줄로 끝난다.

### 7-1. 런타임 버그 수정 — `skill_modules` 형태 불일치 (2026-07-15)

**증상**: ChapterSheet가 열리지만 모듈 목록이 비어 "모듈 정보가 없습니다" 상태.

**원인**: `course_lessons.skill_modules`가 DB에 **문자열 배열**(`["LRN","VLM","SHD","SFB","SMK","RPB","RPF","FRT","OMP"]`, studio 저장 형식)로 저장돼 있으나, `enrolled-courses`의 `normalizeModuleSequence`(`apps/api/src/lessons/lessons.service.ts`)가 **객체 배열**(`[{order, moduleCode}]`)만 처리 → 문자열 항목이 `'moduleCode' in item` 필터에서 전부 탈락 → `modules: []` 반환.

**수정**: `normalizeModuleSequence`가 **문자열 배열·객체 배열 두 형태 모두** 처리하도록 변경. 문자열 항목은 `{ order: i+1, moduleCode: item }`으로 매핑. api typecheck 통과.

> 이 함수는 `getLessonPlan` 등 다른 경로에서도 재사용되므로, 동일하게 두 형태를 안전 처리하게 되어 부수 효과 없이 개선.
> **후속 확인**: 로컬 API 재기동 → learn 페이지에서 Chapter 클릭 시 모듈 목록 표시 확인. 모듈 코드(LRN/VLM/SHD/SFB/SMK/RPB/RPF/FRT/OMP)가 `ai_modules`에 active로 존재하면 name/skill 색상까지 정상 표시, 미존재 시 코드명 + gray fallback.
