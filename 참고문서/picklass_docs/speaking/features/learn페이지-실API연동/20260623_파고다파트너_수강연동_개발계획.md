## 1. 배경 및 목적

본서비스(픽클래스)와 파고다 파트너의 **수강내역 모델이 근본적으로 다르다.** 이를 하나의
`EnrollmentProvider` 골격으로 묶어, learn 페이지가 출처와 무관하게 동일한 `EnrolledCourse[]` +
자격(Entitlement)을 소비하도록 한다.

본 문서는 **파고다 파트너 경로**의 개발방안을 정의한다. 본서비스(access_codes) 경로는 이미
구현되어 있으며([Learn 개발계획](../learn페이지-실API연동/20260619_learn페이지_실API연동_개발계획.md) §3~7),
본 문서에서는 대비 컨텍스트로만 참조한다.

### 1.1 두 수강 모델의 차이

| 구분 | 본서비스 (픽클래스) | 파고다 파트너 |
|------|--------------------|--------------|
| **수강 권한 출처** | `access_codes` (과정당 1코드) | 카테고리 전체 (파트너 소유 L1 카테고리) |
| **접근 범위** | 코드에 연결된 과정 1개 | 파트너 카테고리의 모든 과정 자유 수강 |
| **유효성** | 기간 (`usage_start/end_date`) | 기간 + 상품 유형별 횟수 |
| **상품 구분** | 없음 | **정규상품**(레슨 N회 제한) / **무제한상품**(기간 내 무제한) |
| **나만의 수업** | 자유 (차감 없음) | 정규=레슨풀 차감 / 무제한=20회 cap |
| **이수조건** | 이수율·발화량·수업시간 | 동일 |

### 1.2 파고다 상품 규칙 (요구사항 원문)

- 일정 기간 동안 수업 가능.
- **정규상품**: 레슨 사용 횟수로 제한.
- **무제한상품**: 일정 기간 동안 무제한 사용.
- **나만의 수업** 사용 시 → 정규상품의 레슨 횟수에서 차감.
- 무제한상품은 나만의 수업 사용을 **20회로 제한**.
- 이수조건은 (레슨이수율, 발화량, 수업시간)으로 판정.

| 요소 | 현재 상태 | 위치 |

| 파트너 카테고리 스코프 | `course_categories.partner_id → L1 ids → courses.l1_category_id` 이미 동작 | `apps/api/src/courses/courses.service.ts:24-40` |

> 신규로 만들 것은 **상품/횟수 자격(Entitlement)**과 **소진 카운터**뿐이다.

## 3. 설계 원칙 — 수강을 3개의 직교 축으로 분해

"본서비스 vs 파고다"로 나누지 않고 **3개 독립 축**으로 분해해 한 골격으로 묶는다.

| 축 | 본서비스 | 파고다 정규상품 | 파고다 무제한상품 |
|----|---------|---------------|------------------|
| **① 접근 범위(Scope)** | 과정 1개 | 카테고리 전체 | 카테고리 전체 |
| **② 자격/소진(Quota)** | 기간만 | 기간 + 레슨 N회 | 기간만(무제한) |
| **③ 나만의 수업 정책** | 자유 | 레슨풀에서 차감 | 별도 20회 cap |
| **이수조건(직교·공통)** | 이수율·발화량·수업시간 | 동일 | 동일 |

이수조건은 세 경우 모두 동일하므로 **출처와 무관한 공통 평가기**로 분리한다.

## 4. 확정된 결정사항 (D1~D3)

> 2026-06-23 확정. D4·D5는 §8 미결 항목으로 남는다.

| # | 결정 | 확정 내용 | 근거 |
|---|------|----------|------|
| **D1** | 자격 소스 오브 트루스 | **파고다 = 부여 권한(grant), 픽클래스 = 소진 권한(consumption).** 파고다는 상품·기간·총횟수 grant만 제공하고, 잔여 차감은 speaking 원장에서 계산 | 레슨은 speaking에서 실행됨 → 매 레슨 파고다 write-back 불필요, 장애 격리 용이 |
| **D2** | "1회 사용" 시점/중복 | **레슨 최초 이수 완료 시 1회 차감. 재수강은 무차감.** | 사용자 체감과 일치, 무한차감 방지 |
| **D3** | 무제한 custom 20회 리셋 단위 | **상품 기간당 20회** | 무제한상품 기간 회계와 일치 |

### 4.1 D1 함의 — 잔여횟수 계산식

```
remaining = grant.total(파고다 부여) − used(speaking 원장 집계)
```

파고다는 "이 사용자는 정규상품 30회를 부여받았다"까지만 책임지고, "현재 12회 남았다"는
speaking이 자체 소진 원장으로 계산한다. 주기적 reconcile(§8 D5)로 드리프트를 보정한다.

### 4.2 D2 함의 — 차감 트리거

`lesson_results.completed_at`이 **최초로 NULL→설정되는 순간** 1회 차감 이벤트를 기록한다.
동일 `(user, lesson)`의 재수강(이미 원장에 존재)은 차감하지 않는다.

## 5. 도메인 모델 제안

기존 [Learn 개발계획](../learn페이지-실API연동/20260619_learn페이지_실API연동_개발계획.md) §9.1의
`EnrollmentProvider` seam을 그대로 살리되, 반환에 **자격(Entitlement)**을 추가한다.

```ts
interface Entitlement {
  source: 'access_code' | 'partner';
  scope:
    | { kind: 'courses'; courseIds: string[] }          // 본서비스
    | { kind: 'categories'; l1CategoryIds: number[] };   // 파고다
  validity: { start: Date | null; end: Date | null };    // 둘 다 기간 보유
  quota:
    | { kind: 'unlimited' }                              // 본서비스 / 파고다 무제한
    | { kind: 'lesson_count'; total: number; used: number }; // 파고다 정규
  customPolicy:
    | { kind: 'free' }                                   // 본서비스(현행)
    | { kind: 'shared_pool' }                            // 파고다 정규(레슨풀 공유 차감)
    | { kind: 'capped'; cap: 20; used: number };         // 파고다 무제한
}
```

### 5.1 소진 게이트 규칙 (수업 시작 가능 여부)

| 상품 | 일반 레슨 게이트 | 나만의 수업 게이트 |
|------|-----------------|-------------------|
| 본서비스 | `now ∈ [start,end]` | 자유 |
| 파고다 정규 | `now ∈ 기간` AND `(일반+나만의 사용) < total` | 동일 풀 차감 |
| 파고다 무제한 | `now ∈ 기간` | `customUsed < 20` |

## 6. Provider 설계 (기존 seam 위에)

```
getEnrolledCourses(userId, partnerId)
 ├─ partnerId == null → AccessCodeEnrollmentProvider
 │       (현행 §3-1 SQL 이동, quota=unlimited, customPolicy=free)
 └─ partnerId != null → PartnerEnrollmentProvider
         ├─ scope:      course_categories(partner_id) → L1 ids → courses  (explore 로직 재사용)
         ├─ entitlement: 상품/기간/총횟수 = 파고다 grant (§8 D5 확정 후 실연동)
         └─ used:       소진 원장에서 계산 (§7)
```

두 Provider 모두 `{ courses: EnrolledCourse[], entitlement: Entitlement }`를 반환 →
learn UI와 "수업 시작" 게이트가 동일 인터페이스를 소비한다. **기본 B2B 동작은 무변경.**

## 7. 소진(횟수 차감) 추적 — 신규 원장 테이블

"레슨 사용 횟수"·"나만의 수업 20회"는 안정적 카운터가 필요하다. lesson_results에서 파생하면
재수강·custom 분리가 취약하므로 **append-only 원장**을 둔다(D1·D2 반영).

```sql
-- DDL 초안. 실제 적용은 §15 DB 마이그레이션 규칙(manual-sql)에 따른다.
CREATE TABLE enrollment_usage (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      uuid        NOT NULL,
  partner_id   uuid        NOT NULL,        -- 자격 식별
  usage_type   varchar(20) NOT NULL,        -- 'regular' | 'custom'
  course_id    uuid        NULL,
  lesson_id    uuid        NULL,
  consumed_at  timestamptz NOT NULL DEFAULT now(),
  period_key   varchar(20) NOT NULL,        -- 자격 기간 식별(차감 회계 단위, D3)
  UNIQUE (user_id, lesson_id)               -- D2: 재수강 중복 차감 방지
);
```

- **정규**: `used = count(regular) + count(custom)` → `total`과 비교
- **무제한**: 일반 레슨 unlimited, `customUsed = count(custom WHERE period_key=현 기간)` → `20`과 비교
- 차감 시점: `lesson_results.completed_at` 최초 설정 시 1건 INSERT (D2). `UNIQUE`로 재수강 무차감 보장.

> ⚠️ 본 테이블은 **공유 Supabase 인스턴스**에 생성되므로 tutoring/backoffice 영향 검토 필요(§15.4).
> 소유 주체(speaking 전용 vs 공통)는 D5와 함께 확정한다.

## 8. 미결 항목 (개발 전 확정 필요)

| # | 결정 | 비고 |
|---|------|------|
| **D4** | 이수조건 **임계값 저장처** | 본서비스=과정 단위(backoffice), 파고다=상품 단위 추정. speaking은 데이터 보유→판정만. 저장처/소유 확정 필요 |
| **D5** | 파고다 자격 전달 방식 | 외부 API pull + 단기 캐시 vs 동기화 테이블 push. **파고다 API 스펙(엔드포인트·인증·요청/응답) 미확정** |
| **D5-a** | 파고다 측 사용자 식별자(`user_pk_id`) 확보 경로 | partnerId(기관)와 다른 값으로 아직 speaking에 없음. 파트너 진입 인증 설계에서 확보 |
| **D5-b** | grant↔소진 reconcile 주기/정책 | 드리프트 보정(§4.1) |

D4·D5는 파고다 스펙 의존 → 실연동(Phase D) 전에 합의한다.

## 9. 단계별 개발 (Learn §11 Phase 갱신)

| Phase | 내용 | 의존 | 파고다 스펙 |
|-------|------|------|------------|
| **A** | `EnrollmentProvider` 추상화 + AccessCode provider 이동 + 최근순 정렬 | 없음 | 무관 |
| **B** | `Entitlement` 모델 + 소진 원장(`enrollment_usage`) + 게이트 로직 + **목업 파고다 Provider** | A | 무관(목업) |
| **C** | 이수조건 공통 평가기(이수율·발화량·수업시간) 분리 | B | 무관 |
| **D** | 파고다 실 API 연동(자격 pull/캐시) + 잔여횟수 reconcile | B, **D4·D5 확정** | **필요** |

> Phase A·B·C는 파고다 API 스펙과 **무관하게 진행 가능** → 본서비스 무변경으로 골격을 완성하고,
> Phase D에서 파고다 실연동만 끼운다.
