0. 핵심 결론 — 두 스키마 / 두 거버넌스

Speaking은 하나의 Supabase 인스턴스 안에서 두 개의 Postgres 스키마를 사용한다. 둘은 네이밍 규칙도, 마이그레이션 거버넌스도 완전히 다르다.

5. 발화량 통합 집계 — 재검토 (2026-06-21 실측 반영)

실측으로 전제가 뒤집힘: ① public.module_histories는 63행뿐이고 전부 리딩 모듈(CLR·PRD…) — 스피킹 모듈·FRT 행 0. ② kpis는 전부 array라 마스터플랜이 가정한 kpis.sentence_count 객체 접근이 불가능. ③ saveModuleHistory()는 kpis를 아예 쓰지 않음. → 발화량 통합 집계는 현재 미구현 greenfield이며, 마이그레이션할 기존 로직이 없다.

cross-schema 비용 재평가: 두 스키마는 같은 Postgres 인스턴스라 federation 비용이 없고, 발화량 쿼리는 사용자·기간 한정이라 인덱스만 있으면 저렴하다. 진짜 리스크는 DB 비용이 아니라 핫 read 경로가 "임시" speaking 스키마에 결합되는 것 + Prisma가 그 스키마를 네이티브로 못 읽는 점이다.

speaking 스키마 삭제 내구성 — "둘 다 대비" (2026-06-21 결정)

C안은 speaking 스키마 삭제와 무관하게 발화량 집계가 보존되도록 설계됨. utterance_logs는 speaking 스키마로의 FK가 없고(session_ref는 추적용 text), 데이터는 복제 적재되므로 read 경로가 speaking에 의존하지 않는다.
대상speaking 스키마 삭제 시
발화량 챌린지(utterance_logs read) · 과거 누적치✅ 영향 없음 (이미 public 복제·FK 없음)
FRT 학습 기능 자체 · 턴별 상세 리포트❌ 중단/소실 — Session/Turn/평가가 speaking 스키마에 존재
  • 백필 해당 없음 (2026-06-21 실측): 기존 328 세션은 전부 비-UUID 테스터 데이터(users 매핑 0) → 보존할 실사용자 발화량이 없어 백필 미실행. "오늘 삭제해도 손실 0"이 이미 참.
  • 전제(필수 정리): FRT 엔진은 users.id가 아닌 자체 식별(이메일/닉네임/authCode) 사용. dual-write가 성립하려면 앱이 FRT 세션을 launch할 때 자기 UUID와 session_ref(Session.id)를 연결·보관해야 함 → 구현 1순위 통합점.
  • 미래 A (FRT 저장소만 교체): 상세 데이터 public 이전은 그때 별도 추가. utterance_logs 집계 계약 불변 → 재작업 없음.
  • 미래 B (FRT 폐기/대체): 추가 작업 없음. 누적 발화량은 utterance_logs에 남음.
  • 추상화 핵심: 발화 원천이 바뀌어도 write 훅의 소스만 교체, read/집계(source_module+session_ref)는 그대로.

  persona_code VARCHAR(20), daily_goal_min INTEGER NOT NULL DEFAULT 20,
  preferred_mode VARCHAR(20), subtitle_default BOOLEAN NOT NULL DEFAULT true,
  speed_default NUMERIC(3,1) NOT NULL DEFAULT 1.0, study_started_at DATE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now());

-- 2) 표현노트 / 망각곡선 / 표현카드 (§4.6·§4.7)
CREATE TABLE IF NOT EXISTS public.user_expressions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES public.users(id),
  expression TEXT NOT NULL, meaning TEXT, example_sentence TEXT, category VARCHAR(50),
  source VARCHAR(20) NOT NULL DEFAULT 'note',
  source_lesson_id UUID REFERENCES public.course_lessons(id),
  level INTEGER NOT NULL DEFAULT 0, review_count INTEGER NOT NULL DEFAULT 0,
  last_reviewed_at TIMESTAMPTZ, next_review_at TIMESTAMPTZ,
  status VARCHAR(20) NOT NULL DEFAULT 'active',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, expression));
CREATE INDEX IF NOT EXISTS idx_user_expr_user  ON public.user_expressions(user_id);
CREATE INDEX IF NOT EXISTS idx_user_expr_next  ON public.user_expressions(user_id, next_review_at);
CREATE INDEX IF NOT EXISTS idx_user_expr_level ON public.user_expressions(user_id, level);

-- 3) 나만의 수업 1:1 (§9.2)
CREATE TABLE IF NOT EXISTS public.user_personal_courses (
  user_id UUID PRIMARY KEY REFERENCES public.users(id),
  course_id UUID NOT NULL REFERENCES public.courses(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now());

-- 4) 기관 브랜딩 (§5.1)
CREATE TABLE IF NOT EXISTS public.institution_brands (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id UUID NOT NULL UNIQUE REFERENCES public.institutions(id),
  logo_url TEXT, logo_dark_url TEXT, primary_hex CHAR(7),
  skin_code TEXT NOT NULL DEFAULT 'default', app_name TEXT, app_domain TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now());

-- 5) 동적 수료조건 (§12)
CREATE TABLE IF NOT EXISTS public.program_configs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id UUID NOT NULL REFERENCES public.institutions(id),
  product_code TEXT, program_name TEXT NOT NULL,
  completion_rules JSONB NOT NULL DEFAULT '[]'::jsonb,
  daily_goal_minutes INTEGER NOT NULL DEFAULT 20, start_date DATE, end_date DATE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now());
CREATE INDEX IF NOT EXISTS idx_program_configs_institution ON public.program_configs(institution_id);

-- 6) 프로그램 등록 (§12)
CREATE TABLE IF NOT EXISTS public.user_program_enrollments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES public.users(id),
  program_config_id UUID NOT NULL REFERENCES public.program_configs(id),
  enrolled_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, program_config_id));
CREATE INDEX IF NOT EXISTS idx_enrollments_user ON public.user_program_enrollments(user_id);

COMMIT;
