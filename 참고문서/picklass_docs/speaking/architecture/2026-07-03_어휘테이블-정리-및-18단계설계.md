## 1. 어휘 테이블 현황 (4종)

| 테이블 | 행수 | 성격 | 비고 |
|---|---|---|---|
| `words_6000` | 6,566 | **구버전(뒤죽박죽)** | 큐레이션 3,000 + 원시 빈도 3,566이 한 테이블에 혼재. PK만 존재 |
| `words_12levels_6000` | 5,999 | 빈도순 6천단어 리스트 | 12 빈도레벨 × 각 ~500. **영국식 철자.** 표제어(lemma) |
| `words_30levels_3000` | 3,000 | 큐레이션 세트 | 100단어×30묶음(word_100). 뜻·품사 보유. **미국식 철자.** 표제어 |
| `words_cefr` | 7,988 | 외부 CEFR 참조 | English Profile 계열. headword+pos+CEFR(A1~B2). 영·미 철자 모두 포함 |

### 1.1 words_6000 (구버전)
- NULL 패턴으로 두 구획이 정확히 갈림: **큐레이션 3,000**(뜻·품사·그룹 있음) + **원시 빈도 3,566**(단어+빈도만).
- 죽은 컬럼: `WORD_100_1`, `WORD_10_1`(전 행 NULL). 한글 컬럼명 `구분`(품사).
- → 아래 `words_12levels_6000` / `words_30levels_3000` 두 갈래 정리본으로 **대체됨(폐기 후보)**.

### 1.2 words_12levels_6000
- `id` 1~5999가 `frequency_level`과 완전 단조(레벨1=id 1‑499, 레벨2=500‑999 …). **id == 빈도 전역 순위.**
- 레벨 내부는 알파벳순 → **빈도 해상도의 최소 단위는 500단어 밴드**.
- 죽은 컬럼: `word_100`, `word_10`(전 행 NULL, text).

### 1.3 words_30levels_3000
- `word_100`(1~30, 각 정확히 100개) = 100단어 청크 그룹. `column_5`=품사, `def_kr`=뜻, `column_7`=죽은 컬럼.
- 빈도레벨 1~6에 96% 쏠림 + 이상치(14/15/17).

### 1.4 words_cefr
- `cefr`는 **A1/A2/B1/B2 4단계뿐(C1·C2 없음)**. `coreinventory_2`는 98.6% NULL(죽은 컬럼).
- headword당 품사별 다중행 → 조인 시 `(headword)` MIN CEFR로 축약.
- PK·인덱스 전무.

## 2. 테이블 간 관계 — "깨끗한 포함관계 아님"

`words_12levels_6000`(6000)과 `words_30levels_3000`(3000)은 같은 원본 계열이나 **공유 키(FK)가 없고 `word` 문자열로만 연결**되며, 그마저 어긋난다.

### 2.1 3000 ↔ 6000
- 3000단어 중 6000에 존재: **2,453(81.8%)**. **547(18.2%) 오펀**(6000에 없음).
- 겹치는 2,453개도 `frequency_level` **71% 불일치** → 두 테이블의 빈도 랭킹이 독립적.

### 2.2 불일치의 근본 원인 (검증됨) — 표제어 문제가 **아님**
두 테이블 모두 표제어(lemma) 리스트다(복합어 0, 변화형 소수). 원인은 **서로 다른 소스 리스트**:

1. **철자 규약 차이**: `words_12levels_6000`=**영국식**, `words_30levels_3000`=**미국식**.
   - 예: grey↔gray, favourite↔favorite, theatre↔theater, analyse↔analyze.
   - → 같은 단어도 철자가 달라 조인 실패(오펀화).
2. **어휘 선정 차이**: 6000은 빈도 코퍼스 리스트라 일상어 누락(예: `beautiful`이 6000에 없음).
   오펀 547개 중 **513개(94%)가 words_cefr에 정식 표제어로 존재** → 유효 표제어인데 6000에만 없음.

### 2.3 words_cefr 커버리지
- 6000의 **65.9%(3,952)** 매칭. 미매칭 34%는 **고빈도레벨(7‑12)에 집중** — words_cefr가 B2까지만 존재(천장)해 C1/C2 어휘를 못 잰 것.
- 6000의 빈도레벨 × CEFR은 뚜렷한 대각선(빈도↑ = 난이도↑) → 빈도 기반 레벨링의 근거.

## 3. words_18levels_6000 설계

`words_12levels_6000`을 **픽클래스 18단계로 재분류**하고, `words_30levels_3000`의 고유 어휘를 흡수한 신규 테이블.

### 3.1 픽클래스 18단계 (고정 기준)
CEFR 6밴드 × `-/기본/+` 3세분 = 18. 코드 순서:
```
A1-, A1, A1+, A2-, A2, A2+, B1-, B1, B1+, B2-, B2, B2+, C1-, C1, C1+, C2-, C2, C2+
```
(picklass_rank 1~18. 출처: `picklass-backoffice` 파트너레벨매핑 고정 기준)

### 3.2 설계 3원칙
1. **빈도 순서 보존** — 레벨 부여를 `id`(빈도 전역 순위) 순서 위에서만 수행. `id` 오름차순 == `picklass_rank` 비감소(위반 0 검증).
2. **18단계 = CEFR 세분** — 위 고정 코드 사용.
3. **밴드 경계 = words_cefr 실측 재보정** (아래 §3.3).

### 3.3 CEFR 밴드 경계 (실측 재보정)
균등 2:1이 아니라, words_cefr 실측 분포로 경계를 보정:

| CEFR 밴드 | freq레벨 | id 범위 | 단어수 | 실측 평균 CEFR |
|---|---|---|---|---|
| A1 | 1 | 1‑499 | 499 | **1.10** |
| A2 | 2‑3 | 500‑1499 | 1,000 | **1.90** |
| B1 | 4‑7 | 1500‑3499 | 2,000 | **2.95** |
| B2 | 8‑9 | 3500‑4499 | 1,000 | 3.53 |
| C1 | 10‑11 | 4500‑5499 | 1,000 | 3.60* |
| C2 | 12 | 5500‑5999 | 500 | 3.77* |

- 각 밴드를 빈도(id)순 `NTILE(3)`로 -/기본/+ 3분할 → 레벨당 단어수는 밴드폭 비례(A1~166, B1~666, 다이아몬드형).
- A1~B1은 실측 평균이 목표(1/2/3)에 근접해 정합성 높음.
- *B2~C2는 words_cefr가 B2까지만 존재(천장)하여 **빈도 순위 기준으로 배정**(실측 검증 불가).

### 3.4 미국식 철자 정규화
- 6000(영국식)의 영국식 철자 **42개를 미국식으로 정규화**. 원 영국철자는 `word_uk`에 보존.
- 동철이의어 4건은 미국식에서 기존 단어와 철자가 겹쳐 `word`가 2행(정상, id 상이):
  `cheque→check`, `storey→story`, `tyre→tire`, `draught→draft`.
- 정규화 후 words_cefr 매칭 3,952→3,953(tyre→tire로 +1).

### 3.5 오펀 흡수 (30levels 고유 어휘 533개)
6000에 없는 30levels 단어를 **보충(supplement) 레이어**로 흡수(미국식 정규화 후 기준 533개):

- **밴드 배치**: words_cefr 실측 CEFR 우선(499개, 94%). 미매칭 34개는 `word_100`→밴드 매핑
  (word_100 1‑10→A1, 11‑15→A2, 16‑30→B1 ※ 실측 평균 CEFR 근거).
- **세부(-/기본/+)**: 밴드 내 `word_100`(30레벨 커리큘럼)순 `NTILE(3)`.
- **빈도**: `frequency_rank`/`frequency_level` = NULL(빈도 랭킹 없음).
- **자산 반입**: `def_kr`(뜻)·`pos`(품사)를 30levels에서 가져옴. `source='supplement'`.
- **id**: `100000 + 30levels.id`(원천 추적). 기존 5999행과 충돌 0.

배치 결과: A1 125 / A2 180 / B1 191 / B2 37 (초급 어휘라 C1/C2 없음).

**역할별 묶음**
- **① 식별·표기**: `id`, `word`(미국식), `word_uk`(영국식 원형)
- **② 레벨 = "얼마나 어려운가"**(CEFR 기반, 전 행 공통): `cefr_band` → `picklass_level` → `picklass_rank` (같은 정보의 다른 표현)
- **③ 정렬 = "레벨 안에서 어떤 순서로"**(EFL 우선, §3.7): `difficulty_source` / `word_100`(efl 원값) / `frequency_rank`(corpus 원값) → `difficulty_order`(최종 순번). 실무 정렬은 `ORDER BY picklass_rank, difficulty_order`
- **④ 참조·부가**: `cefr_ref`(공인 CEFR 실측) / `def_kr`·`pos`(30levels 반입) / `frequency_level`(추적) / `created_at`

**NULL 패턴 (헷갈리기 쉬운 부분)**

| 컬럼 | frequency 행 | supplement 행 |
|---|---|---|
| `frequency_rank` / `frequency_level` | ✅ 값 | ⬜ NULL |
| `word_100` | efl이면 값 / corpus면 NULL | ✅ 값 |
| `def_kr` / `pos` | ⬜ NULL | ✅ 값 |
| `cefr_band` / `picklass_*` / `difficulty_order` | ✅ 항상 | ✅ 항상 |

> **주의**: `difficulty_source`는 옛 `source`('frequency'/'supplement')와 **다르다**. frequency 행이라도
> 30levels에 있으면(약 2,471개) `efl`이다. 즉 "어느 테이블에서 왔나"가 아니라 **"EFL 노출 데이터가 있나"** 로 재정의된 값.

### 3.7 정렬 축 — EFL 우선 (difficulty_order)

**배경**: 원어민 코퍼스 빈도(COCA/SUBTLEX 등) ≠ EFL 입력 빈도. 한국 학습자는 원어민 말뭉치가 아니라
**교재·동화책·교실**을 통해 영어를 접하므로, 체감 난이도는 `word_100`(30levels의 EFL 노출순서)이 더 잘 반영한다.
→ 30levels와 6000의 빈도 불일치(상관 0.596)는 30levels의 오류가 아니라 **두 지표가 서로 다른 것을 측정**하기 때문.

**설계**:
- **레벨(picklass_rank)** = CEFR 기반 (모든 단어 공통, §3.3/§3.5 그대로).
- **레벨 내 정렬(difficulty_order)** = ① `word_100`(EFL) 있으면 그 순서 → ② 없으면 네이티브 빈도(`frequency_rank`=id) 순.
  - 한 레벨 안에서 **efl 블록(word_100순) 먼저, corpus 블록(빈도순) 뒤**로 분리 배치(두 척도를 섞지 않음).
- **`difficulty_source`** = `word_100` 보유 여부: `efl`(30levels 계열 ~3,004) / `corpus`(~3,528).

**EFL 커버리지 한계**: `word_100`은 초·중급(A1~B1)에 집중. 검증 결과 레벨별 efl 비율이
A1~A2는 지배적 → B2~C2는 corpus 지배로 얕아진다(상위 어휘의 EFL 노출 데이터 부재).
그래서 상위 구간은 네이티브 빈도로 보완하는 하이브리드가 불가피.

> **참고(폐기된 대안)**: 겹치는 단어를 앵커로 word_100→네이티브 빈도랭크를 **유추**해 단일 빈도축으로
> 통일하는 방안은 오차가 커(중앙 ~330랭크, p90 ~1,300랭크) 비채택. word_100은 커리큘럼 순서이지
> 빈도 순서가 아니므로 유추는 부적절. 대신 레벨(CEFR)을 축으로 두고 정렬만 EFL 우선으로 처리.
