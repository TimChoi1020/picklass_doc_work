## 1. 아키텍처 이해 (중요 — 다음 세션 전제)

```
┌─────────────────────────┐    handoff(external_access_tokens)   ┌──────────────────────────┐
│ speaking.picklass.com    │  ───────────────────────────────▶   │ 별도 학습앱 (모듈 런타임)   │
│ apps/web = 대시보드 셸    │                                      │ 녹음·ASR·5축·완료          │
│ (홈·수업·챌린지·리포트·MY) │   ◀── 학습결과 ??? (연동 미정) ───   │ speaking 스키마(FRT 엔진)   │
└───────────┬─────────────┘                                      └──────────────────────────┘
            │ authFetch
            ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ apps/api (NestJS) ── 공유 Supabase                                            │
│   public 스키마: users·courses·module_histories·utterance_logs·… (manual-sql) │
│   speaking 스키마: Session/Turn/TurnEvaluation/… (별도앱·Prisma migrate)       │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **apps/web = 학습자 대시보드/컴패니언 셸**. 실제 스피킹 학습은 **별도 앱**이 담당.
- `learn-flow/*`(pick·drill·measure·apply…)는 **빈 스텁**, `learn/page.tsx`는 학습 UI가 아니라 **콘텐츠 생성 디버그 패널**. `player/frt`·`player/quiz`는 "구현 예정" 플레이스홀더. → 셸에 모듈 런타임을 만들 필요 없음(별도 앱 소관).
- **두 Postgres 스키마**: `public`(8모듈 콘텐츠·결과, manual-sql 거버넌스) + `speaking`(FRT 엔진, 자체 Prisma migrate). 상세 [[speaking-db-two-schemas]] 메모리.

### ⚠️ 최대 미해결: 별도 학습앱 → public DB 데이터 유입 (미정)
- 발화량 집계 싱크 `utterance_logs`는 만들어졌으나, **실데이터를 넣어줄 주체(별도 학습앱)와의 연동 방식이 미정**.
- speaking 스키마 `Session.userId`는 우리 `users.id`(UUID)가 아니라 이메일/닉네임 → 현재 328세션 전부 비-UUID 테스터, public 매핑 0.
- 따라서 챌린지·홈 발화량·이수율은 **데이터가 들어오기 전까지 0/빈 값**. 배선·계산 로직은 검증 완료, 유입원만 부재.

## 3. 다음 세션 작업 (우선순위)

### P0 — 별도 학습앱 ↔ 백엔드 연동 설계 (블로커)
- **결정 필요**: 별도 학습앱이 (a) 완료 시 우리 API(`saveModuleHistory` 등) 호출 vs (b) speaking 스키마에만 쓰고 우리가 동기화(배치/트리거) vs (c) 신규 연동 채널.
- 핵심: **사용자 식별 정합** — speaking `Session.userId`(이메일/닉네임) ↔ `users.id`(UUID) 매핑 규칙 확정. 이게 풀려야 `utterance_logs`에 실데이터 유입 가능.
- handoff(`external_access_tokens`)로 셸→학습앱 진입 시 UUID·세션 상관키를 넘기는 흐름 설계.

### P1 — 셸 남은 화면 바인딩 (데이터 유입과 무관하게 가능)
- **리포트 탭**: 5축 레이더·약점분석·성장추적 → `GET /feedback/kpi-trends`·`/feedback/summary`·`/feedback/lesson-history`(기존 API 존재) 연동. 현재 홈 5축 레이더는 Mock.
- **수업 탭**: 과정·레슨 목록 → `getEnrolledCourses`(기존) 연동 상태 점검.
- 표현노트 **저장** 경로: 학습 중 표현 저장(별도앱/셸 어디서?) → `POST /expressions` 호출 주체 확정.

### P2 — 실데이터 활성화(운영, backoffice)
- `institution_settings.default_completion_*` 설정 → 수료조건 populated.
- `institution_brands` 설정 → 기관 브랜딩 활성.
- KPI 카탈로그: `LISTEN_COMPLETE`·`EXPRESSION_COM` code_items 미등록 → 추가.

### 참고 — 미적용/주의
- `pnpm-lock.yaml` 변경은 `pnpm install` 부산물(원복 가능).
- `pnpm lint`는 직전 `build`의 `.next/`를 훑어 에러처럼 보일 수 있음 → `.next` 제거 후 정상(소스 clean).
- speaking 스키마는 별도 거버넌스(Prisma migrate) — public 정책과 **혼용 금지**.
