## 1. 5단계 학습 흐름 (Pick-Speak Method)

학습자의 모든 학습 세션은 다음 5단계 흐름을 따른다.

| 단계 | 코드 | 명칭 | 역할 | 표준 시간 |
|---|---|---|---|---|
| 1 | PICK | 미션 픽업 | 시퀀싱 진입 | 1~2분 |
| 2 | LEARN | 입력 학습 | 콘텐츠 + 표현 5개 카드 | 3~5분 |
| 3 | DRILL | 정밀 드릴 ★ | 5축 즉시 피드백 (핵심 차별점) | 5~8분 |
| 4 | APPLY | 적용·자유화 | 3-Phase (Role-Play / Free Talking / 1MP) | 5~10분 |
| 5 | MEASURE | 측정·복습 | 결산 + 다음 추천 | 2~3분 |

**총 18~22분 골든타임**

## 2. 학습 모듈

LEARN · DRILL · APPLY 단계에서 시퀀싱 가능한 9개 모듈이 존재. 단계별 명세는 §7 참조.

| 코드 | 모듈명 | 단계 | 핵심 메커니즘 | LLM |
|---|---|---|---|---|
| LRN | Learn & Study | 2단계 LEARN | 강의 영상 + 표현 5개 카드 | ✗ |
| VLM | Vocabulary Listening & Meaning | 3단계 DRILL — 워밍업 | 어휘 청취·의미 확인 (무발화) | ✗ |
| SHD | Shadowing Drill ★ | 3단계 DRILL | 원어민 음성 따라 말하기 · 5축 피드백 | ✗ |
| SFB | Sentence Fill-in Blank ★ | 3단계 DRILL | 블랭크 문장 PTT 발화 · 5축 피드백 | ✗ |
| SMK | Sentence Making Drill ★ | 3단계 DRILL | 자유 문장 생성 · 20초 힌트 · LLM 코칭 | ✓ |
| RPB | Role-Play Basic ★ | 4단계 APPLY Phase 1 | 표준 다이얼로그 PTT 발화 | ✗ |
| RPF | Role-Play Free ★ | 4단계 APPLY Phase 2 | 분기 자유 대화 · 미션 5개 체크리스트 | ✗ |
| OMP | One Minute Presentation ★ | 4단계 APPLY Phase 3 | 30초 준비 + 1분 발표 · LLM 평가 | ✓ |
| FRT | Free Talking | 4단계 APPLY (별도) | 자유 대화 — 별도 설계 문서 참조 | ✓ |

**모듈 시퀀싱**: 학습자 레벨·목적·시간 기반으로 풀에서 1~3개 자동 선택. **사용자 노출 없음**.

> **구버전 코드 참고**: EDR(Expression Drill) → SHD·SFB·SMK로 세분화 / RPL(Role-Play) → RPB·RPF로 분리 (v1.4 기준)
> **FRT**: 개발 완료 모듈. 상세 진행 방식은 "Picklass Speaking_Free-talking 설계 v3.1" 문서 참조.

## 3. 5대 KPI 체계 (Speaking KPI Framework)

학습 성과 측정의 5축. 모든 화면에서 일관 적용.

| KPI | 영문명 | 측정 정의 | 색상 (HEX) |
|---|---|---|---|
| 발음정확도 | Pronunciation Accuracy | 음소·강세·억양의 정확성 | `#185FA5` |
| 유창성 | Fluency | 발화 속도·끊김·휴지의 자연스러움 | `#534AB7` |
| 문법정확성 | Grammatical Accuracy | 문장 구조·시제·일치의 정확성 | `#BA7517` |
| 화용성 ✦ | Pragmatics | 상황·역할·관계에 맞는 표현 선택 | `#D4537E` |
| 발화량 | Speech Output | 시간당 발화 분량의 풍부함 | `#0F6E56` |

**화용성**은 두 경쟁사가 측정 못하는 픽클래스 차별 지표.

### 모듈별 핵심 KPI 매핑

| 모듈 | KPI 코드 | 5대 매핑 |
|---|---|---|
| LRN | STAY_TIME, READ_COMPLETION | — |
| VLM | VOCAB_RECOG | — |
| SHD | 5축 전체 | 발음·유창·문법·화용·발화량 |
| SFB | 5축 + MISSION_USAGE | 발음·유창·문법·화용·발화량 |
| SMK | 5축 + EXPRESSION_APPROP | 발음·유창·문법·화용·발화량 |
| RPB | MISSION_USAGE · 5축 | 화용·5축 |
| RPF | MISSION_USAGE · INTERACTION_ACT · 5축 | 화용·5축 |
| OMP | LOGIC_STRUCT, RE_UTTERANCE, KEYWORD_RATE, OMP 4영역 · 5축 | 화용·구조·5축 |
| FRT | TOTAL_UTTERANCE, CHALLENGE_TARGET_HIT | 발화량 |

## 4.4 발화량 챌린지 (챌린지 탭 신규 섹션)

### 개요

VLM·DRILL·FRT·RPL·OMP 등 **모든 모듈에서 발화한 문장**을 통합 집계하는 발화량 챌린지.
FRT만의 지표가 아니라 학습 중 실제로 말한 전체 발화량을 측정하며, 챌린지 탭의 독립 서브페이지로 운영.
시간(분)이 아닌 **문장 수**를 1차 KPI로 사용. 학습자가 챌린지 탭에서 4종 미터를 한눈에 확인하고 관리.

### 4종 미터

| 미터 | 기간 | 기본 목표 | 비고 |
|------|------|---------|------|
| 일일 발화량 | 24h | 30문장 | 전 모듈 통합 집계. 탭 모드(마이크 OFF) 인정 (×0.6 가중치) |
| 주간 발화량 | 월~일 | 200문장 | 전 모듈 통합 집계. 주간 챌린지와 별도 추적 |
| 월간 발화량 | 1일~말일 | 800문장 | 전 모듈 통합 집계. 월간 리포트 자동 연동 |
| 페르소나 미터 | 롤링 30일 | 관심 토픽 50문장 | FRT·RPL 토픽 분류 기반 (주제별 세분화) |

### UX 규칙

- 미터 클릭 시 "부족 N문장" 진단 + 추천 모듈(VLM·DRILL·FRT) 딥링크
- 탭 모드 보충 배지: 이동 중 탭 모드만 사용해도 발화량 미터 누적
- 목표 달성 시 축하 토스트 + 뱃지 컬렉션(§4.8) 연동

### 진입 경로

챌린지 탭 메인(`challenge/page.tsx`) → "발화량 챌린지" 섹션 카드 → `challenge/utterance/page.tsx` (신규)

챌린지 탭 메인에는 **4종 미터 % 게이지 요약 위젯**만 표시하고, "자세히 보기 →"로 서브페이지 진입.

### API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/challenge/utterance` | 4종 미터 현재값 반환 |

**응답 예시**:
```json
{
  "daily":   { "current": 18, "target": 30, "pct": 60 },
  "weekly":  { "current": 87, "target": 200, "pct": 43 },
  "monthly": { "current": 340, "target": 800, "pct": 43 },
  "persona": { "topic": "비즈니스", "current": 22, "target": 50, "pct": 44 }
}
```

데이터 소스: `module_histories.kpis.sentence_count` 합산 (§12 수료조건 집계 로직과 동일 쿼리 재사용).

> 컴포넌트 구현 현황은 `2026-06-03_스피킹앱-IA구조정리-개발계획.md` §7 기술부채 참조.

## 4.5 마이 탭 — 앱 설정 알림 세분화

### 개요

기존 마이 → 앱 설정의 단일 "알림" 토글을 **5개 서브 메뉴**로 세분화.
백엔드 알림 발송 시스템(푸시 서버·알림톡·이메일)은 별도 장기 과제로 연기하고,
**프론트엔드 설정 UI + 사용자 선택값 DB 저장만 우선 구현**.

### 5개 서브 메뉴 상세

| # | 메뉴명 | UI 타입 | 내용 |
|---|--------|---------|------|
| 1 | 푸시 알림 | 펼침 목록 (9종 토글) | 오늘의 미션 / 스트릭 보호 / 챌린지 마감 / 친밀도 게이트 / 1MP 리마인더 / 발화량 부족 / AI 캐릭터 메시지 / 관리자 공지(B2B) / 복귀 캠페인 |
| 2 | 방해 금지 시간대 | 시간 범위 선택 | 기본 22:00~08:00, 사용자 변경 가능 |
| 3 | 알림톡 수신 동의 | 단일 토글 + 법적 고지 | B2C 한정, 법적 옵트인 |
| 4 | 이메일 캠페인 수신 동의 | 단일 토글 + 법적 고지 | 법적 필수 이메일(결제·환불)은 별도로 항상 발송 |
| 5 | 마케팅 정보 수신 동의 | 단일 토글 + 법적 고지 | 프로모션·할인 카테고리 |

### DB

```sql
-- users 테이블에 알림 설정 컬럼 추가
ALTER TABLE users ADD COLUMN notification_settings JSONB DEFAULT '{
  "push": {
    "mission": true, "streak": true, "challenge": true,
    "intimacy": true, "omp_reminder": true, "utterance": true,
    "character": true, "admin": true, "return": true
  },
  "dnd_start": "22:00",
  "dnd_end": "08:00",
  "kakao_opt_in": false,
  "email_opt_in": false,
  "marketing_opt_in": false
}';
```

### API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/users/notification-settings` | 현재 알림 설정 반환 |
| `PATCH` | `/users/notification-settings` | 알림 설정 부분 업데이트 |

### Frontend

변경 파일: `app/(tabs)/my/app-settings/page.tsx`

| 서브 메뉴 | 구현 방식 |
|---------|---------|
| 푸시 9종 | 섹션 내 토글 목록 (아코디언 펼침) |
| 방해 금지 | `HH:MM` 텍스트 입력 or 슬라이더 (V1 단순화: 텍스트 입력) |
| 알림톡·이메일·마케팅 | 단일 토글 + 한 줄 법적 고지 문구 |

설정 변경 시 `PATCH /users/notification-settings` 즉시 호출 (debounce 300ms).
서비스 함수: `lib/services/usersService.ts` — `getNotificationSettings()`, `updateNotificationSettings()` 추가.

## 4.6 망각곡선 챌린지 (챌린지 탭 + 홈 탭)

### 개요

지난 학습에서 발화한 표현 또는 **표현노트(§4.7)**에 저장된 표현을 망각곡선 기반으로 복습 시점에 제안하는 발화 챌린지. 홈 탭(미니카드)과 챌린지 탭(풀 카드) 양쪽에 동일 개념으로 노출.

"저장은 학습 중 → 복습은 챌린지 탭" 원칙 하에 게이미피케이션(스트릭·뱃지)과 자연스럽게 결합.

### UX 규칙

- 홈 탭: `DailyChallengeMiniCard` ("망각곡선 챌린지" 레이블, 미니 게이지 바, "도전하기" 버튼)
  - 완료 시 풀스크린 `CompletionModal` 노출 후 카드 잠금
- 챌린지 탭: `DailyChallengeCard` (Brain 아이콘, 표현 텍스트 박스, 진도 바, 풀너비 "도전하기" 버튼, violet 테마)
- 표현 출처: 지난 학습(레슨 결과) 또는 표현노트 저장 항목 중 망각곡선 알고리즘이 선택
- 컨텍스트 표시: "표현노트 · 5/6 저장 · 망각곡선 D+5" 형식

## 4.7 표현카드 챌린지 (표현노트)

### 개요

학습 중 저장한 표현을 챌린지 탭에서 반복 발화하여 레벨업하는 개인 표현 카드 시스템.
**저장은 학습 중(피드백 탭 표현노트 연동) · 복습은 챌린지 탭**으로 역할 분리.

| Lv | 색상 | 조건 |

| 0 | 회색 | 미학습 (복습 0회) |

| 3 | 보라 | 복습 5~7회 |
| 4+ | 초록 | 마스터 (복습 8회 이상) |

### UX 규칙

- 필터 탭: 전체 | 미학습 | 마스터
- 기본 3개 노출 + "더 보기" 펼침

- 망각곡선 챌린지(§4.6)와 동일한 카드 구조 (섹션헤더 + 컨테이너 + divide-y 리스트 + 풀너비 버튼)

## 5.1 기관 스킨·브랜딩 시스템 구현 계획

### 개요

기본 픽클래스 브랜드(로고·컬러)를 유지하되, 기관(institution) 단위로 로고와 스킨을 앱에 동적 적용할 수 있는 구조를 선제적으로 설계. 백오피스 기관관리 화면에서 설정하면 학습자 앱에 즉시 반영.

### DB 스키마 (신규 테이블)

```sql
-- institution_brands: 기관별 브랜드 설정
CREATE TABLE institution_brands (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id  UUID REFERENCES institutions(id) UNIQUE NOT NULL,
  logo_url        TEXT,          -- 라이트 모드 로고 (null = Picklass 기본)
  logo_dark_url   TEXT,          -- 다크 모드 로고 (null = logo_url 사용)
  primary_hex     CHAR(7),       -- "#185FA5" 형식 (null = Picklass 기본)
  skin_code       TEXT DEFAULT 'default',  -- 'default' | 'corp' | 'edu'
  app_name        TEXT,          -- Tier 3만 사용 (null = "Picklass Speaking")
  app_domain      TEXT,          -- Tier 3만 사용
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);
```

> tutoring과 Supabase를 공유하므로, `institutions` 테이블이 이미 존재한다면 참조만 추가. 신규 테이블은 speaking 전용.

### API 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/config/brand` | 현재 사용자의 기관 브랜드 설정 반환. institutionId 없거나 설정 없으면 Picklass 기본값 반환. |
| `PUT` | `/admin/institutions/:id/brand` | 백오피스에서 브랜드 설정 저장 (별도 Admin Auth 필요) |

**GET /config/brand 응답 예시**:
```json
{
  "logoUrl": "https://cdn.example.com/acorp-logo.png",
  "logoDarkUrl": null,
  "primaryHex": "#1A3B6E",
  "skinCode": "corp",
  "appName": null
}
```

### Frontend 구조

**BrandProvider** (`components/providers/BrandProvider.tsx`):
- 인증 완료 후 `GET /config/brand` 호출
- `primaryHex → hexToHsl()` → `--primary` CSS 변수 동적 주입
- 기본값(`#030213`)과 동일하면 CSS 변수 재적용 생략
- `logo`, `appName`은 `BrandContext`로 앱 전체에 공유

CSS 변수 매핑 (primary_hex 변경 시 연쇄 적용):

| CSS 변수 | 계산 방식 |
|---|---|
| `--primary` | `hexToHsl(primaryHex)` |
| `--primary-dark` | hsl에서 L -15% |
| `--primary-light` | hsl에서 L +35%, S -20% |
| `--primary-mid` | hsl에서 L +20% |

**변경 불가 CSS 변수** (BrandProvider에서 절대 건드리지 않음):
- `--kpi-pron`, `--kpi-flu`, `--kpi-gram`, `--kpi-prag`, `--kpi-vol` 및 각 bg 변수

**AppLogo** (`components/layout/AppLogo.tsx`): `logoUrl` 있으면 기관 로고, 없으면 Picklass 기본 로고.

**루트 레이아웃 적용 순서**: `AuthProvider → BrandProvider → PhoneFrame → children`
(BrandProvider는 반드시 AuthProvider 내부 — `user.institutionId` 활용)

### 티어별 적용 범위

| Tier | 적용 항목 | 구현 시점 |
|---|---|---|
| 1 Co-Brand | `logo_url` → AppLogo 표시 | MVP |
| 2 Skin | `primary_hex` → CSS 변수 주입 | MVP |
| 3 White Label | `app_name` → `<title>` + 스플래시, `app_domain` → Vercel 도메인 설정 | V1.1 |

### 변경 불가 항목 및 이유

| 항목 | 이유 |
|---|---|
| 5축 KPI 색상 | 학습 데이터의 의미적 일관성. 색상이 KPI 의미를 내포하므로 기관별 변경 시 학습자 혼란 |
| AI 캐릭터 외형 | 픽클래스 IP 보호 |
| 학습 모듈 흐름 | Pick-Speak Method 교수법 핵심 — 파트너도 변경 불가 |

### 백오피스 연동 (별도 작업)

`picklass-backoffice`의 기관 관리 화면에 브랜드 설정 섹션 추가:
- 로고 업로드 (S3/Supabase Storage)
- Primary Color 컬러피커
- 미리보기 (PhoneFrame 축소 렌더링)
- 저장 → `PUT /admin/institutions/:id/brand`

## 6. AI 캐릭터 친밀도 시스템

## 8. 핵심 차별 메커니즘 (6가지)

1. **5축 즉시 피드백 시스템** (DRILL 모듈) — 발음·유창·문법·화용·발화량 동시 시각화
2. **조용한 모드 (Silent Drill)** — 통근족·공공장소 사용성
3. **한국어 안전망** — 막힐 때 한국어 발화 → AI 영어 풀이 + 권장 표현
4. **블렌디드 1:1 화상 연동** — 실제 파고다 강사 + AI 학습 데이터 자동 전달
5. **발화량 챌린지 미터** (전 모듈 통합) — VLM·DRILL·FRT·RPL·OMP 모든 발화를 집계한 개인 발화량 추이 기반 동적 목표
6. **1 Minute Presentation** (OMP) — OPIc·토익S 답변 형식 일치

## 9.1 개인화 주제 학습 시스템 (Mode B 상세)

### 개요

정해진 커리큘럼 외에 **학습자가 직접 관심 주제를 입력**하거나 **오늘의 이슈 주제를 선택**하면, 해당 주제로 FRT(Free Talking) 세션을 진행한다. **1차 개발에서는 FRT 모듈만 제공**으로 한정한다.

### 진입 경로

학습 탭(Page A) 상단에 **"원하는 주제로 학습하기"** 섹션 노출:
1. **직접 입력**: 자유 텍스트 입력 → "시작하기" → FRT 세션 진입
2. **이슈 칩 선택**: 오늘의 트렌딩 주제 칩 탭 → 입력창 자동 채움 → "시작하기"로 진입

### 최근 이슈 주제 큐레이션

매일 갱신되는 8~12개의 트렌딩 주제. 분야 다양성 확보를 위해 카테고리 로테이션 적용.

| 카테고리 | 예시 주제 |
|---|---|
| 기술·AI | AI와 일자리의 미래, 오픈AI 최신 발표, 반도체 공급망 |
| 비즈니스 | ESG 경영 트렌드, 글로벌 협상 전략, 스타트업 투자 유치 |
| 사회·문화 | 원격근무와 조직문화, 디지털 헬스케어 |
| 시험·스킬 | 퍼블릭 스피킹, 비즈니스 이메일 작성, 영어 면접 |

큐레이션 주체: 초기 어드민 수동 입력 → 추후 Gemini 뉴스 요약 자동화.

### AI 세션 생성 흐름

```
학습자 주제 입력 (예: "AI와 일자리의 미래")
    ↓
Gemini 프롬프트 실행
  → 주제 분석 + 학습자 레벨/직무/관심사 컨텍스트 주입
  → FRT 대화 컨텍스트·가이드라인 생성
    ↓
lesson_results에 임시 레슨 ID 발급
    ↓
FRT (Free Talking) 세션 실행
    ↓
완료 후 lesson_results 저장 + 발화량 KPI 기록
```

### 정규과정과의 차이점

| 항목 | 정규과정 (Mode A) | 개인화 주제 (Mode B) |
|---|---|---|
| 콘텐츠 | 어드민 사전 제작 | Gemini가 FRT 컨텍스트 생성 |
| 제공 모듈 | 코스 기반 모든 모듈 | FRT 단일 모듈 |
| 진도 관리 | 코스 완강 진도 추적 | 단발 세션 (완료 이력만 기록) |
| 추천 | 시퀀스 기반 다음 레슨 | 유사 주제 재추천 |
| 완강 보상 | 뱃지·스트릭 연동 | 스트릭 연동 |

### 향후 고도화 포인트

- **주제 메모리**: 학습자가 자주 선택한 주제를 기억 → 홈 화면 미션 카드에 자동 반영
- **주제 피드백 루프**: FRT 결과 → 약점 KPI와 주제 연관 → 다음 이슈 큐레이션에 반영
- **B2B 커스텀 이슈**: 기업 고객사 전용 사내 주제(프로젝트·제품·업계 동향) 입력 채널 제공
- **모듈 확장**: 2차 개발에서 DRILL·RPL·OMP 모듈 추가 지원 고려

## 9.2 나만의 수업 (개인 커리큘럼) 구현 계획

### 개요

개인화 주제 학습(§9.1)을 통해 생성된 레슨은 학습자당 1개씩 자동 생성되는 **"나만의 수업"** 과정에 누적된다. 단발 레슨이 아닌 지속 성장하는 개인 커리큘럼으로 축적되며, 홈 화면과 학습 탭에서 접근 가능.

### 핵심 동작

```
학습자가 "AI와 일자리의 미래" 주제로 학습 시작
    ↓
POST /courses/my-curriculum/lessons { topic: "AI와 일자리의 미래" }
    ↓
① 나만의 수업 course 없음 → courses 테이블에 자동 생성 (1회만)
② Gemini가 레슨 콘텐츠 생성 → course_lessons에 추가
③ lesson_results에 결과 저장 (기존 흐름 동일)
    ↓
학습 탭 "나만의 수업" 카드에 레슨 누적 표시
홈 화면 Stats → 완료 레슨 수에 포함
```

### DB 구조

기존 테이블 재사용. 신규 테이블 없음.

```sql
-- courses 테이블에 나만의 수업 레코드 (학습자당 1행)
INSERT INTO courses (
  id, title, genre_code, status_code,
  level_code, total_lessons, created_at
) VALUES (
  gen_random_uuid(),
  '나만의 수업',      -- 고정 제목
  'personal',        -- genre_code로 구분
  'personal',        -- status_code로 구분 (정규과정과 분리)
  null,              -- 레벨 제한 없음
  0,                 -- 레슨 추가 시 increment
  NOW()
);

-- user_personal_courses: 학습자 ↔ 나만의 수업 과정 1:1 매핑
CREATE TABLE user_personal_courses (
  user_id    UUID REFERENCES users(id) UNIQUE NOT NULL,
  course_id  UUID REFERENCES courses(id) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

각 AI 생성 레슨은 기존 `course_lessons`에 추가:
```sql

-- course_lessons.status_code = 'personal'
-- course_lessons.skill_modules = AI가 선택한 모듈 배열
```

## 12. 동적 수료조건 시스템 구현 계획

### 개요

향후 고객사의 요청에 대비하기 위해 구현한다. 파트너사(기업·교육기관)마다 수료 기준이 다르다. 백오피스에서 상품 구성 시 수료조건을 설정하고, API를 통해 앱으로 전달. 홈 화면과 학습 탭의 프로그레스바·통계가 이 조건을 기반으로 **동적으로 변경**된다. 조건이 없으면 픽클래스 기본 통계(스트릭·레슨 수)를 표시.

### 수료조건 유형 (CompletionRuleType)

| 코드 | 설명 | 단위 | 예시 |
|---|---|---|---|
| `utterance_sentences` | 발화 문장 수 | 문장 | "3,000문장 달성" |
| `utterance_words` | 발화 단어 수 | 단어 | "10,000단어 달성" |
| `course_completion_pct` | 과정 진도 완료율 | % | "80% 이상 완료" |
| `lesson_count` | 완료 레슨 수 | 개 | "50레슨 완료" |
| `study_days` | 학습일 수 | 일 | "30일 이상 학습" |

복합 조건 가능: `utterance_sentences` AND `course_completion_pct` (모두 충족 시 수료).

### DB 스키마 (신규 테이블)

```sql
-- program_configs: 상품·프로그램별 수료조건 설정
CREATE TABLE program_configs (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id        UUID REFERENCES institutions(id) NOT NULL,
  product_code          TEXT,               -- 파트너 상품 코드
  program_name          TEXT NOT NULL,       -- "A기업 임원 영어과정 2026 H1"
  completion_rules      JSONB NOT NULL,      -- [{ type, target, unit, label }]
  daily_goal_minutes    INTEGER DEFAULT 20,  -- 일일 목표 학습시간
  start_date            DATE,
  end_date              DATE,
  created_at            TIMESTAMPTZ DEFAULT NOW()
);

-- user_program_enrollments: 학습자별 프로그램 수강 등록
CREATE TABLE user_program_enrollments (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             UUID REFERENCES users(id) NOT NULL,
  program_config_id   UUID REFERENCES program_configs(id) NOT NULL,
  enrolled_at         TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, program_config_id)
);
```

`completion_rules` JSONB 예시:
```json
[
  { "type": "utterance_sentences", "target": 3000, "unit": "문장", "label": "발화량" },
  { "type": "course_completion_pct", "target": 80, "unit": "%", "label": "과정이수율" }
]
```

### API 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/config/program` | 현재 학습자의 프로그램 설정 + 각 조건의 현재 달성값 반환 |
| `POST` | `/admin/programs` | 백오피스에서 프로그램 생성 |
| `POST` | `/admin/programs/:id/enroll` | 학습자를 프로그램에 등록 |

**GET /config/program 응답 예시** (수료조건 있을 때):

### 데이터 흐름 (발화량 실시간 집계)

현재 달성값(`current`)은 별도 집계 테이블 없이 기존 테이블에서 ON-DEMAND 계산:

| `study_days` | `lesson_results.completed_at` 날짜 DISTINCT 카운트 |
