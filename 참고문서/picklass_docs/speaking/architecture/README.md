# speaking / architecture

아키텍처 결정, 시스템 구성도, 데이터 흐름, 초기 셋업 등 **장기 참조용** 문서.

## 작성 기준

- 결정의 **WHY**를 남긴다 (대안과 트레이드오프 포함).
- 코드만 보면 알 수 없는 맥락(외부 시스템, 비즈니스 제약, 과거 경험)을 기록.
- 코드가 바뀌어도 결정 자체는 변하지 않는 정보.
- 짧게 변하는 작업 메모는 `features/`에.
