# Picklass 서비스 개발기획 (재정렬안)

**현행 개발자산(v0.20)을 시장조사 방향에 맞게 재정렬하는 개발 실행 계획**

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 성격 | "새로 만드는 계획"이 아니라 **"이미 만든 것을 시장 방향에 맞게 재정렬"**하는 개발기획 |
| 기준 문서 | Picklass 전체서비스 기획서 v0.20 · 지능형 수업 설계 자동화 로직(260421) · Voca_Reading 대화 전략 · 서비스기획서 v0.1(시장조사 반영) |
| 핵심 전제 | 개발은 이미 상당 진척(Reading 베타 운영, 엔진 다수 ✅구현완료). 문제는 역량 부재가 아니라 **우선순위·타겟 정렬** |

## 2. 시장기획 대비 Gap · 우선순위 재정렬 매트릭스

각 기능을 **재사용(Reuse) / 확장(Extend) / 신규(New)** + **Phase 재배치**로 태깅.

| # | 시장 요구 (근거) | 현행 개발 상태 | 판정 | 재정렬 방향 |
|---|---|---|---|---|
| G1 | **성장 리포트 = 지불 스위치** (과금 1순위, 클레임 1위 "학습상황 안 보임" 21%) | 부모/관리자 리포트가 Phase 3(Q4+) | **확장 + 대폭 상향** | Phase 3 → **Phase 1~2로 앞당김** |
| G2 | **진단이 리포트의 입력** (AI 진단 45%, 보습 1순위) | Level/Achievement/PPD 📋 기획만 | **확장 + 상향** | 온보딩 진입점으로 **조기 가동** |
| G3 | **내신 시험범위 기반 자동출제·서술형 쌍둥이** (자동출제 51%, 1순위) | 엔진은 *지문→교수법 수업*, 내신 출제 아님 | **신규(New)** | **별도 출제 트랙 신설** (확인 후 착수) |
| G4 | **Writing/서술형 = 어학원 1순위·진단 도구 겸용** (중등 서술형 급증) | Writing 모듈 Phase 2, 미작성 | **확장 + 상향 검토** | Reading 다음 **2순위 영역**으로 |
| G5 | **1차 타겟 = 중소형 보습(설계형 원장)** (대형은 니즈 낮음) | 개발이 파고다(대형 B2B) 중심(§16) | **재정렬(비개발)** | 파고다=유통 채널 유지 + **중소형 셀프서브 트랙 병행** |
| G6 | **커스터마이징 = 우리 학원 범위 종속** (도입 사활) | AI 자동생성+강사 편집 존재, 내신 범위 종속은 약함 | **확장** | 학원 범위(교과서·진도) 등록→출제 연결 |
| G7 | **원장 검수·AI 개입강도 조절** (완제품 불신) | §9.5 검수 골격 존재 | **재사용 + 노출** | 이미 있음 → UX로 전면화 |
| G8 | **과정 데이터(진짜 학습했나)** (완료여부 아닌 과정) | WPM·정확도 수집 ✅ | **확장** | 시도·시간·오답 → 리포트로 환류 |
| G9 | **12월 도입창 역산** (유일 도입 시기) | 파고다 Q별 일정만 | **신규 트랙** | 중소형 12월 파일럿 역산 일정 |

**핵심 통찰**: G1·G2·G7·G8은 이미 만든 자산을 **앞당기고 연결하고 드러내는** 일이다(저비용·고효과). 진짜 신규 개발은 **G3(내신 자동출제)** 하나이며, 여기에 개발 리소스를 집중해야 한다.

## 3. 재정렬된 개발 백로그

우선순위 순. (P0=12월 파일럿 필수, P1=파일럿 직후, P2=후속)

### P0 — 12월 파일럿 필수 (진단→출제→리포트 루프 최소 완성)

1. **성장 리포트 MVP** (G1) — 진단·수업·과정 데이터를 학부모용 리포트로 자동 생성. 화려함보다 *이 아이만의 정확한 데이터*. 키워드 입력→문장 자동완성.
2. **진단 온보딩** (G2) — Level Test를 신규생 입학 진입점으로 가동. 결과가 곧 리포트 초기값.
3. **내신 자동출제 트랙 착수** (G3, 신규) — 우리 학원 시험범위/교과서 텍스트 입력 → 문제·서술형 쌍둥이 자동 생성. *§9 콘텐츠 엔진·Writing 모듈 재활용하되, 입력을 '지문'에서 '내신 범위'로 확장.* → **개발팀 사전 스코핑 필요(§5).**
4. **중소형 셀프서브 온보딩** (G5) — Studio 자가가입 7일 체험(✅존재) 위에 중소형 원장용 간편 온보딩·학원범위 등록 UI.
5. **강사 검수 UX 전면화** (G7) — 생성물 검수·수정·AI 개입강도(최소/보통/최대)를 워크플로우 표준 단계로.

### P1 — 파일럿 직후

6. **Writing/서술형 영역 구현** (G4) — WFT 등 Writing 모듈 + 첨삭. 서술형을 진단 신호로도 활용.
7. **과정 데이터 → 리포트 환류** (G8) — 시도·시간·오답 패턴을 리포트·진단에 연결.
8. **Achievement Test·PPD 연동** (G2) — 정기평가로 성장 추이를 리포트에 축적.

### P2 — 후속 (파고다·B2C·고도화)

9. Speaking 7모듈 완성(파고다 스펙 연동, 계약 트랙 유지)
10. Orchestrator Rule→LLM 전환, T1 정밀 진단 로드맵
11. B2C 자유가입·구독, 게이미피케이션 풀세트, 다국어

## 4. 12월 도입창 역산 일정 (중소형 보습 트랙)

파고다(대형) Phase 일정과 **병행 트랙**으로 운영.

| 시기 | 중소형 보습 트랙 (신규) | 파고다 트랙 (기존 유지) |
|---|---|---|
| ~2026.08 | P0 1~3 개발 (리포트·진단·출제 스코핑/착수) | Speaking MVP, 엔진 Claude 연결 |
| 2026.09~10 | P0 4~5 + 내부 QA, 파일럿 학원 3~5곳 섭외 | 모듈 확대, B2C 랜딩 |
| **2026.11** | 파일럿 온보딩 준비 (학원범위 등록·리포트 템플릿) | — |
| **2026.12** | **중소형 보습 파일럿 런칭** (내신 없는 도입창) | 파고다 파일럿 |

## 5. 개발팀 확인 필요 항목 (착수 전 스코핑)

1. **G3 내신 자동출제**: 현 `analyzer`/§9 엔진이 '지문'이 아닌 '내신 시험범위 텍스트'를 입력으로 받아 문제·서술형 쌍둥이를 생성하도록 확장 가능한가? 신규 모듈이 필요한가? (가장 큰 미지수)
2. **G1 리포트**: 현재 수집되는 KPI·과정 데이터로 학부모 리포트를 구성하기에 충분한가? 추가 수집 필요 지표는?
3. **G2 진단**: §15 Level Test를 온보딩 진입점으로 조기 가동 시, 적응형(문항 분기) 구현 난이도·일정은?
4. **G5 타겟**: 파고다 계약 마일스톤과 중소형 셀프서브 트랙을 병행할 때 리소스 충돌 지점은?
5. **G4 Writing**: Writing 모듈을 Phase 2에서 P1로 당길 때 의존성(모델·채점 루브릭)은?

## 6. 성공지표(KPI) & 리스크

### KPI

- 파일럿 학원 리포트 자동생성 채택률 / 학부모 발송 빈도
- 원장 자료제작·출제·채점 노동시간 감소율
- 파일럿 → 유료 전환율, 재원율 변화
- 내신 자동출제 사용률(신규 트랙 검증)

### 리스크 & 대응

| 리스크 | 대응 |
|---|---|
| G3 내신 출제가 예상보다 큰 신규 개발 | §5 스코핑 우선, 불가 시 Writing 모듈 재활용 범위로 축소 |
| 파고다 트랙과 리소스 충돌 | 병행 트랙 분리, P0는 중소형 최소기능에 집중 |
| 리포트 앞당김이 엔진 안정화와 경합 | 리포트는 기존 데이터 재활용으로 경량 시작 |
| 12월 도입창 미스 | 11월 온보딩 준비 완료를 역산 마일스톤으로 고정 |
